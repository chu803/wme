## 阶段 373 · 网格平铺检测可行性 spike：负结果（按止损线停）

- 止损线：10 对中位召回 ≥0.50、精度 ≥0.80；干净图误触发 ≤2%。未达 ⇒ 停。
- 样本：45°、周期≈113 px 的圆角方框平铺；`|wm−clean|` **中位 0 / p90 0 / p99 15~29**（极淡）。
- ① 只开 grid：中位召回 **0.000**（早先 2.3% 是其它策略掩码碰巧重叠）；
  ② 旋转+ACF：参数全错、干净图 3/3 误触发；
  ③ 折叠 SNR 搜索：干净图（59）> 真实（7~49）⇒ 判据被画面纹理主导。
- **决定性对照**：把真值差值折叠是清晰的 ⇒ 水印确为规则格点、折叠方法有效；
  失败在"单图分离 0.5 灰阶信号"——场景高通 p99 是水印的 7 倍以上。
- 结论：本项目框架内不可达；要支持需平台模板（过拟合）或学习模型+数百对样本。
  **不接入**，保持「网格不承诺」。若将来有强对比度样本，应重跑 spike 而非引用本结论。

## 阶段 374 · 首屏不再等 205 MB 模型下载

- 旧流程：`ensure_model_ready()` 同步下载 → 下完才 `launch_ui()`；GitHub 不通时 ghproxy ~50 KB/s，
  新用户可能盯着空终端几十分钟（而 OpenCV 引擎本可先用）。
- 改：`model_startup_action` 两条路（sync / background）；缺权重时**界面先起 + 后台线程**下载与预热；
  `_warm_up_ocr()` 抽出、两条路都触发；`model_manager` 新增 `_DOWNLOAD_IN_PROGRESS` +
  `is_downloading()`（下载中 `is_model_available()` 恒 False，防半写文件被 `torch.jit.load`），
  `download_model` 用 `try/finally` 保证成功/失败/回滚后都清标记。引擎每次请求现查 ⇒ 完成后自动生效。
- 实测：空模型目录启动 → **UI 5 秒就绪（http 200）**，后台同时"开始自动下载"；
  入口 `rc=0`（3421 passed / 38 skipped / 6 deselected，456.79s）。
- 守卫：`test_model_bg_start374.py` 4 例 + `test_main_entry` 编排顺序改两条路。
