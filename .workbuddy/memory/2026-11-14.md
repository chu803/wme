## 批量延迟（~20s/图）诊断：先读码， profiling 待 CPU 空闲

- 读码结论：**两条主成本都已有优化**——检测 `DETECT_MAX_SIDE=1280`（已降采样），
  修复 `INFER_CROP_TO_MASK=True`（裁剪到掩码 bbox+256 margin，中位 1.51× / 2048² ~3.2×）
  且默认引擎 `INPAINT_AUTO_PREFER=opencv`（快、保守）。
- ⇒ ~20s/图**不是**「整图推理」的 naive 成本；真正主因需**干净的分阶段 profile**
  （检测 vs 修复 vs 后处理 vs PNG 保存）才能定位。门禁占用 CPU 期间不做计时探针（会污染）。
- 纪律：不臆测改检测/修复路径（属行为改动，需 brainstorming + 用户同意 + 干净基准）。
  下一步＝门禁跑完后做一次单图分阶段计时，再决定杠杆。

### PNG 保存杠杆：已轻量实测（仅 cv2+numpy，门禁占 RAM 时安全跑）

- 环境约束：门禁占 RAM 后整机 **97% 内存负载、仅 430MB 空闲**（gate 进程 2.3GB）⇒
  不能再起 EasyOCR（会 OOM 杀掉门禁）。但 PNG 保存只需 cv2+numpy（~150MB、单线程 zlib，
  24 核机器竞争小）⇒ 单独轻量实测 `.scratch/profile_png407.py`（2048² 真实角标图）：
  | 格式 | 耗时 | 体积 | 相对 level 6 |
  | --- | --- | --- | --- |
  | PNG level 6（现状） | **1.62s** | 5.24MB | 1.0× |
  | PNG level 3 | 0.63s | 5.43MB | 2.57× 快、+4% |
  | PNG level 1 | 0.43s | 5.70MB | 3.76× 快、+9% |
  | PNG level 0 | 0.17s | 12.61MB | 9.8× 快、+141% |
  | JPEG q90 | 0.02s | 0.97MB | 80×（有损，不合无损承诺） |
- **修正假设**：2048² PNG 保存仅 ~1.6s，**不是主因**（E3 的 ~11s 是 3000² + 当时机器负载，
  不能线性外推到 2048²）。降 level 6→1 省 ~1.2s/图（约占 20s 的 6%，仍无损、+9% 体积）——
  是个安全小杠杆，但**不是大鱼**。真正 ~20s 主因大概率在 CPU 检测，待重 profile 确认。
- 数字属「门禁负载下、单线程保存」口径，相对倍率稳健；干净绝对值待门禁后复核。

### 非检测阶段实测：检测占 ~86%（轻量探针，真实后处理 + 忠实复刻 OpenCV 修复）

- 思路：默认引擎 OpenCV（cv2.inpaint，无 torch）、后处理/保存/缩略图都是 cv2 ⇒
  除检测外都能轻量测（`.scratch/profile_nondetect407.py`，仅 cv2/numpy/config +
  真实 `services.postprocess_service.postprocess`；其导入链 superres/quality_service
  均懒加载 torch，已核实 ⇒ 门禁占 RAM 时安全）。再用 ~20s 总量反推检测占比。
- 实测（2048² 真实角标图，右下板块掩码 1.66%，crop 686×446=7.3%）：
  | 阶段 | 耗时 |
  | --- | --- |
  | inpaint（OpenCV，裁剪到掩码） | 0.23s |
  | postprocess（真实，默认 sharpen=0.6） | 0.67s |
  | save PNG level 6 | 1.83s |
  | thumbnail + load | 0.04s |
  | **非检测合计** | **2.78s** |
- **结论：检测（CPU EasyOCR）≈ 17s，占 ~20s 的 86%**。修复/后处理/保存都是小头。
  口径：~20s 锚点来自外部报告；非检测是本机门禁负载下实测；检测占比是**反推**，
  待门禁后用 `profile_batch407.py` 直接测检测坐实。即便总量是 15s 或 25s，检测仍是大头。
- 杠杆方向（属行为/架构改动，需用户同意，不擅自做）：
  · 单图延迟受 CPU EasyOCR 限制（已降采样 1280）；再降分辨率/关 OCR 会伤承诺召回 0.8078，风险高。
  · **批量吞吐**可考虑多进程并行（24 核但 16GB RAM，每个 EasyOCR ~2.3GB ⇒ 约 3–4 路），
    是较大架构改动；或 GPU（本机无 NVIDIA）。
  · PNG level 6→1 仍是安全小杠杆（省 ~1.2s/图），但只占 ~6%，不是主菜。
