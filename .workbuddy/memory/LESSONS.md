# 核心经验（改核心链路前必读）

> 从 `MEMORY.md` 拆出（阶段 91，避免 MEMORY.md 超限被截断）。
> 括号内编号 = 首次形成该经验的阶段。**经验是可复用的判据，不是结论摘抄。**

1. **优先绝对量，相对量只兜底**（49/59/86）；相对阈值随尺寸**双向失真**（57/58）；同族参数主动列一遍防 `_env_int` 静默钳制（66）。
2. 提召回同看**精确率**（52）；**并集恒优于替换**（67）；「聚合/合并」必须放**全部过滤之后**（82）。
3. 恒定比例选像素会跨界复发（49/59）→ 中位数 + k·MAD + 绝对下限；局部结构**先于**全局渐变。
4. 质量口径 = **交付链路**（60/68）：禁按软 mask 混回原图；掩码区 PSNR ≤0.01 dB。
5. **死代码会伪装成已验证功能**（61）；形态与像素内容分开审计（70）；「手工脚本 + 文档」维持的结论 = **没有守卫**（83）——判据是「改坏它有没有任何自动化会失败」。
6. **预设 = 策略子集**，互斥机制必补**并集**用例（62）；单轮成立推不出多轮成立（72）→ 双线契约。
7. 度量口径与扰动解耦（63）；**度量会奖励劣化**（A3）；推理契约用**探针伪模型**断言（A3）；旧结论作废用**修正横幅**而非删除；护栏/阈值必须**真值标定**并溯源实验值写成测试（64/65/83）。
8. 区分**信息论极限**与判据缺陷（69）：换编码就成功 → 判据缺陷；阈值扫描双向。
9. 容错会成为错误的藏身处（79）：配「容错未被触发」断言 + 注入式反例。
10. 同一语义的多条入口必须**共用同一实现**（80）；**主路径正确是其他路径缺陷最好的掩护**。
11. **dtype 决定语义**（85/87）：`arr[idx]` 中 idx 是 uint8 就取行号 → 掩码入口先规整为 bool；含**乘法/累加**的公式同理，uint8 的 `x*x` 是**取模**（200²=64），静默给出确定但错误的结果、不报错。
12. **测试的规模也是判据的一部分**（85）：资源/复杂度缺陷必须用真实尺寸 + `tracemalloc`；**资源错误是语义错误的入口**。
13. 新判据要与既有判据**正交**而非更强（84）；**比值型优先**于绝对量型；取「安全窗中心」而非指标 argmax；合成构造先自证「在目标统计量上有信号」。
14. 陈旧结论会在无关改动中被「顺带复活」（85）→ 重跑旧脚本时把「是否与文档一致」也当断言；改分数函数做**逐用例 before/after**。
15. 门禁的「跳过」必须与「通过」区分（83）；**展示路径不得有能力让功能失败**（83）。
16. **形态学算子会毁掉判据本身**（86）：闭运算破坏「靠描边定义的孤岛」；两类分布区间 < 阈值分辨率时加**正交**判据而非继续切阈值。
17. **「测试引用密度」是有效的审计选点指标（87）**：从**覆盖度荒漠**开始审计，命中率高于从「哪里看起来复杂」开始。
18. **性能优化的精度损失声明必须量化（87）**：实测成立也要**写成测试钉住**，防后人以「优化」名义改坏。
19. **「常量输入下正确」是最危险的假绿（87）**：测试构造必须**让目标统计量有信号**。
20. **改写状态时清点所有配对的观测字段（87）**：改 `level` 就扫 `detail`/`message`/`error`。
21. **多出口模块必须共用「决策」而非「模板」（88）**：默认路径**恰好一致**（最危险），非默认分支立刻分叉。扫描：展示字面量**全仓 grep**，命中 ≥2 处且不在同一共享函数内 = 候选。
22. **「缺数据」必须与「零」在数据结构上可区分（88）**：显式带 `assessed/unassessed` + **对账断言：分项之和 == 总数**。
23. **守卫「单一真值来源」要用哨兵，而非字符串断言（88）**：把共享函数 `monkeypatch` 成哨兵；谁把逻辑**内联**回去就拿不到哨兵 → 立刻失败。
24. **选点指标本身也要被审计（89）**：别名导入下字面计数严重低估 → 分母换为「导入该模块的测试文件里的 `def test_` 个数」。**度量工具本身也是被测对象。**
25. **失败分支的精确原因不得被泛化结论覆盖（89）**：一个布尔同时承担「算不出」与「已算但不匹配」→ 报错必然误导。修法 = **加独立字段 + reason 走优先级链**，而非把措辞改含糊。
26. **返回 dict 的键集必须与分支无关（89）**：用**键常量 + blank 构造函数**作唯一来源 + **键集对账断言**。
27. **可选依赖的资源配对用伪模块注入断言（89）**：把 `sys.modules["pynvml"]` 换成记录 `inits/shutdowns` 的假模块，参数化在成功 + 错误路径断言成对。**静默 `except` 是泄漏最好的藏身处。**
28. **横切面模块的缺陷，影响面是「所有模块的排查能力」（90）**：日志/异常/配置这类被全站调用、却不进核心数值的模块，**零覆盖 = 零守卫**，应优先审。
29. **「资源被谁持有」要在进程级清点（90）**：同一文件被 N 个 handler 各自持有时「写」看起来正常，只有**轮转/改名/删除**才暴露 → 验证必须**真触发轮转**，不能只写一写看有没有输出。
30. **对照实验只改一个变量（90）**：1/2/4 → 0/31/171，结论干净可复现。
31. **库函数的「同名语义」必须实测，不能凭记忆（90）**：Python 3.13 `StreamHandler.close()` **不关流**、`FileHandler.close()` 才关流。
32. **「配置项存在」≠「配置项生效」（91）**：`Final[str]` 常量 + 一整套「白名单校验 + 回退 + 告警」看起来完备，但**零调用点**时只是装饰。判据：给配置项喂两个不同值，看**最终实参**是否不同——相同即名存实亡。**死代码最危险的形态不是"多余的函数"，而是"让人以为某项配置受控"。**
33. **白名单必须从运行时枚举，不能抄写（91）**：硬编码白名单会同时「拒绝合法项」与「放行不存在的项」，而后者的代价可能是**联网请求**（Gradio `Theme.from_hub`）。凡有事实来源（`BUILT_IN_THEMES`）就必须投影它。
34. **「同值」会伪装成「同源」（91）**：品牌色恰好等于 Gradio `blue-600`/`sky-500`，故 `Theme.to_dict()` 天然含 `#2563eb`——用「字典里有没有这个值」判断硬编码残留会得出**错误结论**；必须改判「被 `set()` 覆盖的键是否由哨兵驱动」。
35. **进程级全局注册表必须在入口清空（91）**：声明了用途却无人调用 = 声明≠实现。累积型缺陷的特征是**单次运行完全正常**（2.00× 只在重复构建时出现）→ 守卫必须**显式构造"第二次"**。
36. **守卫被绕过时，「降级」会变成「崩溃」（91）**：同一语义的多入口必须共用同一函数（阶段 80 的复现）。且「降级」是**静默**的，测试必须把「取到了键名本身」当硬失败。
37. **跨层共享令牌的等价性用「产物」判定，而非「源码文本」（91）**：收敛令牌必然改变源码字面量（`rgba(37, 99, 235, 0.35)` → `rgba(37,99,235,0.35)`），CSS/JS 语义不变——用双门禁的**产物指标**背书，比逐字节比对源码更可信。
38. **注入式反例的还原校验不能"自比"（91）**：多处替换的注入脚本必须**只读一次原始字节**（循环内重复写备份会把备份变成"已注入一次"的内容）；还原后必须与**注入前记录的外部哈希**比对——与脚本自己刚记住的值比对**永远成立**，无法发现还原错误。
39. **「门禁全绿」≠「产品可用」，检查手法是"反读每条红线"（92）**：一套评测只对「漏」设红线、不对「过检面积/误报绝对量」设红线时，系统会朝「宁可多擦」演化且**永远亮绿**（实例：真实图 `mask_coverage` 16.15%、`mask_iou` 0.0617、87 区域/图，而无任何红线）。**每条红线都必须能回答「它防的是哪一类『变坏』」；若某类变坏没有红线覆盖，那类就是当前盲区。**
40. **真值标注的"缺席"会被读成"没有漏检"（92）**：真值里只标了 60 个 `corner_logo`，而清单声明 30 张全是 `mixed` ⇒ 未标注的水印不计入 FN，召回被结构性抬高到 1.0。**标注覆盖面本身就是一项必须审计的契约**：必须加「清单声明 vs 真值样式的集合相容性」脚本检查，并允许把「确无该风格」显式登记为 0——**"没标"与"没有"必须可区分**。
41. **「区域级指标好」会掩盖「掩码级指标差」（92）**：`mean_iou` 0.657（单框对得还行）与 `mask_iou` 0.062（整幅只有 6% 对）的**背离本身就是诊断**——不是「框偏了」，是「**框太多了**」。凡有「逐项匹配 + 整体并集」两层的任务，两层都要报，且**整体层不可缺**。
42. **质量结论必须写清"用了谁的掩码"（92）**：`mask_source=truth` 的对决只证明「给定正确掩码修得好」，不能推出端到端可用。**任何"修得好不好"的结论都要标注掩码来源**，并同时给出真值掩码与预测掩码两列。
43. **「已有守卫」必须问「它在当前分布下会不会触发」（93）**：`core/detector` 早有 30% 覆盖率上限，30 张真实图里只有 2 张触发 ⇒ 与没有守卫在功能上等价，却提供「已经有保护」的错觉。凡发现「已存在阈值」，先量化它的**触发率**。
44. **漂移方向必须从红线方向派生，不能各写一份（93）**：`mask_coverage` 越高越坏，而旧的漂移实现只查「下滑」⇒ 掩码膨胀到 30% 也不报。**同一指标的「变坏方向」只能有一个真值来源。**
45. **均值之比 ≠ 逐图比值的均值（93）**：`total_pred/total_truth = 47×` 与门禁实测 `16.62×` 相差近 3 倍，因为各图真值面积不同。**凡"倍率/比率"类指标，必须先明确宏平均还是微平均，并以实现输出为准标定阈值。**
46. **跨口径的指标不可直接比较（93）**：`detect` 模式下 `seam_delta` 更小（9.50 < 13.88）**不是修得更好**，而是掩码区从 0.97% 膨胀到 16.18% 后**区域构成变了**、指标被稀释。**区域级指标的"区域构成"是口径的一部分**，任何"变好/变坏"的结论都必须锁定口径。
47. **「没标」必须与「没有」可区分（93）**：真值稀疏会被结构性读成零漏检。修法两层——① 允许把「确无该类」**显式登记为 0**；② 把「覆盖面不足」做成**可打印/可落盘/可被 CI 要求**的信号（默认告警 + `--strict-scope` 升级），而不是默认失败——**永久红灯会让门禁失去拦回退的作用**。
48. **注入式反例的前置清场必须被验证，不能假设（93）**：注入前先断言「原始状态全绿」；本次该断言第一次运行就拦下了被改坏的两个既有用例。**基线本身是红的时，后续"捕获成功"毫无意义。** 另：期望捕获的用例若**直接构造数据而不经过被注入的函数**，它不会失败——这是预期行为，需在实验记录里注明，否则会被误判为守卫失效。
49. **新增数据字段会打破既有断言，要区分「行为变更」与「掩盖失败」（93）**：给基线快照加 `scope`、给 `mask_iou` 加护栏，都会让原本用 `mask_iou=0.0` 隔离漂移逻辑的用例先撞红线。正确做法是**换用未登记契约的预设来隔离同一意图**（语义不变、意图保持），并在 docstring 里写明为何调整，而不是删断言或放宽红线。
50. **「聚合层缺字段」会让整个维度不可见（93）**：`mask_coverage` 在单图里算了很久，却没进聚合结果 ⇒ 红线无从挂载。**凡"只算不聚合"的指标，都等于该维度在门禁层不存在。**
51. **阈值「标定」会留下一份没人管的人读副本（93）**：`real_gate.py` 头部契约摘要是红线值的**第二份拷贝**，标定把 `coverage_ratio` 从草稿 60 改成实测派生的 25、`mask_iou` 从 0.045 改成 0.042 之后，摘要仍写着旧值——**代码绿、文档绿、只有那张人读的表在说谎**。凡「机器可判定的常量」+「同一文件里的人读说明」并存时，标定动作必须**同时**改两处；更优解是让说明**引用常量**（`{thr}`）而不是复述数字。这是「同一语义两套实现」家族在**注释层**的形态（对应 24/77）。
52. **「选点/排名」类指标必须固化为脚本 + 口径守卫（93 复核）**：`ui/services/core` 的「覆盖度荒漠」排名历来靠**临时探针手算**，于是同一条目在不同阶段写下互相矛盾的值——`auto_pipeline` 记为 `575/10＝57.5`（第三荒漠），2026-09-17 重算实为 **`389/50＝7.8`**（中游），分母差 5 倍。**凡用来做决策的排序，都必须有①可运行的脚本 ②口径自检断言（如「已审过的模块引用数必 >0」）**；否则它就是「手工脚本 + 文档维持的结论」（经验 5），会**安静地**把决策引向错误目标。附带教训：**分子（行数）分母（引用）各自都有"字面计数"陷阱**，别名导入、`from pkg import mod`、patch 字符串三种写法都要算。
53. **测量装置会污染被测对象（94）**：量具**自己的测试文件**会被匹配器算成对目标模块的「引用」——补上 `tests/test_audit_selector.py`（它断言 `ui/tab_models` 是第一荒漠）后，该模块命中文件从 `[test_ui.py]` 变成 `[test_audit_selector.py, test_ui.py]`，比值 **65.5 → 11.4**、掉出前三。修法 = **显式登记 `META_TEST_EXCLUDES`**（不做隐式名字猜测）。**关键区分**：真在测该模块的**审计测试应当计入**（`test_ui_audit94.py` 使比值合法降到 ~13.8）——所以该指标衡量的是「当前测试密度」，**不能**据此判断「还有没有缺陷」。
54. **遍历式守卫必须先断言集合非空（94）**：`for x in SET: assert …` 在 SET 为空时**循环体一次都不执行 ⇒ 断言空转**。注入「清空 `META_TEST_EXCLUDES`」时这条守卫生效地全过（哑巴守卫）。**凡「遍历某集合做断言」的守卫，都要先钉住集合非空**，否则集合被误清空时守卫会静默失效。
55. **注入未捕获时，先怀疑注入本身（94）**：I1 注入「把 `_INITED = True` 移回开头」时未被捕获，一度被读成"守卫是哑巴"——实际是我的锚点把置位挪到了抛点**之后**，**根本没复现原缺陷**。**注入式反例是双向验证：既验证守卫，也验证注入。** 锚点必须能在语义上重建"改坏前"的状态。
56. **「一时显著」不是不变量（94）**：曾写下 `top1 ≥ top2 × 2.5`（当时 65.5 vs 22.2），审计完目标后立刻失效（22.2 vs 19.5）。**把瞬态性质写成断言 = 自造假红灯**。凡基于"当前差距很大"的断言，都该问：这个差距在正常演进的下一步还成立吗？
57. **「先置位、后干活」的惰性初始化必须问「干到一半失败留下什么」（94）**：`_ensure_init` 把 `_INITED = True` 写在初始化之前 ⇒ 中途抛异常后注册表**永久半初始化且不再重试**，异常却仍冒给调用方。叠加「可选增强」（`_init_discover` 自动发现）的 I/O 失败能拖垮整个注册表 ⇒ 内置槽都拿不到。修法两层：**可选增强就地降级**（告警 + 跳过）+ **置位移到全部成功之后**（并说明重入性）。

66. **构建期全局注册表的累积缺陷是「同源类」（96）**：任何在 `build_app()` 期间写入的进程级全局注册表，必须在**构建入口**清空，否则重复构建线性累积（0→5→10），且**单次运行完全正常、不报错、门禁测不出**。凡新增此类注册表，直接复用 `clear_*` 模式，与既有清口同生命周期——这是阶段 91 U3「i18n 注册表累积」的同源兄弟。
67. **UI 回调异常护栏一致性（96）**：同一功能页里的 `on_*` / `process_*` 回调，若有兄弟回调守了异常，自己就不能裸奔——「有的地方有 try/except、有的地方裸露」本身就是缺陷（同风险面多种处理方式）。审计手法：扫某页全部回调，检查异常收口是否一致；凡裸露渲染/I/O 调用，比对同文件其它回调的处理。
68. **字节切片注入：偏移必须全部取自同一原始缓冲（96）**：做「删块 + 替换」式注入时，所有 `start/end` 偏移必须从**未修改**的原始字节算；任何会改变长度的 `.replace` 必须发生在 splice **之后**，否则偏移错位、文件损坏（表现为 `SyntaxError` 而非守卫失败）。中文全角字符的正则易误命中更早的同名块 ⇒ 改用函数体内 `rfind` 唯一锚点，并把「锚点未命中」与「守卫未捕获」分别报错（经验 64）。
- **69**：生成器式 Gradio 回调的 `yield` 必须与 `outputs` 严格等长（97）——凡 `def fn() -> Generator` 且绑定多 `outputs` 的回调，**逐早退分支**核对 `yield` 元组长度；「无输入 / 无可处理 / 参数缺失」等早退分支最易漏字段，漏一个就在该路径触发 `ValueError: Expected N outputs, got M` 运行时崩溃，且单测很难覆盖（需构造走到早退的输入）。修复即补齐缺字段，与兄弟早退分支对齐。
- **70**：承诺「不抛错只返回提示」的回调必须在实现层兜底（97）——若函数的文档/契约承诺「异常时返回可读提示而非抛错」，其实现必须 guard 住**所有**外部调用（含渲染引擎、IO），否则契约与实现不符、异常穿透到所有裸调它的上层 UI 回调泄露 traceback。**根因修复（在契约函数内部兜底）优于在每个调用方各自包 try/except**——一处护全部，并消除「调用方守与不守不一致」的同类缺陷（与经验 67 镜像）。
- **71**：页面回调若只被测试引用、未绑定事件，是死代码（97）——`ui/tab_batch.on_gallery_select`（无 mode 版）定义但只被 `tests/test_compare_viewer.py` 引用、未绑到任何 Gradio 事件（线上走 `on_gallery_select_with_mode`）。审计时**登记为边界、不盲目删除**——删除会牵动测试，且它作为「默认模式」文档化 API 仍有价值。
- **72**：**i18n 泄漏 ≠ 缺键，判据是「英文界面」而不是「键表」**（98）——`t()` 缺键会返回 **key 本身**（降级不崩），所以「键表完整性」这类检查**抓不到「有键不用」**：`utils/recommend_view` 有 4 处硬编码中文（`、` / `：` / `（无）` / `exc="无推荐结果"`），**中文界面 100% 正常**，只有切到 `en-US` 才暴露。注意 `t()` 只管**模板**、不管**入参**——`exc="中文"` 这类「把文案当参数传」最隐蔽。**凡文案生成层，回归测试必须含一次语言切换 + CJK 码点扫描**，否则测的只是「中文界面下的中文」。
- **73**：**同一可视化语义的两条实现，钳制口径必须写进断言**（98）——`_char_bar` 钳制 `[0,1]`、`bars_html` 不钳制，当前**无可触发差异**（上游无 >1 分），肉眼审、甚至跑全量测试都发现不了。这类「**潜伏分叉**」的判据不是「现在对不对」，而是「两条通路对同一**极端输入**的输出是否一致」。修时**只钳该钳的那一半**（宽度），保留另一半（展示值）与另一通路一致——**不然修一个分叉会造出另一个**。
- **74**：**硬编码文案的通解守卫 = AST 扫字面量，而不是 grep 关键词**（98）——grep 中文会被注释与 docstring 淹没（被审模块注释里往往全是中文）。正确做法：`ast.parse` → 取 `ast.Constant` 中的 `str` → **剔除 docstring 节点**与 `__main__` 子树 → 扫 CJK 码点。这样守卫对本模块**尚未写下的第 5 处、第 50 处**同样有效（grep 只守得住你已经想到的那几个词）。并且**守卫自己要有「植入一个泄漏必须变红」的自检用例**，否则它可能因 `skip` 集合写错而永久绿。
- **75**：**「收敛」必须连带刷新基线，否则改进可以静默回退；而且守住它的未必是红线**（99）——把 `DETECT_MAX_COVERAGE_RATIO` 0.30→0.15 后 coverage 由 0.1618 降到 0.1266；把闸改回 0.30，门禁**确实红了（EXIT=1）**，但报的是**漂移**而非红线——因为回退后的 0.1618 / 16.62× **仍在红线内**（0.19 / 19.5×）。⇒ 判据：**改完核心指标后，亲手把改动撤回去，看门禁是否变红**。只改行为不刷基线 = 收敛等于没做。
- **76**：**同向的一组指标，必须逐项核对「守卫是否存在」，不能因为「红线里写了」就当作被守住**（99）——「过检三项」同向（`mask_coverage` 高=坏、`coverage_ratio` 高=坏、`mask_iou` 低=坏），但 `coverage_ratio` **原本完全不在 `REAL_TOLERANCES` 里**（零漂移容差），`mask_iou` 的容差 0.20 还比 `mask_coverage` 的 0.15 宽。⇒ 实际只有一项被漂移守着。防法：写一条**把这一组指标整体回退**的注入反例，逐项断言「每一项都被拦下」——这条断言在首轮就抓出了缺口。
- **77**：**不能为了让测试通过而调窄阈值**（99）——要让 `mask_iou` 抓住本次回退，容差得压到 ≤9.2%（它只动 −9.2%），余量不足 0.2%。调到 0.09 能让测试变绿，但那是把守卫**钉在噪声上**。正确做法：承认该指标的职责边界（**正交交叉校验**，守崩坏而非守变化），并**把这条边界写进测试注释**，防日后有人把容差越调越紧。判据：**如果调整阈值的唯一理由是「让断言通过」，那多半是断言的期望写错了。**
- **78**：**「看起来最优的改法」必须用双侧实测去否决或采纳**（99）——`edge_text` 在真实图侧贡献 30% 过检且**零命中**，抬 `DETECT_EDGE_ABS_DELTA` 在真实图侧等价于砍掉 −4.58pp（禁用残差通路后 4.845%→0.269%）；但合成侧 45→65 掉召回 **3.3pp**、ΔPSNR **1.32dB**，45→90 直接崩（R 0.6873 / ΔPSNR 8.887），且 config 注释写明 25~60 是**刻意留的宽平台**。⇒ **只在一侧测量的「优化」，很可能是在另一侧换代价**；单侧漂亮的结果必须拿到对侧门禁上复验，否则「修好一个指标」= 悄悄卖掉另一个。
- **79**：**判据与目标概念「语义重叠」时，阈值路线必然失败，应改用显式 opt-in 开关**（100）——MSER 找「稳定极值区」，而自然照片**本身就由大量稳定极值区构成**；15 个真命中的实心度仅 **0.25~0.58**（比误报还低），`solidity≥0.7` 会**杀 100% 真命中**、只削 93.8% 误报，边缘锐度 P90≥100 只削 6.5% 误报。⇒ 这不是「阈值没调好」，而是**判据与目标概念没有相关性**——此时最诚实的处置不是再切一刀，而是**承认该通路净增量为负、把它变成默认关闭的可选项**，并在红线层守住它不被悄悄打开。
- **80**：**「关掉一条通路」的结论必须两侧量、且逐用例对照，而不是只看聚合指标**（100）——只在真实基准上消融，可能把合成基准的东西卖掉（经验 78 的延伸）。本次合成侧 12 用例里**只有 1 个动**（`photo/corner_logo` P 0.620→0.914）、**其余 11 个逐字节相同**——这才是「不误伤」的**直接证据**；只报「合成聚合指标没变差」是**推断**（本次聚合其实**变好了**：P 51.8→54.2、IoU 49.7→52.1，所以「没变差」的表述本身就不准确）。逐用例对照才是事实。
- **81**：**重标红线/刷新基线会连带打破「夹具里硬编码旧基线」的用例，必须全量跑才能捞净**（100）——改 `real_gate` 红线后，**单跑新增测试文件全绿，全量跑才暴露 7 处失败**（`tests/test_real_gate.py` 的 `_preset_m` 默认值 / `test_boundary_values_pass` 边界值 / `test_drift_improvement_never_fails` 的 0.09；`tests/test_watermark_scope95.py` 的 `_MEASURED` 全套 / `test_metrics_unchanged...` / markdown 的 `0.0385`）。这些是**合法的连带损伤**（夹具语义本就是「恰好等于当前基线」），**修法是把夹具同步到新基线，而不是放宽红线**（经验 77 的镜像）。⇒ 凡改红线/基线，**必须全量跑**，并预判「哪些用例把旧值写死了」。（103 再验证：本次全量跑捞出 1 处 `test_grid_resolution` 的写死值。）
- **82**：**同一文件的多处编辑必须串行提交，且逐条重读校验**（100 再现，阶段 91 已登记）——本次把同一文件的 3 处编辑**并行**发出（同一消息内 3 个 Edit），工具报告「成功」但**实际只落盘 1 处**（另 2 处静默丢失），靠事后 `grep`/`Read` 复读才发现。⇒ 多编辑**改一处、读一处**；文件级写操作不可并行。**旁证**：本行为是「静默」的——工具返回成功、无任何警告，与经验 82 家族（静默缺陷）同源。
- **83**：**「验证」必须基于终态证据，不能基于中途快照；也不能用「先前说过通过」代替复读**（102 复检）——交付报告前复读 `pt102final.log`，只见 893 字节、进度停在 **57%**，一度被判为「后台进程被中断 ⇒ 原 exit=0 无证据」。补跑全量后才确认原进程其实**跑完了**（后来同一日志补全为 `PYTEST_EXIT=0` + 100%）。⇒ 两个方向的错都能发生：**把「进行中」误读为「已失败」**（本次），以及**把「摘要声称通过」当作「已通过」**（本次若不复检就会把阶段 102 的零回归结论建立在别人一句话上）。判据：① 引用测试/门禁结论前，先看**日志尾部的汇总行**（`N passed` / `EXIT=` / `PYTEST_EXIT=`），没看到就不引用；② 后台任务的**状态字段**（running/completed）与**日志内容**要一致时才下结论；③ 报告里的每个质量数字都应有**本次可复现的出处在 `%TEMP%` 日志**，而不是「上一轮跑过」。
- **84**：**聚合指标只能告诉你「哪里痛」，逐策略隔离量测才能告诉你「为什么痛」**（103）——阶段 102 的结论是「多擦 0.58×~11.36×、双向失准」，据此**假设**主因是「角标的框太小」，准备做「向外扩到完整实体」。逐策略隔离量测（直接调各策略函数，绕开合并阶段）后发现主因完全是另一条：**只有区域框、没有形状掩码的策略（`edge_text`）在整框填满**——该通路在 4 类上涂 10.0/6.8/9.0/7.0% 图面，而 `mask% ≈ bbox%`（证明几乎 100% 是矩形填充），精确率低到 **0.009**。**若不归因就直接实现外扩，会去优化一个不是瓶颈的东西。** 同一次量测还发现：同一指标在 **4 图样本上是 0.58×、10 图样本上是 0.89×** ⇒ 门禁/基线必须建立在足够样本量上（阶段 102 已把「4 图样本不宜当精确基线」登记为边界，本阶段取得了它的实证）。判据：**凡从聚合指标推导成因，先做一次按通路/按类型的隔离量测再动手。**
- **85**：**复用「另一条通路的判据」时，必须问「先验是否相同」**（103）——把半透明通路的证据门限（`DETECT_MIN_DELTA` + `k_sigma×σ`）原样搬到「框内二次确认」上，看起来是最省事、也最「一致」的做法（判据全项目只有一处定义）。但两者的**先验不同**：框外任何像素都可能是噪声，需要高置信；框内「这里存在水印」的先验**已由策略建立**，判据只需回答「这个像素是否属于该实体」。实测沿用全域门限会把**极淡水印的子集**剔掉：`edge` 框内真值 17 210 → 12 933 px（丢 24.9%），恰好等于 `faint_tiled.removal` 的 0.019 跌幅。**「共用一套判据」是可贵的工程目标，但它不等于「共用一套阈值」。** 修法：判据复用、**阈值按先验单独标定**（`DETECT_BOX_REFINE_K_SCALE`，附扫描表）。
- **86**：**一个「大幅改进」的改动可能同时带坏一个指标——只有多门禁并行才抓得住**（103）——`k_scale=1.0` 那一版在**合成质量门禁**（P 54.2→59.3、IoU 52.1→57.1）与**真实图门禁**（掩码覆盖率 0.0745→**0.0319**、掩码 IoU 0.1163→**0.2075**、过检 7.65×→**3.27×**）上都是**大幅**改进，唯独 `e2e 修复侧门禁` 判红（`faint_tiled.removal` 越过红线）。若只有前两条门禁，这一版会被当成纯胜仗合入。⇒ **门禁的「视角」必须互相不同**（合成×修复链 / 真实×检测 / 真实×修复），否则一种视角的改进会掩盖另一种视角的劣化。并且**判红之后不要立刻调阈值**——先做定向探针把机制量化出来（本例：丢 4 277 px ⇒ 0.019），再据此改实现。
- **87**：**「刷新基线」的动作必须与「红线判定」在同一次运行里完成**（103）——`--update-baseline` 若写完就 `return 0`，它就成了一条**绕过检查的静默通道**：任何人只要带上这个开关，门禁就恒绿，且基线已经被改掉。改法：刷新后**继续走红线判定**（此时漂移层恒为 0，但红线层仍会执行），并在输出里明说「基线已刷新，继续按红线判定」。判据：**凡「写基线 / 写期望值 / 生成快照」这类动作，都要问「它能不能被用来绕过判定」。**
- **88**：**pytest 在用例内首个失败断言处停止 ⇒ 同一用例里后续断言不会被验证；同步夹具必须逐条量测所有被写死的值**（103）——`tests/test_grid_resolution.py::test_grid_640_gradient_unchanged` 第 69 行断言精确率失败（0.386→0.651），**掩盖了第 70 行的 IoU 断言同样过期**（0.385→0.650）。只改报错那一行、再跑一次就会「换个行号继续红」。修法：**对该用例涉及的全部被写死值一次性重新量测**（本例两个都改），而不是跟着 traceback 走。
- **89**：**注入式反例优先用配置开关完成，而不是改源码**（103）——本项目已有 `WME_*` 环境变量，故反例可以直接 `WME_DETECT_BOX_EVIDENCE_REFINE=0` 启动脚本，**不改一行代码、完全可逆、可重复执行、不需要备份与 sha256 校验**。结果：门禁 EXIT=1，命中 3 项（红线 `edge_text.overdraw` 6.87>6.50 + 漂移 collateral +16.4% / overdraw +37.5%）。⇒ 凡新增能力都配一个 env 开关，反例成本就从「编辑+备份+还原+核对哈希」降到「加一个环境变量」。
- **90**：**「缺席」与「过松」是两种缺陷，症状相同、修法相反**（104）——上一阶段把目标写成「`tiled_enh` 判据过松」，实测成因是**守卫缺席**：基础通路在阶段 82/84 装的两道连通域守卫，这条通路重新取了一遍候选却一道都没接，于是同一批**已被基础通路否掉**的像素从这条通路重新进入并集。两者的修法不同：「过松」要调阈值（而阶段 99 已用两侧量否决过这条路），「缺席」要**把已有的判据接上**（零调参、零新阈值）。⇒ 拿到「某通路指标差」这类症状时，先问一句：**它该有的判据都到位了吗？**（本项目已有同族先例：`_ssim_channel` / `inpaint` 掩码值域 / MSER 通路，症状都是「静默全绿」。）
- **91**：**「一致」不是理由，量测才是——成套搬东西之前必须做单件隔离**（104）——两道守卫在基础通路上一起装、一起工作，把它们**成套**搬到平铺通路是「最一致」的做法（第一版就是这么做的）。单件隔离实验却显示两者贡献极不对称：真实照片削减率 **26.0% vs 72.9%**（两道全接 75.4%），而「多余的那一道」恰好是**弱信号杀手** —— 它把「纹理 + 极淡平铺」整类抹零、「渐变 + 网格」砍掉 28% 召回，合成 6 场景 IoU 合计 2.319（只纹理）→ 1.882（两道）。顺带得到机制解释：本通路门限（k=2.2）比基础通路更严，**弱而软**的自然光影梯度够不到门限，能穿过严门限的是**锐利自然纹理** ⇒ 只有纹理守卫是这条通路的真靶子。**成套搬 = 把别人的标定条件一起搬了过来，而那条件可能不成立。**
- **92**：**「零断言放宽」应当作选型的硬约束，而不是事后的辩护**（104）——「两道全接」那版让两条既有用例失败（`test_run_case_textured_faint_tiled_low_coverage` 整类抹零 + `test_rescue_recovers_blackout[256-webp75-textured-grid]` 兜底失效）。当时的第一反应是「用数据证明旧断言的前提是错的（实测该检出精确率 0.073 / 召回 0.014），然后改断言」——这个念头本身有风险：它让「改断言」成为最省力的出口。更有价值的问法是 **「有没有既拿到同等收益、又完全不碰断言的配置？」** 实测有（只接纹理守卫），而且它在多数口径上更好。⇒ 把「需不需要放宽断言」当成一个**信号**（它在说「你正在把系统推向一个它本来不该去的状态」），而不是一个**决定**。
- **93**：**豁免/例外契约要用「间谍」钉住调用参数，不能靠输出反推**（104）——低分辨率兜底臂要豁免纹理守卫（`guard=(_rescue_depth == 0)`）。若只断言「兜底后掩码非空」，后人删掉豁免时代码照样跑得通、只是那条 e2e 用例会红，**很难定位**；而且「输出非空」可能是别的原因造成的。改法：monkeypatch 目标函数记录每次调用的 kwargs，直接断言「主臂传 `True`、兜底臂传 `False`」。⇒ 凡「在特定上下文里传不同参数」的契约，测**参数本身**，不测它的下游效果。
- **94**：**指标口径要写成「集合表达式」，才能判断目标与参数是否可兼得**（105）——「外溢」自阶段 102 起就被当作一个「待优化的百分比」，全项目没人写出它的定义式。写出来只有一行：融合式 `image*(1-m3*s)+result*(m3*s)` 在 `m3=0` 处逐字节等于原图 ⇒ **改动区 ⊆ support(proc_mask)** ⇒ 外溢下界 ≈ `dilate·周长/掩码面积`（固定宽度环带 / 面积）。于是「外溢 ≤5%」与「dilate ≥1」**在数学上不可兼得**，不需要再试参数。⇒ 凡写下「指标 X 要 ≤ y%」，先写它的**集合表达式**：若它是「新增区域 ⊖ 已有区域」这类形式，就能直接读出下界，避免把不可能的目标当成「还没调好」。
- **95**：**一维扫描会把 A 的功劳记到 B 头上**（105）——阶段 65 判定「默认膨胀 = 2」，依据是「细字在 dilate 2~4 时残留最低」。但当时的 `run()` 只在 dilate 维变档，`feather` **仅在 `d == 默认值` 时才换挡**，于是 **(0,0) 这个角从未被测量**，把「高斯羽化把 1px 笔画权重压到 0.33」的代价记到了膨胀头上，并以默认值形式固化了两代。补齐交叉档后：细字在 `(0,0)` 的残留 9.09/8.48，与 `(2,5)` 的 9.95/8.44 持平——真自变量是 feather。⇒ 凡声称「参数 X 有效」，必须给出 X 在其余参数**全部**档位下的响应，或至少补齐各维最小值组成的角点；**扫描网格的角点是最容易被漏掉、又最容易藏因果的地方**。
- **96**：**融合权重被稀释 = 静默的半量修复**（105）——`m3 = proc_mask/255` 意味着 `m3<1` 的地方修复只被**按比例施加**。`feather=5` 作用在 1~2px 笔画上时，二值核峰值只剩 0.33 ⇒ 细字/网格「修了，但只修了三成」，而代码不报错、指标也只表现为「残留偏高」。⇒ 凡出现「看起来修了但有残影」，**先查融合权重而不是换模型**；凡是「用模糊后的掩码当权重」的管线，都要问一句：**掩码内部的权重还是 1 吗？** 同族缺陷：85（dtype 决定语义）、87（uint8 溢出）、102（值域决定是否空操作）。
- **97**：**改进必须立刻接入门禁，且新指标要有双向守卫**（105）——外溢自阶段 102 起就是已知数字（23.3%），却因为**没有任何红线会因它变大而失败**，安稳地存活了三个阶段，直到本阶段才收敛。只把数字印在报告里 = 「手工脚本 + 文档维持的结论」（经验 5）。另：新接的指标必须**双向守卫**——改动全在掩码内 ⇒ 外溢 = 0、全在掩码外 ⇒ 外溢 = 1；只测一侧的指标与恒绿门禁一样是哑巴。并且红线要选**有物理含义的值**（本例 5%），而不是「实测 × 1.3」（0.7%×1.3≈0.9% 会在浮点噪声上乱响，同经验 77）。
- **98**：**先探针、后改码：「按推理确实存在的缺陷」也可能已经被同一处改动顺带修好了**（105）——推理链是：`bin_mask = threshold(羽化后的 proc_mask)`，故 1px 笔画会被羽化压到阈值以下 ⇒ 引擎收不到 ⇒ 静默不修（与 102 同族的 P0）。这个推理**每一步都对**，但探针实测显示：新的 `max(soft, binary)` 已经把 255 核心交回给 `bin_mask`，两种方案**逐字节相同**（16 个组合）。若不做这一步，就会多改一处公开契约、多担一份风险、多一条无收益的回归面。⇒ **「推理正确」不等于「修法必要」**；改第二处之前，先量它现在是否还存在。
- **99**：**「加判据」与「加守卫」是两个方向，别把守卫成套搬到形态不同的通路上**（106）——半透明通路的两道连通域守卫（自然光影 82 / 纹理稠密 84）在那条通路上是纯胜；把它们接到「框内证据场」（同一套 `_residual_fields`，看起来最「一致」）后，`grid`/`faint_tiled` 也确实更好，**但细笔画的边缘小字被误杀**：`edge_text` 去痕率 0.2407 → **0.0905（−62%，越红线）**。机制：守卫的统计量在「候选 ∪ 2px 邻域」上算，**1~2px 笔画的邻域几乎全是笔画边缘** ⇒ 被判成「处处高频的纹理」。⇒ 判据可以共用，**守卫是形态相关的**；搬之前先做单件隔离（经验 91 的加强版）。
- **100**：**几何膨胀必须与判据分开量测**（106）——阶段 103 在 `pad=2` 的几何下扫出「`k_scale=1.0` 会伤 `faint_tiled` 的去痕率（越红线）」，于是取了折中的 0.5。阶段 106 把 `pad` 收敛到 1 后重扫，发现 **0.65 反而全面更优**、1.0 的伤害也不复现。根因：`pad` 是 5×5 的面积放大器，它把「门限效应」掩盖了。⇒ 凡历史结论涉及**两个相乘的参数**，必须连同**当时的另一个参数取值**一起引用；参数之间会耦合，别把一个几何前提下的结论当成普适规律。
- **101**：**「能降指标」不等于「该降」——取舍判据里必须有「不得伤害被承诺的那一类」**（106）——把合并阶段的收口膨胀（`DETECT_MERGE_DILATE`）设为 0，四类 `overdraw` **全面更好**（corner 0.886→0.669、edge 3.80→2.77、grid 5.02→3.74），纯几何看它「多余」；但它同时把**唯一承诺类型 `corner_logo` 的去痕率从 0.3555 打到 0.2264（−36%）**⇒ 那 1px 覆盖的是水印的抗锯齿/羽化边缘。⇒ 面对「某个全局参数能让多类指标同时变好」的方案，先查**它是否动了被承诺那一类的分子**；并把这个反例写进 config 与门禁注释（否则后人会再试一次）。
- **102**：**红线标定必须双约束：防误判 + 防静默回退**（106）——沿用两代的规则「新值 × 1.30，向宽松侧取 0.05 整数倍」只满足前者；当**改进幅度 < 30%** 时，回退值会落回红线之内：`grid.overdraw` 旧值 6.206 < 1.30 × 5.015 = 6.52 ⇒ 红线形同虚设，而该指标的漂移容差（15%）又抓不住 +23.8% 之外的小回退。⇒ 新增约束②「红线必须低于改动前实测值（留 5% 余量）」，取两约束交集里最宽松者；并逐项校验「回退值 > 新红线」。**凡改进幅度小于红线余量，旧口径必然失效**——先算这个比值再动手标线。
- **103**：**零集也要登记：无法被自动判定守住的改进，如实写下来**（106）——本阶段 `precision` 只 +5.0%，既低于红线 15% 的分辨率、也低于其 25% 的漂移容差 ⇒ **该改进目前没有任何自动判定能守住**。正确动作是**显式登记**（并说明「把容差压到 <5% 等于把守卫钉在噪声上」，经验 77），而不是为了「有所守」去拟合一个更紧的阈值；同理，某一口径的排序若只剩噪声级差距（本阶段 `detect` 侧 IoU 在 dilate 0/4 间差 0.5pp），该写成**容差式断言**并注明实测值，不要再写成严格不等式。
- **104**：**补监控维度时，优先挑「不需要真值」的量**（107）——`real_gate` 对四类未承诺预设**结构性失明**（它们没有真值，precision/recall 算不出来），于是「把守卫关掉」这类回退**没有任何自动判定会失败**；换成**掩码面积**（`掩码像素 / 图面像素`）后立刻可判，因为面积不需要真值。⇒ 面对「这块没护栏」的缺口，第一个问题不是「怎么补真值」，而是**「有没有一个不需要真值、却对这族缺陷敏感的量」**。
- **105**：**红线必须低于量程上限，否则是哑巴红线**（107）——`ai_grid` 在真实图上的面积最大值 14.97% 正贴着检测器内置面积闸 `DETECT_MAX_COVERAGE_RATIO=0.15`（说明该通路的面积被闸截断）；若把面积红线设到 ≥0.15，它将**永远不会触发**。⇒ 给任何指标标红线前，先找它的**量程/饱和点**（本项目的同族现象：经验 77 的「钉在噪声上」、99 的「恒红=哑巴」）。
- **106**：**恒为零的指标不能设「均值上界」，要改设「静默守卫」**（107）——`ai_gradient` 在 30 张真实图上**一次都没触发**（0/30），「设计上恒为零输出」这条自述由此第一次被量测确认。对恒零量设 `≤ 0×1.15` 的上界会**恒红**；正确做法是换成**计数型不变量**：`n_with_mask ≤ 0`——一旦它开始在普通照片上触发，门禁变红并要求人来更新契约。⇒ 对「零集」要区分「恒零是契约」与「恒零是缺陷」：契约用不变量守，缺陷用上界守。
- **107**：**输出编码不得决定退出码**（107，真实缺陷）——Windows 上 stdout 被重定向到管道时按 **ANSI 代码页（简体中文 = GBK）** 编码，而 `real_gate` 的横幅含 `⚠`（U+26A0，GBK 编不出）⇒ `print(to_markdown(...))` 抛 `UnicodeEncodeError`，**退出码 1**；更糟的是 `--update` 的写盘在打印之后 ⇒ **连刷新基线也一起失败**。修法：脚本入口 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。⇒ 凡"判定结果要经过打印"的脚本，都要问一句：**打印失败会被读成判定失败吗？**（同族：经验 90 的"静默全绿"、经验 83 的"中途快照当终态"。）
- **108**：**新增基线字段必须同步测试夹具；「旧版基线」的判定要看「键是否存在」而非「值是否为空」**（107）——给基线加 `aggregate.area_only` 后，凡是手工构造基线字典的单元测试都会撞上新加的「旧版基线请 --update」硬失败。两条处置：① 测试夹具补上该键（**同步夹具，不放宽断言**，经验 81）；② 判定写成 `"area_only" not in base_agg` 而不是 `not base_area`——**空字典是合法的**「知道该层、但本数据集无结果」，缺键才是旧版格式。⇒ 兼容性判定要盯**结构**，不要盯**内容**。
- **109**：**配置开关被调用点实参遮蔽 = 死开关；而"被宣称的注入式反例"会因此长期无效**（107，真实缺陷）——`detect_watermark_mask` 的调用点写死了 `guard=(_rescue_depth == 0)`（主臂恒 `True`），而 `detect_tiled_translucent` 内部是 `config.DETECT_TILED_PATH_GUARD if guard is None else bool(guard)` ⇒ **实参遮蔽 config**，`WME_DETECT_TILED_PATH_GUARD=0` 从未生效（实测：`guard=True`+config=False 与 `guard=None`+config=True **逐位相同**；`guard=None`+config=False 是 3.2× 面积）。于是阶段 104 宣称的「注入式反例（可逆、不改代码）」**自诞生起就是一句声明**。两条一般化判据：① 当「配置项」与「显式实参」都能决定同一行为时，**实参只应出现在确实需要不同值的那条臂上**（本例：主臂 `None` 交回 config、兜底臂 `False`），并且**测试要断言主臂传 `None`**——而不是断言它传了某个恰好等于 config 默认值的字面量；② **任何"注入式反例"都必须在脚本里被真正跑过一次、并看到它变红**，否则它不算验证（同族：经验 83「摘要声称通过 ≠ 已通过」）。**旁证**：既有的间谍测试恰好断言 `True in calls`——它守住了「兜底臂豁免」这条真契约，同时把缺陷**钉在了原地**；这也说明间谍测试要钉的是**契约语义**，不是当下的实参取值。
- **110**：**用检测器自己的输出当"承诺类型的真值"，是循环论证**（108）——项目里有个便利工具 `build_real_ground_truth.py auto`，它把检测结果直接写成真值（`labeled_by="auto:<preset>"`）。当它被用于**未验证类型**的真值时，`recall`/`precision` 会结构性偏高（**评测者与被执行者是同一套判据**），而这类偏差**不会以任何报错的形式出现**。⇒ 两条一般化：① **评测集必须记录"标注来源"，并让来源成为可判定字段**（本项目：`labeled_by`），且**承诺面升级前必须审计来源**；② 把审计做成**预检工具 + 现场守卫**（`scripts/real_asset_preflight.py` 把任何 `auto:` 标注判为「不可升级」；`test_real_dataset_annotations_are_all_manual` 钉住现有 60 条全为 `manual:measured`）——**"谁标的"必须是机器可查的，而不是写在文档里的一句承诺**。同族：经验 103（零集也要登记）、「门禁自述与对外承诺互相矛盾」那一类
- **111**：**「推荐/选择」类模块的缺陷是「把检得出的变成检不出」——比阈值松更坏**（109）——`core/preset_recommender` 的 `_periodicity` 要求**两个方向都有**周期（AND），而它要推荐的 `detect_grid_watermark` **只用 OR**（该处注释明确否决过 AND：可分离网格 `g(x,y)=f(x)·f(y)` 的自相关也可分离 ⇒ 要求两方向同时非零会漏掉最常见的网格）。后果：**一维周期图案（竖/横条纹）**被判「非周期」⇒ 推 `ai_text_heavy`（**该预设不启用网格通路**）⇒ **recall 0.000**；同一张图手动选 `ai_tiled`/`ai_grid`/`ai_multi` 均为 **0.769**。⇒ 两条一般化：① **凡"推荐器/选择器"型模块，必须与它推荐的那条通路的判据对齐**——比下游更严就是缺陷（且用户看不见，因为推荐结果看起来"也是一种合理预设"）；② 验收要度量**"推荐后能不能检出"**（recall of the recommended preset），而不只是"推荐本身合不合逻辑"。
- **112**：**判据与目标概念"语义重叠"时不要调阈值；还要防"看起来能分开的判据"**（109，技能 5g 的实例）——真实 30 图上推荐器 20/30 推 `ai_multi`（precision 0.0274 vs `general` 0.1552，差 5.7×），根因是 `f_text` 在真实照片上**恒真**（97% 触发）。可分性实测：真实照片的梯度密度 `overall_d` 中位 **0.3431**，**高于**合成「满图笔画」的 0.1742~0.3120 ⇒ 判据与目标概念**没有相关性**（照片纹理本身就让边缘密度饱和）⇒ **任何单点阈值都切不开，收紧只会先杀真命中**。处置：**登记 + 量化代价**，不动上游的实测裁决（阶段 61 的「多族 ⇒ ai_multi」有 72%→97% 的召回依据）。**同时记录一条正交发现**：`regularity`（频域峰聚度）在真实照片与真周期图案之间**完全不重叠**（0.004 vs 0.022）——但**当前没有一个可复现的后果**，故**不做投机改动**，只登记为可选加固点。⇒ 「判据可分」是**必要条件**，不是**充分理由**：还得有一个**已复现的劣化**才值得动。
- **113**：**框架按位置传参时，「控件数 ≠ 形参数」就是静默错位——必须把接线做成可判定的契约**（110，P0）——`run_btn.click(inputs=[…21 项…])` 而 `process_single` 有 **22 个形参**，且内部开关 `record` 排在最后一个 UI 控件 `dual_run` **之前** ⇒ Gradio 按位置传参 ⇒ **「双跑择优」复选框绑到 `record`、`dual_run` 恒吃默认值**。两个功能**各自静默失效**（一个不生效、一个默认路径不记录历史），**不报任何错**：① 只差 1 且 docstring 写错长度（"四元组"），肉眼扫过去像对齐；② 都无异常。两条一般化：**① 凡"框架按位置绑定"的回调，必须有模块级契约常量（控件形参前缀）+ 测试逐位对账**；**② 内部开关形参必须排在全部 UI 控件形参之后**（这是一条可直接检查的不变式）。**推广手法**：把个案写成**全层扫描**（本例扫全 `ui/*.py` 的 45 处接线）——一次就抓出**第二处同族缺陷**（`tab_auto.process_auto_repair` 25/24），并顺带把四处**合法**的差异（Gradio 注入的 `progress`）显式登记，避免"名字猜测"式豁免。
- **114**：**「同一语义多处拼装」要写成 AST 通解守卫，不能靠人 grep**（110）——「修复参数摘要」在 `tab_single` / `tab_auto` / `tab_batch`（**两处**）/ `tab_history` **各写一份且硬编码中文**，而它会被报告层渲染进 HTML/PDF ⇒ 切 en-US 后报告里仍是中文（i18n 泄漏）。**实证**：我按 grep 只改了 1 处，写完 AST 守卫（扫 `ui/` 常量、剔 docstring）后**又抓出 3 处**（其中 `tab_history` 那处 grep 没命中——因为特征片段被后缀 `（重新处理）` 打断）。⇒ **判据：凡"某文案/数值在多处拼装"，守卫必须是 AST 扫常量**（对**尚未写下的第 N 处**同样有效），而 grep 会被文案变体与注释淹没。**另一条边界**：抽出共享实现时要按**参数可得性**决定合不合并——`tab_history.reprocess` 只有 3 个参数在作用域内，硬套 6 参数模板会拼出 `None` ⇒ **同语义也要允许两个构造器**（`repair_params_text` / `..._short`），并各配一个 i18n 键。
- **115**：**「改了某模块的注册表/常量，它的专属测试文件必须进受影响面」（110，踩坑）**——阶段 110 给 `scripts/audit_selector.py` 的 `AUDITED_SINCE` 加了 `ui/tab_single`，但受影响面定向跑只列了 ui/i18n/recommend 测试，**漏了 `tests/test_audit_selector.py`** ⇒ 全量跑才抓到 `test_unaudited_filters_registered_modules` 红（写死样本恰好被新注册吞掉）。⇒ 凡改动**自带测试文件**的模块（尤其 `scripts/*` 的注册表/常量、`config.py` 的派生量），把该测试文件**显式加进受影响面**；更省心的判据是：改完直接跑全量（本项目全量 ~5.5min，比事后追回归便宜）。
- **116**：**真值审计不一定每次都找到缺陷；模块干净时交付物是「钉死未测不变量 + 如实登记误报」（111）**——`core/mask_editor` 25 项对抗性探针全绿，核心代数无真缺陷。正确动作不是"为产出硬找/硬改"，而是：① 把既有测试未覆盖、却正确的不变量（RGB 亮度 / RGBA alpha / manual 空分支 / 精确上采样 / 浮点圆心 / 输出纯度 / 1D 报错 等）写成机器可判定守卫；② 把"看似缺陷其实正确"的项（本例：上采样放大掩码面积是 `target_shape` 语义，像素数不守恒是预期）用断言显式钉死，防止后人误修。⇒ **审计的产出可以是"证明它正确 + 防止它变错"，不必是修复**。同族：经验 112（判据可分但无复现劣化 → 只登记）、技能 5g（不硬调）。

- **117**：**回调文档的「返回元组数」声明必须与真实返回 + Gradio outputs 对齐**（112，经验 113 的同类但性质不同）——`run_video` 文档写「四元组」实为**六元组**（多出的 5th=浏览画廊值、6th=导出文件占位 `None`）。审计手法：全仓 grep 文档「元组」声明，用 AST 解析每个 `return` 的 `Tuple` 元素数 + `.click(... outputs=[...])` 长度，三者必须一致。**关键区分**：本例**绑定本身正确**（16 控件 == 16 形参 == 6 输出），只是文档误写 ⇒ 修文档、**不要动接线**（否则把"干净模块"改坏）。同族：经验 113（文档写错长度 + 控件≠形参）、经验 114（i18n 泄漏）。

- **118**：**Gradio 按位置绑定的回调，统计「接线控件数」时必须剔除框架自动注入的形参**（112，探针首版踩坑）——`progress`（`.click`/`.change` 末位自动注入）与 `evt`（`.select` 首位的 `gr.SelectData`）**不算**控件数。stage-112 探针第一版把这两个算进"形参数" ⇒ 误报 `run_pdf 10≠12`、`run_video 11≠16`。一般化：任何"框架自动注入参数"的回调，契约统计要**显式剔除注入项**（同族：经验 113 全层扫描里把"Gradio 注入 progress"显式登记，避免名字猜测式豁免）。

- **119**：**「疑似已知缺陷」先复测其判定条件，再决定改不改**（112）——`run_pdf`/`run_video` 都高度疑似阶段 110 的 P0（控件≠形参错位），但 AST 实测 `12==12==3`、`16==16==6` **全部对齐**，唯一真缺陷只是文档「四元组」误写。⇒ 凡"看起来像某类已知缺陷"，先用量具复测该类缺陷的**判定条件**（控件数 vs 形参数 vs 输出数），而不是直接套用修复；避免把"干净的模块"误改成"被改坏的模块"。同族：经验 116（干净模块交付=钉死不变量）。

- **120**：**「某参数已死」的断言必须在调用点重新验证，再决定是否动接线**（112，跨阶段）——阶段 109 把 `sensitivity` 标记为 dead；但 stage-112 验证 `ui/tab_media` 的 `run_pdf`/`run_video` 仍把它透传给 `process_pdf`/`process_video`，且两服务**形参仍接受** `sensitivity`（pdf_service:321 / video_service:415），`auto_pipeline` 里它**实际驱动** `recommend_preset`/`resolve_preset` ⇒ 在接线层删掉这个透传反而会让"智能推荐"失去敏感度输入。**结论**：接线层正确、不改动；"死参数"的判定只在"真正无人消费"时才成立，跨模块引用会复活它。

- **121**：**「参数名暗示可控、实现恒等」的死参数：凡 `if not X:` 分支里重建出的对象与原来逐字段相同，就是空操作**（113）——`extract_sampled_frames(..., return_indices=False)` 的分支把每条 `{"idx","image"}` 原样重建（`out = [{"idx": d["idx"], "image": d["image"]} for d in out]`），于是 `return_indices` **永远不生效**（无论 True/False 都返回含 `idx` 的 dict），与参数名及文档承诺的「控制 idx 是否返回」矛盾。**识别法**：把 `if` 分支的列表推导左式与原对象逐字段比——键集与取值全同即空操作。**危害**：未来调用方传 `False` 期望不带 `idx`，会静默拿到 idx；这是「既错又无害」的潜伏缺陷（现无调用方传 False，故 6 个调用点全传 True）。**修复**：让分支真正改变形状（`[{"image": d["image"]} for d in out]`）并同步订正 param/return 两处 docstring；**守卫**：正/反两分支各一断言（False 时 `keys()=={"image"}`，可直接抓回空操作回归）。同族：经验 119（先复测判定条件再改）、120（调用点验证再动接线）。

- **122**：**「声明的开关只对部分输入生效」= 静默失效**（114）——CLI 的 `--superres`/`--superres-amount` **只在图片路径（`_run_one`）透传**，PDF 路径（`_run_pdf`）漏传，而 `services/pdf_service.process_pdf` **明确接受并逐页使用** `superres` ⇒ 用户在 PDF 上加该标志被**静默忽略**，帮助里却没有任何「仅图片」说明。**识别法**：把同一个「全局开关」在**各输入类型的执行体**里逐个 grep——凡下游函数**接受**该参数、而某执行体**未传**者即候选（这是「声明 ≠ 接线」，与经验 121 的「参数名暗示可控/实现恒等」同族但方向相反：那时是参数永不生效，这里是参数**只对一部分输入**生效）。**为何可安全修**：该开关是 `store_true`（默认关）⇒ 补齐透传**零行为变化**，仅用户显式开启时生效。反例警戒：修前必须确认「下游真的消费它」（否则补传 = 给死参数加一条死接线）；且若下游（如 `process_video`）**不接受**该参数，就不能硬传——此时应登记为边界。

- **123**：**调用方读「下游返回字典的键」时，应在生产者侧 setdefault 自保证键集，而不是依赖「下游各分支恰好都带」（114）**——`cli._print_result` 按 `original_name → input_path` 取文件名，二者皆缺即打印**空文件名**；而 `cli._run_one` 此前只 `setdefault("kind")`，**未自保证**这两个展示键，靠的是「`process_file` 当前 4 个分支都恰好带它们」这一**跨模块隐含契约**。当前不可达（潜伏期），但下游一旦新增不带这两键的分支或换生产者，CLI 就会静默打印空名。**修法**：在生产字典的那一层（`_run_one`）用 `setdefault` 补齐展示键——`setdefault` 语义保证**不覆盖**下游已给的值（单真值来源）。同族：技能候选 #5「返回结构随分支变化 / 键集对账」。

- **124**：**「降级/占位分支」的产出物必须真的是它自称的东西——随机初始化的网络不是「恒等/双三次」**（115）——`core/superres` 的 esrgan「无权重」分支保留了**随机初始化**的卷积网络，注释/note 却称「双三次上采样 + 恒等卷积」；实测输出是**噪声**（与干净双三次 `mean_abs_diff≈102`、画面均值 138→**1.45**）。**这是 ML 代码特有陷阱**：随机初始化的网络 ≠ 恒等映射，注释里的「退化/占位」措辞会让人以为它是直通。识别法：凡「降级/兜底」分支声称产出某具体结果（恒等 / 双三次 / 直通 / 空操作），**必须实测它与那个参照物的偏差**，而不是相信注释。**更隐蔽的是下游「非 None 即用」**：`postprocess_service` 拿到非 None 就直接采用（忽略 `used_real` 旗标），于是噪声直接成为最终结果 ⇒ **兜底分支「错误的非 None」比「返回 None」危险得多**（后者会触发正确回退）。判据：**兜底分支宁可返回 None 让上层回退，也不要返回一个错的非 None**；若确要产出（如本项目设计为「双三次放大」），就必须让它真的是双三次。

- **125**：**缓存模型/对象时，缓存键必须覆盖所有影响产出的因素**（115）——`_ensure_model` 用单个 `_built` 布尔缓存模型，却**未把 `scale` 纳入键**，于是同一实例先请求 2×、再请求 4× 时复用旧模型，第二次返回的仍是 2× 尺寸（实测 `(96,128,3)` 而非 `(192,256,3)`）。识别法：**「缓存命中判据里出现的变量」是否 ⊇「影响构建结果的变量」？** 差集非空即缺陷。修法 = 用 `(built, built_scale)` 联合键控，并把置位移到**全部成功之后**（顺带消除技能候选 #8 的「先置位后干活」隐患）。同族：经验 121（参数名暗示可控）、123（生产侧自保证）。

- **126**：**自检与守卫必须「与环境无关」——凡断言「默认行为 / 形状不变」的调用都要显式入参，不能读 config 默认值；并给 `__main__` 自检配一条「子进程实跑」守卫**（122）——`services/postprocess_service.py` 的 `__main__` 自检用**默认调用**（`postprocess(raw, original_rgb=orig, mask=mask)`），而该函数在 `real_superres=None` 时读 `config.REAL_SUPERRES_ENABLED`；本机 `config.user_overrides.json` 恰是 `{"REAL_SUPERRES_ENABLED": true, "REAL_SUPERRES_SCALE": 2}`（用户设置页保存的**机器本地**偏好）⇒ 每条默认调用都把画布放大 2× ⇒ 第一条 `assert improved.shape == raw.shape` 崩（EXIT=1）。第二处：用例 7 硬编码「真实超分后端不可用⇒不应改变尺寸」，而**装了 torch 时 esrgan 后端可用**（缺权重退化为纯双三次放大）⇒ 同样必崩。**通解四件**：① 断言「不变」的调用**显式传参**（`real_superres=False`）；② 或在自检开头**显式解耦环境**（本模块采用，因 `postprocess` 调用时读该属性 ⇒ 改一处即解耦全篇）；③ 对环境相关的断言改为**双向可接受**（`形状 ∈ {原尺寸, 恰好 4×}`）并打印实际走向；④ **守卫用子进程实跑模块自检并断言 `returncode==0`**——普通单测**不会执行 `__main__`**，这是唯一能永久抓住此类缺陷的判据。同族：经验 113（「模块自检通过就以为没问题」的反例升级版——自检**自己**就崩了）；经验 119（先复测判定条件：本阶段另有三个候选 `_edge_blend` 死参 / `real_superres` 需 geom / 部署级放行闸，**复测后发现设计文档都写了**，判为非缺陷）。

- **127**：**注入式反例脚本在 Windows 上「写回还原」必须用 `open(p,'w',encoding='utf-8',newline='')`，否则文本模式会把 LF 写成 CRLF，导致还原后 sha256 不一致、自比失效**（123）——注入流程是「读原文 → 落盘回退版 → 跑守卫(必红) → 写回原文 → 断言 sha 一致」。在 Windows 沙箱里 `open(p,'w',encoding='utf-8').write(orig)` 的**写**侧会做通用换行翻译，把 LF→CRLF，于是还原出的字节和原文（纯 LF）不同，断言 `restored_sha != orig_sha` 误报「还原失败」。判据：**凡是「逐字节还原」的脚本，写回一律加 `newline=''`**（读侧不影响 sha 比对，但写侧致命）；若图省事只读不写，则把还原交给 `newline=''` 这一步。顺带：项目源文件是纯 LF（仓库历史曾 CRLF，但 Edit/Write 写出的是 LF），注入字符串匹配失败若非字符差异，先排除换行符——本阶段第一次用多行注释串 `in` 判定未命中，正是串里混入了不同全角字符，改用「短锚点 + 只回退行为行」才稳定。**【阶段 163 勘误】**「纯 LF」已过时：实测仓库**行尾异构**（`core/detector.py`、`ui/tab_single/tab_history/tab_batch`、`services/validators.py`、`utils/i18n.py` 为 CRLF，其余 LF）；且本轮 6 个注入脚本**全部违规**（未加 `newline=''`），把 6 个文件悄悄改成 CRLF——「还原校验 OK」是文本 sha 自比，靠**原始字节 sha 复核**才暴露（详见 188），已全部转回 LF（raw sha == 各阶段记录 sha）。

- **128**：**「是否放大/缩小」的判定必须比对「原始尺寸 vs 原始尺寸」，绝不能比对「某一侧原始尺寸 vs 另一侧对齐/归一化后尺寸」**（124）——`services/compare_service.summarize_pair` 旧逻辑用 `(raw结果尺寸) != (对齐后尺寸)` 判 `upscaled`；而 `align_pair` 会把结果缩回原图尺寸，于是「结果≠原图」时两侧尺寸恒不等，**无论放大还是缩小都得到 True**，结果比原图小也误报「已放大」。判据：凡涉及「A 相对 B 是否变大/变小」，先问清楚比对基准 —— 对齐、resize、归一化都会让某侧尺寸「变成」另一侧尺寸，使 `!=`/`==` 比较失去意义；正确做法是**在变换发生前各存一份原始尺寸**，再直接比较两份原始尺寸。同族：经验 125（缓存键必须覆盖所有影响产出的因素——本质都是「比较/键控的变量集合 ⊇ 真正决定结果的变量集合」）。

- **153**：**写「同步/同参数/一一对应」这类契约注释时，必须回到实现核对「参与者是否真的共享同一个决策量」——`_rsz` 各自算 `max_side/max(h,w)` 看起来像同步，实际是各按自身尺寸，宽高比不同的两张图必然失同步**（140）——`_downscale_for_eval` docstring 写「把两张图按同一目标边长等比缩放」，实现却是两个 `_rsz(img)` 各自判断 `max(h,w) <= max_side` 并各自算 scale：原图 800²（未超限）原样返回、结果图 1600² 缩到 1024² → 尺寸不一致，下游那句 `cv2.resize(r_rgb, 原图尺寸)` 变成**非等比**回缩，SSIM/changed_ratio 双双失真（实测同一对图正确路径 good/99、坏路径 warn/81）。修法 = 先把结果图等比回缩到原图尺寸，再对两图施加**同一个 target**。判据：凡注释出现「同一/同步/一一对应/等价」，逐字核对实现里是否存在**共享的决策量**（同一 scale、同一 target、同一循环变量）；两个调用点各自算同一个公式 ≠ 共享。同族：经验 145/151（文档声明是契约）、102（值域/形状决定语义）。危害放大：值域仍落 0~1、不报错（经验 26）。

- **157**：**「静默兜底」有两种方向——兜底成默认值，与兜底成"另一个看起来正常的值"；后者更隐蔽，而 `str(x)` 是它的最常见载体**（141）——`utils/brand.hex_to_rgb` 的 docstring 明明写着「不静默返回黑色：静默兜底会把配色错误伪装成『看起来正常』」，但实现第一行 `s = str(hex_color).strip().lstrip("#")` 就是同一类伪装：`hex_to_rgb(123456)` 把整数转成字符串再当十六进制解析，**静默返回 (18,52,86)** 且从不报错；`hex_to_rgb((37,99,235))` 报的却是误导性的「长度应为 3 或 6」（真因是类型错）。判据：① 凡函数首行出现 `str(x)` / `int(x)` / `float(x)` 这类**无校验强制转换**，问「传错类型的调用方会得到什么」——若答案是「一个不报错但语义错误的结果」，即为缺陷；② 类型错与值错必须**抛不同异常类型**（`TypeError` vs `ValueError`），否则调用方无法区分，且错误文案会把后来者带偏。同族：经验 140（docstring「抛 X」也是契约）、102（dtype/值域决定语义）、150（登记也要过探针）。

- **158**：**解析器的「空白容忍」口径必须一次定死并全路径一致——`strip()` 只处理首尾，`int(x,16)` 却额外容忍内部前导空白，两者叠加会制造「长度对、字符也对」的假象**（141）——`hex_to_rgb("#12 456")`：`strip()` 不动内部空格 → 长度恰为 6 → `int(" 4", 16)` 成功（`int` 容忍前导空白）→ 静默返回 (18,4,86)。同一函数下 `"#2563e\t"`（strip 后长度 6）通过、`"#12 456"` 也通过，**实现无法区分有意缩进与笔误**。修法 = 在 `strip()` 之后显式判 `any(ch.isspace())` 并拒绝，保留首尾容忍以兼容既有调用方。判据：写字符串解析器时，把「首尾空白 / 内部空白 / 制表符换行」三类分开决策并写进 docstring；不要依赖 `int()`/`float()` 的内置容忍度来做校验——**内置转换函数的宽容度通常比业务契约大**。同族：经验 157（静默伪装）、151（契约须配机器校验）。


- **159**：**`astype(uint8)` 是 numpy 里第二常见的「静默伪装」载体——`str(x)` 伪装类型（157），`astype` 伪装值域：>255 的浮点回绕成小值、恰好低于阈值 ⇒ 整片掩码被清零 ⇒ 静默空操作**（142）——`core/inpainter.inpaint()` 的 docstring 承诺 mask「任意值域，0=保留、非0=修复」，阶段 102 已覆盖 `bool`/`{0,1}`，但 `float32` 全片 `300.0` 经 `astype(np.uint8)` 回绕成 **44** < 阈值 127 ⇒ **改动 0 px、不抛异常**；`256.0` 回绕成 0 ⇒ 误抛 `EmptyMaskError` 并把原因写成「掩码为空」。更危险的是 `511.0` 回绕成 255 **恰好正常工作**——同一份代码按数值给出「对 / 静默错 / 报错误原因」三种行为，无一致性。修法 = 在 `astype` **之前**取 `raw_max`，一旦 `>255` 就按「非零即修复」归一，并留可见告警。判据：① 凡「外部传入的掩码/权重/标签」先做 `astype` 的地方，都要问「输入超出目标 dtype 值域时会怎样」；② 落点放在**契约承诺方**（此处 `inpaint()` 入口），不要放在 `image_utils.threshold_mask` 这类被检测侧共用的底层函数里。同族：经验 157、102、26。

- **160**：**同一句契约 docstring 可能蕴含「多个值域类别」，每轮审计只覆盖一类——审完 102/105 不等于审完 `inpaint()`；判据是「把 docstring 拆成若干可枚举的输入类别，逐个问『有守卫吗』」**（142）——`mask` 的「任意值域」实际含四类：`bool`（102 已覆盖）、`{0,1}`（102）、`0~255` 灰度（105 覆盖了语义、未覆盖越界）、`>255` 越界（本轮才发现零覆盖）。历史守卫测试 `test_inpainter_mask_range.py` 的 I1 只参数化了前三类，`test_inpainter.py::test_empty_mask_raises` 还用 `pytest.raises(Exception)` 过宽 —— 连 `256.0` 误抛也照收。判据：续审「已被审过的模块」时，第一件事不是重读代码，而是**把它的契约 docstring 逐项枚举**，对每一项标注「哪个阶段的哪个用例守它」，空白项即候选。同族：经验 151（契约须配机器校验）、150（登记也要过探针）。

- **161**：**注入式反例的「备份基准」必须是修复后版本，且注入锚点必须精确落在目标分支内部——锚点跨入字符串字面量会造成收集期 `SyntaxError`，那是假绿灯**（142）——本轮两次翻车：① 首次备份取的是修复前旧文件 ⇒ 还原后哈希与「修复后基准」不符，产生虚假「哈希不一致」告警（真因是基准取错，不是文件被写坏）；② 首次注入锚点 `ANCHOR_END` 落进了 `EmptyMaskError("掩码为空…")` 字符串内部，替换后源码语法错误 ⇒ pytest 在**收集期**报 `SyntaxError`（rc=2），而非测试断言失败 —— 若只看到「有红灯」就收工，会误判「守卫有效」，实际上一个断言都没跑到。判据：① 注入前 `shutil.copy2` 的目标必须是「刚刚验证过全绿」的那版文件，并在日志里打印其 sha256；② 注入后先断言「收集成功」（或直接看 `-v` 的逐用例 PASSED/FAILED 清单），**必须看到具体用例名**才算命中；③ 替换用 `txt.count(anchor) == 1` 前置断言，避免多处命中。同族：经验 83（注入式反例方法论）、150。

- **162**：**`-q` 的 pytest 输出只保留最后一行 summary，注入反例的「失败清单」必须用 `-v` 或显式 grep `FAILED` 行——否则会严重低估覆盖**（142）——本轮 `-q` 只显示 `FAILED ...test_J4...`（1 条），改用 `-v` 后真实失败是 **6 条**（J1×4 + J3 + J4）。若不复核，会错误地认为「注入只触发一个守卫」，从而怀疑 J1 是否有效，甚至去改本来正确的守卫。判据：注入反例一律用 `-v`（或解析 `FAILED`/`PASSED` 全量行），并在文档里贴出**完整失败清单**。同族：经验 161、150。


- **163**：**「全局模块属性」是比「写盘」更隐蔽的测试污染载体——污染源在哪个文件，就该在那个文件加 autouse fixture 快照/还原，而不是在被污染的文件里补断言**（142 连带 A）——`ui/tab_settings.apply_processing_prefs()` 直接赋值 `config.IMAGE_APPLY_EXIF_ORIENTATION` / `IMAGE_NORMALIZE_BIT_DEPTH` / `INPAINT_DUAL_RUN` / `PNG_KEEP_ALPHA` **四个模块属性且无还原**。于是 `test_processing_prefs.py` 与 `test_input_normalization.py` 同进程连跑时，后者 **21 条假红**（EXIF 方向、位深归一化全失效）；单独跑 41/41 绿。判据：① 凡测试调用的函数内部有 `config.X = ...` / `module.Y = ...` 这类**直接赋值**，单点 `monkeypatch` 管不住（它只拦截「读」路径的 patch，拦不住「写」），必须在该测试文件加 `autouse` fixture 全量快照/还原被测的属性集合；② 定位污染的**杀手锏是二分**：`pytest A B` 红而 `pytest B` 绿 ⇒ 污染在 A；③ 排除自身嫌疑时，「把改动临时还原 + 单跑失败用例」是最快的归因（本轮用此法 10 秒内证明 21 红与 inpainter 无关）。同族：经验 155（写盘污染）、162。

- **164**：**「榜单单元素快照」类断言一旦写死第一名，任何提高覆盖度的正当改动都会让它变红——正确做法是写「结论 + 变更原因」到 docstring，并在第二次复用同一条断言时改成「与权威计算源一致」**（142 连带 B）——`tests/test_audit_selector.py::test_real_repo_current_top_desert_snapshot` 锁 `targets[0].key == "ui/tab_auto"`；本阶段新增 13 例（inpainter）+3 例（processing_prefs）后，`tab_auto` 比值由 18.9+ 降到 18.46，被 `services/queue_worker`（18.86）反超 ⇒ 红。该断言原 docstring 已自述「本条是结论编码，不是不变量」，因此更新是**正当的**。同时把 `test_cli_json_roundtrip` 从写死 `"ui/tab_auto"` 改为 `== asel.collect(_ROOT)[0].key` —— **同一份「易过时事实」不要在两个地方各写一遍**，留一处硬编码（用于显式提醒「该更新了」）+ 一处自洽断言。判据：① 快照断言必须有「何时该更新」的说明；② 同一个会漂移的值出现第二次引用时，改成与计算源比对。同族：经验 64（「一时显著」不可写成不变量）、151。


- **165**：**「参数默认值是 None」不等于「传 None 的路径可达」——判可达性必须读完整调用链的每一层参数回填**（143）——`core/detection_presets.resolve_preset(name, base_sensitivity)` 的 `base_sensitivity` 类型标注是 `float`（必填），传 `None` 会 `float(None)` 抛 `TypeError`；而 `process_image(sensitivity=None)` / `process_file(sensitivity=None)` 的**签名默认值正是 None**，我据此判「P0：默认参数组合会崩」并写了「可达路径」分析。**读调用链后证伪**：`process_image:182` 与 `process_file:425` 都在函数最前面做了 `sensitivity = config.DETECT_TRANSLUCENT_SENSITIVITY if sensitivity is None else sensitivity` ⇒ 传给 `resolve_preset` 的**永远非 None**。判据：① 追可达性时逐层确认「形参默认值是否被本层回填」；② 区分「**违反类型契约的显式失败**」（抛 TypeError，不是缺陷）与「**静默错误**」（不报错但语义错，是缺陷）——只有后者才算缺陷。同族：经验 157/159（静默伪装有三种载体：`str(x)` 类型、`astype` 值域、`float(x)` 契约）。

- **166**：**`not obj` 对「无 `__bool__` / `__len__` 的普通 dataclass」恒为 `False`——写成 `if not obj or not obj.field:` 时前半句是死条件，后果是「类型错被伪装成值错」**（143）——`register_preset` 原实现 `if not preset or not preset.name: raise ValueError("预设必须提供非空 name。")`：`DetectionPreset` 无 `__bool__`/`__len__`（`hasattr` 实测 False）⇒ `not preset` 永不触发；于是 `register_preset(None)` 与 `register_preset({})` 都落到后半句，报出「必须提供非空 name」——**指错了原因**（真实原因是类型不对）；而 `register_preset("abc")`/`(42)` 抛的是 `AttributeError` ⇒ **同一个「类型不合法」的输入族给出了两种异常类型**，调用方无法区分。修法 = 先 `isinstance` 抛 `TypeError`（**信息含 `type(x).__name__`**），再查字段抛 `ValueError`。判据：凡 `if not X or not X.attr:` 形式的校验，先问「`not X` 在 X 的合法类型上可能为真吗」——若 X 是 dataclass/普通对象，答案是**永远不为真**，那就是把两种错混成一种。同族：经验 157（类型错与值错须抛不同异常类型）。

- **167**：**「硬编码一份「应存在」的清单 + 用 `in` 判定」= 哑巴自检——它对「清单漏项」不敏感，且对「多出来的实体」完全不设防**（143）——`core/detection_presets.__main__` 原自检写 `for expected in ("general", …, "ai_logo"): assert expected in names`：内置实为 **10** 个（阶段 61 新增的 `ai_multi` 没被抄进清单），而自检**照跑不误**（`in` 只查「清单项是否都在」，不查「实体是否都在清单」）。这与阶段 138/139 修过的「哑巴自检」同形，但形态更隐蔽：**它看起来有断言、且断言确实在跑**。修法 = 与**真值来源集合对账**：`expected = {p.name for p in _BUILTIN_PRESETS}` + `assert not (expected - names)`；再加一层「数量对账」（`choices` 数 == 预设数）与「对象同一性对账」（`get_preset(p.name) is p`）。判据：**自检的期望值必须从被检对象的真值来源派生，不能手抄**；手抄清单的失效方式是**静默的**（新增实体时没人会去数）。同族：经验 150（登记也要过探针）、151（契约须配机器校验）。

- **168**：**探针与守卫自身的五种写法陷阱——「结果为零」先问「夹具有没有区分力」，文本断言先问「会不会撞到 docstring」**（143，一次踩全）——① **探针变量名与实测状态错配**：`display_known_zh = preset_display(...)` 但赋值前循环已把语言切到 `en-US`，于是读到英文、一度看起来像「中文界面漏出英文」的缺陷（**探针的 bug，不是产品的 bug**）；② **纯色夹具无区分力**：用纯色图测「sensitivity 越界后果」得到全 0，误以为「越界必然零检出」，实际是该图本来就没水印；③ **monkeypatch 打错层**：patch `dp.get_preset` 影响不到测试文件顶部 `from … import get_preset` 绑定的**局部名**（K0 自检因此假失败），修法是**显式注入 `lookup` 参数**；④ **文本断言撞 docstring**：`assert "not preset or" not in SRC` 会被「修复后 docstring 里引用的旧写法作说明」命中而**误报**（K1 因此假失败），修法是 **AST 扫函数体内的 `if` 测试节点**；⑤ **自造幻觉代码**：我在自检里写下 `import pytest as _pytest_missing` 与 `@pytest.mark.parametrize("name", [n for n in ()] or None)` 两行**无意义代码**——正是本阶段审计要抓的「形参幻觉」族，说明**审计者自己也会犯被审对象的病**，写完后必须复读。判据：探针的**每个「零结果 / 异常结果」都要先自证夹具能产出非零**；守卫里凡「断言源码文本」一律改 AST。同族：经验 161/162（注入反例的锚点与失败清单）。


- **169**：**「兜底 / 默认参数」也走同一条清洗管线——而且它往往绕过的**不止一层**；只补一层时守卫会替你抓到第二层**（144）——`sanitize_filename(name, fallback=...)` 的第 5 步 `stem = fallback` 直接赋值，而那时清洗管线已执行完毕，于是 fallback **同时绕过两层**：②③ 步（控制字符 / 非法字符替换）与 ④ 步的 `strip(" .")`。后果：`fallback="a/b"` → **含路径分隔符**、`fallback="..\\..\\etc"` → 目录穿越形态、`fallback="   "` → **纯空格主名**、`fallback="..."` → **全点号主名**。**我的第一版修复只补了 ②③ 步**（抽 `_scrub`），守卫当场变红（`"   "` / `"..."` 两个参数化用例失败）⇒ 才发现遗漏了 ④ 步。判据：① 凡「兜底值 / 默认值 / fallback」被赋给**已清洗变量**的位置，问「它是否跳过了该变量此前经过的每一步」——**逐层核对，不要只看第一层**；② 修法是让兜底值走**完全相同**的管线（抽公共步 + `or <内置名>` 兜底），而不是复制一半。同族：经验 157/159（静默伪装）、166（校验漏层）。

- **170**：**平台相关的路径 API 会让「剥离任何目录成分」这类绝对承诺单向失效；而这类缺陷的行为用例在开发机上**永远变不红**——必须补源码层断言作第二道防线**（144）——`make_unique_path` 用 `Path(str(desired_name)).name` 取词干：`Path` 在 Windows 上认 `/` 与 `\\` 两种分隔符，在 **POSIX 上只认 `/`** ⇒ `Path("a\\b.txt").name` 在 Windows 是 `"b.txt"`、`PurePosixPath("a\\b.txt").name` 是 `"a\\b.txt"`（**不剥离**）。docstring 承诺的是「剥离**任何**目录成分」，该承诺**只在 Windows 成立**。修法 = 不依赖平台语义，显式 `str(x).replace("\\", "/").rsplit("/", 1)[-1]`。**守卫设计的推论（重要）**：注入 F5 后**只有源码断言用例变红**（行为用例在 Windows 上恰好正确，无法红）⇒ 平台相关缺陷的守卫**必须同时含**「行为断言（守本平台）」+「源码断言（守另一端）」+「用 `PurePosixPath` / `PureWindowsPath` 显式展示两端差异的存在性自检」。判据：凡文档里出现「**任何** / **所有** / 无论…都…」的路径分隔符承诺，检查它是否依赖了 `os.sep` / `Path` 的平台语义。同族：经验 165（可达性须逐层看回填）。

- **171**：**docstring 的「异常」段「漏列」比「多列」危险得多——漏列会让调用方漏捕获，而多列只是冗余**（144）——`assert_file_readable` 的「异常」段只写了 `FileNotFoundError : 文件不存在时抛出（中文提示）。`，而实现里明明还有一条 `IsADirectoryError`（实测传目录即抛）。按 docstring 只写 `except FileNotFoundError` 的调用方，传目录时会让 `IsADirectoryError` **逃逸到上层**（表现为「未预期的异常」而不是友好的中文提示）。判据：① 审读每个函数的 `raise` 语句，与 docstring 的「异常 / Raises」段**逐条对账**（这是一个可以完全静态完成的检查）；② 区分方向——多列无害，漏列有害，故对账时**以下界为准**（实现里有几个 raise 就必须列几个）。同族：经验 151（契约须配机器校验）、167（自检期望值须从真值来源派生）。


- **172**：**NaN 是「两个边界比较都为假」的**唯一**浮点值 ⇒ 所有「双边界钳制」逻辑对 NaN **全部失效**；而同一族的整数版本往往天然安全**（145）——`_env_float` 的钳制是 `if value < min: ...` + `if value > max: ...`，对 `nan` **两条都不触发** ⇒ NaN 原样穿透到业务代码。实测 `WME_X=nan` → 返回 `nan`（既不是 default 也不是钳制值）。**危害链**：`WME_DETECT_TRANSLUCENT_SENSITIVITY=nan` ⇒ `sensitivity=nan` ⇒ 检测器零掩码（静默零检出）⇒ 而 `validate_config` **报绿**。**同族的 `_env_int` 反而安全**（`int("nan")` 先抛 ValueError ⇒ 走回退）⇒ 判据：① 凡「钳制 / 区间夹逼」逻辑（`min`/`max`/`clamp`/手写双 if）都要问「NaN 会怎样」；② **同族两个函数要分别验**，不能因为一个是安全的就假定另一个也是（经验 166 是「校验漏层」，本条是「钳制漏值」）。修法 = `if value != value: value = default`（只拦 NaN，`inf` 路径零变更）。同族：经验 159、142。

- **173**：**审「元守卫」（validate_config / 门禁 / 自检）时，不要逐条读它写了什么，而要**自动枚举它本该覆盖的全体**再算覆盖率**（145）——`validate_config` 自称 17 项检查，看起来完备。改用命名空间**自动枚举**全部 `X_MIN/X_MAX`、`X_MIN_Y/X_MAX_Y`、`X_LO/X_HI` 成对项后实测：**11 对里只覆盖 2 对（18%）**，漏检 9 对 —— 而漏检的 GRID / LOGO 族与已覆盖的 PLATE 族**完全同族**（都是「区间反了 ⇒ 判据恒不产出 ⇒ 静默漏检」），**检查 16 的注释甚至已经写明这条道理，却没推广到同族**。⇒ 这是一类**元缺陷：「意识到一条判据，却没有让它机械化地覆盖整族」**（与阶段 142「一句契约含多类值域只覆盖一类」、143「硬编码清单漏项」同族）。判据与修法：① **枚举 → 反例 → 数覆盖率**，而不是读代码数检查项；② 修法**优先用元检查**（从真值来源自动派生约束），而不是逐条补 —— 逐条补只解决今天这 9 对，明天新增第 12 对照样漏，**与被修的缺陷同病**；③ 元检查必须配「**无误报**」用例（默认配置 `problems == []`）。同族：经验 167、151、142。

- **174**：**探针里的「文本匹配」（`if name in problem_text`）在非英文消息上必然假阴性 —— 判定必须改成**结构化量**（数量增量 / 显式字段）**（145，本会话第三次探针翻车）——我用 `if a in p or b in p` 判断「validate_config 是否捕获了某对约束」，而 `validate_config` 的消息是**中文人话**（「水印检测的最小面积占比(0.35) 不应大于等于 最大面积占比(0.0002)」），**里面没有变量名** ⇒ 明明被捕获的 2 对也报「未捕获」，得出「11 对全部漏检」的**完全错误结论**（差点据此去补 11 条检查）。更正为「**`len(problems)` 相对基线的增量**」后，真实结论是「2 对覆盖、9 对漏检」。判据：① 探针的判定量如果是**另一方的自然语言输出**，一律改为**数值/结构**（计数、集合、字段）；② 出现「全部为负」这种**过于整齐**的结果时，先怀疑探针而不是产品（与 5n「全 0 结果先自证夹具有区分力」同族）；③ 本会话探针翻车三次（143 语言变量错配 / 143 纯色夹具 / 145 中文消息匹配）⇒ **探针写完先用手测复现一条**再信它。同族：经验 168、161。


- **175**：**元守卫有两类动作——「判定」与「写操作」。审完判定层不等于审完：`--update` / `--save-baseline` 这类**刷新动作**常常是绕过全部判定的「静默通道」**（146）——三条门禁都有「刷新基线」功能，但 `quality_gate.py` 与 `real_gate.py` 在写完基线后**直接 `return 0`**：绝对红线不判、数据完整性不判、漂移层不判，用户看到「基线已刷新 + 退出码 0」会以为一切正常。判据：① 凡脚本有「**写回/持久化**」类开关（`--update`/`--save`/`--write-baseline`/`--accept`），先问「写完之后的代码路径是什么」——**若它以 `return 0`/`exit(0)` 结束，它就是一个绕过全部判定的静默通道**；② 正确形态是「**写完之后继续跑完整判定**」（用刚写入的快照比漂移，差值恒 0，但红线与完整性照样判）；③ 审这一层时**先找同仓里已经做对的那个**——本项目 `e2e_real_probe.py` 的注释早就写着「否则刷新基线的动作会绕过红线检查，成为一条静默通道」，两个主门禁是**漏了对齐**，不是新决策（技能第四步「不推翻上游裁决，只补遗漏」）。同族：经验 173、166（校验漏层）。

- **176**：**「同族指标里只有一个没有绝对红线」= 保护级别的不对称缺口；它比「完全没有红线」更难发现，因为旁边的指标看起来保护得很好**（146）——合成门禁的 `aggregate` 有三个检测侧指标：`precision`（RED_LINES ≥0.35 ✅）、`iou`（≥0.35 ✅）、**`recall`（查无此项 ❌，只有 20% 相对漂移容差）**。而 `recall` 代表的正是**漏检**方向。配合「`--update` 无护栏」⇒ `0.819 ─刷→ 0.655 ─刷→ 0.524 ─…` 每步都在容差内，**门禁全程绿而漏检率趋近 100%**。判据：① **自动枚举**「参与漂移层的指标」集合，再**逐项标注它的保护级别**（绝对红线 / 仅相对漂移 / 无保护），差集即缺口（这正是 173 的机械化思路，只是把「有没有检查」升级为「保护到什么级别」）；② 修法可以**不必立刻补阈值**——先切断「可被渐进刷新」这条路径（加刷新护栏），阈值**等实测分布够了再定，不拍脑袋**。同族：经验 173、142（一句契约含多类值域只覆盖一类）、143（硬编码清单漏项）。**本条与 173/142/143 共同指向一个元缺陷族：「意识到一条判据，却没让它机械化地覆盖整族」。**

- **177**：**注入式反例不只验产品，也验守卫 —— 本轮它当场抓出我守卫里的一处假阴性（断言窗口过长）**（146）——`test_O3_refresh_block_can_refuse` 首版用「文本片段扫 3000 字」找 `return 1`，而刷新块**外面**（`evaluate()` 之后）本来就有 `if not ok: return 1` ⇒ 注入「旧静默通道」后该用例**仍然绿**（假阴性）。改用 **AST 限定在刷新块 body 内**后，同一注入的失败数从 4 升到 5。判据：① 凡「断言某段代码里含/不含某构造」，**必须用 AST 限定作用域**（函数体 / 特定 If 的 body / 特定节点类型），**绝不用「文本窗口扫 N 字」**——窗口长短是任意的，长一点就跨出作用域、短一点就漏掉尾部；② 判据：**注入后失败用例数不变 ⇒ 该守卫对这次注入不敏感**，要问「是不是窗口/作用域写错了」。同族：经验 161/162、5k（注入反例三条硬规矩）、174（探针判定量须结构化）。


- **178**：**「枚举优于记忆」——修「硬编码清单漏项」缺陷时，我自己又凭记忆列清单并漏了项**（146）——本轮要审的是「含刷新开关的门禁」，我**凭记忆**列了 3 个（`quality_gate`/`real_gate`/`e2e_real_probe`），修完后跑全量才发现 `tests/test_prompted_area_gate.py` 里有个 slow 用例在跑**第 4 个**门禁 `scripts/prompted_area_gate.py` —— 它**同样有 `--update` 且同样是静默通道**。这**正是** 143/167 的「硬编码清单漏项」同族病：**我在修这个病的同时犯了它**。判据：① 列「某类对象的全集」时**必须从真值来源机械枚举**（`os.listdir` + grep 模式 / `ast` / 注册表），**绝不凭记忆**；② 枚举结果要**写进守卫**并与登记集合对账（本轮补了 `test_gates_registry_matches_disk`：从磁盘 grep `--update` 与 `_GATES` 比对，新增第 5 个门禁时自动变红）；③ **旁证信号**：修完后跑全量若出现「我没预期的用例名/文件名」，先问「它是不是我漏审的第 N 个成员」。同族：经验 167、173、143。**放宽到一般规律：凡是「我列了一份清单」的动作，都要问「这份清单该从哪派生」。**

- **179**：**测试套件被「单条超预算的慢用例」整锅端掉时，先看 `pytest timeout` 与该用例自述耗时的余量，而不是怀疑自己的改动**（146）——全量跑突然 `EXIT=1` 且**零 FAILED/零 ERROR**、结果数只有 1440（应 ~1880）⇒ 说明 pytest 被**中途中止**。根因：`tests/test_prompted_area_gate.py::test_gate_end_to_end_exit0` 的真实耗时是 **171.44s**（单跑实测），而 `pytest.ini` 的 `timeout = 300` ⇒ 余量仅 43%；全量跑时机器负载更高 ⇒ 被拖过 300s ⇒ pytest 杀它并**中止整个套件**（summary 都来不及打）。判据：① `EXIT≠0` 但**零 FAILED** + 结果数明显偏少 ⇒ **先找 Timeout/INTERRUPTED 字样**，别急着改代码；② 排除自身嫌疑的最快证据是**逻辑隔离**：「该用例跑的命令里**没有**我改过的那个开关」⇒ 我改的分支**结构上不可能被执行**（比反复重跑更快更确定）；③ 处置 = 全量跑时 `--deselect` 该用例（与其它 slow 用例一致）+ **登记**为「测试资源预算」问题（建议提高该用例的 pytest timeout 或缩短其数据集）。同族：经验 168（探针自身陷阱）、174。


- **180**：**`from __future__ import annotations` 让「注解里引用了未导入的名字」变成完全静默的潜伏缺陷 —— 静态枚举（AST）是发现它的**唯一**手段**（147）——该 future import 让**所有注解延迟为字符串、永不求值** ⇒ 运行时代码路径**永远不会**触发 `NameError`。实测一次全仓扫描（215 个 `.py`）抓到 **3 处**：`core/detector.py` 的 `Dict`（import 只有 `List, Optional, Tuple`）、`services/validators.py` 的 `_os`（import 是 `import os`）、`ui/tab_history.py` 的 `Optional`（**完全没导入 typing**）。**但任何会求值注解的东西都会立刻炸**：`typing.get_type_hints()`（实测修复前 NameError、修复后 0 错误）、Sphinx autodoc、`dataclasses` 的部分反射路径、pydantic 模型装配、以及 mypy/pyright。⇒ 判据：① 凡文件顶部有 `from __future__ import annotations`，**不能**用「运行时没报错」推断注解没问题；② 必须用静态枚举（`scripts/undef_scan.py` 的 `Name(Load) − 绑定 − builtins` 差集）定期扫；③ 反过来看：**任何「运行时观测不到」的缺陷族，都只能靠静态工具守**。同族：经验 174（判定量须结构化）、177（AST 限定作用域）。

- **181**：**自检 / CLI 脚本的「死代码 + 静默失效」：`__main__` 块里自检后 `raise SystemExit(0)` ⇒ 后面的 `main()` 永不可达，命令行参数全部失效、且没有任何症状**（147）——我在 146 写的 `scripts/undef_scan.py` 正是如此：`__main__` 里跑完自检就 `raise SystemExit(0)`，于是 `python scripts/undef_scan.py --all` **完全无效**（它照样打印「自检通过」并以 0 退出）。**它躲过了 146 的模块自检守卫** —— 因为它确实有 print、有 assert、rc=0（三条新老判据全过）。⇒ 判据：① 凡「`__main__` 里既有自检又有 `main()`」的脚本，检查**自检之后是否提前 `return`/`raise SystemExit`**，那会让 `main()` 成为死代码；② 正确形态 = 自检后**继续**调用 `main()`（自检失败则先抛异常），并让 `python <script>` 的**默认行为**本身就是一次有意义的检查；③ 更一般：**「有输出 + 有断言 + rc=0」三条仍不足以证明自检有意义** —— 还要问「它的判定结果真的会影响退出码吗」「它的主体代码真的可达吗」。同族：经验 175（元守卫的写操作层）、177。

## 阶段 152 新增

- **⚠ 守卫拒绝 ≠ 无副作用（经验 182）**：凡「先写后判」的顺序，被拒绝的只是**登记**，
  不是**写入**。`collect_real_assets.add --copy` 就是先 `copy2` 覆盖、再让 `_upsert` 拒绝，
  提示说「拒绝登记」而磁盘已经变了。⇒ **判定必须排在一切破坏性写之前**；
  且守卫要断言**磁盘上的字节**，不能只断言返回值/退出码——缺陷的本质正是
  「返回值说成功/拒绝，磁盘却是另一回事」。
- **⚠ 有守卫 ≠ 有覆盖（经验 183）**：`_upsert` 明明有「路径存在但哈希变化 ⇒ 拒绝」的守卫，
  缺陷却存活至今，因为 `cmd_add` **零测试**（只有 `scan` 有测试）。⇒ 审一个入口时，
  先枚举「它的每个子命令 / 每个分支有没有测试」，差集就是缺陷温床；
  不要因为「这个模块看起来有守卫」就跳过。

## 阶段 153 新增

- **⚠ 两个工具校验同一对象 ⇒ 必须有单一实现（经验 184）**：`build_real_ground_truth.validate`
  与 `real_asset_preflight` 都「校验 ground_truth.json」，却各维护一套判据 ⇒ 必然漂移成

  ⇒ 同一语义的校验只能有一份实现（本例抽 `structural_problems`），两处都调它。

  等于给另一个留盲区。要么都查、要么都不查——把判据**上收到共享函数**，让两边同时获得。
  同族：经验 24/77（同一规则两套实现）。

## 阶段 154 新增

- **⚠ 打印出的契约 ≠ 被强制的契约（经验 186）**：`baseline_seam_delta` 被计算、写进结果、文档声明为
  「不修复下界」，却只喂给打印格式化器，胜者判定函数根本不接收它 ⇒ 两引擎都比「留着水印不修复」更差时，

## 阶段 155 新增

- **⚠ 聚合指标口径：docstring 定义 recall=micro（ΣTP/ΣFN）时，头条绝不能用 per-image 均值（macro）（经验 187）**：`run_real_benchmark._aggregate` 把 per-image precision/recall 取平均当头条，而文件头 recall 定义本就是 micro；少数干净小图与多数重残大图权重相同，macro 系统偏松（探针：1 完美+1 重残 → macro 0.75 vs micro 0.505，+0.25 绝对差；9 完美+1 重残 → macro 0.95 vs micro 0.541，红线 precision≥0.6 由假绿翻转）。更糟的是 `real_gate` 直接把 macro 喂给红线 ⇒ 误绿。修法：`_aggregate` 增 micro 字段（按汇总 TP/FP/FN），micro 为头条、macro 降级次级；门禁改取 micro。判据：凡聚合指标，先确认 docstring/红线定义的是 micro 还是 macro，二者不可混用；macro 仅作「每图均衡」参考，绝不可单独驱动门禁。

## 阶段 156 新增

- **⚠ 量测被测 ≠ 决策被测：gate 的量测函数有守卫，不代表其决策函数有守卫（经验 188）**：`e2e_real_probe` 的 J1-J6 把 removal/collateral/spill 的量测响应测得很全，但其**决策函数 `evaluate_gate`**（红线方向 + 漂移三层判定、驱动退出码）却零守卫——量测正确 ≠ 门禁不会误绿。决策函数的**红线方向是契约**（removal 守下界、collateral/overdraw/spill 守上界），必须单独钉成测试；一旦方向写反（如 removal 错守上界），「去痕率跌成负值」会被静默放过。判据：审计门禁时，量测覆盖与决策覆盖要**分开看**；决策函数的每个红线方向、0-case/缺类型/引擎不符等边界，都要有断言；注入式反例翻转一个方向即应让 in-spec 输入被判失败。

## 阶段 157 新增

- **⚠ 写入口落地前必须就地校验：外部输出落成持久化真值前，先按下游校验口径过滤（经验 189）**：`cmd_auto` 把检测器区域直接 `int()` 拼 bbox 写入 `ground_truth.json`，全程不校验这些候选能否经得起 `audit_truth`（bbox 非负 / 在图内）——于是「检测器返回 0 区域」会写空条目、「越界/非正 bbox」原样落盘，`validate` 静默失败却打印「预填完成」。这是「打印契约 ≠ 强制契约」（186）在**写路径**上的具体形态：打印出的候选数 ≠ 合法候选数。判据：任何把外部/不可信输出落成持久化数据（真值、配置、manifest）的入口，落盘前必须**就地**按下游同一套校验口径过滤，无效则跳过或拒绝，**绝不原样写入再等下游去抓**；否则写入口与校验入口之间永远留一段「先脏写、后报错」的静默损坏窗口（同族：186 打印契约≠强制契约）。

- **182**：**下载路径也是写入口，先判定后落盘必须覆盖它；bool 返回值无法区分「同图跳过」与「路径冲突拒绝」（158）**：`collect_real_assets.cmd_download` 旧实现直接把文件下载到 `images/<fn>` 再交给 `_upsert` 判定 ⇒ 「已登记图被不同内容覆盖 + 判定拒绝」时磁盘已改、manifest 仍旧、退出码误报 0（与 `add --copy` 的 P0 同构）。修法同 152：先下临时文件、算 sha、判定**接受**后才 move 进 `images/`。配套：`_upsert` 返回 bool 时「跳过/拒绝/接受」坍缩成真值 ⇒ 必须升级为可区分的状态字符串（`accepted/skipped/rejected`）。**凡「判定后可能拒绝」的写入口，返回值语义必须能区分「已存在跳过」与「冲突拒绝」，否则拒绝分支会被调用方误读为成功。**

- **183**：**验证装置的裁决必须可证伪——退化样本（平局/缺失）不得计入一致性**（159）：`validate_selector` 的一致性判定 `gt = "opencv" if do > dl else "lama"` 在平局时静默倒向 lama 且**计入**，于是「指标零判别力」的退化样本被读成「指标与真值一致」——全平局时打印「一致性 4/4 = 100%」（零信息满分），把诚实的 0/2=0% 抬成 2/4=50%。判据：**凡「通过率/一致率」类裁决，必须把「无判别力（平局/退化）」与「数据缺失」单列且不计入**，否则验证装置会给出不可证伪的结论（同族：经验 7 度量会奖励劣化、15 跳过≠通过、22 缺数据须与零可区分）。

- **184**：**人眼复核通道的「取景」必须完整覆盖被修复区域，否则退化配置会静默给出无水印/无上下文的对比图**（160）：`make_real_compare_crops` 的 mask 用 `--pad` 外扩、crop 用 `--view` 外扩，二者独立且无 `crop ⊇ mask` 约束 ⇒ `view < pad` 时 crop **整幅落在 mask 内**（探针实测列比例 1.00），对比图里既没有水印也没有上下文、肉眼复核被静默误导而 rc 仍 0；而 `--pad` 帮助文本恰好写着「掩码与取景同步」，正是诱导。判据：**凡「生成给人看的对比/裁剪图」的工具，都要问「取景是否保证把被修复/被比较的区域整幅纳入」**——用一个 `eff_view = max(view, pad)` 之类的**不变量**兜住，并在被夹紧时**显式告警**（不静默改尺寸）；同时把「帮助文本/注释声明的取景语义」与实现对齐（同族：51 注释层两套实现、150 打印契约≠强制契约）。附带：**人眼复核通道属「验证装置」家族，净增量为零时交付物是「钉死取景/面板/退出码契约」，而非硬找缺陷**（经验 116）。

- **185**：**`or` 兜底会静默吞掉「显式 0」；带下界的参数缺校验会让状态机卡在非终态**（161）：`BatchQueue.__init__` 用 `max_concurrency or config.X` 这类写法 ⇒ 调用方**显式传入的 0 被静默换成 config 默认**（而同函数的 `retry` 用了正确的 `is not None`——**同一风险面两种写法本身就是缺陷信号**）。更实质的是：`retry` **无下界校验** ⇒ `retry < 0` 时 `attempts = retry + 1 <= 0`，`for attempt in range(attempts)` **一次都不执行** ⇒ `_execute` 直接返回，`task.status` 仍停在 **RUNNING** ⇒ 破坏 `run()` 「完整消费后无 PENDING/RUNNING」的**终态不变量**，界面进度条永久卡住。判据：① **凡「缺省用 A、传入用 B」的参数，用 `is not None` 判定，别用 `or`**（除非 0/空确实是"未提供"）；② **凡「数量/次数/并发」参数，都要有下界校验**——缺它时下游要么崩溃（`ThreadPoolExecutor(0)`）、要么静默走空循环把对象**留在非终态**；③ 状态机模块（队列/任务/连接）的守卫必须包含**终态不变量**：一轮跑完后不得残留任何非终态对象，且各类计数之和 == 总数。

- **186**：**i18n 文字量守卫若只扫 CJK 汉字，会系统性漏掉「全角/CJK 标点」这一类泄漏**（162）：项目的三个 i18n 文字量守卫（`_first_cjk`、`test_ui_audit94` 正则、`test_ui_wiring_contract110` 的 `cjk` lambda）**都只扫 U+4E00–U+9FFF**，于是 `tab_models._render_status_md` 里硬编码的全角分隔符 `f"- {dev_line} ｜ {dev_label}"`（U+FF5C）**永远扫不出来**——而项目自身的约定恰恰是「分隔符放在**本地化模板**内」（同页 `slot_line` 就是 zh`｜`/en`|`）。判据：① **扫「硬编码文案」时字符类要含全角标点（U+FF00–FFEF）与 CJK 标点（U+3000–303F）**，否则一整类泄漏不可见；② 守卫的**字符类范围本身也是被测对象**——「扫不到」与「不存在」必须可区分；③ 源码级扫描要**剔除 docstring / `t()` 实参 / `log.*()` 实参**（后两者是键名与开发者日志，不是用户可见文案）。附带：`note`/`display_name` 等**注册表数据**若为中文不算模块文案泄漏（数据 vs 文案须区分）——守卫测试要用 ASCII 假数据隔离。

- **187**：**「数学上更正确」的改法可能破坏交互语义——UI 状态机的「所见即所得」分支必须显式钉死**（163）：`tab_auto` 的 merge 模式若实现成严格 `det ∪ 编辑框`，字面上更贴近「∪」，但会把用户用橡皮擦擦掉的误检**加回来**（橡皮擦静默失效、且无任何报错）。判据：① 凡「带编辑器 / 可擦除 / 可撤销交互」的功能，**编辑框内容是唯一真值**，检测/预填只是初值与兜底——改合并逻辑前先问「这会不会让某个交互失效」；② 中间量不出现在返回值里时，守卫的**观察点选「交给下游的实参」**（桩掉引擎捕获 mask），而不是返回值（返回值只有图像/状态/路径）；③ **矩阵化探针**（mode × 编辑框状态 × 上游状态）是把「最不直观的业务逻辑」变成可守卫契约的最省力方式——每格断言「交给引擎的掩码 == 期望」，语义分歧当场显形。

- **188**：**「还原成功」的判据必须是原始字节 sha（`'rb'` 读入），文本 sha 会自比失效；且注入脚本读写都必须 `newline=''`**（163，127 的实证与升级）：阶段 158–163 的 6 个注入脚本全部用了 `open(p,'r').read()` + `open(p,'w').write()`——Windows 上写侧把 LF 规范成 CRLF、读侧把 CRLF 归一成 LF，于是「还原后 sha 一致 ✓」其实是**文本 sha 自比**（LF 归一化后的字符串再哈希），磁盘行尾已被悄悄改成 CRLF 而校验全绿。靠「**原始字节 sha vs 记录 sha**」的独立复核才暴露（`tab_auto.py` raw `33b48633…` ≠ 记录 `2294337a…`）。三条硬规矩：① 注入脚本读写一律 `open(..., newline='')`（读写两侧都要，写侧致命、读侧影响哈希可比性）；② **记录与复核的 sha 必须对原始字节计算**（`open(p,'rb')`），文本 sha 只能用于锚点匹配；③ 复核时若 raw sha ≠ 记录 sha，**先怀疑行尾**再怀疑内容——用 `b.count(b'\r\n')` 一眼定位。附：本轮已把 6 个文件转回 LF，转换后 raw sha **逐一等于**各阶段记录 sha（这本身就是「恢复到签收状态」的硬校验）。

- **189**：**本地化「拼接消息」只解决外层模板；被填充的 `{reason}` 可能来自更深一层的硬编码文案**（164）：把 `tab_batch` 的 `raise ValueError(f"跳过（{exc}）")` 改成 `t("batch.task_skip", reason=exc)` 后，en-US 下整条消息**仍含中文**——因为 `{exc}` 是 `utils/exceptions` 抛出的中文文案（`【不支持的图片格式】\n原因：…\n建议：…`）。判据：① 守卫断言要**按层隔离**——先钉「外层模板随语言切换」（`msg.startswith("Skipped (")`），再单独追 `{reason}` 的来源；**若直接对整条消息断言「无 CJK」，会把「修对了」误判成「没修」**；② 追到更深层（`utils/exceptions`）的同类泄漏时**登记为独立边界**、不在一层阶段里扩散修（避免阶段无边界膨胀）；③ 配套操作教训：注入脚本改用 `newline=''` 后，**多行锚点必须用文件真实行尾拼接**——`newline=''` 保留 CRLF 后，用 `\n` 拼的锚点在有 `\r\n` 的文件上匹配不到，须 `nl = "\r\n" if "\r\n" in text else "\n"` 再 `nl.join([...])`。

- **190**：**兜底不得回退到「别人的」默认值；同一资源的两条写路径，其「缓存/清理」必须对称**（165）：`core/model_manager.download_model` 在槽无 `urls` 时回退到 `config.MODEL_DOWNLOAD_URLS`（= **内置 lama 的地址**）⇒ 把 lama 权重下进**别的槽**路径，而该槽无 `expected_size`/`sha256` 时 `verify_model` **静默通过** ⇒ 用户拿到的是错权重。判据：① **凡「缺省回退到某个默认值」，先问「这个默认值属于当前对象吗」**——把 A 的默认资源用到 B 上是「静默装错对象」，应改为**明确失败**（内置槽本就自带 urls，回退从未被需要）；② 同一资源的两条写路径（`download_model` vs `rollback_model`）对**内存缓存**的处置必须对称——实测 rollback `_CACHE.pop(dest)`、download 却没有 ⇒ 下载新权重后仍命中旧模型对象（除手动热重载外静默用旧权重）；**「同一风险面两种处理方式」在这里表现为「一条路径清了、一条没清」**；③ 测试隔离「进程级单例注册表 + 惰性初始化」时，**快照必须在 `_ensure_init()` 之后**——在初始化前快照（`_SLOTS` 为空）再还原，`_INITED` 仍为 True ⇒ `_ensure_init()` 短路、注册表被清空且不再重建（同族：经验 35/66 的注册表生命周期）。

- **191**：**数量参数缺下界还有第三种后果：判据恒真 ⇒ 行为静默退化**（166）：`generate_pdf` 的 `records_per_page <= 0` 会让分页判据 `placed_on_page >= per_page` **恒真** ⇒ 静默变成「一图一页」——既非崩溃、也非空转，而是「悄悄换了个策略」，最难在测试里被发现（图还是能出）。至此数量参数缺下界的三种后果齐了：**负数→崩溃**（`ThreadPoolExecutor(0)`）/ **`<=0`→判据恒真静默退化**（166）/ **`range(负数)`→循环空转、对象留非终态**（161 的 `retry<0`）。判据：凡「每页 N / 每批 N / 上限 N / 重试 N」这类**数量参数**，构造期显式 `>= 下界`，**不接受 0 或负**（除非 0 有明确语义且被文档化）。附带：同一口径的「唯一真值来源」要用**双端断言**锁定——HTML 与 PDF 从同一 entries 生成后，断言两端的**总条数与逐项计数完全相同**（阶段 88 的护栏，本轮补成机器守卫）。

- **192**：**「首次推理 ≠ 稳态推理」——任何「进程内第一次检测即量」的门禁会被冷启动伪影漂绿/漂红**（181）：torch 算子 / OpenCV 线程池 warming-up，刚 import 后的首次 `detect_watermark_mask` 在边界样本上可能与后续推理差之毫厘，翻转「是否误发 corner_logo」这类**布尔判定**。180 曾把「首轮 OFF 误发 0↔1 翻转」误判为基线缺陷，181 用「进程内测量前先烧热 + 5 次 warm 复跑」证明那是**冷启动离群点**，基线在干净图上稳态不误发。判据：① 凡门禁/探针在**同进程**测量，先做一次废图推理 `_warmup()` 把检测器烧热，再量真实样本；② 复跑验证要**在已烧热之后**做多次（跨进程首跑仍可能踩冷启动，故 `_warmup` 必须在每次进程启动的测量前执行）；③ 不要把「跨进程复跑结果翻转」直接当成 DUT 缺陷——先排除冷启动，再下非确定结论（同族：经验 188 量测≠决策、191 静默退化）。

- **193**：**探针观察点必须在决策点（变换前），否则量到的是被裁剪后的世界**（182）：给 179 先验设计收紧判据时，探针读 `res.regions`（**合并后**）发现 syn_02/syn_05 零 translucent/edge_text 信号——但 180 实测先验在它们上**确实触发了**。矛盾根源：`_apply_plate_completion_prior` 的输入是**合并前**的 `all_regions`，弱信号在决策时存在、随后被合并阶段裁掉，事后从结果反推看不到。修法 = monkey-patch 包装决策点函数捕获真实输入，再量分离面（真实牌证据 max fp_ov ≥0.54 vs 误报源 ≤0.46）。判据：凡「读取内部状态做量化」的探针，先问「这个状态在决策点**之前还是之后**」——只观察变换后状态会系统性漏掉「决策时存在、事后被裁剪」的数据，进而得出「不可能触发」的错误归因（同族：经验 188 量测≠决策——量错对象比不量更危险；191 静默退化）。附带：第一候选判据（牌体白板极性 bright_frac）被数据当场否决（真实暗底牌 bright 仅 0.12~0.15），再次验证「候选判据必须先探针量化再实现」的项目流程。

- **195**：**「脚本能独立运行」是一个独立缺陷类别：`from scripts.x import y` 必须先有 `sys.path` 引导**（183）：阶段 170 把编码加固抽成 `scripts/console_encoding.py`（`from scripts.console_encoding import force_utf8_stdio`）推广到 13+ 脚本，其中 `scripts/undef_scan.py` **漏了项目根引导** ⇒ `python scripts/undef_scan.py` 抛 `ModuleNotFoundError: No module named 'scripts'`（`sys.path[0]` 是 `scripts/` 而非项目根）⇒ `test_module_selfcheck[scripts/undef_scan.py]` 自 170 起**常红**。判据：凡脚本内 `import scripts.*`（或任何以项目根为基准的包），必须在 `_ROOT` 定义后 `if _ROOT not in sys.path: sys.path.insert(0, _ROOT)`；**并用「枚举」核查整族**（183 扫出 17 个含该导入的脚本，唯一漏引导的就是它）——「推广到 N 个文件」的操作必须带一个机械化的整族守卫，否则漏网者静默潜伏（同族：187 打印契约≠强制契约、183 的登记表守卫）。

- **197**：**「声明了门禁」≠「门禁会运行」：任何质量门禁都必须有一个被**强制调用**的执行入口，否则它只是文档**（184）：`.github/workflows/ci.yml`（阶段 116 新增）把「CI 跳过 torch/network」写得很完整，但**项目根本不是 git 仓库（无 `.git`）** ⇒ 工作流**从未执行**；本地也没有「一键跑全库」入口 ⇒ 每阶段只跑子集，红灯被隔离在视野外，直接酿成 183 的 6 处**跨阶段**腐化（守卫常红数月无人知）。判据：① 新增任何门禁/守卫后，问「**谁**在什么时候**强制**跑它」——答不出就是「存在但从未运行」；② 该入口必须是**单一真值来源**：本地与 CI 调**同一个**脚本（184：`scripts/run_all_checks.py`），且要有**防漂移守卫**断言「CI 的可执行部分不得复制一份选择逻辑」（否则本地绿、CI 红）；③ 入口自身必须固化已知环境坑（184：pytest 强制项目内 `--basetemp`、统一 `sys.executable`）。附带教训：**先核实文件是否存在再动手**——本阶段一度误判 CI 引用的 `requirements-min.txt` 缺失（实为我的枚举漏了变体名），差点「修一个不存在的缺陷」（经验 178 枚举优于记忆）。

- **198**：**断言「某处缺 X / 某指标无人守」之前，必须**读当前实现**，不得依据旧注释或记忆**（185）：盘点全产品时我写「precision 没有门禁守」——**错**。`scripts/real_gate.py` 现状是：precision **有红线**（`("min", 0.050)`）**且进漂移层**（容差 0.25）**且在标定表内** `(0.0392, 0.0690)`。我的错误来源是**读到了阶段 106 的历史注释**（当时确实「未重标」）而没读 177 之后的实际值——**旧注释在代码里是「历史」，不是「现状」**。同一类错误本轮已出现两次（另一次是误判 `requirements-min.txt` 不存在）。判据：① 凡要下「缺口/未覆盖」结论，先 `grep` 当前实现并**贴出证据行**（表名 + 行内容），不引用注释里的数字；② 注释里的阶段号是**时间戳**，用前先确认它是否已被更晚的阶段改写（本项目注释会追加「⚠ 阶段 N 修正」）；③ 把「盘点/清单」类产物里的每条断言都标注**证据形式**（文件:行 / 实测值 / 登记来源），无证据的条目宁可写「未核实」——**盘点里的错误比代码里的错误更危险，因为它会被当成决策依据**（同族：178 枚举优于记忆；194 升级数据源须重扫消费者）。

- **199**：**性能门禁的工作量必须来自真实素材——合成工作量会系统性低估真实成本**（186）：给「P95 < 1.5s」建门禁时，首版用「固定 seed 合成图」当工作量 ⇒ P95 = **0.113s**；换成**真实基准图**后 P50 = **1.427s**、P95 = **3.209s** ⇒ **差约 9~28 倍**（合成底太平滑，检测器多数通路不干活）。若照合成数据设阈值，门禁会**掩盖真实回退**。判据：① 基准/门禁的输入必须与「用户真实会喂的东西」同分布（本项目 = 真实平台图）；② 兜底输入（合成 / 极小样本）必须**在结果里标明来源**，且**跨来源拒绝比较**（`source` 进可比性检查）；③ 换输入口径时必须重标基线——**「量错对象」比「没量」更危险**（同族：188 量测≠决策、193 观察点须在决策点）。

- **200**：**门禁的统计量必须先证明它高于噪声地板，否则会「常红失效」**（186）：给检测阶段建 P95 门禁时，首版「每图只跑一次」，连续两次同批测量 P95 = **1.558s → 4.037s**（同图 1.558 → 4.036）——**机器负载噪声约 150%**，而护栏只有 30% ⇒ 门禁会一直在红，等价于没有门禁（「红旗常亮=红旗失效」）。修法是换**统计量**而不是放宽阈值（放宽到 200% 等于哑巴）：改「**逐图 min-of-k**」（min = 能力度量，天然滤掉负载尖峰）后，连续两次 P50 +3.6%、P95 +2.9%，噪声被压到可判定水平。判据：① 建任何时间/性能类门禁前，先**连测两次**看同口径差多少——差值必须**远小于**护栏余量，否则先改统计量或加重复次数；② 在输出里**打印噪声参考量**（如逐图重复内极差），让读者能立刻判断「本次测量是否可信」；③ 报告绝对成绩时如实标注口径（本阶段实测：CPU 检测 P95 3.2s = 路线图 1.5s 的 2.1 倍 ⇒ 目标隐含 GPU），**不得**为了让门禁好看去调阈值（经验 77）。

- **201**：**覆盖率要成为门禁，先得把「统计口径」与「工具的收尾动作」都锁死——两者都会让数字静默失真**（187）：首次给本项目量覆盖率（`pytest-cov` 装了但从没用过），踩到两件事：① **口径**：不写 `.coveragerc` 就会把 `tests/`、一次性探针、运行时目录一起算进去 ⇒ 数字既不可比也无意义；必须显式 declare `source` + `omit`，并把「语句覆盖 vs 分支覆盖」「哪些是合理未覆盖（需 GPU/网络）」写清楚。② **工具收尾**：pytest-cov 默认用**并行数据**（`.coverage.<host>.<pid>…`），收尾 `combine()` 会**删除**这些文件——在受限沙箱里删除撞批量护栏 ⇒ `SystemExit` ⇒ **pytest INTERNALERROR、报告整体丢失**（实测用例跑到 97% 才崩，14 分钟白跑）。修法 = `.coveragerc` 里 `parallel = False`（**消除删除动作本身**，而不是去放宽沙箱护栏）；并把这条环境坑写进配置注释与统一入口的模块头。判据：① 数字类门禁上线前先问「**谁**在算、**算哪些文件**、**收尾会不会动文件系统**」；② 覆盖率地板必须**来自实测再向下取整**（本阶段 75.29% → 67），且要显式说明「环境差异（skip 集合）会改变数字」故留 10% 余量；③ **未测量口径不得启用判定**（CI 的 `not torch_required` 子集尚未测 ⇒ 明确不启用 `--cov`，避免假红）——与 186「先测量后标定」同族。

- **202**：**受限环境里的「删除」是两段式受限的——归档（rename）优于删除，且绝不要在脚本里反复重试删除**（188）：本沙箱的删除护栏有两级：① **单次删除请求**目标下文件数 > 50 即拒（`shutil.rmtree(build/)` 65 文件被拒；pytest 清理 92 文件的 garbage 目录被拒；coverage 收尾删并行数据被拒）；② **一旦被拒，该 turn 内所有删除权限被闩锁**——此后连**单个文件** `os.remove` 也被拒，且报错消息**始终指向最初那个已被搬走的路径**（= 缓存裁决，不再重新计算），极具误导性。实战结论：**要「清空根目录」就用 `os.rename` 归档**（rename 不触发护栏，且保留可复核证据）；真要删除则**在沙箱外交给用户**，不要改写成「逐文件删除」去绕过——那既无效，又会持续触发审批弹窗消耗用户（本轮实测：两轮尝试全部被拒并明确要求停止）。附带：把文件移进归档目录后**必须为新目录补忽略规则**——原 `/.*.py`、`/.*.txt` 是**锚定根目录**的，移动后即失效（188 实测：补 `.scratch/` 后 `git status` 才干净）。

- **203**：**改变「审计视野」（把某目录纳入/移出扫描范围）会连带使所有基于该视野的清单失效——必须重跑这些守卫**（190）：给「自检登记守卫」的跳过表补上产物目录（`build/dist/.scratch/htmlcov`）后，立刻冒出**两类连带失效**：① `build/lib/**` 的 52 个源码副本此前被当成「未登记模块」（**产物目录本不该进入审计视野**）；② 移进 `.scratch/` 的两个探针、以及位于已跳过数据集目录内的 `_gen_synthetic.py`，其豁免条目**变成幽灵**（登记名指向不再被枚举的路径）——两类都由**既有守卫**当场抓出，属「守卫正常工作」而非回归。判据：① 任何「跳过表 / 白名单 / 豁免清单」都是**相对于一个视野**定义的，改视野必须同时重审这份清单（`登记集 ∩ 视野 = ∅` 即幽灵）；② 同一张跳过表若被多处各写一份，**注释声称「同一口径」不代表真的一致**（190 实测两份早已漂移：一方有 `temp/logs/assets/plugins`、另一方有 `uploads/benchmark_real`）⇒ 抽为**单一真值来源**并让使用方直接导入；③ 兜底：**「登记表/清单类」守卫必须整文件运行，禁止按关键字筛子集**——本轮首跑用 `-k` 筛掉了幽灵条目那条用例，只看到 1/3 的失败（与 194「阶段收口必跑全库」同源）。

- **204**：**`pytest-timeout` 的「内外层超时」必须外层严格大于内层，否则测试自身的超时意图被静默截断、且一旦触发就中断整场 session**（191）：`pytest.ini` 的全局 `--timeout=300` 作用于**测试函数**，而用例给其 spawn 的子进程传 `timeout=600` ⇒ 外层(300) < 内层(600)。实测代价：全库覆盖率跑在 71% 被 `pytest-timeout` 掐断，**16 分钟的数据全部丢失**（连数据文件都没写出）。枚举发现 4 处：2 处 inner=600、2 处 inner=300（**相等即竞态**）。修法 = 显式 `@pytest.mark.timeout(M)` 且 `M > inner`，并把不变式机械化为 `tests/test_timeout_contract.py`（扫描 `tests/`：凡函数体内 `timeout=N ≥ 300` 必须带更大外层标记）。**守卫自身的教训**：首版扫描器**把注释里的 `timeout=600` 当成代码**，于是「解释契约的注释」反把守卫判红 ⇒ **扫描源码的守卫必须先剔除注释**（同族：189 顺序断言被 docstring 干扰、190 文档字符串干扰子集筛选）。判据：① 凡「外层守卫（超时/重试/内存上限）」，先核对**它是否 ≥ 被它包裹的内层预算**——外层小于内层等于内层永远达不到、且报错归因错位；② 相等也不行（竞态）；③ 慢用例的**注释估值**要用实测更新（本轮顺带改正 `test_prompted_area_gate` 注释里的「≈40s」→ 实测 ≈171s）。

- **205**：**改既有函数之前，必须先枚举并跑该函数的「全部既有测试」；否则你会打破一条早已被守着的契约**（192）：191 把 `tab_batch._normalize_file_value` 抽成共用件时，我只跑了自己新写的测试，把**顶层未知标量兜底**从「丢弃（`3.14 → []`）」改成了 `str(value)`，而这条契约**一直由 `tests/test_tab_batch_helpers.py` 守着**——直到 12 分钟的全库跑才发现（`[123] → ["123"]` 与 `3.14 → []` 的**不对称是有意的**且两条各有测试）。判据：① 动任何「看似只在本地使用」的函数前，先 `grep` 该函数名，**把命中的测试文件全部跑一遍**（`pytest <files>`），再动代码；② 「保留旧行为」这种说法必须**逐条对着既有断言核对**，不能凭对新旧代码的目测（我 191 文档里那句「保留旧的兜底行为」就是错的）；③ 与既有契约不一致时，先判断「旧行为是否是有意的」——不确定就**保留旧行为**并把不对称写进文档，别顺手统一。

- **218**：**「承诺面」必须实测；分类器产出的每个类别处理器都必须有处置，否则一个未处置类别即中断整轮**（204）：① `pyproject.toml` 写着「足以支撑本地可安装（`pip install .`）」，**从未有人真跑过** ⇒ 首次实测就发现它在**残留 `build/`** 时失败（`WinError 183` 撞名）——`pip install .` **不幂等**（新克隆没事，开发者日常工作树中招）⇒ **未经实测的承诺等于没有承诺**。② 为清 `build/` 而 dogfood 项目自己的 E2 工具，**`clean_artifacts.py --archive` 当场崩溃**：`classify_file` 早就产出 `stray_nul` 类别（源码有文档有实现，报告也单独列出），但 `archive()` **没处理它** ⇒ `os.path.relpath("D:\\...\\NUL", root)` 抛 `ValueError: path is on mount '\\\\.\\NUL'`（ntpath 把 Windows 保留设备名当**设备路径**；实测 `NUL`/`CON`/`AUX` 触发、`COM1` 不触发），而该调用**在 try 之外** ⇒ **整个归档轮次当场中断，一个坏条目毁掉其余 78 条**——`分类器与处理器不一致`比「分类错误」更隐蔽（分类明明是对的）。③ **逐条隔离 > 全或无**：`relpath`/`makedirs`/`move` 这类每条目都可能独立失败的调用必须包进 per-item `try`；④ **成功路径的展示性输出不可先行**——原实现 `print("归档 → X")` 在 `move` 之前，失败时输出与真实状态矛盾（skill 里早有此提醒，**这次真的撞上了**）；⑤ 修法 = `_NON_ARCHIVABLE` 登记表（带理由）+ 逐条隔离 + print 后置 + 汇报「成功/失败/跳过」并列出跳过项，配 3 条守卫 + 2 个注入式反例（清空登记表 / 取消隔离，后者**复现原始 ValueError**）；⑥ 反例脚本须**每步后立即还原并核对 sha256**，防"注入测试自身留下污染"。

- **219**：**清完还要看「剩下的是什么」；体积是仓库卫生的隐藏维度；否定式承诺须配主动式机器判据**（205）：① 204 的产物退管让追踪文件从 5172 掉到 **743**，**降幅本身是信号** ⇒ 必须核实「没有误伤源码」，而核实过程恰好暴露了**一个 196 MB 的 `models/big-lama.pt` 被 git 追踪**（它本不在清理目标里）——**磁盘清理由「该删什么」与「剩下的是什么」两问组成**，只做前者会漏掉后者。② `.gitignore` 审查通常只看"哪些路径被忽略"，**不看"留下的有多大"**；而 **GitHub 对单文件 > 100 MB 硬性拒收**（>50MB 仅警告）⇒ 196 MB 会让 **`git push` 直接失败**，也就是我在 199~204 反复建议的「推远端跑 CI」**会被这个缺陷当场阻断**，且当时**没有任何守卫能发现**⇒ **仓库卫生审计必须包含体积维度**。③ 根因是**文档与实现矛盾**：`models/.gitkeep` 写着「权重文件…已被 .gitignore 忽略，不会上传到代码仓库」，但 `.gitignore` **压根没有 `models/` 规则**——这是**否定式承诺**（"我不会做 X"），比"我会做 X"更容易悄悄失效（**没人会去验证"没发生的事"**）⇒ 否定式承诺必须配**主动式机器判据**（用 `git check-ignore` 实测，而不是"看着像对的"）。④ 修法 = 补 `models/*.pt` 等规则 + `git rm --cached` 停止追踪 4 项（**保留磁盘文件**）+ 新增 `tests/test_repo_hygiene.py` 两条守卫（追踪文件 ≤50MB 用 `git ls-files` 作唯一真值来源；文档承诺的忽略必须被 `git check-ignore` 证实）——反例有效性已验证（`git add -f` 后守卫精确报出 `196.1 MB`）。⑤ **清理要防「过头」**：我一度给 `.workbuddy/scratch/` 与 `*.bak` 加忽略规则，随即撤销——那里面有阶段 158–167 的探针脚本（E1 约定"每阶段保留 1 份"的**有意证据**），过宽规则会把证据一并退管。⑥ **历史 blob 未清**：`git rm --cached` 只影响此后提交，196MB 仍在历史里 ⇒ 未推送过则应重建首个提交（或 `git filter-repo`），已推送过需 `filter-repo` + 强推；**本阶段未动历史**（破坏性操作需用户决策）。
