## 阶段 106 · 掩码—实体对齐收尾：框内证据几何收敛 + 网格模板门限

**触发**：用户选「下一阶段」，承接 P1.53 的候选 1 —— 把 `overdraw`（掩码面积 ÷ 真值面积）
的双向失准收回 0.9~1.5（阶段 105 基线：`edge_text` 5.00 / `grid` 6.21）。
产出 `docs/106-掩码实体对齐收尾-框内证据几何收敛与网格模板门限.md`。

### ① 归因（模式 A：逐策略消融，10 图 × 4 类）

三条**与直觉相反**的事实：
- **网格通路本身已对齐**（`solo` overdraw **1.79**；它只占 `grid` 案例 6.21 中的 0.87 个面积点，
  却是 0.64/0.74 个真阳性点的来源）；`−edge` 少 2.50 点、`−trans` 少 1.95 点。
- **框型（edge）通路是最大单一 FP 源**：`faint_tiled` 上多涂 **4.45** 个图面百分点（TP 仅 +0.30）。
- **唯一承诺类型的真阳性主要来自半透明通路**（`−trans` 后角标 TP 0.51 → **0.07**）。

**机制**：`_refine_regions_to_mask` 末步 `dilate(ellipse(2·pad+1))` ⇒ **pad=2 时每个证据像素
变成 5×5 块**（对 1~2px 笔画是约 25× 面积放大）；网格折叠模板门限**从不乘余量** ⇒ 纹理残留
伪结构占该通路 FP 的 **82%**。

### ⑤ 红线标定升级为「双约束」（方法论）

「新值 ×1.30」只满足「防误判」；本阶段改进幅度 19~25% ⇒ ×1.30 会让**回退值落回红线内**
（`grid.overdraw` 旧值 6.206 < 1.30×5.015=6.52，且漂移层也抓不住 +23.8%）。
⇒ 新增约束②「**红线须低于改动前实测值（留 5% 余量）**」，并逐项校验「回退值 > 新红线」。
真实图 `mask_coverage ≤0.045` 本身即编码了阶段 93 目标已达成。
**如实登记两个例外**：`precision` +5.0% 无任何自动判定能守住；`mask_iou` 回退由漂移层负责。

### ⚠ 本轮最重要的发现：`DETECT_TILED_PATH_GUARD` 是**死开关**

两个注入（`WME_DETECT_TILED_PATH_GUARD=0`、`WME_DETECT_GRID_TMPL_K_MULT=1.0`）都返回 **EXIT=0**，
且面积数值与基线**逐位相同** ⇒ 追根因（`%TEMP%/s107_guard_check.py`，3 张真实图）：

| 调用 | 平铺通路掩码像素 |
|---|---|
| A `guard=None` + config=True | 12957 |
| B `guard=None` + config=False | **41764（3.2×）** |
| C `guard=True` + config=False | 12957（**与 A 逐位相同**） |

完整管线 `ai_faint_tiled`：config=True 36957 px / config=False 36957 px ⇒ **完全相同**。

**根因**：`detect_watermark_mask` 的调用点写死了 `guard=(_rescue_depth == 0)`（主臂恒为 `True`），
而 `detect_tiled_translucent` 内部是 `_guard = config.DETECT_TILED_PATH_GUARD if guard is None else bool(guard)`
⇒ **实参遮蔽了 config** ⇒ 开关从未被读取，阶段 104 宣称的「注入式反例（可逆、不改代码）」
**自诞生起就是无效的**（守卫行为本身正确，坏的是开关与那份被引用的验证）。
⇒ 修法：调用点改为 `guard=(None if _rescue_depth == 0 else False)`（主臂交回 config、兜底臂仍豁免），
并让 `test_tiled_path_guard` 的间谍断言改为「主臂传 `None`（= 由 config 决定）」。
