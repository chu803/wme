- 失败即从 `sys.modules` 摘除并写入结构化报告；

## 阶段 78 · 文件命名与路径安全真值审计（完成）

**动机**：用户「继续深化其他模块」。命名链路（`sanitize_filename` / `build_output_filename` /
`make_unique_path`）是**每次上传与导出必然经过**的公共路径，被 14 个服务模块 + 4 个界面页 +
API/CLI 依赖，输入完全不可信 —— 但审计发现它**零直接测试覆盖**（`grep sanitize_filename tests/` 为空）。
零覆盖正是缺陷长期潜伏的原因。

**探针取证（七项缺陷，全部实测复现）**：
1. **N1（最高危，默认配置即触发）**：`build_output_filename` 强制扩展名时盲目
   `rsplit(".", 1)[0]`，隐含假设「最后一个点之后是扩展名」；而**默认模板
   `{stem}_cleaned_{time}` 本身不含扩展名** → 含点主名信息被静默丢弃：
   `my.photo` → `my.png`（丢 `.photo` 与 `_cleaned_{time}`）；`{time}` 消失还会让同批多张图
   **坍缩同名**（`a.b` / `a.c` 都变成 `a.png`）。含点原图名（`photo.2024.png`、`v1.2.jpg`）极常见；
2. **N2**：清洗**只作用于主名**，扩展名位置是盲区 → `a.//evil` 原样保留路径分隔符；
3. **N3**：Windows 保留设备名未处理（`CON.png`/`aux.jpg`/`COM1.png` 创建会失败或写入设备）；
4. **N4**：控制字符未剔除（`\x00` 让 `open()` 抛 `ValueError`；`\n` 破坏日志与界面）；
5. **N5**：去尾只覆盖主名 → `a.png␠` 的尾随空白/点从扩展名位置漏过；
6. **N6**：`normalize_unicode` 是**死代码**（唯一「调用」是自检断言），全角转半角从未生效；
7. **N7**：`max_length` 只约束主名，不约束整个文件名（主名 3 + 扩展名 120 → 总长 123）。

**修复（三类根因 × 三条对策）**：
1. **语义假设不成立 → 不猜，选可恢复的一侧**：扩展名策略改为「仅当末尾段在 `_KNOWN_EXTS`
   白名单内才替换，否则**安全追加**」——多一个点只是难看，少一段名是不可恢复的静默信息丢失；
2. **管线顺序错 / 判据不完整 → 先净化再解析、约束选完整对象**：`sanitize_filename` 重写为单向管线
   （NFKC → 控制字符 → 非法字符 → **才**分离扩展名 → 分别去尾 → 保留名加前缀 → 长度控制），
   N2/N4/N5 一并根治；`max_length` 改为约束整个文件名（N7）；
3. **死代码与零覆盖 → 接入真实调用链 + 从零建测试**：`normalize_unicode` 接入清洗管线（N6）。

**纵深防御**：`make_unique_path` 自行剥离目录成分（`../escape.txt` → `escape.txt`），
是写出路径的最后一道防线。

**实现期踩到并当场修复的坑（均被测试抓住）**：
- `suffix.strip(" .")` 把**扩展名自己的前导点**也吃掉（`my.png` → `mypng`）→ 改为 `rstrip`；
- `Path("..").name` 返回 `".."` 而非空串 → `make_unique_path` 必须显式兜掉 `.`/`..`，
  否则会拼出「父目录(1)」这种荒谬结果。

**顺带修复测试隔离缺陷（审计副产品）**：跑子集时 `test_history_filter.py` 出现 2 例失败，
根因**不是本次改动**——多个测试设置 `i18n.set_language()` 后**不还原**，语言状态跨用例泄漏；
全量跑时被后面某个「设回 zh-CN」的文件碰巧掩盖。实测复现：
`test_cache_disk`（设 `en-US`）→ `test_history_filter`（断言中文文案）→ 失败。
已在 `conftest.py` 加 autouse fixture `_isolate_i18n_language` 快照/还原语言状态根治。
**「全量跑绿」不等于「测试彼此独立」——换执行口径（子集/乱序）才会暴露顺序耦合。**

**交付**：`utils/path_helper.py`、`conftest.py`、`tests/test_filename_safety.py`（**61 例**，
含 7 例「正常文件名逐字不变」的回归保护）、`docs/78-文件命名与路径安全真值审计设计.md`、
README §2.26 + §4 + §6、TODO P1.32、MEMORY（阶段进度加 78、经验 22、命名边界；压缩至 10.6KB）。

   用户写 `"ESRGAN"` / `" esrgan "` 被静默丢弃退回 `auto`——而同表的
   `INPAINT_DUAL_SECONDARY` 却正确做了 `.lower()`（**同类不一致**）；
5. C5 115 个数值配置 min/default/max ✅ 不自洽 = 0；
6. C6 `OUTPUT_ALPHA_FORMATS ⊆ SUPPORTED_OUTPUT_FORMATS` ✅。

**C2 的真实后果**：`{"INPAINT_DUAL_RUN": "false"}` → **意外开启双跑**（耗时翻倍）；
`{"REAL_SUPERRES_ENABLED": "0"}` → **意外开启真实超分**；`{"PNG_KEEP_ALPHA": "no"}` → 反而保留 alpha。
**两条触发路径**：手工编辑 overrides 文件；或脚本调用
`save_user_overrides({"X": "false"})`——后者会把 `True` **固化写入文件**。

**为什么从没被发现**：设置页写入的是**原生 JSON 布尔**，`bool(True)` 恰好正确
→ **主路径正确掩盖了另一条路径的错误**，常规使用中完全隐形。

**修复**：
1. 抽出 `parse_bool(value, default)` 作为全项目布尔解析的**唯一实现**，两条入口共用
   （原生布尔原样通过、字符串字面量正确识别、数字只认 0/1 不做「非零即真」、
   **bool 判断必须在 int 之前**）；`_env_bool` 改为调用它；
2. 5 个布尔验证器（`REAL_SUPERRES_ENABLED`/`INPAINT_DUAL_RUN`/`PNG_KEEP_ALPHA`/
   `IMAGE_APPLY_EXIF_ORIENTATION`/`IMAGE_NORMALIZE_BIT_DEPTH`）改用 `parse_bool`；
3. 同类一并统一：新增 `_normalize_superres_backend`（大小写无关 + strip），
   并给 `INPAINT_DUAL_SECONDARY` 补 `.strip()`；
4. `load_user_overrides` 对「校验失败」与「清单缺校验器」补 **stderr 留痕**
   （此前完全静默；用 stderr 而非 logger——config 是基础层，依赖 utils.logger 会循环导入）。

**核心守卫**：`test_bool_entries_agree_on_strings` 把「两条入口对同一输入必须给出相同结果」
变成断言；另有「验证器默认值与源码 `_env_bool("X", D)` 的 D 一致」交叉守卫（正则解析源码）、
「白名单与验证器清单一一对应」守卫。
**守卫经注入式反例验证**：注入 `bool(v)` → **10 例失败**（覆盖全部假值字面量）并精确定位
→ 还原后通过。

**两条通用规律（并入经验 24）**：
1. **同一语义的多条入口必须共用同一实现，并用断言锁死**——`bool(v)` 之错在于借用了
   **语义相近但不等价**的规则（Python 真值性 vs 配置字面量），二者在 `""` 上恰好一致、
   在 `"false"` 上分道扬镳；
2. **主路径正确是其他路径缺陷的最好掩护**——设置页写原生布尔使 C2 从未被任何测试触碰，
   只有「换一条入口」才能让它现形（与阶段 79「全量跑绿 ≠ 测试彼此独立」同源）。

**交付**：`config.py`、`tests/test_config_parse.py`（**76 例**）、
