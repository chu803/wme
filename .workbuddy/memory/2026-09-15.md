## 发现的缺陷家族 R1（报告质量汇总口径分裂）

**根因**：`_summary_stats` 只统计 `quality is not None` 的条目，**没有「已评估 / 未评估」维度**；
随后 HTML 出口按「`entries` 是否非空」、PDF 出口按「`avg` 是否为 None」两个**不同判据**各自渲染。

| 形态 | 触发 | 现象 |
|---|---|---|
| **R1a** | `REPORT_INCLUDE_QUALITY=False`（config 注释推荐用于「纯交付」） | HTML 报「良好 0 · 告警 0 · 待复核 0」而总条数 3（和 ≠ 总数 → 读者只能理解成「全都待复核」），PDF 却报「未包含质量评估」 |
| **R1b** | 逐条 `evaluate_quality` 抛错被 `except` 吞掉、该条 `quality` 留 `None` | **HTML 与 PDF 都静默漏计**：3 条只报 1 条，与同文档逐条明细的「未评估质量」自相矛盾 |

## 修复

- `_summary_stats` 增加 `assessed` / `unassessed`；
- 新增 `_quality_summary(stats)` → 段列表 `{mode, counts, note, avg}`，`mode ∈ {empty, none, partial, full}`；
- HTML 与 PDF **改为只消费段列表**，不再各自判断（渲染差异只留加粗/纯文本）。

修复后：场景 A 两侧**逐字一致**；场景 B 两侧都报「未评估 2」，且**分项之和恒等于总条数**。

## 已验证为非缺陷 / 边界（各写成测试钉住）

- `video_export._resolve_out_dir` 静默吞 `OSError` → 后续 `save_image` 必失败并被捕获 warning，**不会伪装成成功**；
- `export_frame_compare` 仅形状不同时把结果缩回源尺寸 → 符合设计意图（2× 结果视频用例钉住）；
- `extract_sampled_frames` 返回契约（`list[dict{"idx","image"}]`）→ 正确；
- `_extract_one` 越界帧号夹取 → **边界登记**（结果视频被 `max_frames` 截断时帧号不同源；UI 路径不可达）；
- CLI 质量行「需复核/告警/良好」**只统计单张图片**（PDF/视频刻意跳过，代码注释有说明）→ **设计而非漏计**，写成测试钉住。

# 阶段 96 · `ui/tab_auto` 审计（异常护栏一致性 + 构建期注册表累积同源缺陷）· 已完成 2026-09-15

## 两个真实缺陷（均为一致性 / 同源类，非算法错误）

- **P1 · `on_enhance` 异常护栏不一致**：同文件 9 个 `on_*`/`process_*` 回调里 8 个包 try/except + `format_exception_for_ui`，唯独它裸调 `render_compare_html`，失败时把 traceback 直接抛给 Gradio（违反阶段 81「UI 唯一异常入口」契约）。修法 = 补齐为与兄弟回调一致的「捕获 + `format_exception_for_ui` 降级为错误提示」；不动上游渲染逻辑；错误文案用正确键 `compare.viewer.render_fail`（非不存在的 `compare.render_fail`）。
- **P2 · `build_app()` 不清空超分控件注册表**：`_SUPERRES_WIDGETS` 重复 `build_app()` 时线性累积（探针实测 0→5→10）；单次正常、不报错、门禁测不出。修法 = 构建入口补 `clear_superres_widgets()`——与阶段 91 U3 `clear_registry()` **同源同构**（进程级全局注册表必须在入口清空）。
