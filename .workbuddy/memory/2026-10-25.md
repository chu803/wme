## 阶段 322a · 修复侧门禁化

**红线（类型中位数 × 绝对容差）**：R1 检回 ≥ 基线−0.05 / R2 擦除度 ≥ 基线−0.05 /
**R2b `faint_tiled`+`grid` 擦除度 ≥ 0（擦完不得比不擦更差）** / R3 误伤 ≤ 5%（320f 的默认承诺）。
退出码 0/1/2；接入 `run_all_checks --gates` 第 6 道，默认步骤不跑，成本 ≈4.5 分钟。

**为什么现在升**：317 当时「恒退出 0」的理由是无基线；现在 317/318/321 三轮 60 用例
同配置的角标检回/擦除度中位数**三次完全一致**（0.267 / 0.532）⇒ 判据可复现。
其余 5 道门禁全在检测侧或产物合法性侧，修复侧此前**零自动拦截**。

**价值反证（不是自称）**：把 317 首轮（318 后处理收窄**之前**）的 60 用例喂给判据
⇒ R2/R2b/R3 三条全红（误伤中位 49%~51%、`faint_tiled` −0.117、`grid` −0.172）。
即 318 那类回归放到今天会被 `--gates` 直接拦下。

**预演当场抓到的三个门禁自身 bug（详见 LESSONS #305）**：
① 用没装 `easyocr` 的系统解释器跑，数字照样自洽（`edge_text` 检回 0.992→0.0、
`faint_tiled` 擦除度 +0.010→−0.030）⇒ 新增 `_has_ocr()`，OCR 不在位 = **环境不合格 ⇒ 2**；
② `--write-baseline` 要求 rc==0，而 rc==0 要求基线存在 ⇒ 首份基线死锁，改为「无基线时视为首次锚定」；
③ 空掩码 `skipped` 被记成 `valid=False` 排除出中位数 ⇒ 检测器集体失明只会让 n 变小、
中位数照样漂亮（哑巴口）；改为按真实空操作计入（检回 0 / 擦除度 0 / 误伤 0）。

**基线口径的两个测量依据**（不是拍脑袋）：
- 用**中位数**而非均值：单例误伤可到 8.68%（`faint_tiled`）、16.46%（`grid`），
  用均值门禁会随个别图抖；15 样本的中位数 LOO（leave-one-out）波动仅 0.001~0.003。
- **R2b 不放宽**：现值 `faint_tiled` 0.010 / `grid` 0.002，距 0 只有几个千分点，属**贴地飞行**。
  故意留 0（负增益=擦完比原图更脏，产品上没有灰色地带）；将来若某改进把它压负，
  处理方式是据实重锚或修实现，**不是把 `GAIN_ABS_FLOOR` 改成负数**。
