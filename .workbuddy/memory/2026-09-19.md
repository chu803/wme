## `detect_watermark_mask` 对接契约核实（应用户转来的三个提问）

**性质**：为用户对接给**第三方 AI**（由它写合成测试集脚本）而做的**接口取证**。探针 `%TEMP%/api_contract_probe.py` + `%TEMP%/oob_probe.py` 直连源码实测；产出 `%TEMP%/水印检测对接契约.md`（交接文档）。

**三个提问的正确答案（其中两条是纠错）**：
1. ❌「输入图片路径，返回单通道二值数组」**两半都错**。实为 `detect_watermark_mask(image: np.ndarray, *, preset=None, ...) -> DetectionResult`：入参是 **numpy 数组**（RGB/RGBA/灰度均可，RGBA 的 alpha 被丢弃）；传字符串路径实测抛 `AttributeError: 'str' object has no attribute 'size'`。返回 **dataclass**，掩码在 `res.mask`。
2. ❌「角标文字需要你指定」**根本不成立**：函数**没有文字入参**。`use_ocr=True` 只是辅助证据；角标走的是「白底圆角板块」**绝对量形貌判据**（86），不识字。⇒ 决定检出率的是**形貌**（底色/圆角/字号/透明度/对比度），换文字几乎无影响。
3. 格式 = `config.SUPPORTED_INPUT_FORMATS` **9 种**（`.png .jpg .jpeg .jpe .webp .bmp .tif .tiff .jfif`）；**文件夹默认不递归**（CLI 需 `-r`）；`detect_watermark_mask` / `load_image` 都**不收目录**。

**实测确认的契约细节（写进文档，避免下游踩坑）**：
- `res.mask`：`uint8 (H,W)`、取值 **{0,255}**、**与原图同尺寸**（内部降到长边 ≤1280 检测后用 `INTER_NEAREST` 放大回来）⇒ 取二值必须 `res.mask > 0`（直接当索引会踩 85 的 dtype 陷阱；实测「当布尔索引用」能跑通而不报错）。
- `res.regions[].x/y/w/h` 是 **`np.int32`**，不是 Python `int` ⇒ 写 JSON/格式化前要 `int()`。
- `kind` 共 7 种；`used_ocr` / `stats`（`mask_pixels` / `coverage_ratio` / `region_count` / `by_kind`）。
- 面积闸：`DETECT_MAX_COVERAGE_RATIO=0.15` / `DETECT_MAX_AREA_RATIO=0.35` ⇒ **合成整图型水印覆盖 >15% 会被闸削掉**（非 bug，评估需注明或临时 `WME_DETECT_MAX_COVERAGE_RATIO=1.0` 对照）。
- `MAX_IMAGE_PIXELS=80M` 超限**抛异常**（不是跳过）⇒ 打分脚本必须逐图 `try/except` 计数跳过。

**本轮新发现两处「声明 ≠ 实现」（登记不改，非本阶段目标）**：
- **D1（SSOT 漂移，真）**：`cli.py:80` 自写 `IMAGE_EXTS`（8 项，**多 `.avif`、少 `.jpe`/`.jfif`**）≠ `config.SUPPORTED_INPUT_FORMATS`（9 项）。后果：CLI 文件夹模式**会收下 `.avif` 然后在加载时抛 `UnsupportedFormatError`**；`.jpe`/`.jfif` 则被**静默跳过**（单文件传入又能读）。
- **D2（边界越界，低危）**：`res.regions` 的包围盒可能超出画布 —— 实测 5 预设 × 30 图 = 24608 个区域中 **833 个越界（3.39%）**，**最大幅度 4 px**，全部是贴边的 `translucent`(488) / `grid_watermark`(345)（掩码膨胀/取整的边界效应，非逻辑错）。⇒ 下游按框裁剪**必须 clip**。

**顺带**：`bbox-IoU` 会对**长条带**与**整图型**目标在数学上失真（真值框细长 / 即整幅图）⇒ 已确定统一改用掩码级 `mRecall`/`mPrec`/`mask_iou`，并把这条假缺陷陷阱写进 `eval-blindspot-audit` 技能（新增探针 7）。
