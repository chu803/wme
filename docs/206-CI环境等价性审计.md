# 阶段 206 · CI 环境等价性审计（发现 15 个「推上去就会红」的用例）

> 起点：仓库已具备推送条件（阶段 205），但**没有任何人验证过「推上去 CI 会不会绿」**。
> `ci.yml` 只在远端触发，本地无从检验；而它只装 `requirements-min.txt` +
> `requirements-dev.txt`（**刻意不含 torch / PyMuPDF**），开发机却是**完整环境**
> ⇒ 这正是我一路在追的「环境差异掩盖缺陷」（同 LESSONS 184/216）。

## 一、方法：在导入层模拟 CI 的依赖缺失

**关键思路**：沙箱是**超集**环境。要模拟 CI，只需在本地**屏蔽 CI 提供不了的模块**
（`sys.meta_path` 插一个 finder，对它们抛 `ModuleNotFoundError`），
再把模型目录指向空目录（真实 CI 是全新 clone，权重不入库 ⇒ `is_model_available()` 为 False）。

**为什么屏蔽清单必须「只列 CI 真正缺的」**（我在本轮踩到的坑）：首版把
`yaml` / `pandas` 也列进去 ⇒ **25 个测试文件收集失败**。查因发现
`yaml` 是 **gradio→huggingface_hub 的传递依赖**，`pip install -r requirements-min.txt`
会**自动装上**。**屏蔽传递依赖 = 模拟错了环境 = 制造假红**。
⇒ 最终清单：`torch` / `torchvision` / `fitz`(pymupdf) / `easyocr` / `onnxruntime`。

## 二、发现：15 个用例在 CI 上会失败

模拟运行（CI 等价子集，2500 用例）实测：

| 类别 | 数量 | 涉及文件 |
|---|---|---|
| 缺 **torch** | 5（1 FAILED + 4 ERROR） | `test_device_manager_gpu.py`（1+4）、`test_auto_engine.py`（1） |
| 缺 **fitz** | 10 | `test_services_audit88.py`（6）、`test_validators_media.py`（2）、`test_report_service.py`（1）、另有 1 |
| **合计** | **15** | |

全部报 `ModuleNotFoundError`——**没有一条是断言失败**，即纯「环境前提不满足」。

**这意味着：`git push` 之后 CI 会红。** 而此前无任何机制能发现。

### 两个必须区分清楚的「真假」问题（我本轮自查过）

1. **`yaml` 的 25 个收集错误 = 我的工具配置错**（屏蔽了传递依赖），**不是缺陷**。
2. **`test_auto_engine.py::test_auto_honors_lama_preference_when_model_present`
   在真实 CI 上不会失败**：它的 guard 是 `skipif(not is_model_available())`
   ——检查**权重文件**；而真实 CI 是全新 clone、`models/big-lama.pt` 不入库
   （阶段 205 刚停止追踪）⇒ `is_model_available()` 为 False ⇒ **本就 skip**。
   我的模拟器当时保留了沙箱里的权重 ⇒ 才让它跑起来而失败。
   ⇒ 为忠实模拟，探针**额外把 `WME_MODEL_DIR` 指向空目录**。
   （仍有价值：补 `importorskip("torch")` 使依赖声明与实现一致——「有权重、无 torch」
   的组合仍会失败。）

## 三、修复：给缺可选依赖的用例加**守卫**，而不是给 CI 加依赖

CI 刻意保持轻量（见 `ci.yml` 说明），故正确方向是让用例**声明自己的依赖前提**：

| 文件 | 修法 | 理由 |
|---|---|---|
| `test_device_manager_gpu.py` | 模块级 `pytest.importorskip("torch")` | 全模块都要 torch；torch 在位就跑（完整环境/真机），不在位就 skip（min CI）。**同时修正文档**：原 docstring 写「沙箱/CI 均可跑」不准确 |
| `test_auto_engine.py`（lama 偏好用例） | 测试内 `pytest.importorskip("torch")` | 走 LaMa 路径需 torch |
| `test_services_audit88.py` | `_render` 助手内 + PDF 那一步 `importorskip("fitz")` | 放在 PDF 那一步而非用例开头，**保留 HTML 侧断言照常执行**（不损失可运行覆盖） |
| `test_validators_media.py` | 补 `@pytest.mark.skipif(not is_pdf_available(), ...)` | 该文件**已有此约定**（`test_validate_pdf_file_happy` 有、另两个漏了）——沿用同约定而非引入新风格 |
| `test_report_service.py::test_generate_pdf_real_file` | `pytest.importorskip("fitz")` | 生成真实 PDF 需 fitz |

> **自查抓到我自己的 bug**：给 `test_report_service.py` 加 `pytest.importorskip` 时
> 该文件**并未导入 pytest** ⇒ `NameError`。是重跑模拟时被当场抓出（**dogfood 生效**）。

## 四、新增常驻工具：`scripts/ci_env_probe.py`

「CI 能否绿」必须在**推之前**就可验证，故把模拟固化为项目脚本：

```bash
python scripts/ci_env_probe.py                 # 跑 CI 等价子集（约 10 分钟）
python scripts/ci_env_probe.py --check         # 零副作用自检（毫秒级）
python scripts/ci_env_probe.py --list-blocked  # 打印被屏蔽的模块
```

退出码与门禁家族一致：**0 通过 / 1 有失败 / 2 跳过**（pytest 不可用）。

## 五、验证

| 项 | 结果 |
|---|---|
| CI 等价模拟（首轮） | **15 个问题**（11 FAILED + 4 ERROR） |
| CI 等价模拟（修复后，`scripts/ci_env_probe.py` 实跑） | **2 个失败，且均为沙箱删除闩锁连坐**（`test_utils_audit90` 日志轮转的 `SystemExit: 1`）⇒ **CI 阻塞为 0** |
| `tests/test_ci_env_probe.py`（新增守卫 7 例） | **7/7** |
| `tests/test_scripts_console_encoding.py`（阶段 170 元守卫） | **通过**（新脚本补 `force_utf8_stdio()` 后） |
| `tests/test_legacy_selfcheck.py`（含自检登记） | **通过**（新脚本按约定登记进 `NOT_REGISTERED_BY_DESIGN`，附理由） |
| 三者合跑 | **84/84** |

> **探针自身的边界**：它在**本机沙箱**里跑，因此也会受「会话级删除闩锁」影响——
> 涉及删除/日志轮转的用例会以 `SystemExit: 1` 失败，那是**本机限制、不是 CI 问题**。
> 探针的失败提示里已写明这一辨识要点（**判据：见 `SystemExit: 1` 且行号指向删除/rotate 逻辑**）。

### 被既有守卫拦下的两次（项目纪律生效）

1. `test_scripts_console_encoding.py`（阶段 170 元守卫）——新脚本 `print` 了 `⇒`
   （**GBK 不可编码**）却未加固 ⇒ 变红。已补 `from scripts.console_encoding import force_utf8_stdio`。
2. `test_legacy_selfcheck.py::test_selfcheck_coverage_is_accounted_for`——
   新脚本含 `__main__` 却既未登记也未豁免 ⇒ 变红。已按 S 类约定登记并写明理由
   （默认模式跑全量 10 分钟，不适合做子进程自检）。

⇒ **这正是「新脚本自动纳入家族守卫」的价值**（LESSONS 205/208）。

## 六、诚实边界与一处**自我纠错**（写这条教训的人违反了它）

### 我在自己的新守卫里犯了 LESSONS 213

`tests/test_ci_env_probe.py` 要验证屏蔽器，而屏蔽器会**永久改写 `sys.meta_path`**
（全局单例）。首版**忘了还原** ⇒ 实测**同进程后续所有测试**的 torch/fitz 全被屏蔽：

```
FAILED tests/test_validators_media.py::test_validate_pdf_file_happy  - ModuleNotFoundError: [CI 环境模拟] fitz ...
FAILED tests/test_device_manager_gpu.py::test_cuda_explicit_raises_when_unavailable - [CI 环境模拟] torch ...
（共 5 个用例集体失败）
```

**这正是 LESSONS 213「改全局单例必须自包含」的反面教材**——我三天前刚写下那条判据。
修法：加 `_restore_import_state` fixture（保存/还原 `sys.meta_path` 与 `sys.modules`
中被屏蔽模块的**原始对象**，保住模块身份一致），并让 `--check` 用例也套上它
（`--check` 内部同样会 `install_blocker()`）。

顺带修掉另一个同类问题：模型目录用例会永久写 `WME_MODEL_DIR` ⇒ 改用 `monkeypatch.setenv`。
以及一个低级自伤：**我直接调用了 `find_spec("torch")` 并断言它返回 None**
——而屏蔽器的 `find_spec` **按设计就是抛异常**的。

⇒ 教训：**「新守卫自身也会污染全局状态」**。凡守卫要动单例（`sys.meta_path`、
`sys.modules`、`os.environ`、`config.*`），**它自己**就必须自包含——
不能只要求被测对象自包含。

## 七、诚实边界（环境差异的其余维度）

- 本探针只模拟**依赖缺失**这一个维度。CI 与本地仍可能因
  **操作系统（ubuntu vs windows）**、**Python 版本（3.11 vs 3.13）**、
  **路径分隔符**、**文件大小写敏感**而不同。它把最易被忽视的维度变成可本地验证，
  **不声称等价于真实 CI**。
- **未真跑 `git push` / 未观测真实 CI 结果**（无远端）。
  「CI 会红 / 修完会绿」均为**基于模拟的推断**，其中修复效果已由模拟前后对比支撑。

## 八、教训 → LESSONS 220

**① 「CI 会不会绿」必须是可本地验证的命题**——CI 只在远端跑，若不主动模拟，
「本地绿、CI 红」可以**长期无人发现**（本项目的 CI 从未运行过，本轮一测就是 15 个）。

**② 模拟环境时，屏蔽清单只能列「目标环境真正缺的」，绝不能屏蔽传递依赖**——
`yaml` 是 gradio 的传递依赖、CI 装了 gradio 就有它；把它列入屏蔽造成 **25 个收集错误**的假红。
判据：屏蔽前先问「这个模块会不会随某个**已声明依赖**自动装上」。
（这是「模拟器自身配置错」而非代码缺陷——**模拟结果异常时先审工具，再审代码**，同 215。）

**③ 「有权重但无 torch」这类**组合前提**最容易漏**——`test_auto_engine` 的 guard
只查权重文件，真实 CI 因权重不入库而 skip（巧合地安全）；但这种「靠另一端缺席而侥幸通过」
的守卫是脆的。**依赖声明应把所需条件写全**（权重 + torch）。

**④ 复用文件内既有约定，而非引入更好的新风格**——`test_validators_media.py` 已有
`skipif(not is_pdf_available())` 的写法（只是漏了 2 处）。补那 2 处要**沿用同一写法**，
而不是换成 `importorskip`——否则同一文件出现两种风格，后人无从判断哪个是"对的"。

**⑤ 守卫要放在**能保留最多覆盖**的位置**——`test_html_and_pdf_consume_same_quality_summary`
的 guard 放在 PDF 那一步（而非用例开头），HTML 侧断言仍照常执行。
「一律在用例开头 skip」会白白丢掉本可运行的覆盖。
