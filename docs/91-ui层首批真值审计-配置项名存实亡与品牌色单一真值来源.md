## 0. 为什么是它

阶段 90 之后重扫覆盖度，旧的「`postprocess_service` 最荒漠」印象被**修正**——
那是字面字符串计数造成的低估：

| 模块 | 行数 | 导入它的测试文件中的 `def test_` 数 | 比值 | 判读 |
|---|---|---|---|---|
| `ui/theme.py` | 164 | **0** | **∞** | ⚠️ 全仓唯一零覆盖 |
| `ui/app.py` | 442 | 4 | 110.5 | ⚠️ 界面总装配点 |
| `ui/tab_models.py` | 356 | 4 | 89.0 | 同层后续候选 |
| `services/queue_worker.py` | 464 | 14 | 33.1 | 阶段 87 补测后已大幅下降 |
| `services/postprocess_service.py` | 655 | 34 | 19.3 | **并非最荒漠**（旧口径低估） |

`ui/theme.py` 与 `ui/app.py` 同属「界面引导逻辑」：它们是**所有标签页/所有组件的装配入口**，
一旦配置或视觉令牌在这里失效，影响面是「整个界面」，而不是某一个功能。

## 1. 探针量化

### 1.1 候选清单

| # | 候选 | 判定 |
|---|---|---|
| **A1** | `_resolve_theme()` / `_VALID_THEMES` 是**死代码**，`config.SERVER_THEME` 全仓无人消费 | **真缺陷（配置项名存实亡 + 死代码）** |
| **A2** | `_VALID_THEMES` 是**假守卫**：与 Gradio 运行时注册表不一致，且漏放行会触发**联网下载** | **真缺陷（守卫内容错误）** |
| **B1** | 品牌主色 **12 处字面量、跨 3 文件**，含两种空格变体；改一处不全局生效且无守卫 | **真缺陷（无单一真值来源）** |
| **U3** | `build_app()` 从不调用 `clear_registry()` → 重复构建使注册表**线性累积** | **真缺陷（声明≠实现 + 累积型）** |
| **U4** | `_tab_rename_map_json()` 直索引 `TRANSLATIONS`，**绕过 `t()` 的缺失回退守卫** | 现网无缺陷（键齐全）；守卫被绕过 → 已硬化 |

### 1.2 A1 / A2 的决定性证据

**A1 —— 「喂两个不同值，看最终实参是否不同」**（AST 级 + 假 app 捕获 `launch` 实参）：

```
_resolve_theme   def=True  called=False        ← 全仓仅出现在定义行
```

| `config.SERVER_THEME` | `launch(theme=)` 实参类型 | 实参值 | 传入 CSS 长度 | 传入 JS 长度 |
|---|---|---|---|---|
| `'soft'` | Soft | `<Theme 对象>` | 1486 | 4956 |
| `'monochrome'` | Soft | `<Theme 对象>` | 1486 | 4956 |
| `'not-a-theme'` | Soft | `<Theme 对象>` | 1486 | 4956 |

三行**完全相同** ⇒ 配置项名存实亡。`_resolve_theme()` 单独调用时行为其实是「正确」的
（`'soft'`→`'soft'`、`'banana'`→`'default'`+告警）——**它只是从来没被调用过**。

**A2 —— 白名单 vs Gradio 6.22 运行时注册表**：

```
gradio.utils.BUILT_IN_THEMES = {base, citrus, default, glass, mario,
                                monochrome, ocean, origin, soft}   ← 9 个
阶段 91 前的 _VALID_THEMES   = {default, soft, gradio-dark, monochrome,
                                huggingface, base}                 ← 6 个
```

| 类别 | 成员 | 后果 |
|---|---|---|
| 交集 | `default` / `soft` / `monochrome` / `base` | 正常 |
| **白名单里有、Gradio 里没有** | `gradio-dark`、`huggingface` | 放行了不存在的主题 |
| **Gradio 里有、白名单没有** | `glass`、`ocean`、`citrus`、`origin`、`mario` | 误拒 5 个合法主题 |

而 Gradio 的 `get_theme()` 对未注册名会 **`Theme.from_hub(theme)` 去 HuggingFace 联网下载**
（本仓网络不可达）——即「放行不存在的名」的代价不是报错，而是**启动期静默联网超时后回退**。

### 1.3 B1 —— 品牌色字面量分布（全仓 `*.py`）

| 字面量 | 合计 | 位置 |
|---|---|---|
| `#2563eb` | 3 | `ui/theme.py`×2（常量 + CSS 渐变）、`ui/app.py`×1（注入 JS 边框） |
| `#1d4ed8` | 2 | `ui/theme.py`×1（常量）、`ui/app.py`×1（JS hint 文字） |
| `#0ea5e9` | 2 | `ui/theme.py`×2（常量 + CSS 渐变末端） |
| `rgba(37,99,235,…)` | 3 | `ui/app.py`×2（浮层底/阴影）、`services/export_service.py`×1（AFTER 角标） |
| `rgba(37, 99, 235, …)` | 2 | `ui/theme.py`×1（按钮阴影）、`services/export_service.py`×1（对比图文字 RGB） |

主色族共 **12 处、跨 3 个文件**，且**存在空格变体**（`37,99,235` / `37, 99, 235`）——
朴素 grep 无法对齐，改一处不会全局生效，而**没有任何自动化会因此失败**（阶段 83 判据）。
墨色族另有 4 处（`ui/theme.py` 暗色卡片 + `export_service.py` 的 Before 文字 / 联系表底 / Before 角标）。

### 1.4 U3 —— 重复构建的累积量

| 轮次 | 注册组件数 | 属于当轮 Blocks 的组件 | 属于上一轮（废弃）的组件 | 抛错 |
|---|---|---|---|---|
| 第 1 次 `build_app()` | 288 | 288 | 0 | 无 |
| 第 2 次 `build_app()` | **576** | 288 | **288** | 无 |

比值 **2.00×**（严格线性），`apply_language()` 返回 576 项，其中一半指向已废弃 Blocks 的组件。
**不抛错**——累积型缺陷在单次运行下完全正常，只有重复构建才显形。
`clear_registry()` 的 docstring 早已写明用途（"重复 build_app 时避免重复注册"），
但 `build_app()` **从未调用它**：声明≠实现。
（顺带记录：`docs/19-国际化多语言设计.md` 称"注册组件 146 个"，实测 288——历史文档数字陈旧，不改。）

## 2. 修复

### A1 —— 让配置真正生效（而不是删掉配置）

`_resolve_theme()` 原本就是**为 launch 准备的**，缺的只是那次调用。因此修复 = 接上它：

* `ui/app.py::launch_app()`：`theme_name = _resolve_theme()` → `"brand"` 走
  `build_app_theme()`，否则把经校验的内置主题名**原样交给 `launch()`**；并 `log.info` 打印解析结果。
* `config.SERVER_THEME` 默认值 `"soft"` → **`"brand"`**（语义明确：品牌定制主题），
  注释列出可用内置名与「非法值告警回退、不联网」的契约。
* `launch(css=...)` 改为 `build_app_css()`（启动期展开），保留 `APP_CSS` 模块常量作兼容别名。

### A2 —— 白名单改为从运行时枚举

`ui/theme.py` 新增：

* `builtin_theme_names()` —— **投影 `gradio.utils.BUILT_IN_THEMES`**，不抄写；
  注册表读不到时返回空元组（任何非品牌名都会被判非法并回退，绝不误放行）。
* `resolve_theme_name(value)` —— 唯一解析入口；非法值 **warning + 回退品牌主题**
  （「回退」与「生效」在日志上可区分）。
* 删除 `app.py` 的 `_VALID_THEMES` 硬编码副本。

### B1 —— 品牌令牌收敛到 `utils/brand.py`（单一真值来源）

新建叶层模块 `utils/brand.py`：

* **十六进制为唯一主键**（`PRIMARY_HEX` / `PRIMARY_HOVER_HEX` / `ACCENT_HEX` / `PAGE_BG_HEX` /
  `INK_HEX` / `SURFACE_HEX`），RGB 一律**派生**（`primary_rgb()` 等），不并列存储；
* `rgba(rgb, alpha)` 输出统一紧凑写法（`%g` 格式化 alpha，避免浮点尾数进入 CSS）；
* `hex_to_rgb()` 对非法输入**显式抛 `ValueError`**（不静默返回黑色）；
* 消费方必须 `brand.XXX` / `brand.xxx_rgb()` **在调用时读取**（而非 `from ... import` 冻结绑定），
  这是哨兵测试能生效的前提。

消费侧改动：`ui/theme.py`（主题对象 + CSS 模板，`build_app_css()` 展开）、
`ui/app.py`（拖拽浮层样式 `_overlay_css()`）、
`services/export_service.py`（对比图 After 文字色 / Before 文字色 / 联系表默认底色 / 两处角标底色）。

**不改的**：`utils/recommend_view.py` 的 `#eef2f7`（语义是进度条轨道底色，与 PAGE_BG 同值不同义）、
`server.py` 的 `#0f172a`/`#e2e8f0`（代码块底/文字色）、`ui/theme.py` 内只出现一次的
中性灰阶（`#ffffff`/`#dbe3ee`/`#cbd5e1`/`#e2e8f0`）——**避免"同值即同源"的假耦合**。

### U3 —— 入口处清空注册表

`build_app()` 开头调用 `clear_registry()`（docstring 早已声明的用途，只是从未被执行）。

### U4 —— 抽出 `t_in(lang, key)` 并共用守卫

`utils/i18n.py` 新增 `t_in(lang, key, **kwargs)`，`t()` 改为 `t_in(get_language(), ...)` 的薄封装
——「取当前语言词」与「取指定语言词」**共用同一套缺失回退与占位符守卫**；
`_tab_rename_map_json()` 改为走 `t_in`（不再直索引 `TRANSLATIONS`）。

|---|---|---|

| I3-B1 | `build_app_css` 令牌换回字面量 | `test_app_css_reads_brand_tokens_at_call_time`、`test_no_brand_literals_left_in_ui_and_export` |

定位方式：脚本打印的还原 sha 与 `BEFORE` sha 不一致；因同一文件在 I2 已正确还原过一次
（`sha256 = dedd6c02c36d…`），据此精确回滚并校验回同一哈希，再单跑 I3 复验通过。

## 5. 新增经验（68~73）

68. **「配置项存在」≠「配置项生效」**（91）：`Final[str]` 常量 + 一整套「白名单校验 + 回退 + 告警」
    看起来完备，但**零调用点**时它只是装饰。判据：给配置项喂两个不同值，看**最终实参**是否不同——
    相同即名存实亡。**死代码最危险的形态不是"多余的函数"，而是"让人以为某项配置受控"。**
69. **白名单必须从运行时枚举，不能抄写**（91）：硬编码白名单会同时「拒绝合法项」与「放行不存在的项」，
    而后者的代价可能是**联网请求**（Gradio `Theme.from_hub`）。凡有事实来源就必须投影它。
70. **「同值」会伪装成「同源」**（91）：品牌色恰好等于 Gradio `blue-600`/`sky-500`，
    因此 `Theme.to_dict()` 天然包含这些值——用"字典里有没有这个值"判断硬编码残留会得出**错误结论**；
    必须改判「被 `set()` 覆盖的键是否由哨兵驱动」。
71. **进程级全局注册表必须在入口清空**（91）：`clear_registry()` 声明了用途却无人调用。
    累积型缺陷的特征是**单次运行完全正常**（比值 2.00× 只在重复构建时出现），
    因此守卫必须**显式构造"第二次"**，而不是断言"当前值合理"。
72. **守卫被绕过时，「降级」会变成「崩溃」**（91）：`t()` 有缺失回退，但直索引 `TRANSLATIONS`
    是唯一的例外路径——键改名就升级为**构建期 KeyError**。同一语义的多入口必须共用同一函数
    （阶段 80 的复现）；且「降级」是**静默**的，测试必须把"取到了键名本身"当作硬失败。
73. **跨层共享令牌的等价性用"产物"判定，而非"源码文本"**（91）：把品牌色收敛到 `utils/brand`
    必然改变源码字面量，但 CSS/JS 语义不变——用双门禁的**产物指标**背书，比逐字节比对源码更可信。
