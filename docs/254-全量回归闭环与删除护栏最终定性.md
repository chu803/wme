## 3. 那 2 条失败的最终定性（三重证据）

### 证据 A · traceback 决定性确认护栏命中
`.scratch/stage253_traceback_batch032.txt` 头部：
```
# 护栏命中：True
# 重跑 rc=1；重跑仍失败
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":50,"threshold":50,"scope":"turn",...}
>           raise SystemExit(1)
E           SystemExit: 1
```
⇒ 进程在删除第 50 次时被 `SystemExit:1` 掐断，**断言从未执行**。

### 证据 B · 隔离实验证伪「邻居耗尽配额」假说
253 原假设「rotation 与删除密集测试同批时，配额被邻居耗尽 ⇒ 被牵连」。254 将其**单独成批（批 032）**后**仍失败**，且 `count` 恰好 = 阈值 50 ⇒ 是 `test_utils_audit90.py` **自身进程内**的文件删除就 ≥50 次（轮转 24 次 × 每次删 1 个最旧备份 + pytest 末 rmtree），**与邻居无关**。

### 证据 C · 减容复现证明断言本身成立（关键）
写 `.scratch/verify_rotation_guard.py`，**逐字复刻两条测试的断言逻辑**，仅把写入量降到阈值以下（healthy 用例 `maxBytes` 4096→65536 使单进程删除 <50；stale 反例仍用 4096 强制轮转以复现冲突），运行结果：

```
rotation_healthy:   0 错误 / 连续备份 / 大小受控 ✅
stale_multi_handler: 注入反例仍复现旧失败行为 ✅
```

⇒ 两条测试的**断言逻辑正确、产品代码（含 245 修复）无缺陷**；在完整全量中只是被护栏在删除第 50 次时掐断、断言没机会跑。

## 6. 两条方法论教训（#271 / #272）

- **#271 周期性失败要查「自身足迹」，不能只查邻居与代码**：253 用「单独成批」隔离后仍失败，才暴露真因是测试自身的文件轮转量 > 护栏阈值。编排能解决「邻居耗尽」，解决不了「自身超阈」。
- **#272 护栏掐断进程前断言未执行 ⇒ 必须用「减容复现」补证**：只看 traceback 只能证明「被护栏杀了」，不能证明「断言会不会过」。减容复现（降到阈值下、断言逻辑逐字一致）才是「无产品缺陷」的闭合证据，且不复改原测试、验证完即删。

## 7. 遗留与建议

- **环境机制层**：批量测试的单进程文件删除量有上限（50/进程）。`test_utils_audit90.py` 是轮转压力测试，天然超阈；若要其在护栏下也跑绿，要么（a）在护栏豁免通道跑（如本地/CI 无此护栏），要么（b）把 `maxBytes` 调大到使删除 <50（会弱化压力强度，不推荐）。
- **建议登记**：在 `docs/252`/本阶段明确标注该 2 条为「护栏不兼容，非缺陷」，避免下一轮全量再被误判为回归。
