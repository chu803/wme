# 阶段 193 · D2 批量 / 媒体页耗时展示（收口）

> 优化清单 D2：「用户看不到『为什么这次慢』」——阶段 190 已为**单图结果区**补上「本次耗时」，
> 并把拼装逻辑抽成纯函数 `_compose_status` + 共享接缝 `ui.components.format_elapsed`。
> 本阶段把同一范式**推广到批量与媒体页**，让三页共用同一段 `{seconds:.2f}` 格式化口径，
> 文案随页适配（单图=修复+增强 / 批量=整批 / 媒体=本次处理）。

## 1. D2 推广：三页共用 `format_elapsed` 接缝

| 页 | 入口函数 | 计时边界 | i18n 键 |
|---|---|---|---|
| 单图 | `ui/tab_single.py::_compose_status`（阶段 190） | 修复 + 增强 | `single.msg.elapsed` |
| 批量 | `ui/tab_batch.py::run_batch` | 从「开始跑队列」到「队列结束」（不含文件收集/入队准备） | `batch.msg.elapsed` |
| 媒体·PDF | `ui/tab_media.py::run_pdf` | 进入 `process_pdf` 到返回结果 | `media.msg.elapsed` |
| 媒体·视频 | `ui/tab_media.py::run_video` | 进入 `process_video` 到返回结果 | `media.msg.elapsed` |

**共享接缝**（`ui/components.py::format_elapsed`）：
```python
def format_elapsed(seconds, *, key="single.msg.elapsed") -> str:
    return t(key, seconds=seconds)   # 含前导换行，直接拼进多行状态文本
```
调用方只传各自的键，措辞差异交给 i18n，三页不因改写而漂移（同族：LESSONS 187/195）。

### 新增 i18n 键
| 键 | zh-CN | en-US |
|---|---|---|
| `batch.msg.elapsed` | `⏱️ 本次批量处理耗时 {seconds:.2f} 秒` | `⏱️ Batch took {seconds:.2f} s` |
| `media.msg.elapsed` | `⏱️ 本次处理耗时 {seconds:.2f} 秒` | `⏱️ Processing took {seconds:.2f} s` |

（单图键 `single.msg.elapsed` 已在 190 就位；此处 `media.msg.elapsed` 与 `batch.msg.elapsed`
补齐 D2 的剩余两页，占位符统一 `{seconds:.2f}`，en-US 零 CJK。）

## 2. 改动落点

| 文件 | 改动 |
|---|---|
| `ui/components.py` | `format_elapsed` 接缝（阶段 190 已加，本阶段被批量/媒体复用） |
| `ui/tab_batch.py` | ① 导入 `format_elapsed`；② `run_batch` 在 `queue.run` 循环前取 `_t0`，循环后拼 `format_elapsed(_time.perf_counter() - _t0, key="batch.msg.elapsed")` |
| `ui/tab_media.py` | ① 导入 `format_elapsed` + `import time as _time`；② `run_pdf` 在 `process_pdf` 前取 `_t0`、返回前拼 `media.msg.elapsed`；③ `run_video` 同范式（`_t0` 在 `process_video` 前、返回前拼耗时行） |
| `utils/i18n.py` | 新增 `batch.msg.elapsed`（zh+en）、`media.msg.elapsed`（zh+en，本阶段补齐） |

**口径一致性**：批量只量「真正的修复工作量」（队列运行），不含毫秒级准备；
媒体只量「进入服务层到返回」，与单图「修复+增强」口径对齐——都是用户感知的修复耗时。

## 3. 测试（`tests/test_elapsed_display_d2.py`，18 例）

- **接缝单测**：`format_elapsed` 默认键=单图、调用方键生效、en-US 零 CJK、`_compose_status` 仍委托 `format_elapsed`（钉死 190 契约不被悄然改回硬编码）。
- **i18n 双键 parity**：`batch.msg.elapsed` / `media.msg.elapsed` / `single.msg.elapsed` 三者 zh/en 双语言、占位符集合一致、en 无 CJK。
- **集成（服务层桩隔离）**：`run_pdf` / `run_video` / `run_batch` 在成功路径下，返回的多行日志**必须**含「耗时…秒」行；服务层 / 缓存 / 聚合 Markdown 一律 monkeypatch 成桩，避免拉起 torch / 真文件 / FFmpeg，断言聚焦、确定性。

## 4. 修复过程中的真实坑（诚实记录）

本次首轮编辑**多处以「Successfully edited」回报却未落盘**——具体为：
`tab_batch.py` 的 `format_elapsed` 导入与耗时 append、`tab_media.py` 的 `run_pdf` 计时起点与耗时 append、
`i18n.py` 的 en `batch.msg.elapsed` 键、测试文件的 `import ui.tab_single as ts` 全部静默未生效。
根因是**同批次多段编辑中某些 old_string 未真正命中当前内容**（之前被误判为「已落盘」），
靠 `Grep`/`Read` 复核才逐一发现并重放。

> 教训固化：**编辑后用 Grep 逐项复核落点**是必须步骤，不能信任 Edit 的成功回执
> （同族：LESSONS 205「改动函数后跑全部相关测试」——但本轮更前置，落在「编辑是否真的落盘」）。
