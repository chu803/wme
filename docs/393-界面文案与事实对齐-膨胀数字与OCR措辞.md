# 393 · 界面文案与事实对齐（膨胀数字 + OCR 措辞）（2026-11-07）

> 起因：要给外部 AI（豆包）做验收，我用**界面同一条处理链**（Gradio 端点 = 那两个按钮背后
> 的同一批函数）做了一次真机端到端，顺手读了界面 DOM 与状态文案 ⇒ 抓到两条
> **「界面说的 ≠ 实际发生的」**。

## 问题 1 · 膨胀提示停在旧数字

- 滑块说明写着「完全擦净率 51%→84%；仍嫌不够可调到 36（88.9%）」——
  84% 是阶段 390（只加 24px 膨胀下限）的口径；阶段 392 加了**板块整块填充**之后，
  默认路径实测已经是 **97.9%**。
- 修：中英文案都改成「51%→84%，**整块填充后 97.9%**」；
  守卫 `tests/test_dilate_hint386.py` 增钉一条 `97.9%` 必须出现在两种语言里。

## 问题 2 · OCR 提示在撒谎（更严重）

- 干净图那次检测，界面写「**未启用 OCR**，使用 OpenCV 原生检测；**装 EasyOCR 可提升文字水印精度**」。
- 实情：EasyOCR **装着、开着、也跑了**，只是那张图没命中 OCR 文字框。
- 根因：`used_ocr` 的语义是「本次**命中过** OCR 文字框」，却被当成「OCR **是否启用**」——
  两个不同的事实被一个布尔量顶替 ⇒ 只要没命中文字框，界面就宣称"没装 EasyOCR"。
  用户会被这句话**误导去装第二个 OCR**。
- 修：
  - `core.detector.is_ocr_available()`：新增**公开口径**（OCR 通路是否可用），与 `used_ocr` 分开；
  - `ui/tab_auto._ocr_tip(used_ocr, ocr_available)`：三态措辞
    ① 命中过 → 「已启用 OCR 文字增强」；
    ② 开着但没命中 → 「已启用 OCR 文字增强，但本次没检出 OCR 文字水印」；
    ③ 真没装/没开 → 「未启用 OCR……装 EasyOCR 可提升文字水印精度」；
  - `ui/components.build_detection_stats_markdown(stats, ocr_available=...)`：命中率面板同一处措辞；
  - i18n 新增 4 个键（中英各 2 个）。
- 守卫：`tests/test_ocr_tip_truth393.py`（5 条，先红后绿）。

## 顺带：公网隧道在本机网络下走不通（实测三条）

| 方案 | 结果 |
| --- | --- |
| Gradio 自带 share | 需要 frpc 二进制，**HF CDN 不通**（http=000 / 21s 超时） |
| cloudflared 直下 | GitHub release 资产走 `release-assets.githubusercontent.com` 只有 1/4 个 IP 通（185.199.110.133），下载速率 ~750KB/分钟（50MB 要一小时） |
| ssh 隧道 localhost.run | 通，但 **~10KB/s**（60s 只传 640KB），且空闲即被 "tunnel activity timeout" 掐断 |
| ssh 隧道 serveo.net | 速度快（0.7s），但**响应被截断**（256KB / 425KB 断流）⇒ Gradio 首屏 870KB 加载不了 |

⇒ 公网暴露要么**用户本机下载 cloudflared**（`D:\qoder\tools\` 放好即可，
`cloudflared.exe tunnel --url http://127.0.0.1:7860` 一条命令出随机公网地址），
要么**用户自己开 `http://127.0.0.1:7860`**、外部 AI 只做截图复评。
