# 阶段 104 · 平铺增强通路的连通域守卫（判据收紧）

> 阶段 103 报告把下一阶段的目标写为「`tiled_enh` / `grid` 两条形状掩码通路的判据过松」。
> 本阶段最终交付的结论里有两条否定：
> **① `grid` 那半不需要改**（套守卫是纯亏本）；**② `tiled_enh` 那半的成因不是「判据过松」**，
> 是**基础通路早已装上的连通域守卫在这条通路上缺席**；而且接上时**只该接一道**（纹理稠密），
> 自然光影那一道会把弱信号档误伤成空掩码。

---

## 1. 起点：三个数字与一个假设

阶段 103 的归因探针给出：

| 策略 | 在真实底图上涂了 | 精确率 |
|---|---|---|
| `tiled_enh` | 13.2% 图面 | 0.064 |
| `grid` | 12.1% 图面 | 0.131 |

承接的假设是「判据阈值过松」。但阶段 99 已经用两侧量否决过「单纯抬阈值」这条路线
（抬 `DETECT_EDGE_ABS_DELTA` 同时打穿召回），所以本阶段先做归因，不先动参数。

**做法**：写一个**带自校验的复刻件**（`%TEMP%/s104_attrib.py`）—— 在探针内逐步复刻
`detect_tiled_translucent` 与 `detect_grid_watermark` 的内部流程（带阶段捕获、守卫开关），
并强制断言「守卫关闭时复刻输出 == 真实函数输出」（逐字节，10 张底图 × 2 通路）。

```
自校验：复刻件（guards=()）与真实函数的输出是否逐字节一致
结果：一致（复刻件可信）
```

这一条是必要的：复刻件若与真身不一致，后面所有归因都是在分析一个**新造出来的**缺陷。

## 2. 归因：过检来自「缺席的守卫」，不是「过松的阈值」

### 2.1 阶段拆解（10 张真实底图，`faint_tiled` 预设，sens=0.72）

| 阶段 | 面积% | 精确率 |
|---|---|---|
| `tiled_enh`：证据门限之后（连通域过滤之前） | **14.18** | 0.118 |
| `tiled_enh`：连通域过滤后 | 8.90 | 0.141 |
| `tiled_enh`：5×5 闭运算后（最终） | 10.47 | 0.141 |

关键读数在**第一行**：`_evidence_gate` 之后就有 14.18% 的像素通过。后续的连通域过滤
（−5.28 点）与闭运算（+1.57 点）都只是在这个数上做加减。**过检不是过滤阶段造的，
是门限阶段就有的。**

### 2.2 门限阶段为什么放行 14%？

`detect_translucent`（基础通路）在阶段 82/84 加了两道**连通域级**守卫：

| 守卫 | 测什么 | 设计靶子（docs/82、docs/84） |
|---|---|---|
| `_suppress_natural_light` | 边缘锐度 `edge_sharp` 与相对锐度 `ratio` | 真实照片误报的 **92.5%** 是自然光影（水面、云层、树叶） |
| `_suppress_texture_like` | 梯度**稠密度** `density` | 剩余大头是**锐利自然纹理**（枝干、草地、织物、砖墙） |

而 `detect_tiled_translucent` **重新取了一遍候选却一道都没接**。于是同一批被基础通路
已经否掉的像素，从这条通路重新进入并集。`grid` 通路的 `evidence = marks`（同一门限的
0.9 倍，**更松**）同样没有接。

**这就是「13.2% / 12.1%」的来源。**

### 2.3 合并层对照（并集口径 = 预设真实启用集合，10 张真实底图）

只做单策略隔离还不够——门禁量的是**并集**。对照实验（`%TEMP%/s104_merge.py`）：

| 变体 | faint_tiled 预设面积% | ai_grid 预设面积% | 干净图纯误报% |
|---|---|---|---|
| V0 现状 | 9.619 | 10.188 | 3.207 |
| V1 只收紧 `tiled_enh` | **2.362** | **3.537** | **0.803** |
| V2 只收紧 `grid` | 9.619 | 10.146 | 3.207 |
| V3 两者都收紧 | 2.362 | 2.853 | 0.689 |

两条读数决定了方案：

1. **只收紧 `tiled_enh` 就拿到 65% 的削减**（10.188 → 3.537 中的 6.65 个点）。
2. **只收紧 `grid` 几乎不动**（10.188 → 10.146），却要付 0.194 的召回
   ⇒ 网格通路在并集里的**边际**过检只有 0.68 个百分点，是**纯亏本买卖**。

## 3. 三个被否决的方案（附数据，勿重试）

### 3.1 给 `grid` 通路也接守卫 —— 否决

合成侧对照（`%TEMP%/s104_synth.py`，`ai_grid` 预设）：

| 底图 | 通路 | 收紧前 精确率 / 召回 | 收紧后 精确率 / 召回 |
|---|---|---|---|
| gradient | grid | **1.000** / 0.997 | 1.000 / 0.714 |
| textured | grid | **1.000** / 0.871 | 1.000 / 0.455 |
| photo | grid | **1.000** / 0.991 | 1.000 / 0.676 |

精确率**已经是 1.000**——阶段 53 的 `DETECT_GRID_EVIDENCE_AND` 早就把假响应收干净了。
再套守卫**没有任何精度收益**，只有召回损失（0.99 → 0.68）。故只作用于平铺通路，
并写成守卫测试 `test_C_grid_path_untouched_by_switch`（逐字节锁定：切换本开关不得
改变 `detect_grid_watermark` 的任何输出）。

### 3.2 用「周期性」做判据（复用 ACF）—— 否决，且这个否决更重要

`tiled_enh` 是「平铺/重复水印增强器」，却从不验证水印是否真的重复（同族的 `grid`
通路用 ACF 自相关峰验证周期）。看起来是一条**结构化**判据，优于「抬阈值」。实测
（`%TEMP%/s104_acf.py`）：

| 底图 | 干净 | +faint_tiled | +grid |
|---|---|---|---|
| 合成 gradient | 0.211 | 0.199 | 0.833 |
| 合成 textured | 0.052 | 0.045 | 0.119 |
| 合成 photo | **0.043** | 0.041 | 0.188 |
| **真实照片（10 张）** | **0.268**（min 0.116，**100% 过阈**） | 0.248 | 0.245 |

`DETECT_GRID_MIN_ACF = 0.09` **只在合成底图上可分**。真实 640px 照片上连**干净图**
都 100% 通过（最小值 0.116 仍高于阈值 29%）——真实照片天生充满周期纹理（砖墙、织物、
树叶、栏杆），而残差场是局部对比度的产物，把这些周期性原样保留。

由此得到一条**推论**（比否决本身更有价值）：`grid` 通路的 `is_grid` 判定在真实照片上
**是空的**，所以折叠模板会「铺满全图」（实测 `tmpl_frac` 达 0.966 / 1.000 / 0.261 /
0.299 四档），**真正承重的是 `DETECT_GRID_EVIDENCE_AND`**。

写成反例测试 `test_D_periodicity_is_not_a_valid_criterion`：一张干净的周期棋盘纹理
（无水印）必须**通过** ACF 判据 —— 若后人想用 ACF 收紧本通路，该用例会失败。

### 3.3 折叠模板占空比上限 —— 降级为「登记」

一个看似合理的形状先验：真实网格水印的模板占空比应该很小（点/线阵），
模板若占满整个 tile（`tmpl_frac` → 1.0）说明折叠没有提取到任何结构。实测：

| | 面积% | 召回 | 干净图误报% |
|---|---|---|---|
| V3 两者收紧 | 2.853 | 0.369 | 0.689 |
| V4 两者收紧 + 占空比上限 0.5 | 2.853 | 0.369 | **0.608** |

**默认配置下几乎零效应**（面积与召回逐位相同，只有干净图误报 0.689 → 0.608）。
它唯一的实际作用是在 `DETECT_GRID_EVIDENCE_AND=False` 这个非默认回退档下防灾难
（该档下模板铺满全图 ⇒ 整图修复）。按「任何优化先问：它改变了结果吗」的原则，
本阶段**不加这个旋钮**，改为在边界里登记：

> `DETECT_GRID_EVIDENCE_AND` 是**承重结构**，绝不可关闭。其承重性由
> 「`DETECT_GRID_MIN_ACF` 在真实照片上无区分力」决定（见 3.2），二者是同一件事的两面。

## 4. 落地

### 4.1 只接**纹理稠密**一道（不是两道）

`core/detector.py::detect_tiled_translucent` —— 在证据门限之后、连通域过滤之前：

```python
_guard = config.DETECT_TILED_PATH_GUARD if guard is None else bool(guard)
if _guard:
    cand = _suppress_texture_like(cand, residual_abs)
```

新增配置 `config.DETECT_TILED_PATH_GUARD`（`_env_bool`，默认 `True`）。

**为什么只接一道**（完整隔离数据见 §6）：真实照片上纹理守卫单独拿到 **72.9% / 68.6%**
的削减（自然光影守卫只有 26.0% / 21.7%，两道全接 75.4% / 72.0%），而接上自然光影守卫
会把「纹理 + 极淡平铺」整类抹零、把「渐变 + 网格」砍掉 28% 召回。机制上这也讲得通：
本通路门限（k = 2.2）比基础通路更严，**弱而软**的自然光影梯度本就够不到门限，
能穿过严门限的恰恰是**锐利自然纹理** —— 正是纹理守卫的设计靶子；自然光影守卫的靶子
已由始终生效的基础通路接住。

**为什么放在「门限之后、连通域过滤之前」**：与基础通路的既有约定一致 —— 守卫之后
`regions` 与 `mask` 同源于同一个 `cand`，保证「掩码 = 区域并集」这条不变量不被破坏。

**推翻阶段 49 的理由，写进注释**：阶段 49 刻意不接守卫，理由是「本通路 k=2.2 比 k_sigma
更严，候选集中在最强残差像素上，bbox 均值被结构性抬高 → ratio 跌破阈值 → 补隙组件被误杀」。
这个推理的漏洞在**把两件事混为一谈**：守卫测的是**连通域形态**，与门限高低无关。

### 4.2 低分辨率兜底臂**豁免**本守卫

`detect_tiled_translucent` 新增关键字参数 `guard: Optional[bool] = None`，
在 `detect_watermark_mask` 的调用点显式传 `guard=(_rescue_depth == 0)`。

理由（`docs/67` 的低分辨率兜底臂）：兜底臂把长边 <640 的输入用 `INTER_CUBIC` 放大到
640 再检测，其残差被「重采样平滑 + 有损编码块效应」主导 —— 正好落在纹理守卫的抑制带上。
实测 `256²/webp75/textured/grid` 在守卫下**整类抹零**，兜底臂「救回黑屏」的契约随之失效。
而兜底臂本身就是显式 opt-in（`DETECT_LOWRES_RESCUE` 默认 `False`，阶段 67 已声明
「宁可滥杀，也要救回黑屏」），与守卫的取舍方向相反 ⇒ 在臂内豁免。

这条契约由 `tests/test_tiled_path_guard.py` 的两个用例锁定：
`test_E_rescue_arm_mechanism_guard_matters`（机制：该口径下守卫确实会抹零）与
`test_E_rescue_arm_passes_guard_false`（**间谍函数钉住调用参数** —— 主臂 `True`、
兜底臂 `False`，防止「恰好也非空」蒙混）。

## 6. 单守卫隔离：为什么最终只接一道

### 6.1 真实照片 10 张（并集口径）

|---|---|---|---|---|---|
| `ai_faint_tiled` | 涂改面积% | 9.619 | 7.122 | **2.605** | 2.362 |
| | 干净图纯误报% | 3.207 | 2.410 | **0.865** | 0.803 |
| | 削减率 | — | 26.0% | **72.9%** | 75.4% |
| `ai_grid` | 涂改面积% | 10.188 | 7.977 | **3.198** | 2.853 |

1. **自然光影守卫是「弱信号杀手」**：它把「纹理 + 极淡平铺」打到 0.000%、「纹理 + 边缘小字」
   打到 0.066%（召回 0.248 → 0.075），而它自己在真实照片上只贡献 26% 的削减。
2. **纹理守卫在纯渐变场景上几乎无损**：「渐变 + 网格」G2 与 G0 **逐位相同**
   （1.211 / 1.000 / .997 / .997）—— 干净梯度上没有被纹理判据误伤的成分。
3. **IoU 合计 G2 > G1 > G3**。即「只接纹理」是这三档里合成侧质量最高的配置。

### 6.3 一条被验证的健全性检查

中途曾想当然地「两道全接」（更"一致"、更保守），它确实把真实照片面积进一步压到
2.362 / 2.853（−2.5 / −3.4 个点），但代价是上述两条通路整类/近整类抹零，以及
**两条既有断言失败**。这一段被完整保留在文档里，作为「一致性不是理由，量测才是」的样本。

## 7. 边界（诚实声明）

1. **ΔPSNR 的代价是真实的**：相对「两道全接」，本阶段交付的配置在合成交付链上
   ΔPSNR 为 11.70 dB（两道全接 14.28 dB）。选它的依据是消除侧（overdraw / collateral /
   removal）与检测侧（P/R）全面更优，且不放宽任何既有断言。**改回「两道全接」只需在
   `detect_tiled_translucent` 里加回 `_suppress_natural_light` 一行**（并会立刻打破
   `test_run_case_textured_faint_tiled_low_coverage`）。
2. **`faint_tiled` 的去痕率仍为负**（−0.037）。它已从「反而更糟 60%」收敛到接近 0，
   但根因（极淡平铺的掩码与实体对齐）**未解决**。
3. **`real_gate` 对 `tiled_enh` / `grid` 预设结构性失明**（只跑 `general`）。
   本阶段的真实图改进因此**只有修复侧门禁能看见**，检测侧在真实图上仍无量化证据。
   ⇒ 建议后续给 `real_gate` 增加「未承诺预设的掩码面积」表（该口径**不需要真值**，
   纯面积即可，正是本阶段用探针量出来的那个数），把探针升格为门禁。
4. **`DETECT_GRID_MIN_ACF` 在真实照片上无区分力**（干净图 100% 过阈，min 0.116 /
   均值 0.268）；`DETECT_GRID_EVIDENCE_AND` 因此是承重结构，**绝不可关闭**。
5. **`grid` 通路的守卫被刻意不接**（纯亏本，见 3.1），并由测试逐字节锁定。
6. **兜底臂豁免是一条新的显式契约**：低分辨率兜底臂不施加纹理稠密守卫。
   若后人想「统一」两臂，必须同时重新量测 `256²/webp75/textured/grid`（会重新黑屏）。
7. **折叠模板占空比上限**：可控但未加（默认配置下近乎零效应），理由见 3.3。
8. 未变的既有边界：真实基准 30 张的 60 个真值**全是角标**（`recall ≥ 0.98` 只守角标，
   另 4 类真实召回仍是**未知**）；修复侧外溢 23.3%（阶段 104b 未开工）。
