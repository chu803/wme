# 阶段 203 · 判据对称性审计（docs 索引防腐烂守卫补反向）

> 起点：阶段 202 的全量回归把 `test_docs_index` 的**正向**守卫跑绿了。收尾时我追问了一句
> 「这个检查**有反向**吗？」——答案是没有。这是 LESSONS 185「判据不对称即 bug」的又一实例。

## 一、发现的缺口：单向判据

`tests/test_docs_index.py` 原本只有**一个方向**：

| 方向 | 判据 | 状态 |
|---|---|---|
| 磁盘 → 索引 | 每个 `docs/*.md` 都必须在 `INDEX.md` 里被引用 | ✅ 有（196 阶段） |
| **索引 → 磁盘** | `INDEX.md` 里每条引用都必须能解析到真实文件 | ❌ **无** |

⇒ **删掉 / 改名一篇文档后，索引里的引用会变成死链，而没有任何守卫变红。**
「索引指向空气」是静默腐烂的另一种形态，与「文档没进索引」同等有害。

## 二、探针：先量清现状再动

写探针枚举索引里的全部 `*.md` 引用并逐个解析（报告用，不改文件）：

| 迭代 | 结果 | 说明 |
|---|---|---|
| 第 1 版 | 引用数 **0** | 正则 `[A-Za-z0-9_-]` 漏掉中文文件名 ⇒ **解析式本身有 bug** |
| 第 2 版 | 引用数 209 / 死链 **5** | 正则修好；5 个是 `.workbuddy/memory/*.md`（相对仓库根） |
| 第 3 版 | 引用数 209 / 死链 **1** | 按引用形态分别解析后，只剩 `YYYY-MM-DD.md` |

**结论：当前索引无真实死链。** 那 1 条是**命名约定占位符**
（`.workbuddy/memory/YYYY-MM-DD.md`，用于说明日志命名格式），故意不是真实文件。

> 探针迭代过程本身是个教训：**第 1 版"0 引用"若不复核就会得出「索引没问题」的错误结论**
> ——「解析式失效」与「被解析对象健康」在输出上都是「没有异常」（同 LESSONS 183
> 「有守卫≠有覆盖」）。故新版守卫里加了 `assert refs, "未解析出任何引用（解析式已失效）"`。

## 三、修复：补反向判据 + 豁免自守卫

在 `tests/test_docs_index.py` 新增两条用例：

```python
def test_every_index_reference_exists():
    """索引里每个 *.md 引用都必须解析到真实文件。
    含路径分隔符 ⇒ 相对仓库根；裸文件名 ⇒ docs/ 下。"""

def test_placeholder_exemptions_are_all_actually_used():
    """豁免表每一条都必须真的被索引用到（防豁免表变成藏死链的后门）。"""
```

设计要点：

1. **两类引用形态分别解析**——含 `/` 的（如 `.workbuddy/memory/LESSONS.md`）相对**仓库根**；
   裸文件名（如 `197-C5-Docker容器化.md`）在 `docs/` 下。混用一套规则会误报。
2. **豁免必须显式登记且带理由**——`_PLACEHOLDER_REFS` 目前只有 1 条，
   注释写明「YYYY-MM-DD 是格式占位，非具体文件」；
3. **豁免表自身要防幽灵**——否则一条过期的豁免会给**未来的同名死链**开后门
   （同源经验：LESSONS 203 的「幽灵条目」、跳过表随视野变化失效）。

## 七、教训 → LESSONS 217

**① 「这个检查有反向吗？」应成为护栏评审的固定一问。**
「A 必须在 B 里」与「B 的每一项都能解析到 A」是**两条独立判据**；只写一条会留下
静默腐烂的通道——而且它给人「这里有保护」的错觉，保护的却恰好不是会坏的那边。

**② 探针的第 1 版"没有异常"可能只是解析式失效。**
本轮探针第 1 版报「0 个引用」，若不复核就会得出「索引没问题」的错误结论。
⇒ 凡「枚举 + 判定」式探针，必须加 `assert 枚举结果非空`（否则「解析式失效」
与「对象健康」在输出上无法区分，同 183）。

**③ 豁免机制是旁路，必须自守卫。** 一条过期豁免不会自动消失，而会给**未来的同名问题**
开后门。⇒ 每条豁免必须带理由 + 加「幽灵豁免」检查（同 203 幽灵条目）。
