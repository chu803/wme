# 阶段 315 · PDF / 视频链路门禁（补齐「全源」承诺的验证缺口）+ API 预设面对称

> 一句话：项目宣称「图 / PDF / 视频全源」，但**三个质量门禁全部只测静态图**，
> 媒体两条链路长期处于「有代码、有单测、无端到端验证」状态。本阶段补 `media_gate`，
> 并在第一次实跑时就撞出一个真实的 API 门面缺陷。

---

## 一、缺口是怎么确认的（先证明缺，再补）

| 检查 | 结果 |
|---|---|
| `scripts/` 下的门禁 | 只有 `quality_gate`（合成图）· `real_gate`（真实图）· `prompted_area_gate`（次级档面积）——**全部静态图** |
| `benchmark_real/` 里的媒体样本 | **0 个** PDF、**0 个** 视频（只有 `images/`） |
| PDF/视频相关测试 | 7 个文件，全是**服务层单测与 mock**（`test_pdf_service_audit131` / `test_video_*`） |
| 端到端断言 | 没有任何一条在说「一份真 PDF 走完检测+修复后，水印区确实被改了、页数没丢」 |

⇒ 用户拿真 PDF/视频用，**出了问题是无人知晓的那一类**。

## 二、`scripts/media_gate.py` 的设计

不引入需要外部维护的资产：**样本现场合成**，可复现、零下载。

```
ground_truth.json 的「有水印 bbox 标注 + 图片在位」真实图
  → 收敛 1024² → 合成多页 PDF / 固定水印 8 帧视频
  → api.remove_watermark_pdf / remove_watermark_video（engine=opencv, preset=ai_logo）
  → 把输入 PDF 也渲染回像素作为**基准**（JPEG 往返与渲染噪声两侧同现，不污染判据）
  → 逐页/逐帧比对
```

判据分两层：

**红线（任一破 → EXIT=1）**

| 编号 | 内容 | 防的是 |
|---|---|---|
| R1 | 输出页数 == 输入页数 | 静默丢页（多页文档只剩一页） |
| R2 | 标注 bbox 内（内缩 4px）平均绝对差 ≥ 2.0 | **跑完全程什么也没改**的静默成功 |
| R3 | 每页/至少一帧能读回像素；链路 `status==success` | 输出文件不可用 |
| R4 | 可解码帧数 ≥ 输入 × 0.5 | 视频帧数塌陷 |

**诊断（打印不判红）**：非水印区平均差与改动占比、全图改动占比、逐链路耗时。

### 为什么「非水印区必须不变」不设红线

这是本阶段最重要的一个取舍。阶段 314b 实测：默认链的后处理（降噪 + 锐化 + 边缘融合）是**全图作用**的，一次修复会改动约 79% 像素（关掉后处理为 5.05%）。若把它写成红线，门禁从第一天就常红 ⇒ 结果一定是有人把它关掉——这正是 LESSONS 里「守卫被绕过」的老路。
⇒ 先用诊断指标长期曝光，等「后处理作用域收窄」真落地，再升级为红线。

## 三、实跑就撞出来的真缺陷：视频门面漏 `preset`

第一次跑 `media_gate` 直接：

```
TypeError: remove_watermark_video() got an unexpected keyword argument 'preset'
```

往下查发现是**门面不对称**，不是服务层不支持：

| 层 | `preset` | `auto_preset` |
|---|---|---|
| `services/pdf_service.process_pdf` | 有 | 有 |
| `services/video_service.process_video` | **有**（第 419/430 行） | **有** |
| `api.remove_watermark_pdf` | 有 | 有 |
| `api.remove_watermark_video` | **没有** ← 缺陷 | **没有** ← 缺陷 |
| `ui/tab_media.py`（走服务层直调） | 有 | 有 |

⇒ 后果：UI 里能选视频预设，**脚本化调用不能**；而 `api.py` 文件头明明白白写着这两层薄封装的目的是「让你在脚本里保持统一的调用姿势」。既有守卫 `test_api_layer_sync.py` 只核对了 `dual_run` 一个参数的对称性，没覆盖 `preset`。

**修复**：给 `api.remove_watermark_video` 补 `preset`/`auto_preset` 并转发（服务层本来就吃这两个参数）；
**加守卫**：`test_pdf_video_preset_surface_is_symmetric` —— 不仅查签名有这两个参数，还查函数体里**确实写了 `preset=preset` / `auto_preset=auto_preset`**（防「收下就丢」）。

## 四、实测结果（本机 · RTX 5060 · engine=opencv · 2 页 PDF + 8 帧视频）

| 链路 | 耗时 | 水印区差（R2 阈值 2.0） | 非水印区改动（诊断） | 全图改动（诊断） | 判定 |
|---|---|---|---|---|---|
| PDF 第 1 页 | 12.5s（整体） | **43.2** | 90.3% | 92.9% | ✅ |
| PDF 第 2 页 | — | **34.7** | 65.1% | 67.0% | ✅ |
| 视频 8→8 帧 | 10.4s（整体） | **42.4**（最差帧） | 94.8% | 97.4% | ✅ |

**结论**：PDF 与视频两条链路**功能是真的通的**（水印区都发生了大幅变化、页数帧数没丢）。
但诊断指标同时量化了那个产品级事实：**用户以为只动了水印，实际整张图/整段视频都被改动了 90% 以上**（后处理所致）。

## 五、接入与守卫

- 已接入 `scripts/run_all_checks.py --gates`（默认不带 `--gates` 时不跑，保持 CI 轻量），
  并同步更新了脚本头部的步骤清单注释（声明与实现一致）。
- `tests/test_media_gate.py`（7 例）：判据不为哑巴（改了要能测出、没改要为 0）、
  诊断必须能看见全图改动、资产缺失必须 `rc=2`（**绝不能 `rc=0`**）、
  已接进 `--gates`、默认步骤里不含它、红线阈值不得被改成 0。

写守卫时踩到并记录一件事：判据在 64px 小图上「非水印区改动」恒为 0 —— 不是 bug，
是 bbox 外扩 48px 已经把 64px 图全部盖住。测试图必须显著大于 `bbox + 2×BBOX_DILATE`。

## 六、诚实边界

- 本门禁用 `engine=opencv`（不依赖 torch/权重，跑得动、可进 CI），**未覆盖 LaMa 引擎下的媒体链路**。
- 视频默认 `reuse_mask=True`，本门禁的输入是**静止水印**，未覆盖「滚动字幕/飘动水印 + `--no-reuse-mask`」形态。
- 只取真值集里前 N 个「有角标标注」的用例（`--limit`，默认 3），未覆盖多水印/多页混合版式。
- R2 判的是「水印区确实被改动」，**不等于「水印被干净去除」**——后者需要干净原图做真值，
  而 PDF/视频没有干净基准集（`benchmark_real` 只有图片级真值）。这是刻意划出的边界，
  不做「看起来像去干净了」的伪断言。
- 无基线漂移层（第一版只设绝对红线）。待本门禁跑稳一段时间后，可把 D1/D2 纳入基线。
