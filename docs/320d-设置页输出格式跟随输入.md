# 阶段 320d · 设置页开关：输出格式跟随输入

> 日期 2026-10-23 · 产物 `ui/tab_settings.py`、`config.py`（user_overrides 双清单）、
> `utils/i18n.py`、`tests/test_processing_prefs.py`（+2 例）

## 一、动机

320c 把「输出格式跟随输入」做进了引擎、能力也经 `get_capabilities()` 暴露了，但**网页用户用不到**
（只有环境变量/配置文件能开）。这是同一条教训的第三次复现（LESSONS #298）：
**能力存在但对调用方不可达**。

## 二、做法（与 318c 同款，收窄范围）

在 **设置页 → 处理偏好** 加一个复选框「输出格式跟随输入」，与「只动水印区」并列：

- 点「应用处理偏好」⇒ 立即写 `config.OUTPUT_FMT_FOLLOW_INPUT`（`process_file` 每次调用都读）；
- 勾「保存为默认」⇒ 写入 `config.user_overrides.json`，下次启动仍生效；
- `user_overrides` 的**两份清单**必须同时登记（`_USER_OVERRIDABLE_KEYS` +
  `_USER_OVERRIDE_VALIDATORS`）——318c 已踩过「只加一份」的坑，这次一次到位；
- 确认文案补「输出格式跟随输入：{fmt}」——318c 的教训：不加这一项，用户看不出是否生效。

`apply_processing_prefs` 的新参数同样是**三态**（`None` = 不改这项），旧调用方/旧测试保持原语义。

## 三、验证

- 单测：`tests/test_processing_prefs.py` +2 例（白名单往返 `"true"/"off"`、`None` 不写覆盖文件）；
  外加 i18n 双语键与确认文案占位符更新（`{fmt}`）。
- **真开界面点过**（7899 端口）：设置页 → 处理偏好 → 复选框渲染正常、默认未勾 →
  勾选 → 「应用处理偏好」→ 文案返回
  `…；只动水印区：关闭；输出格式跟随输入：开启`。
- 全程未勾「保存为默认」，未改动用户配置文件。

## 四、诚实边界

- 默认仍是**关**（一律 PNG）。翻默认会让所有用户拿到的文件从 PNG 变成 JPG/WebP，
  是可见的产品行为变化——本阶段只给「能开」，不替用户决定。
- 只覆盖图片路径（PDF/视频由各自服务决定输出格式）。
- JPEG/WebP 输出会再经历一次有损编码（处理本身已重编码一次，无代际叠加）。
