## 二、三条已核实并已修的缺陷

### ① 去重命中键只有文件哈希（最重的一条）

`services/cache_service.py:546`（修复前）：

```python
if r.status == "success" and r.file_hash == file_hash and r.result_path:
    return r
```

而记录里**明明存了** `mode / engine / params`，判据一个都不看。`ui/tab_batch.py:266` 的用法是
「同一张图（哈希一致）且已有成品，直接复用」，并且这段**排在掩码生成之前** ⇒
用户换个引擎、调灵敏度、甚至换一张完全不同的涂抹掩码重跑同一个文件夹，
每张都会直接返回上一次的旧成品，还在日志里记成「✅ 命中缓存，已复用历史结果」。
这不是「少算一次」，是**把错图交给用户并声称成功**。

**修法**：给 `HistoryRecord` 加 `cache_sig`（去重命中键），`find_by_hash(file_hash, cache_sig)` 只命中
签名一致的记录；签名由 `_process_one` **自己的入参 `locals()` 快照**派生：

```python
_sig_params = {k: v for k, v in locals().items() if k not in ("task", "on_progress", "path", ...)}
sig_base = cache_signature_for(_sig_params)          # sha1(排序后的 JSON) 前 16 位
cache_sig = sig_base if mask_path is None else f"{sig_base}|{compute_file_hash(mask_path)}"
```

三个决定性的设计点：

1. **为什么不手抄参数清单**：`_process_one` 有 26 个参数，手写清单必然漏一个（漏了就是今天这个 bug 的
   翻版）。用入参快照 ⇒ 将来新增一个影响输出的参数，**自动**进入键。测试
   `test_process_one_signature_snapshot_covers_new_params` 钉住「签名必须仍从 `locals()` 派生」。
2. **掩码内容必须进键**，且要为此**调整顺序**：旧代码「先查缓存再找掩码」，所以掩码根本没法参与判定 ⇒
   改成手动模式先定位本图掩码、再算命中键。
3. **老记录（`cache_sig=""`）一律不命中**，`tab_auto`/`tab_single` 写的记录也一样不命中。
   代价说清楚：**这次之后所有历史缓存退化为「第一次要重算」**，多花时间；
   换来的是**不会再出现「命中但结果不属于这组参数」**。方向是安全的（少命中，不是错命中）。

### ② 手动掩码批量是必然失败（形态错读）

`ui/tab_batch.py` 用的是 `gr.File(file_count="directory", type="filepath")`，它返回的是
**目录里的每个文件**；而旧代码取 `(... or [""])[0]` 当**目录**用 ⇒ `_os.path.isdir(某个 .png 的路径)`
恒为 False ⇒ 每张都抛「未找到同名掩码文件」。**这个功能整条是死的。**

测试之所以一直没抓到：既有单测都直接 `tb._mask_path_for(str(tmp_path), …)` 传目录字符串
（`tests/test_tab_batch_helpers.py`），**没有一条走 UI 那条取值路径**。

**修法**：新增 `mask_candidates(...)` 把「文件列表」与「目录」两种形态统一建成 `{主干: 路径}` 索引，
`_mask_path_for_index()` 查索引；`_process_one` 优先用索引、回落到旧的目录函数 ⇒ 旧调用口径不变。

### ③ 输入白名单误用了「掩码后缀」

`img_paths = [p for p in file_paths if p.lower().endswith(_MASK_EXTS)]`，
`_MASK_EXTS = (.png .jpg .jpeg .bmp .webp)` 名字与文档都写着「缩略图/掩码后缀」。
而真正的输入白名单是 `config.py:1937 SUPPORTED_INPUT_FORMATS`（多 `.jpe .tif .tiff .jfif`），
`services/validators.is_supported_input` 用的就是它，README 也写 `.tif/.tiff` 支持。
⇒ 挑 20 张 TIFF 批量会得到「未选择任何图片文件」；混合目录则**少掉 N 张且日志里一个字都不提**。

**修法**：`batch_input_extensions()` 从 `config.SUPPORTED_INPUT_FORMATS` 派生（单一真值来源），
`select_batch_inputs()` 返回 `(kept, dropped)`，dropped 写进 `log.warning` —— **不能让文件凭空消失**。
