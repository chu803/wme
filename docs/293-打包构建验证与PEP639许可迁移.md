# 阶段 293 · 打包构建验证 + PEP 639 许可迁移

> 上一轮记分卡把「发布 v1.0」列为路线图 Phase 2；`pyproject.toml` 早已存在但**从未实跑构建**。
> 本阶段实跑 `build` 验证可分发性，并修复验证中暴露的前向兼容缺陷。

## 一、结论先行

**pyproject 可构建出干净、完整、可导入的纯 Python wheel + sdist；抓到并修复 `project.license` 弃用（2027-02-18 后构建将不被支持）。** 「发布 v1.0」的打包风险由此去化。

## 二、构建验证（build_meta 实跑，非读配置）

- `setuptools.build_meta.build_wheel` → `wme_watermark_eraser-1.0.0-py3-none-any.whl`；`build_sdist` → `wme_watermark_eraser-1.0.0.tar.gz`（均落 `.scratch/dist`，gitignored）。
- **wheel 内容干净完整**：恰为声明的 6 个 py-modules（api/cli/config/download_model/main/server）+ core/services/ui/utils 四包 + LICENSE + dist-info 元数据；**无 tests/scripts/docs/benchmark 膨胀**。
- **零非 .py 数据文件**：core/services/ui/utils 全纯 Python（主题 CSS/JS、i18n 均代码内生成；`cache/i18n_state.json` 为运行期状态不入包）⇒ **无缺失 package_data 风险**。
- **装包 smoke**：解压 wheel 加入 sys.path，`import config / utils.brand / utils.i18n / core.preset_recommender` 全 OK，`config.APP_VERSION = 1.0.0`。

## 三、抓到并修复的缺陷（前向兼容 · P1）

- **现象**：构建时 setuptools 报 `project.license` 为 TOML table（`license = { file = "LICENSE" }`）**已弃用**，明示 **2027-02-18 后构建不再被支持**。
- **根因**：PEP 639 改变了许可声明方式；旧 table 形式被 SPDX 字符串 / `license-files` 取代。
- **修复**（metadata 脚手架，非业务逻辑）：迁移到 `license-files = ["LICENSE"]`（本作专有、无 SPDX，故只随包附许可文本、不写 SPDX 表达式）；`build-system` 的 setuptools 下限 `68 → 77`（保证 `license-files` 可用）。
- **守卫**（`tests/test_packaging_meta.py`）：原「必需字段含 `license`」改为 `license-files`；新增 `test_license_uses_modern_pep639_form`——双向锁定「必须有 license-files」且「不得回退弃用 table」，防 2027 构建中断回归。

## 四、验证（双向）

- 重建 wheel：**deprecation 警告消失**（迁移前 True → 迁移后 False）。
- `pytest tests/test_packaging_meta.py` → **RC=0**（含新守卫）。
- `git status`：仅 `M pyproject.toml` + `M tests/test_packaging_meta.py`；`build/`、`*.egg-info` 正确被 .gitignore 忽略，无杂散产物。

## 五、说明与边界

- **sdist 仍含 tests/**（无 MANIFEST.in prune 的默认行为）；wheel 已正确排除 tests。sdist 含测试属常规，留作可选优化，非缺陷。
- **PyPI 发布仍是 pyproject 自述的「显式待决策」**（console 入口名 / 发布口径 / 专有许可下的分发授权）。本阶段只验证「能构建 + 完整 + 可导入 + 无弃用」，**不代做发布决策**。

## 六、自反证伪

- 「能构建」与「弃用已修」均以 `build_meta` 实跑 + 警告布尔翻转双向证明，非读配置自述。
- **未验证**：GPU/全推理运行期行为（smoke 仅导纯 Python 模块，未拉 torch 跑端到端）；真 PyPI 上传需账号与发布决策（blocked_on user/product）。这两项不因本阶段而变为「就绪」。
