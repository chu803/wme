# 阶段 43：历史记录批量删除（按当前筛选结果）+ 破坏性操作二次确认

> 项目：AI 智能水印擦除工作台（AI Watermark Eraser Workbench）
> 日期：2026-08-13
> 前置阶段：42（历史记录文件名搜索与联合筛选）

## 1. 背景与动机

历史记录页（阶段 5 起）已具备：缩略图画廊、点击详情、下载、重新处理、单条删除
（`delete_selected`）、清空全部（`clear_all`）、类型筛选（阶段 41）、文件名搜索（阶段 42）、
按类型/关键词打包导出（阶段 41/42）。

遗留两块明显短板：

1. **没有「批量删除」**：用户只能一条条删，或「清空全部」一刀切。当记录很多、只想清理
   某一类（如全部 PDF）或某个关键词相关记录时，缺乏高效手段。
2. **破坏性操作无二次确认**：`delete_selected` 与 `clear_all` 一点即删，Gradio 6.22 无
   原生 `ConfirmDialog`，误触代价高。

本阶段补齐：**按当前筛选视图批量删除** + **统一二次确认复选框**，让「所见即所删」且
「误删可防」。

## 2. 设计原则

- **所见即所删**：批量删除严格复用 `list_records(kind, query)` 同一套过滤口径，删除范围
  与画廊当前展示完全一致，不引入第二套过滤逻辑。
- **只删索引与缩略图，不误删用户资产**：历史结果成品图（outputs 目录）是用户资产，删除
  记录时**保留结果成品图**，仅清理缓存缩略图（与既有 `delete` / `clear` 语义一致）。
- **二次确认统一且强制**：一个 `confirm_cb` 复选框同时守护「批量删除」「清空全部」
  「删除所选」三处破坏性操作；未勾选即拒绝执行并返回警告；执行成功后自动复位复选框，
  强制下次再确认。
- **零 gradio 于 core/services**：确认逻辑在 `ui` 层完成；`cache_service` 不依赖 Gradio。

## 3. 改动清单

### 3.1 `services/cache_service.py`

新增方法（约 553 行 `clear` 之后、`prune` 之前）：

```python
def delete_by_filter(self, kind: Optional[str] = None,
                     query: Optional[str] = None) -> int:
    """删除当前筛选视图下全部记录，清理缩略图，返回删除条数。"""
    if not self.enabled:
        return 0
    recs = self.list_records(kind=kind, query=query)
    ids = [r.id for r in recs]
    removed = 0
    for rid in ids:
        if self.delete(rid):      # 复用 delete：仅清理缩略图，保留成品图
            removed += 1
    if removed:
        log.info("已按筛选批量删除 %d 条历史记录（kind=%s, query=%s）。",
                 removed, kind, query)
    return removed
```

- 复用 `list_records` 的 kind + query 过滤（AND 叠加），保证口径一致。
- 复用 `delete` 的缩略图清理，成品图不动。
- `delete` / `clear` / `prune` 既有语义不变。

## 4. 行为对照

| 操作 | 勾选确认 | 结果 |
|---|---|---|
| 批量删除当前筛选结果 | 否 | 返回警告，零删除 |
| 批量删除当前筛选结果 | 是 | 删除画廊当前全部可见记录，缩略图清理，复选框复位 |
| 删除所选 | 否 | 返回警告，零删除 |
| 删除所选 | 是 | 删除 `_LAST_SELECTED_ID` 记录，复选框复位 |
| 清空全部 | 否 | 返回警告，零删除 |
| 清空全部 | 是 | 清空索引（保留成品图），复选框复位 |

## 6. 风险与边界

- **成品图保留**：批量删除仅清缓存索引与缩略图，结果成品图（outputs 目录）不删，
  符合「不误删用户资产」底线；若用户确需释放磁盘，应另设「清理孤儿成品图」功能（留待后续）。
- **Gradio 无 ConfirmDialog**：用显式 Checkbox 替代，语义明确、可单测，规避弹窗 UX 风险。
- **二次确认的复位**：任何破坏性操作成功后复选框自动取消勾选，防止「勾一次连删多次」。
