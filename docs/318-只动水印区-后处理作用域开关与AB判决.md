# 阶段 318 · 只动水印区：后处理作用域开关 + A/B 判决

> 日期 2026-10-23 · 产物 `config.POSTPROCESS_PRESERVE_UNTOUCHED` / `POSTPROCESS_PRESERVE_BAND_PX`、
> `services/postprocess_service.py::_preserve_untouched`、`tests/test_preserve_untouched318.py`（11 例）

## 一、为什么动它：三条实测串成的因果链

| 阶段 | 实测 | 说明 |
|---|---|---|
| 314b | 关后处理改动 **5.05%**，开默认 **35.05%** | 单张 2048²，UI 一键修复 |
| 316 | 原分辨率真实图上「水印**外**改动 **46.9%–88.4%**」 | 17 文件混合批量演练 |
| 317 | 误伤 **33.8%–72.7%**，且**四种水印类型几乎一样** | ⇒ 与「选了哪个预设」无关 |

317 那条是决定性的：如果误伤来自检测/擦除，它就该随水印类型大幅波动；四类都在 50% 上下，
说明它来自**对所有图都一样的那个环节**——后处理。

**根因不是 bug。** 阶段 60 明确裁决过：「掩码内不锐化（unsharp 会放大填充区残留）、
**掩码外照常锐化**」。所以「把你没要求的地方也锐化一遍」是**有意设计**，为了让成片更讨喜。
本阶段不改这个裁决，而是**提供第二种契约**，让用户/部署方自己选。

## 二、能力设计

```
POSTPROCESS_PRESERVE_UNTOUCHED = False   # 总开关，默认关（现行交付观感零变化）
POSTPROCESS_PRESERVE_BAND_PX   = 8       # 掩码向外保留多少像素仍走后处理
```

开启后，后处理链的最后一步把「掩码 + 外扩带之外」**逐字节还原成原图像素**：

```python
keep = _preserve_band(mask, config.POSTPROCESS_PRESERVE_BAND_PX)
return np.where(keep[:, :, None], out, original_rgb)
```

三个设计取舍：

1. **契约是「逐字节一致」，不是「差不多」。** 否则"只动水印区"这句承诺没法验收，
   A/B 也会被噪声污染。守卫用 `np.array_equal`，不用 PSNR 之类的近似判据。
2. **保护带 8px ≈ `MASK_FEATHER_DEFAULT`(5) + 边缘融合余量。** 羽化与边界融合本身要跨掩码
   边界写像素；带太窄会把改动挤到最显眼的那一圈（1px 硬接缝）。
3. **纯 config 驱动，不加任何门面参数。** 四条调用链（UI 单图/自动/批量/历史重处理、CLI、
   `api.py`、REST）最终都走同一个 `postprocess()`，所以一个 config 开关即全链路生效——
   刻意避开阶段 315 那个「服务层支持、门面漏接」的坑（LESSONS #298）。
   需要给最终用户暴露时，再单独做一个「门面 + UI」阶段，并按对称性守卫推进。

**缺原图/缺掩码/形状不符时静默跳过**（记一条 info），与真·超分的既有惯例一致：
宁可少保护，不可改错像素。

## 三、守卫（11 例，纯 numpy，毫秒级）

`tests/test_preserve_untouched318.py` 采用三段式，缺一不成对：

| 段 | 用例 | 防的是什么 |
|---|---|---|
| 关（现状不变） | `test_default_is_off…`、缺原图/缺掩码/形状不符/满图掩码 4 例 | 开开关时的旧行为被意外改动 |
| 开（确有差异） | `test_outside_band_is_bit_exact_when_on`（**先断言关闭态带外真有 >50% 像素被改**） | 实现没接线、守卫永远绿（LESSONS #304） |
| 作用域边界 | `test_band_zero_restores_the_ring_that_band_eight_keeps`、`_on_empty_mask_stays_empty` | 带宽失效、`keep` 方向写反、`cv2.dilate` 边界值陷阱 |

**两个真实踩到的坑（都在实现里，不在测试里）**：

- `cv2.dilate` 默认边界值是 `morphologyDefaultBorderValue`（DBL_MAX），对**膨胀**等于
  「图外全是前景」⇒ 沿四边凭空生出 8px 实心带，把最该还原的边缘错误保留成后处理结果。
  修法：显式 `borderType=BORDER_CONSTANT, borderValue=0`。（与阶段 317 探针同族）
- OpenCV 5 的 `dilate` **不接受 bool**（`Unsupported data type (=9)`）⇒ 先 `astype(np.uint8)`。

## 四、A/B 判决（同一批 60 用例，只翻这一个开关）

`off` = 阶段 317 基线（`rt_full2.json`），`on` = `WME_POSTPROCESS_PRESERVE_UNTOUCHED=true`（`rt_318_on.json`）。
60 个用例逐一对得上（按 `照片+类型` 配对，交集 60/60）。

| 水印类型 | gain off → on | 误伤% off → on | ΔPSNR off → on |
|---|---|---|---|
| edge_text 底部小字 | 0.939 → 0.939 | 50.58 → **1.09** | −5.97 → **−2.31** |
| corner_logo 角标板 | 0.532 → 0.532 | 50.59 → **0.80** | −5.42 → **−3.17** |
| faint_tiled 极淡平铺 | **−0.117 → 0.010** | 49.58 → **2.09** | −7.88 → **−5.82** |
| grid 点阵 | **−0.172 → 0.002** | 49.02 → **1.39** | −7.65 → **−6.09** |

逐用例硬判据（不看中位数，看每一例）：

| 判据 | 结果 |
|---|---|
| gain 不得变差（容差 −0.005） | **0/60 变差** ✅ |
| 误伤必须显著下降 | **60/60 下降**，中位 50% → **约 1%（20–60 倍）** ✅ |
| ΔPSNR 不得变差 | **60/60 变好** ✅ |
| 误伤是否**归零** | 57/60 仍有 0–16.5% 的残余（见下） ⚠ |

**三条读法：**

1. **`faint_tiled` 与 `grid` 从「净伤害」变成「不伤害」**：gain −0.117/−0.172 → +0.010/+0.002。
   注意这**不是**"擦掉了"——它们的检回仍只有 0.05/0.015，擦除能力没变；变的是
   **原先全图锐化把"漏检的水印区"也一起破坏了**，现在那些像素被还原成输入原样。
   负收益消失，是"停止帮倒忙"，不是"开始帮上忙"。
2. **残余误伤不是后处理乱动，是检测误报。** 开启后仍被改的像素，全部落在
   **工具自己判定的水印区（掩码 + 8px 带）** 里——只是那个判定是错的（误报）。
   典型如 `clean_01 + grid` 残余 16.46%：检测器认为那里有水印。这部分归检测侧，
   不该赖给后处理。
3. **`ΔPSNR` 仍为负**（−2.3 ~ −6.1），因为真值区内的水印残留仍在（gain 0.5/0.9 不等于 1）。
   但相对 off 全部改善 2.2–3.7 dB，说明**关掉的那部分改动确实是"白改"**。

**计时（重要，别抄错）**：跨会话的两轮总耗时 304s → 680s（2.2×）**不能读成"开关很贵"**——
今天整机的 off 基线本身就从 4.0s/张 变成 11.5s/张（重启后机器状态不同）。
用**同进程、同图、A/B/B/A 交替**做对照（`D:/qoder/.cache/perf_ab_318.py`）：
```
off=11.1 on=11.1 | off=12.3 on=12.5 | off=8.9 on=8.7 | off=11.9 on=11.6
整体中位 off=11.48s on=11.39s 比值=0.99x
```
⇒ **这个开关不增加耗时**（一次 `dilate` + 一次 `np.where`，毫秒级）。

## 五、结论与建议

**三条判据全数通过**：误伤 50% → ~1%，gain **零回退**，ΔPSNR 全数改善，且不花钱。

于是问题只剩「默认值该不该翻」——这是产品决策，不是技术决策：

| 选项 | 得到 | 失去 |
|---|---|---|
| **保持默认关**（当前） | 成片延续「整体锐化」的讨喜观感；既有用户零感知 | 承诺不诚实：用户只圈了角标，却换了半张图 |
| **默认开** + 设置页可关 | 「只动水印区」成为默认承诺；误伤 ≈ 0；自动化的可预测性变好 | 成片不再整体变锐；老用户会觉得"没以前清楚" |
| **不动默认，只暴露开关**（推荐先做） | 两种人都照顾到：要锐化的人继续，要保真的人能选 | 需要 318b 做门面/UI 暴露，否则只有会用环境变量的人享受得到 |

**我的建议**：先按第 3 行落地（318b：`--preserve-untouched` CLI 开关 + 设置页一项 + REST 参数，
并按阶段 315 的对称性守卫推进），跑一段时间看真实用户反馈，再决定要不要翻默认。
理由：默认值是**观感承诺**，翻它等于换一代产品的观感；而这里已有 60/60 的数据说明
「不改默认也能让需要的人拿到」——没必要为了一个开关赌老用户的第一眼。

**本阶段不动默认值**（用户已定「先看判决再定」，见 2026-10-22 的选择记录）。

## 六、诚实边界

- **PSNR 对"无害的锐化"同样罚。** 所以本阶段的收益读法是「**不再动用户没要求的地方**」，
  不是「图变好看了」。要不要更好看，得人眼看真渲染图——`collateral` 归零不代表观感更讨喜，
  它代表**承诺更诚实**。
- **保护带内仍会变。** 8px 带里后处理的痕迹还在（这是刻意留的，避免接缝）。所以
  「逐字节不变」的准确表述是「**带外**逐字节不变」。
- **剩余误伤 ≠ 后处理乱动。** 开启后仍有 0–16% 的"带外改动"，来自**检测误报**：
  工具认为某处有水印、在那里修复并保留（那是它的作用域定义内）。这部分该由检测侧解决，
  不该赖给后处理。
- **计时本轮不可用**：A/B 第一次运行时我并发跑了单测，个别用例被拖到 28s；第二轮重跑才是干净数字。
  性能结论一律以第二轮为准。
- 只有 15 张底图、4 种合成样式、`engine=auto`。真实多平台水印与 LaMa 通路未覆盖。
