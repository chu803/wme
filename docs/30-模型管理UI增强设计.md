# 阶段 30 · 模型管理 UI 增强（运行状态面板 + 缓存热重载 + 模型详情）

> 项目：AI 智能水印擦除工作台（去 AI 生成图水印）
> 日期：2026-08-05
> 定位：**增强**而非重建——模型管理 UI 主体已于阶段 12 建成，本阶段填补「状态可见性」与「热重载」两类真实缺口。

---

## 1. 现状盘点（阶段 12 已实现，未重写）

经调研确认，模型管理核心能力在阶段 12 已落地：

- `core/model_manager.py`（654 行）：`register_model_slot` / `list_models` / `get_active_model` / `set_active_model`（切换时自动 `clear_cache()`）/ `verify_model`（存在性+体积+SHA256）/ `load_model`（torch 延迟导入、按路径缓存）/ `rollback_model`（备份回滚）/ `download_model`。
- `ui/tab_models.py`：列出模型槽（存在性/体积/已加载/当前模型）、下拉切换、下载（gr.Progress 进度条+速度）、校验、回滚，全部走 `utils/i18n`。
- `api.py` / `cli.py`：模型管理公开接口与命令组（`list_models` / `set_active_model` / `verify` / `rollback` / `download`）。
- `tests/test_model_manager.py`：11 例（注册/切换/缺失/校验/回滚/自动发现）。

**结论**：从零搭建已不成立，本阶段聚焦「已有实现未暴露的能力」。

---

## 2. 真实缺口（本阶段解决）

| 缺口 | 现状 | 影响 |
|------|------|------|
| 运行状态不可见 | `get_model_info()` 已算 `device`/`loaded` 但 UI 从未展示 | 用户不知当前跑在 GPU 还是 CPU、是否开 FP16、内存里缓存了几个模型 |
| 无缓存热重载入口 | `set_active_model` 会 `clear_cache`，但「运行中手动替换/重下同一路径权重文件」时旧内存模型驻留，只能重启 | 运维不友好，尤其调试权重时 |
| 详情不足 | `verify` 只给 pass/fail + reason | 看不到实测 SHA256、文件修改时间，难以确认权重真伪/时效性 |

---

## 3. 设计方案

### 3.1 `core/model_manager.py`（零 torch 依赖，仅 `load_model` 内部延迟导入）

- 新增 `cache_size() -> int`：返回 `_CACHE` 长度（进程内已加载模型数）。
- 新增 `reload_active(device=None) -> dict`：`clear_cache()` 后 `load_model(None, device, force_reload=True)`，返回 `{ok, name, loaded, error}`，异常转为失败字典（不抛出）。
- 新增 `slot_detail(name=None) -> dict`：在 `verify_model` 基础上补充 `display_name` / `path` / `mtime`（本地修改时间）/ `sha_computed`（仅当槽登记了 `sha256` 时才计算实测值）/ `loaded`（是否在 `_CACHE`）。
- 丰富 `get_model_info()`：保留旧字段（`active_model`/`models`/`device`/`exists`/`path`/`size_mb`/`loaded`），新增 `device_name` / `device_is_gpu` / `vram_mb` / `fp16`（= `DEVICE_USE_FP16 and is_gpu`）/ `cache_count`。

### 3.2 `utils/i18n.py`

- 在 `zh-CN` 与 `en-US` 的 `models` 块新增：`status_title` / `status_device` / `status_device_gpu` / `status_device_cpu` / `status_vram` / `status_fp16`(+`_on`/`_off`) / `status_active_path` / `status_loaded`(+`_yes`/`_no`) / `reload` / `reload_done`(+`_yes`/`_no`) / `reload_fail` / `detail` / `detail_done` / `detail_missing`。
- `__main__` 自检新增阶段 30 断言（先 `set_language("zh-CN")` 再校验中英两套）。

### 3.3 `ui/tab_models.py`

- 新增 `_render_status_md()`：基于 `get_model_info()` 渲染「推理设备 / GPU或CPU / 显存(GPU时) / FP16 / 内存缓存数+当前模型载入状态 / 权重路径」。
- 新增 `on_reload()`：`_mm.reload_active()` 包装，刷新 `status_md` + `models_md` + 提示；`reload_btn`（`variant="secondary"`）。
- 新增 `on_detail(name)`：`_mm.slot_detail()` 渲染详情（路径/大小/修改时间/预期SHA256/实测SHA256/状态），权重缺失时提示；`detail_btn`。
- `build_models_tab()`：在清单下方新增 `status_md` 面板；底部新增 `detail_md` 文本框与「🔄 清空缓存并重新加载」「📄 模型详情」两按钮；`refresh_btn` / `set_active_btn` 的 outputs 由 3 元补为 4 元（加入 `status_md`），对应 `on_refresh` / `on_set_active` 返回元组同步扩充。
- 全部文案走 `t()`，`status_md` / `detail_md` 注册进 `ui.i18n_rt` 以支持实时语言切换。

### 3.4 测试

- `tests/test_model_manager.py` 新增 4 例（不依赖真实权重 / torch）：`test_cache_size_and_clear`、`test_slot_detail_missing`（monkeypatch `os.path.exists=False`）、`test_slot_detail_no_sha`（无 sha256 不计算 SHA 且 ok）、`test_reload_active_mock`（monkeypatch `load_model` 模拟填充缓存）。
- `tests/test_ui.py` 新增 `test_models_tab_handlers`：monkeypatch `_mm.get_model_info` / `reload_active` / `slot_detail`，断言 `_render_status_md` 含设备名与路径、`on_reload` 返回三元组含模型名、`on_detail` 缺失文件提示（语言无关断言）。

## 5. 已知边界

- `reload_active()` 实际加载依赖 torch + 真实权重文件，仅在运行环境（装了 torch）生效；测试中已用 mock 覆盖其逻辑分支。
- `slot_detail()` 计算实测SHA256仅在槽登记了 `sha256` 时触发（`lama` 默认登记，约 205MB 文件分块计算约 1–2s，仅手动点「详情」时触发，不影响列表渲染性能）。
- `verify_btn` / `rollback_btn` 的 outputs 未加入 `status_md`：校验/回滚只改磁盘文件不改内存缓存状态，内存热更新由「🔄 清空缓存并重新加载」按钮统一负责，避免职责混乱。

---

## 6. 分层合规

- 改动严格遵循 `ui → services → core → utils → config`；新增 `cache_size`/`reload_active`/`slot_detail` 均在 `core/model_manager.py`，零 gradio 依赖；`ui/tab_models.py` 仅做呈现与事件绑定，业务逻辑全部委托 `core`。
