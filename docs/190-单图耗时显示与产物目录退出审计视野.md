# 阶段 190 · 单图耗时显示（D2）+ 产物目录退出审计视野

> 优化清单 D2：「用户看不到『为什么这次慢』」——单图状态文案只给引擎与保存路径。
> 本阶段在结果区加**本次耗时**（纯本地计时，不涉遥测，符合离线定位）。
> 过程中连带修掉一处**结构性隐患**（产物目录被当成源码审计）。

## 1. D2：单图结果区显示「本次耗时」

| 项 | 内容 |
|---|---|
| 新增 i18n 键 | `single.msg.elapsed`（**zh-CN 与 en-US 同形**，占位符均为 `{seconds:.2f}`） |
| 文案 | zh：`\n⏱️ 本次修复 + 增强耗时 {seconds:.2f} 秒`；en：`\n⏱️ Repair + enhancement took {seconds:.2f} s` |
| 计时代码 | `ui/tab_single.py::process_single`：`_t0` 取自 `inpaint()` **之前**，`elapsed` 收口于 `pp_postprocess()` **之后** |
| 展示 | 状态文案 = `done`（引擎 + 路径）+ `elapsed` + `upscaled_note`（超分提示） |
| 抽出的接缝 | `_compose_status(engine, out_path, elapsed, upscaled_note="")` —— 纯函数，便于**运行时**验证 |

**口径与措辞一致**：耗时的天然边界是「**修复 + 增强**」，**不含**涂抹解析与落盘；
文案说的正是「修复 + 增强耗时」。若把测量点挪到落盘之后，文案就会**高估**实际修复成本
⇒ 故用**顺序断言**把代码位置钉死（`_t0` < `inpaint` < `pp_postprocess` < `elapsed` < `_compose_status`）。

**测试**（`tests/test_single_elapsed_display.py`，8 例全绿）：
- 双语都能解析、占位符集合一致、`validate_i18n_parity()` 无差异、en-US 无 CJK/全角标点；
- **顺序断言**钉住口径（只在 `process_single` 函数体内搜索——首版命中了 `_compose_status`
  文档里提到的键名，属「结构断言被文档字符串干扰」的经典坑）；
- **运行时**验证：真调用 `_compose_status`，断言引擎名大写、耗时两位小数、超分片段在末尾。

## 2. 连带修复：产物目录退出「自检登记」审计视野

**症状**：加完 D2 后跑相关子集，`test_selfcheck_coverage_is_accounted_for` 变红，
列出 **52 个 `build/lib/**` 的 .py** 与 `.scratch/probes/` 里的 2 个探针 ——
它们都被当成「含 `__main__` 但未登记的模块」。

**归因（两类，都不是「忘登记」）**：
1. **构建产物**：上一阶段无法删除的 `build/`（setuptools 复制出的源码副本）含 52 个 `.py`
   ⇒ 被枚举器当源码审计。**产物目录本不该进入审计视野**。
2. **归档目录**：E1 把根目录点文件移进 `.scratch/`，其中 2 个探针仍在豁免清单里
   （登记名还是根目录旧路径）⇒ 条目失效（幽灵）。

**修复（单一真值来源）**：
- `scripts/undef_scan.py` 暴露 **`SKIP_DIRS`**（唯一真值来源）+ `SKIP_DIR_PREFIXES`，
  并补入产物目录 `build / dist / .scratch / htmlcov`；
- `tests/test_legacy_selfcheck.py` **直接导入**该集合（不再自写一份）——
  实测这两份清单**早已漂移**（一方有 `temp/logs/assets/plugins`，另一方有 `uploads/benchmark_real`，
  注释却声称「同一口径」）；
- 移除 3 条失效豁免（`.probe181.py`、`.probe183_holdout.py`、`benchmark_real/clean/_gen_synthetic.py`
  —— 后者所在的数据集目录本身就在跳过表内 ⇒ 它已不在审计视野，豁免自然作废）；
- 新增 `test_artifact_dirs_are_skipped_by_the_enumerator`：产物目录不得进入审计视野。

## 3. 诚实记录：子集运行会掩盖失败

第一轮我只跑了 `-k "single or i18n or coverage"` 子集 ⇒ **幽灵条目那条用例被过滤掉了**，
只看到 3 条失败中的 1 条。**这与 183 的教训同源**（「只跑子集 = 系统性漏检」）：
本次改为**整文件运行** `test_legacy_selfcheck.py` 才看全（41 例全绿）。
经验：**凡是「登记表 / 清单类」守卫（它们的失效方式是条目失效），必须跑整个文件，不能按关键字筛。**
