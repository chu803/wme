# 阶段 372 · 首屏示例图必须演示「承诺能力」——它原来的角标通路检出为 0

> 日期 2026-11-04 · 性质：**首屏体验的真实缺陷 + 随包资源重做 + 契约守住**

## 一、怎么发现的：用真浏览器走了一遍已发布版本的黄金路径

1.0.3 发布后，用 browser-use 在真实浏览器里打开 `http://127.0.0.1:7860`（源码树启动，因安装版
的模型路径不在 wheel 里、首次运行会去下载 205 MB 权重），确认：页面渲染正常（标题 `v1.0.3`、
7 个页签、合规与适用范围说明都在），示例加载 → 智能推荐 → 自动检测 → 一键修复整条链路可跑通
（检测 8 个区域/覆盖 6.5%，结果落盘）。**修复链路本身没问题**（同一张图用已发布 CLI 处理 5.9s 出图）。

但「试一张示例」这条首屏路径的结果是**肉眼可见的坏**：深色角标底板原样留着，只擦掉一部分文字。

## 二、测量：不是通路坏了，是示例图落在能力边界外

| 观察 | 结果 |
|---|---|
| 旧示例（`ui/assets/sample_watermarked.png`，640²，深色圆角板**占宽 36%**） | 角标通路在 `corner_ratio` **0.20 / 0.28 / 0.36 / 0.45 / 0.55 全部 0 px** |
| 同一张图的整图检测 | 归为「半透明×6 + 边缘小字×2」，**没有 corner_logo** |
| 真实 2048 角标图（`ai_logo_02` / `ai_logo_04`） | 角标通路正常：各检出 1 区域（298×104 / 355×125） |
| 修复结果 | 深色底板残留（目视确认，`.scratch/sample_corner_after.png`） |

⇒ 角标通路没有坏，是**示例图的角标比例不真实**（36% vs 真实 11~17%），且深色板在暗背景上
会被判据的「触碰搜索区边界」规则丢掉。首屏演示恰好落在「承诺处理角标 LOGO」的边界外。

## 三、修法（用户选 A）：重做随包示例，比例回到真实档

- 底图：`benchmark_real/clean/clean_01.jpg`（水面日落），缩到 **768²**；
- 角标：**白底圆角板 + 深色「StudioAI」**，占宽 **10.7%**、距边 3.5%，用仓库钉住的
  `scripts/assets/DejaVuSans-Bold.ttf` 渲染（跨 OS 同字节，见阶段 369）；
- 实测：角标通路 **2553 px**（≥1000 的守卫线），整图检测含 1 个 corner_logo 区域；
  一键修复后角标区与干净底图的平均差 **26.7**（修复前整块白板覆盖），底板消失；
- 资产体积 730 KB（原 553 KB），仍随 wheel 发布（`[tool.setuptools.package-data] ui/assets/*.png`）。

## 四、守卫：把「示例必须能演示承诺能力」钉成契约

`tests/test_sample_image320.py` 新增
`test_sample_is_detectable_by_the_promised_path`：

- 随包示例的**角标通路必须 ≥1000 px**（换图/调参把它弄失明 ⇒ 红）；
- 同一测试内附**反例**：纯灰图必须 0 px（证明判据不是恒真，否则该守卫不含信息）。

同时把两处尺寸断言 640→768，并在 `ui/tab_auto.py` 的资源注释里写清「为什么是 10.7%」，
防止下一个人把它换回「大而显眼」的角标又踩回来。

## 五、边界（诚实）

- **只改示例资产，没动检测阈值**：深色大板在暗背景/大比例下仍可能检不出。要支持这类，
  需要真实样本另立阶段评估（与 #22 同源）。
- 修补痕不是零：2× 放大仍能看到水面一块轻微补丁；首屏 1× 观感可接受，但不宣称"无痕"。
- 本次只验证了「示例→检测→修复」这条主路径；批量/PDF/视频等页签未在浏览器里逐一点过。
- 安装版（wheel）首次运行仍会去下载 205 MB 权重（路径在 site-packages 下、模型不在 wheel 里，
  README 已写明），本次未改这一行为。
