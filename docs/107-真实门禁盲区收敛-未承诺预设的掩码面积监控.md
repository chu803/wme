# 阶段 107 · 真实门禁盲区收敛：未承诺预设的「掩码面积」监控

> 承接阶段 104/106 两次登记的同一个缺口：**`real_gate` 只跑 `general`，而 `general` 的
> `enhance_tiled=None` / `enable_grid=None` ⇒ 平铺增强与网格两条通路在真实图上结构性失明。**
> 阶段 106 把网格通路假阳性砍掉 76%，真实图侧**一点都看不见**——改进如此，劣化亦然。

## 1. 结论先行

| 检查 | 结果 |

| 新增红线 | `ai_faint_tiled ≤7.5%` / `ai_text_heavy ≤4.25%` / `ai_grid ≤12.5%` / `ai_gradient` **静默守卫** |

| 全量测试 | **1462 用例**：改动前**零失败**；改动后 1453 pass + 7 env-skip + **2 例环境 artifact**（沙箱批量删除护栏命中日志轮转用例，见 §6） |

**另外修掉两个真实缺陷**（都属「看起来有护栏、实际不生效」）：
**`DETECT_TILED_PATH_GUARD` 是死开关**（调用点实参遮蔽 config ⇒ 阶段 104 宣称的注入式反例自诞生起无效）、
**输出编码决定退出码**（管道 + GBK + `⚠` ⇒ `UnicodeEncodeError` ⇒ 退出码 1，且 `--update` 连刷新基线一起失败）。

**一句话**：阶段 104 与 106 的改进此前**只有"改进时无人察觉"这一半是坏的**——现在平铺通路在
真实图侧第一次被自动守备（把守卫关掉 ⇒ **+97.2%**，立刻变红）；而网格那一档的改进幅度低于本层
分辨率，由路径级单测守住，两者分工在 §7.3 列清。

## 3. 判据设计（三个刻意的选择）

### 3.1 为什么「面积」不需要真值

`mask_coverage = 掩码像素 / 图面像素` 只依赖检测输出本身。于是它能回答一个**与"认得准不准"
无关**的问题：

> **这条通路在真实照片上会不会涂满全图？**

这正是「守卫被关掉」「模板门限被调回」这类回退的**直接症状**——而它们此前恰好没有任何
自动判定会失败（因为 precision/recall 需要真值，而这四类没有真值）。

### 3.2 为什么监控这 4 个预设

监控集合 = `config.WATERMARK_TYPE_SCOPE` 里 `committed=False` 的**恰好四类**
（`ai_faint_tiled` / `ai_text_heavy` / `ai_grid` / `ai_gradient`）：

- `general` 有真值 ⇒ 已在红线层；
- `ai_logo` 是**承诺类型** ⇒ 已在红线层；
- 其余 4 个预设（`ai_tiled` / `ai_signature` / `ai_corner` / `ai_multi`）是 UI 变体或其它预设的
  并集，监控它们只会重复计数。

该等式被测试钉住（`test_monitored_set_equals_uncommitted_classes`）：**承诺面一变，
就必须有人来更新监控集合与红线表**，而不是静默少监控一类。

### 3.3 为什么只守上界 + 漂移

面积是「越大越坏」的单调量（涂得多 = 擦得多 = 伤画质）。故：
绝对红线只设上界（**任何"面积下降"都不会被判失败**），另设 15% 漂移容差盯「相对基线变胖」。

## 5. 标定（两条必须同时说的读数）

### ① `ai_grid` 的面积被**内置闸**压住，所以面积红线必须低于它

`ai_grid` 的最大值 14.97% 正贴着检测器内置的面积闸 `DETECT_MAX_COVERAGE_RATIO = 0.15`
（阶段 100 引入）⇒ **该通路的面积在 fattest 图上被闸截断**，均值因此也被压低。

推论：**任何面积红线都必须 < 0.15，否则永远不触发 = 哑巴红线。**
该不变式被 `test_area_redlines_are_upper_bounds_below_internal_cap` 钉住。

### ② `ai_gradient` 在 30 张真实图上**一次都没触发**

它的预设只开渐变通路（`enable_gradient=True`，其余全 False），实测 `0/30` 有掩码、
覆盖率 0.00% ⇒ **「设计上恒为零输出」这条自述第一次被量测确认**。

故对它**不设"均值上界"**（0 的 1.15 倍仍是 0 ⇒ 恒红 = 哑巴），改设**静默守卫**：
`n_with_mask ≤ 0`——一旦渐变通路开始在普通照片上触发，**必须有人来更新这份契约**，
而不是让它静默发生。

### 红线表

| 预设 | 指标 | 上界 | 实测 | 余量 |
|---|---|---|---|---|
| `ai_faint_tiled` | `mask_coverage_mean` | 7.50% | 6.12% | +22.5% |
| `ai_text_heavy` | `mask_coverage_mean` | 4.25% | 3.43% | +23.9% |
| `ai_grid` | `mask_coverage_mean` | 12.50% | 10.46% | +19.5% |
| `ai_gradient` | `mask_coverage_mean` | 5.00% | 0.00% | 兜底 |
| `ai_gradient` | `n_with_mask` | 0 | 0 | 静默守卫 |

另设 `AREA_DRIFT_TOLERANCE = 0.15`（与 `REAL_TOLERANCES` 同值）。

## 7. 注入式反例（不改代码、完全可逆）

两个注入都指向**已经落地、但此前没有护栏**的改动：

| 注入 | 含义 | 退出码 | 命中 |
|---|---|---|---|
| `WME_DETECT_TILED_PATH_GUARD=0` | 回退**阶段 104** 的「平铺通路纹理稠密守卫」 | **1** | **5 项**：`ai_faint_tiled` 6.12% → **12.07%（+97.2%）**、`ai_grid` 10.46% → **13.03%（+24.6%）**（各触发红线 + 漂移，另 1 条 P90 漂移） |
| `WME_DETECT_GRID_TMPL_K_MULT=1.0` | 回退**阶段 106** 的「网格模板门限余量」 | 0 | **未命中**（见 §7.2，如实登记） |

### 7.1 注入①：阶段 104 的盲区就此关闭

`ai_faint_tiled` **6.12% → 12.07%（+97.2%）**、`ai_grid` **10.46% → 13.03%（+24.6%）**，
而 `ai_text_heavy`（不启用平铺增强）与 `ai_gradient`（只开渐变通路）**零扰动**——与预设结构完全一致。

这正是阶段 104 登记的那个缺口：**它当时只能靠 e2e 侧看见**，本门禁在真实图上完全沉默。

### 7.2 注入②：未命中，且这是**面积的粒度边界**，不是缺陷

`ai_grid` 的总面积只从 10.46% 升到 **10.94%（+4.6%）**、区域数 547.7 → 624.7：

- `ai_grid` 预设的掩码是 **4 条通路的并集**（translucent + tiled + corner + edge + grid），
  其中 grid 通路自身只占约 8%（10.46% 里的 0.87pp 量级）⇒ 该通路内部 ×1.3 的门限变化
  在并集口径上被稀释到 **+4.6%**；
- 而该总面积的量级（10.46%）被内置闸与其它通路主导，**15% 的漂移容差与 12.5% 的红线
  都够不到这一档**。

⇒ **如实登记**：阶段 106 的网格模板改进**不由本层守护**，而由**路径级单测**守护
（`tests/test_alignment106.py::test_grid_tmpl_mult_cuts_fp_keeps_truth` /
`..._revert_is_visible`，确定性合成分辨率上图，直接断言「1.3 的掩码严格小于 1.0 且真值覆盖不降」）。
这与经验 103 同族：**改进幅度低于某层的分辨率时，要显式说明它由哪一层守住**，
而不是把容差压到噪声级去"抓住"它。

### 7.3 谁守住什么（本阶段后的护栏全景）

| 改动 | 守住它的层 |
|---|---|
| 平铺通路守卫（104） | **本层**（注入①：+97.2% ⇒ 红线 + 漂移）+ e2e |
| 网格模板门限（106） | **路径级单测**（+4.6% < 本层分辨率）+ e2e 漂移 |
| 框内证据几何收敛（106） | e2e 红线（overdraw 4.40/1.15 等）+ 真实图红线（0.045/4.35）+ 单测 |
| 合并收口膨胀承重（106） | e2e 红线（`corner_logo.removal ≥ 0.25`）+ config 警示守卫 |
| 修复侧外溢（105） | e2e 红线（`spill ≤ 5%`）|

## 8. 一条被本阶段顺手发现的缺陷链（值得单独记）

**A. 死开关。** 两个注入最初都返回 EXIT=0、数值与基线**逐位相同**，追根因发现
`DETECT_TILED_PATH_GUARD` 被调用点实参遮蔽（详见 §5 与 `docs/107` 开头）：主臂写死 `True`
⇒ 开关从未被读取 ⇒ **阶段 104 宣称的注入式反例自诞生起无效**。修法：主臂传 `None`。

**B. 测试把缺陷钉住。** 既有的间谍测试断言 `True in calls` —— 它守住了「兜底臂豁免」这条
真契约，同时把「主臂写死 True」这个缺陷**冻结成了被测行为**。修法：断言改为
`None in calls` 且显式 `assert True not in calls`（把原缺陷形态写成反例）。

**C. 输出编码决定退出码。** 见 §5 末尾：`⚠` + GBK 管道 ⇒ `UnicodeEncodeError` ⇒ 退出码 1，
且 `--update` 写盘在打印之后 ⇒ 连刷新基线一起失败。修法：入口 `reconfigure(encoding="utf-8")`。

**共同点**：三者都是**"看起来有护栏、实际不生效"**——与经验 83（摘要声称通过）、
90（缺席被读成过松）同族。判据：**任何"注入式反例"都要被真正跑过一次并看到它变红**。

## 9. 未达成与边界（诚实登记）

1. **面积监控不判"认得准不准"**：它守的是「不得突然变胖」，不是精度。四类未承诺类型的
   真实 precision/recall 仍是**未知**——需要真实水印图（阶段 101 起登记，目前唯一 P0）。
2. **样本是"无该水印的真实照片"**：30 张真实图上这四类**都不存在水印** ⇒ "面积越小越好"
   方向明确正确，但**回答不了"有该水印时够不够"**（那是 recall 的问题）。
3. **粒度边界**（§7.2）：面积层看不见单条子通路的细粒度参数回退（+4.6% 档）。
4. `ai_grid` 的读数受内置闸压缩（§5①）：若有人**关掉**内置闸，面积会上升 ⇒ 本层会报，
   但"关闸"本身是另一个决策点，未纳入本层。
5. 成本：+2~5 分钟（视机器负载；`--no-area` 可跳过）。

## 11. 新增经验（见 `LESSONS.md` 104–109）

- **104**：补监控维度先问「这个量需不需要真值」——面积不需要真值 ⇒ 未承诺类型的劣化第一次可判。
- **105**：红线必须低于量程上限，否则是哑巴红线（内置闸 0.15）。
- **106**：恒零指标不能设「均值上界」（0 的任意倍仍是 0），要改设**静默守卫**。
- **107**：输出编码不得决定退出码。
- **108**：新增基线字段要同步夹具；「旧版基线」判定看**键是否存在**，别看值是否为空。
- **109**：**配置开关被调用点实参遮蔽 = 死开关**，且「被宣称的注入式反例」会因此长期无效；
  间谍测试要钉**契约语义**，不是当下的实参取值。
