# 阶段 63 · 有损压缩（JPEG）鲁棒性审计与度量口径护栏

> 一句话：真实输入几乎必经 JPEG（截图、社交平台再压缩），而 benchmark 全部用无损合成图。
> 补做有损压缩审计时先踩了一个**度量口径陷阱**：用「压缩后配对」求真值会把水印支撑区从
> 1.2% 膨胀到近全图，把 grid 召回算成「12%」，得出"JPEG 毁掉检测"的错误结论；改用
> **无损配对**求真值后结论反转——**检测器对 JPEG 相当鲁棒**（grid 召回 77.9~99.7%、
> edge_text 98~100%、corner_logo 100%，干净误报 ≤1.05%）。本阶段交付永久审计脚本 +
> 14 例护栏（含口径陷阱测试），把这次误判机制固化下来。

---

## 1. 动机

阶段 49~62 的所有量化结论都基于**无损合成图**（`make_demo_assets` 直接叠加水印，PNG 保存）。
但真实使用链路是：用户提供 JPEG（截图/下载再上传/平台压缩）→ 检测 → 修复。JPEG 的
8×8 DCT 量化会削掉高频细节，而**边缘小字与网格点恰恰依赖高频对比**——这构成一个此前
从未验证的鲁棒性假设。

## 2. 度量口径陷阱（本阶段最重要的发现）

第一次审计（错误口径）：对 clean 与 marked **各自**做 JPEG 往返，再求差作为真值：

```
gt_wrong = |jpeg(marked) − jpeg(clean)| > 0
```

两幅图各自的 JPEG 噪声**互相独立**（块效应相位、量化误差不同），差图上几乎每个像素都非零
→ 真值从 1.2% 膨胀到 **~90%** → `recall = tp / gt_size` 被稀释成极小值。于是出现了
"grid 召回 12%、edge_text 50%"的**假性崩塌**，而 clean 误报（不依赖真值）看起来"毫无变化"。

**正确口径**：真值取自**无损配对**的水印支撑区，与压缩条件解耦：

```
gt_correct = |marked_raw − base_raw| > 0      # 未压缩图求支撑区
detect_input = jpeg(marked_raw, q)            # 只有检测输入是压缩后的
```

这一条已写成测试（`test_compressed_gt_inflates_and_fakes_recall_collapse`），断言压缩真值
覆盖率 > 5× 无损真值且 > 50%，防止后人"顺手"改回错误口径。

## 3. 真实审计结果（正确口径）

| 用例 | 底图 | PNG | JPEG90 | JPEG75 | JPEG60 |
|---|---|---|---|---|---|
| corner_logo | gradient | 100.0 | 100.0 | 100.0 | 100.0 |
| corner_logo | textured | 100.0 | 100.0 | 100.0 | 100.0 |
| corner_logo | photo | 100.0 | 100.0 | 100.0 | 100.0 |
| edge_text | textured | 98.2 | 98.0 | 98.0 | 98.0 |
| edge_text | photo | 98.2 | 98.2 | 98.2 | 98.0 |
| grid | gradient | 99.7 | 99.3 | 99.7 | 99.7 |
| grid | textured | 88.7 | 80.2 | 78.9 | **77.9** |
| grid | photo | 99.2 | 96.8 | 97.0 | 95.5 |
| （干净图四预设平均误报） | textured | 1.01 | 1.02 | 0.97 | 0.97 |

**结论**：
1. **召回基本不受影响**——corner_logo / edge_text 全档 98~100%；grid 在 textured 上从
   88.7% 温和降至 77.9%（q60），仍高于红线；photo/gradient 保持 95~99.7%。
2. **干净误报不反弹**（0.74~1.05%，与 PNG 同量级）——没有被压缩噪声"喂出"假水印。
3. 有些**精确率波动**（photo corner_logo 62% → 43~90%），来自压缩后掩码几何/MSE 差异，
   不是召回问题；对修复流程无实质影响（掩码覆盖真值即可）。

## 4. 交付：永久审计 + 护栏

- **`scripts/jpeg_robustness.py`**：可复跑审计（PNG/90/75/60 × 3 底图 × 4 用例 + 干净误报），
  内置**红线判定**（`RECALL_FLOORS` 按"用例×底图"设下限、`CLEAN_FPR_MAX=2%`），
  越线 exit 1；支持 `--quick`（只跑 JPEG75）与 `--json` 落盘。
- **`tests/test_jpeg_robustness.py`（14 例）**：
  · 红线判定语义（健康通过 / 召回跌破报警 / 误报反弹报警 / 红线覆盖完整性）；
  · **口径陷阱护栏**（压缩真值膨胀 + 假性崩塌机制）；
  · 端到端：JPEG75 下 textured/photo × corner_logo/edge_text/grid 召回达标、
    干净误报 < 2%（slow）；
  · 审计档位常量覆盖 PNG + JPEG90/75/60。

## 5. 意义与边界

- **意义**：把"真实输入常带 JPEG"这一隐含前提变成了**有数据、有红线、有测试**的结论，
  直接降低 P0 真实图验证的风险——若真实图召回不理想，可先排除"压缩导致"这一因素。
- **边界（诚实声明）**：
  1. 只覆盖 JPEG（未测 WebP/AVIF、多次转码级联、缩放+压缩叠加）；
  2. 合成用例的压缩敏感性未必等价于真实照片（真实图的纹理/噪点与 JPEG 交互更复杂），
     待 P0 真实图用同一脚本口径复核；
  3. textured grid 在强压缩下 77.9% 是当前信息论水平附近的温和损失，未做针对性调参
     （任何放宽 `kσ` 都会牵动阶段 57/58 的误报平衡，收益不足时不值得动）。
