## 发布步骤（你侧执行）

1. **准备 PyPI 凭据（一次性）**
   - 在 PyPI 账号生成 API token（https://pypi.org/manage/account/token/）。
   - GitHub 仓库 `Settings → Secrets and variables → Actions` 新增仓库 Secret：
     `PYPI_API_TOKEN` = 上面的 token。
   - （可选）改用 PyPI Trusted Publisher（OIDC，免 token）：在 PyPI 项目页配置对应
     仓库/工作流，并改 `publish.yml` 用 `permissions: id-token: write` 且删掉 `password` 段。

2. **确认版本号**
   - `pyproject.toml` 的 `version`（当前 `1.0.0`）与 `config.APP_VERSION` 必须一致
     （`tests/test_packaging_meta.py::test_version_has_a_single_source_of_truth` 守卫）。
   - 若发补丁版，两处同步改。

3. **把关质量**
   - 推送前先合并到 `main`，让 CI（`.github/workflows/ci.yml`）全绿。
   - 本地可跑 `python scripts/run_all_checks.py` 复刻。

4. **打 tag 触发发布**
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```
   - `publish.yml` 自动：跑门禁 → `python -m build` → `pypa/gh-action-pypi-publish` 上传。
   - 在 GitHub Actions 页面看 `Publish` 工作流结果；成功后 PyPI 项目页出现新版本。

5. **冒烟（发布后）**
   ```bash
   # ⚠ 阶段 348：必须在**全新 venv** 里做（源码目录里跑测不到分发缺陷）
   python -m venv /tmp/wme-smoke
   /tmp/wme-smoke/Scripts/pip install wme-watermark-eraser
   /tmp/wme-smoke/Scripts/pip install -r requirements-min.txt   # 包不声明依赖（见 README 3.3）
   /tmp/wme-smoke/Scripts/wme --help                         # 网页 UI 入口（等价于 python main.py）
   /tmp/wme-smoke/Scripts/wme-cli --help                     # 批量命令行
   /tmp/wme-smoke/Scripts/wme-api                            # REST 服务（默认 127.0.0.1:7861）
   ```
   为什么要强调「全新 venv」：阶段 348 实测——wheel 漏了 `job_manager` 顶层模块 ⇒ 装出来的三个命令
   **启动即崩**；而源码目录里跑一切正常（`sys.path` 含仓库根）。**分发缺陷只在安装态存在**。
   同批还修了 `wme-cli --help` 崩溃（help 文本里的 `50%→` 被 argparse 的 `%` 展开炸掉）。
   ⇒ 冒烟必须**从 `Scripts/` 里的命令跑**，不是 `python cli.py`。

## 诚实边界（披露，非隐藏）

- **本机未真跑全量 `pip install .` / `python -m build`**：managed venv 缺 numpy/gradio 等运行期依赖，
  且清华镜像缺 `build` 包与 `setuptools>=77`（均 `from versions: none`），`python -m build` 在本机无法复现。
  但 `python main.py` 在你那套完整 dev 环境本就能跑，console 命令与之等价；且 `publish.yml` 在 GitHub 官方环境
  用 `requirements-min/dev` 跑门禁、用官方 PyPI 取 `build`/setuptools 构建依赖，正好补上本机缺的环节。
  本机已用等价的 `pip wheel --no-build-isolation` 验证：wheel 构建成功、entry_points 真实写入、临时 venv 真装生成正确启动器。
- **构建产物安全网**：`publish.yml` 在 `python -m build` 后新增 `actions/upload-artifact@v4` 步骤，
  将 wheel+sdist 上传为 Actions artifact——**即使未配 `PYPI_API_TOKEN`，tag 触发也能在 Actions 页面下载产物本地试装**，
  不必等 PyPI 即可验证分发包。
- **权重不入包**：`big-lama.pt` 不随 wheel 分发，首次运行由 `download_model.py` 下载
  （或放入 `./models`）；发布不影响此行为。
- **PyPI 项目名**沿用 `pyproject.toml` 的 `name = "wme-watermark-eraser"`；若想换名，
  改 `name` 并重发（旧名占用的风险需你侧先查 PyPI）。
- **构建隔离拉 setuptools>=77 在本机清华镜像失败**：仅本机 `pip wheel --build-isolation`
  受影响；GitHub 官方 PyPI 不受此限，发布链路无此问题。
- **依赖清单的 pin 必须有 cp311 轮子**（阶段 347 实测，代价是 CI 连续红了 8 天）：
  CI 矩阵是 **Python 3.11**，而本机是 **3.13** ⇒ 「本机装得上」≠「CI 装得上」。
  实测 `numpy 2.5.1` / `scipy 1.18.1` **没有 cp311 轮子** ⇒ runner 上 `pip install` 必然失败
  ⇒ 每次红在 26~92 秒（跑不完入口步）。
  ⇒ 规则：清单里**不要钉本机的精确版本**；用区间（下界 = 上一版 CI 装成功过的版本），
  并把「本机验证过的组合」单独记在 `requirements-verified.txt`（记录用，不用于安装）。
  守卫：`tests/test_requirements_ci_installable.py`（把守卫放到旧清单上跑会逐个点名那几个装不到的版本）。
  **发布前自检**：改动依赖清单后，先确认目标 Python 版本的轮子存在（`pip index versions` 看 cp 标签）。
