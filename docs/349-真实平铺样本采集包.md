# 阶段 349 · 把 #22 变成「你只管丢文件」：样本采集包 + 成对性机器判定 + 召回测量

> 日期 2026-10-27 · 性质：**工具/流程**（不改产品行为；把「需要用户动手」这件事变成一条命令）

## 一、为什么要做这个

#21（提升 grid 点阵水印的检测召回）唯一的阻塞是**真实样本**；而样本能不能用，取决于
**成对性**（同一张文件的两种导出、像素逐位对齐、只多一层水印叠印）。
`docs/P0` §六 已经写清要求，但那是**给人读的**——历史上有两次成对图被当成真值用，
判据是「人眼看像不像」，结果两次都判**不可用**（非像素配对：两次生成的画面本身不同）。

⇒ 本阶段把判据**变成机器判定**，并把采集动作压缩成「生成 + 丢文件 + 跑一条命令」。

## 二、采集包（已放在 D 盘）

```
D:\wme-1.0.3\samples_grid\
├── README.txt     采集要求、成对规则、怎么跑校验、样本进来之后我会做什么
├── prompts.txt    10 条可直接粘进豆包/即梦的提示词（点阵/网格水印 × 10 种内容）
└── pairs\         ← 你把样本丢这里（每对一个子目录，或扁平命名）
```

## 三、工具：`scripts/grid_sample_check.py`

一条命令给出三个答案：

```
D:\wme-1.0.3\venv\Scripts\python.exe D:\qoder\watermark-workbench\scripts\grid_sample_check.py ^
    --pairs D:\wme-1.0.3\samples_grid\pairs --measure
```

1. **成对性是否成立**（逐对给结论 + 原因）：
   * 尺寸不一致 ⇒ **不可用**（不是同一张图）；
   * 两张完全相同 ⇒ **不可用**（没有水印叠印）；
   * 差异像素占比 > 30% ⇒ **不可用**（疑似两张不同画面）；
   * 长边 < 1024 ⇒ **不可用**（要原图导出、不裁剪）。
2. **真值像素数 / 差异占比**（成对成立后，这就是构造保证的像素真值）。
3. **`--measure`：当前检测召回** —— 对带水印版跑检测器，报告「真值区被检出的比例」中位。
   这就是 **#21 要提升的那个数**，而且从样本到位那一刻起就能看到它的起点。

退出码：`0` 够量且全可用 / `1` 有不可用项或不足 20 对 / `2` 目录或参数问题（**不能是 0**）。

## 四、守卫（`tests/test_grid_sample_check349.py`，6 例）

把判据本身钉住：两种目录形态都能被发现、**尺寸不一致⇒不可用**、**两张一样⇒不可用**、
**差异过大⇒不可用**、**正常成对⇒可用且真值像素数算得出**、**空目录⇒退出码 2**。
（其中"正常成对"用例特意用 1024² 画布——脚本有一条「长边 ≥1024」的硬要求，
小图被判不可用是**正确**行为；第一版测试用 64² 画布被这条规则拦下，当场改成 1024²。）

## 五、边界（写清免得被当成万能钥匙）

* 本脚本**只读**样本目录，不改不删；
* 它**不能**替代"这批样本值不值得采"的判断——那是 324 的 oracle 实验已经钉过的
  （grid 值得、faint_tiled 不值得）；
* 样本入库后仍要走「据实重锚基线」的流程（对外口径翻转要先给判决表）。
