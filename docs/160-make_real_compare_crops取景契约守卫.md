# 阶段 160 · `make_real_compare_crops` 取景契约守卫（人眼复核通道）

## 动机

`scripts/make_real_compare_crops.py` 是**人眼复核通道**——脚本 docstring 自述「数值指标会骗人……
数值给方向，肉眼给结论」，它为每个真值水印框生成「原始 / OpenCV / LaMa」三格对比图。
但该脚本此前**零专属测试**。

审计它 = 审计「肉眼给结论」这条通道本身。若它静默产出**看不到水印 / 看不到修复痕迹**的对比图，
那么所有人眼结论都被污染，且不会有任何报错。

## 探针（`probe_160.py`：合成色块 + 桩 inpaint，不加载 torch）

### (a) 主路径 by design 正确（承阶段 159 探针，本轮正式化）
合成图（灰底 + 红块水印）+ 桩 inpaint（掩码处涂绿/蓝）下：
- 三格顺序 original / opencv / lama 与着色（红 / 绿 / 蓝）正确；
- crop 窗口与真值 bbox 精确对齐（默认 pad=24,view=70 → panel `h=115 w=140`）；
- `--ids` / `--limit` 过滤正确；缺文件 → rc=1、空真值 → rc=2。

### (b) 抓到静默误导：`view < pad` 时取景切掉被修复区域
mask 用 `--pad` 外扩、crop 用 `--view` 外扩，二者**相互独立**且无 `crop ⊇ mask` 约束。量化：

| pad, view | crop x 区间 | mask x 区间 | crop 内落在 mask 的列比例 |
|---|---|---|---|
| 24, 70（默认） | [0,140) | [16,94) | **0.56**（两翼有上下文，正常） |
| **40, 10** | [30,80) | [0,110) | **1.00** |
| **60, 0** | [40,70) | [0,130) | **1.00** |

比例 = 1.00 意味着**整幅裁剪完全落在被修复区域内**：对比图里既没有水印、也没有上下文，
肉眼无法判断修复质量，而**退出码仍是 0**（无任何信号）。
而 `--pad` 的帮助文本恰恰写着「真值框外扩像素（**掩码与取景同步**）」——与实现不符，正好诱导。
（这是项目「同一语义两套实现」家族在**注释层**的形态，经验 51。）

## 最小修复

1. **取景强制 `eff_view = max(view, pad)`**，保证 `crop ⊇ mask`（被修复区域永远完整可见）；
   并在 `view < pad` 时**显式告警**（stderr）说明已夹紧——不静默改尺寸。
2. **订正帮助文本**：`--pad` 改为「**掩码**外扩；取景见 `--view`」；`--view` 注明「小于 `--pad` 时会被夹紧」。

## 守卫

`tests/test_make_real_compare_crops.py`（**11 例**，合成色块 + 桩 `core.image_utils`/`core.inpainter`）：

- **核心**：`view < pad` 时 crop（面板）**不得窄于** mask（`wp >= mask_w`，且 `wp != 50`）；
- `view < pad` 必须告警、`view ≥ pad` 不得告警；
- 默认参数下 crop 比 mask 宽（两翼有上下文）；
- 面板顺序与着色（精确色像素计数，规避标题文字抗锯齿）；
- `--ids` / `--limit` 过滤；缺文件 rc=1 / 空真值 rc=2；`--sheet` 生成总览图；
- 帮助文本不得再含「掩码与取景同步」。

守卫口径：**从 composite 尺寸黑盒反推 crop 窗口**断言 `crop ⊇ mask`，不复述实现内部公式。

## 诚实边界

- 修复只保证 **`crop ⊇ mask`（不切掉被修复区域）**；`view < pad` 时 `crop == mask`、无额外原图上下文——
  这是「用户显式要求小取景」时的最合理结果（不能显示比 mask 更小的区域）。
- **输出目录的陈旧文件未清理**：若真值被改动（删水印 / 改 style），上一次运行留下的旧对比图不会被删除，
  目录里可能同时存在新旧文件。未修（删除属破坏性操作，保守不动），登记为已知边界。
- 主路径（三格/过滤/退出码）本就 by design 正确，本阶段不改，仅补守卫钉死契约。
