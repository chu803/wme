# 阶段 4 设计文档：智能水印自动检测模块

> 配套代码：`core/detector.py`（检测核心）、`ui/tab_auto.py`（智能自动模式标签页）、
> 配套改动：`ui/app.py`（接入页签）、`config.py`（新增 `DETECT_MAX_SIDE`）、`utils/exceptions.py`（新增 `DetectionError`）。
> 验证环境：Python 3.13.12 + numpy 2.5.1 + opencv-python-headless 5.0.0（无 torch、无 easyocr，自动降级路径全部生效）。

---

## 一、设计目标与约束

智能自动模式要解决的核心问题是：**用户不涂抹、不框选，算法自动找出图片里的水印并生成修复掩码**。

需求明确列出三类水印形态：

1. **半透明水印**：低对比度、与背景同色的文字/图案，肉眼可见但残差很小。
2. **角落文字 LOGO**：集中在四角的图标、署名、平台水印（如「图虫」「视觉中国」角标）。
3. **边缘小字水印**：图片上下边缘横贯的版权声明、网址、账号 ID。

约束条件（来自阶段 1 分层铁律）：

- `detector` 属于 `core` 层，**禁止依赖 Gradio**。它只返回 numpy 数组和区域列表，由 `ui/tab_auto` 决定如何呈现。
- 必须兼容「无 GPU、无 torch、无 easyocr」的最弱环境，任何缺失都降级而非崩溃。
- 检测是**辅助**手段，结果必须可手动增删：我们返回可视化图 + 可直接预填进 ImageEditor 的图层，用户能用画笔补涂或橡皮擦除。

## 二、三类检测算法原理

### 策略一：半透明水印检测（`detect_translucent`）

**思路：残差法 + 自适应局部阈值。**

| 步骤 | 操作 | 目的 |
|---|---|---|
| 1 | 灰度化 `cv2.cvtColor(RGB2GRAY)` | 降维，单通道处理 |
| 2 | 中值滤波估计背景 `cv2.medianBlur(gray, ksize)` | 大核保留低频背景，抹掉细小水印形状 |
| 3 | 残差 `\|gray - bg\|` | 水印形状处残差大，平滑处接近 0 |
| 4 | 局部归一化 `residual / (bg + eps)` | 把「绝对残差」转成「相对残差」，让浅灰底与白底上的同等水印得到同等响应 |
| 5 | 自适应阈值 `local_norm > (1 - sensitivity)` | sensitivity 越高，越灵敏（阈值越低，越多像素入选） |
| 6 | 形态学开运算 `morphologyEx(OPEN)` | 去掉椒盐噪点，保留连续水印 |
| 7 | 面积过滤 `[min, max]` | 过滤过大块（可能误判为纯色背景）和过小噪点 |
| 8 | 孔洞填充 `floodFill` | 避免水印内部镂空导致修复不彻底 |

**为什么用中值背景而非高斯**：水印文字是细线结构，高斯模糊会把文字也模糊进背景估计里，残差被压低；中值滤波排序取中值，能更好地「穿过」细线保留背景平面。

**sensitivity 映射**：滑块 0~1 → 阈值 `(1 - sensitivity)`。sensitivity=0.55 → 阈值 0.45，即相对残差超过 45% 的像素判定为水印。该映射在 `ui/tab_auto` 的 `_sensitivity_to_threshold` 中统一换算。

### 策略二：角落 LOGO 检测（`detect_corner_logos`）

**思路：分块→MSER/Otsu 文字检测→坐标过滤。**

1. 把图按 `corner_frac`（默认 0.18）切成左上、右上、左下、右下四块候选区。
2. 每块内部：
   - 若 `use_ocr 且 easyocr 可用`：用 EasyOCR 识别文字框，取高置信度框作为水印区（文字类角标最准）。
   - 否则降级：在灰度图做 **MSER**（最大稳定极值区域）提取候选连通区；若 MSER 不可用（部分 OpenCV 构建缺失），再降级为 `THRESH_BINARY_INV + Otsu` 阈值化 + `connectedComponentsWithStats`。
3. 用 `min_area_frac`（默认 0.0002，即至少占角块 0.02%）过滤噪点碎片。
4. 把角块坐标还原回全图坐标，生成 `DetectionRegion`。

### 策略三：边缘小字检测（`detect_edge_text`）

**思路：边缘带裁剪 + OCR/MSER 文字定位。**

1. 按 `bands`（默认 `("top", "bottom")`）从原图切出上下边缘横带（高度约全图 8%）。
2. 横带内部走与策略二相同的文字检测（OCR 优先，MSER/Otsu 降级）。
3. 还原坐标，过滤面积，输出区域。

> 设计取舍：边缘小字与角落 LOGO 本质都是「文字/小图标定位」，因此共用同一套文字检测后端（`_ocr_text_boxes` / `_mser_text_boxes`）。差异仅在于搜索区域不同——一个限定四角，一个限定上下边缘带。

## 三、结果合并与可视化

`detect_watermark_mask` 是三类策略的总入口：

```
输入 rgb, sensitivity, use_ocr, detect_scale, enable_* 三开关
  ↓
[可选降采样] 长边 > DETECT_MAX_SIDE(2000) 时缩图检测，坐标按比例放大回原图
  ↓
策略一 ∪ 策略二 ∪ 策略三  → 合并区域列表
  ↓
面积过滤（min_region_area_frac，默认 0.00008）
  ↓
按区域外接框生成二值掩码（含羽化填充）
  ↓
输出 DetectionResult(mask, regions, used_ocr, warnings)
```

`visualize_detections(rgb, regions)` 返回一张 **RGB 标注图**：

- 在每个区域外接框画红框；
- 框上方写类型标签（`半透明` / `角落LOGO` / `边缘小字`）与置信度；
- 该图直接作为 `gr.Image` 预览，让用户一眼看清「算法标了哪里」。

**为什么不直接回掩码图给用户看**：纯掩码是黑白遮罩，不直观；标注图叠加原图，用户能立刻判断检测是否准确，再决定是否用画笔增删。

## 四、与 ImageEditor 的衔接（关键设计）

智能模式不是「检测完直接跑修复」，而是**检测→预填→用户确认→修复**三段式：

1. `process_auto_detect` 调用 `detect_watermark_mask` 得到 `mask` 与 `regions`。
2. 把 `mask` 转成「带 alpha 的彩色图层」（`mask_to_editor_value`），拼成 Gradio 6.x 的 dict：
   ```python
   {"background": rgb, "layers": [带 alpha 的掩码图层], "composite": None}
   ```
3. 这个 dict 直接喂给 `gr.ImageEditor` 的 `value`，用户打开页签就看到水印已被红色半透明层标出。
4. 用户可继续用画笔补涂、或用橡皮擦掉误检区域。
5. `process_auto_repair` 从编辑框回读 `layers` 的 alpha 生成最终掩码，再调 `core.inpainter.inpaint` 修复。

这套衔接复用了阶段 3 已验证的 `core.mask_generator.build_mask_from_editor`（双兼容 4.x 元组 / 6.x dict），保证手动模式与自动模式的掩码语义一致。

## 五、参数映射表（UI 滑块 → 检测内部）

| UI 控件 | 变量名 | 取值范围 | 映射到 |
|---|---|---|---|
| 检测敏感度 | `sensitivity` | 0.30 ~ 0.95，默认 0.55 | 半透明阈值 `(1 - sensitivity)` |
| 启用半透明检测 | `en_translucent` | 勾选 | `enable_translucent` |
| 启用角落 LOGO | `en_corner` | 勾选 | `enable_corner` |
| 启用边缘小字 | `en_edge` | 勾选 | `enable_edge` |
| OCR 增强 | 跟全局 `DETECT_USE_OCR` | — | `use_ocr`（装了 easyocr 才生效） |

修复参数（力度/膨胀/平滑/阈值/降噪/引擎）与阶段 3 手动模式**完全一致**，从 `config` 取默认值，确保两种模式体验统一。

## 六、降级策略汇总

| 缺失项 | 现象 | 程序行为 |
|---|---|---|
| 无 `torch` | LaMa 不可用 | `inpainter` auto 引擎降级 OpenCV，日志 WARN |
| 无 `easyocr` | OCR 文字检测不可用 | 降级 MSER/Otsu，状态栏提示「装 EasyOCR 可提升精度」 |
| MSER 不可用 | OpenCV 构建缺模块 | 降级 Otsu + 连通域 |
| 某策略抛异常 | 局部检测失败 | `try/except` 跳过该策略，其余策略照常，不中断整体 |
| 超大图 | 检测慢/显存高 | `detect_scale` 触发降采样检测 |

## 七、验证结论

- `core/detector.py` 自检：三类策略全部生效，无报错，处理函数内部布尔开关遮蔽 bug 已修复（参数 `enable_*` 重命名）。
- `ui/app.py` `build_app()` 在 Gradio 6.x 下构建无报错（自动检测页签已替换占位）。
- **端到端打通**：合成图（浅灰底 + 半透明文字 + 角落 LOGO + 顶部小字）→ 检测出 2 个区域 → 预填编辑框（图层数 1）→ 回读掩码 36708 像素 → OpenCV 降级修复 → 保存 → 与原图差异 49476 像素（确认水印区被改写）。

**已知局限（非阻断）**：

- 在「无 easyocr」环境下，文字类水印依赖 MSER/Otsu，对**极低对比度**的半透明小字召回率有限；装 EasyOCR 后精度显著提升。这属于算法能力边界，已在状态栏如实告知用户，不夸大效果。
- 半透明检测对「与背景完全同色的纯色平铺水印」效果依赖残差幅度，极端情况下需用户手动补涂——这也正是「检测→预填→增删」三段式设计的用意：算法打底，人工兜底。

## 八、下一阶段（阶段 5）衔接

阶段 5 批量处理需要「检测 + 修复」作为单图原子操作。本阶段的 `process_auto_repair` 与阶段 3 的 `process_single` 已暴露统一签名：

```
(image_or_editor, engine, strength, dilate, feather, threshold, denoise) -> (orig, result, status, out_path)
```

阶段 5 的队列 worker 将直接复用这两个函数作为处理单元，无需重复实现修复逻辑。
