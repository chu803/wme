# 阶段 28 设计文档：推荐理由可视化

> 关联阶段：25（检测自动预设推荐内核）→ 26（批量逐图推荐）→ 27（媒体逐页/逐帧推荐）→ **28（把「为什么推荐这个预设」可视化）**
> 日期：2026-08-05
> 状态：完成

---

## 1. 背景与动机

阶段 25–27 让「智能预设推荐」覆盖了自动 / 批量 / 媒体三个入口，推荐结果能区分每张图/每页/每帧最合适的检测预设。
但用户只看到**预设名**（如「AI 平铺水印」），看不到**为什么**——是哪些图像特征触发了这次推荐、置信度多高。
这带来两个痛点：

1. **不可复核**：推荐错了也不知道错在哪，只能盲信。
2. **报告缺信息**：导出的批量修复报告（HTML/PDF）只列了参数与质量分，丢了「AI 为什么这么修」的关键上下文。

阶段 28 把 `core.preset_recommender.Recommendation`（含 8 维特征评分 `scores`、触发特征 `triggered`、置信度 `confidence`）**渲染成人类可读、可可视化的文案**，在三个入口 + 报告里补上「推荐理由」。

---

## 2. 核心设计：共享渲染器（utils 层）

新增 `utils/recommend_view.py`，作为三处共用的「推荐理由」渲染器。

### 2.1 分层选择
- 渲染涉及翻译（`detect.preset.<name>.title` / `detect.recommend.*`），本应放 UI 层；
- 但**报告服务（services 层）也要用**（不能 import ui），而 `services → utils` 合规、`ui → utils` 合规；
- 因此放在 **utils 层**，只依赖 `utils.i18n`，不引入 gradio / torch，无反向依赖风险。

### 2.2 三个渲染接口
| 函数 | 产出 | 用途 |
|------|------|------|
| `reason_line(rec)` | 单行紧凑理由：`推荐 AI 平铺水印（置信度 71% · 触发 填充式平铺水印）` | 批量/媒体日志、PDF 报告文本行 |
| `bars_html(rec)` | 自带 `<style>` 的水平分数条（HTML） | HTML 报告卡片可视化 |
| `markdown(rec)` | Markdown（含 `█░` 字符分数条） | 自动页「智能推荐」按钮结果 |

### 2.3 健壮性
- `get_recommendation_dict(rec)`：兼容 `Recommendation` 对象与 dict，无效（None / 无预设）返回 `None`；
- `preset_label` / `feature_label`：i18n 缺失时回退到原始键名，绝不暴露裸键；
- 空值安全：`reason_line(None)`、`bars_html(None)` 均返回空串；
- 模块自带 `__main__` 自检（标签翻译、置信度、触发特征、空值）。

## 3. 三入口接入

### 3.1 自动页（ui/tab_auto.py）
- 原本地 `_build_recommend_markdown` 改为直接复用 `utils.recommend_view.markdown`，
  点「🔍 智能推荐预设」按钮后展示**含字符分数条**的理由（预设 + 触发特征 + 各特征分值条）。

### 3.2 批量页（ui/tab_batch.py）
- `_on_update` 中：每张图若存在 `recommendation`，日志追加一行
  `🤖 智能推荐：<reason_line>`（含置信度与触发特征），替代原先只显示预设名的 `log_preset`；
- 把 `recommendation` 随 `ReportSource` 传入报告（供报告可视化）。

### 3.3 媒体页（ui/tab_media.py）
- **PDF**：逐页明细追加子行 `↳ <reason_line(pr.recommendation)>`；
- **视频**：`VideoResult` 新增 `recommend_conf_avg`（逐检测帧推荐置信度的均值），
  汇总行展示 `🤖 智能推荐平均置信度：XX%`，衡量整段推荐的靠谱程度。

## 8. 设计取舍
- **为何分数条用 HTML/CSS 而非图片**：报告要自包含（base64 内嵌对比图已够重），再生成图片反而增加依赖；CSS 条轻量且矢量清晰。
- **为何批量/媒体日志用单行 reason_line 而非 bars**：日志是纯文本框，逐行展示，bars（多行/HTML）不适合；分数条的「可视化」重头戏放在 HTML 报告卡片与自动页按钮（Markdown 字符条）。
- **视频只给平均置信度**：逐帧 reason 在日志里噪音太大，平均置信度足够表达「整段推荐靠不靠谱」。

---

## 9. 已知边界
- 推荐理由依赖 `RECOMMEND_ENABLED` 总开关；关闭时 `recommendation` 为空，三入口均不展示（与阶段 25 行为一致）。
- 报告/UI 的语言跟随全局 i18n 当前语言（应用默认简体中文）；测试用语言无关断言避免环境差异。
