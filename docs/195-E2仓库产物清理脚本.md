# 阶段 195（E2）· 仓库产物清理脚本

> 关联清单项：E2（仓库产物清理脚本）。本文档为权威记录；脚本行为以 `scripts/clean_artifacts.py` 为准。

## 结论

- 新增 `scripts/clean_artifacts.py`：把「盘点 → 隔离 → 回收」固化成一条可重复命令，**默认 dry-run 只列不改**，规避了此前零散 `rm -rf` 思路与沙箱删除护栏（LESSONS 202）。
- 三类模式互斥：**`--dry-run`（默认）/ `--archive`（rename 隔离到 `.scratch/cleaned/<ts>/`）/ `--delete --i-am-sure`（真正删除，≤50 小批量）**。
- 主路径是 `--archive`：rename 到 `.scratch/`（已被 .gitignore 忽略），既清出工作树主干、又不破坏任何文件，**可逆可找回**；`--delete` 仅供沙箱外回收空间。
- 守卫测试 `tests/test_clean_artifacts.py` 7 例全绿（纯函数 + 合成树确定性断言；delete 用 monkeypatch 拦截真实删除验证逻辑）。
- 真实仓库 dry-run 实测：**79 个条目 / 16078 内部文件 / 68.2 MB**（详见下表），一键可见、可决策。

## 设计

### 三种模式（互斥，默认 dry-run）

| 模式 | 行为 | 文件系统影响 | 适用场景 |
|---|---|---|---|
| `--dry-run`（默认） | 扫描 + 打印分类报告 | 零 | 反复盘点、CI 预检 |
| `--archive` | rename 到 `.scratch/cleaned/<ts>/<相对路径>` | 移动（同 fs 零拷贝） | **主路径**：清乱、可逆、可找回 |
| `--delete --i-am-sure` | 真正删除（≤50/批） | 删除 | 仅沙箱外、确需回收空间 |

- **删除护栏**：`--delete` 强制 `--i-am-sure` 双确认；按 `_DELETE_BATCH_LIMIT=50` 小批量推进，规避沙箱「单次 >50 即拒 + 会话闩锁」（LESSONS 202）。沙箱内若被护栏拒删，回退 `--archive` 或沙箱外手动清理。
- **归档优于删**（LESSONS 202）：默认与推荐路径都是 rename，不破坏任何文件。
- **`stray_root` 锚定根目录**：`classify_file` 对 `.*.py` / `.*.txt` 仅当位于仓库根（`relpath == "."`）才命中，对应 .gitignore 的 `/.*.py`、`/.*.txt`（阶段 185 E1 规则），不会误伤子目录里的正常点文件。

### 真值审计锚点

分类规则集中在**单一真值来源** `ARTIFACT_SPECS`（脚本内的 `_EXACT_DIRS` / `_DIR_PREFIXES` / `_DIR_SUFFIXES` 与 `classify_file` 的扩展名表），**不解析 .gitignore**——保持确定、零依赖、易守卫。纯函数 `classify_dir` / `classify_file` / `scan` 可独立测试，不触碰真实仓库即可确定性验证。

- 扫描跳过 `.git` 与归档目标 `.scratch`，命中目录后停止递归其内部（避免重复计数与自我归档）。
- 每个类别路径排序后返回，保证确定性（测试可断言、归档顺序稳定）。

### 退出码（与门禁家族一致：0/1/2）

- `0` = dry-run 成功列出 / archive 或 delete 完成（delete 无失败）。
- `1` = archive/delete 有失败（如沙箱拒删），或 root 不是目录。
- `2` = `--delete` 缺 `--i-am-sure`（拒绝执行）。

## 验证

- `tests/test_clean_artifacts.py`：**7 passed**（classify 纯函数 / scan 命中+跳过 .git/.scratch / build_report 结构 / archive 真实 rename / delete 缺确认返回 2 / delete 分批编排 monkeypatch 拦截）。
- 真实仓库端到端：`python scripts/clean_artifacts.py --dry-run` 退出码 0，报告如上表。
- 回归：CI 等价子集（`not torch_required and not network`）随本阶段一并跑，确保新增脚本/测试未扰动既有链路。

> 注：本测试在 `tmp_path` 下运行时，conftest 的 autouse `_isolate_runtime_dirs` 会额外创建 `_wme_runtime/{cache,...}`，它们同样被 `classify_dir` 命中——证明脚本也能抓到这类目录；测试断言已改为「期望路径成员判定」而非精确计数，避免环境耦合。

## 用法

```bash
python scripts/clean_artifacts.py                      # 默认 dry-run 报告
python scripts/clean_artifacts.py --verbose            # 报告 + 列具体路径
python scripts/clean_artifacts.py --json report.json   # 报告写 JSON（--verbose 才含明细）
python scripts/clean_artifacts.py --archive            # 隔离到 .scratch/cleaned/<ts>/
python scripts/clean_artifacts.py --delete --i-am-sure  # 真正删除（沙箱外）
```

## 诚实边界与待办

- 本脚本**不解析 .gitignore**：它服务「盘点/隔离/回收」的运维意图，分类表是手工维护的单一真值来源；若未来新增产物类型，需在 `ARTIFACT_SPECS` 同步，并在 `tests/test_clean_artifacts.py` 补一条成员断言。
- `--delete` 在受限沙箱内可能被护栏直接拒删（属预期防守），不是脚本 bug；真要回收空间请在沙箱外执行。
- 与 `run_all_checks.py` 的关系：清理脚本**不属于质量门禁家族**，故未注册进验证入口；它是独立的运维工具，按需手动调用。
- 阶段 185 遗留的「E2 删除（沙箱外执行）」从此可由本脚本承接——用户在沙箱外跑 `--archive`（首选）或 `--delete --i-am-sure` 即可，无需手敲 `rm`。
