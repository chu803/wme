## 三、新增守卫（扩展既有 `test_repo_hygiene.py`，不另造重复）

既有的 `test_repo_hygiene.py` 只守「追踪文件体积」与「文档承诺的忽略规则生效」，
**缺「根目录散落文件」这一维**。本阶段**追加**两条不变式（经验 #24/77：同一语义共用同一守卫）：

1. `test_root_dir_has_no_unexpected_files` —— 根目录不得出现白名单外的散落文件。
   白名单**逐项显式登记**（非通配），让「根目录多了个文件」成为需要解释的决定。
2. `test_root_junk_is_not_git_tracked` —— 白名单外的文件**必须未被 git 跟踪**
   （安全网：即使守卫被绕过，也不让垃圾悄悄进版本库）。判定用 `git ls-files`（唯一真值来源）。

### 过程中的一处 Windows 语义修正（诚实记录）
最初以为 `os.rename` 跨目录会「移动」（源文件消失），实测**源文件仍在**⇒
Windows 下 `os.rename` 跨目录实为「复制+删除源」的反直觉组合。后续改用
`os.remove` 删根目录残留（单文件，远低于护栏阈值），归档区保留一份作证据。

## 五、自反证伪

- 白名单是**显式枚举**：新增合法根文件（源码/配置）时**必须同步登记**，否则守卫会红——
  这是刻意的「摩擦」（LESSONS 267 声明须机器判定），但也意味着新增文件时需一并更新本守卫。
- 本守卫只管**根目录**这一层；`docs/`、`tests/` 内部的命名与体积不在此列
  （体积由既有 50 MB 追踪上限守）。
- 未清理的大目录（`.pytest_*` / `logs/` / `temp/` / `cache/` / `exports/` / `outputs/`）
  仍待沙箱外删除（188 §E2已列，均 gitignored，不影响仓库与构建）——本阶段不重复尝试
  （LESSONS 202：不要在脚本里反复尝试删除）。
- 归档区 `.scratch/junk_261/` 保留 7 个垃圾作**证据**（可随时由用户侧删除）。
