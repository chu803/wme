## 2. 锁住的关键不变式（比覆盖率更重要）

**`--selftest` 必须在 `ensure_model_ready()` 之前返回。**
`main.py` 的注释写明了理由：自测只需核心算法，若走到模型就绪检查会**触发网络下载**
（可能长时间超时）。这是**编排顺序的设计意图**，原先无人守——现在用**间谍函数**钉死：
`test_selftest_returns_before_model_steps` 断言 selftest 路径下
`ensure_model_ready` / `warm_up_model` / `launch_ui` **绝不允许被调用**。

其余被锁行为：
- 正常路径的**完整调用顺序** = `banner → env → perf → device → model → warmup → launch`
  （顺序改动即测试失败）；
- 环境自检**致命失败**时不得进入模型/启动段（返回 1）；
- **自测模式忽略**自检失败（交给 `run_selftest` 给友好提示，而非硬失败）；
- `--no-download` 确实把 `config.MODEL_AUTO_DOWNLOAD` 置 False（用 try/finally 复原）；
- `launch_ui()` 两条分支：ui.app 可用（返回值原样传出）/ 加载失败（打印
  `requirements.txt` 安装指引 + 缺 Gradio 时明确「核心算法仍可运行」，并退回自测）。

## 3. 测试设计要点（可复用于其它入口）

1. **假模块注入**：`sys.modules["ui.app"] = <假模块>` ⇒ 既不启 Gradio 服务、
   也不受「本机是否装了 gradio」影响 ⇒ **结果确定性**（否则同一测试在不同机器上走不同分支）。
2. **确定性地覆盖「缺依赖」分支**：`sys.modules["gradio"] = None` 会让 `import gradio`
   抛 `ImportError`（CPython 既有行为），无需卸载真包。
3. **只测编排**：不真跑模型/推理/超分 ⇒ 秒级、无副作用、可进 CI 的快速子集。
4. **惰性导入的结构守卫**：断言 `main.py` 的**模块级**不得出现 `cv2/torch/gradio/numpy`
   （重依赖必须在函数内导入，否则「导入即拖慢/可能失败」）。

## 4. 边界

- 入口的**真实启动**（`launch_app` 起服务、端口占用、浏览器打开）仍**不在自动化范围**——
  那适合由 `docs/187` 提到的「容器/CI 冒烟」承担，本阶段只锁编排与降级路径。
- 剩余未覆盖分支需要 torch / 权重 / 网络；若要覆盖，应在**带 GPU/权重**的环境单独跑
  （与 `pytest.ini` 的 `torch_required` / `network` 标记约定一致），不要为刷数字写「假装测试」。
