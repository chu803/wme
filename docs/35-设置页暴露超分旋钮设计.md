## 1. 背景与目标

阶段 32–34 已经把「真实超分」三旋钮（总开关 `REAL_SUPERRES_ENABLED`、放大倍数
`REAL_SUPERRES_SCALE`、后端 `REAL_SUPERRES_BACKEND`）落到单图 / 自动 / 批量 / 视频四个
功能页的修复参数面板里，但**用户只能在四个处理页分别设置**，没有统一的、可「一次改全站」的入口；
且改动**不会持久化**，重启后回到代码默认 / 环境变量值。

阶段 35 目标：在「设置与导出」页（阶段 6 起）新增「真实超分」面板，提供：

1. **实时生效**：点击「应用」后，立即改写运行时配置，并跨页刷新四个功能页的真实超分控件
   （总开关 / 倍数 / 后端），无需重启。
2. **保存为默认（可选）**：勾选后，把三旋钮写入项目根目录 `config.user_overrides.json`，
   下次启动自动生效（环境变量优先级最高）。

## 2. 设计要点

### 2.1 运行时改写 `Final` 属性

`config.py` 中 `REAL_SUPERRES_*` 标注为 `Final[...]`。`Final` 仅受类型检查器约束，
**运行时通过模块属性赋值（`config.REAL_SUPERRES_ENABLED = ...`）完全可改写**，
且所有消费方都以 `config.REAL_SUPERRES_*` 属性访问（无 `from config import X`），
因此运行时覆盖对全项目即时生效。此机制在阶段 34 已确认，阶段 35 复用。

### 2.2 跨页刷新：控件注册表（ui/components.py）

设置页在 `build_app()` 中于四个功能页**之后**构建，因此构造设置页时注册表已填满。

- 新增模块级注册表 `_SUPERRES_WIDGETS: list[dict]`，每个元素为
  `{"enabled", "scale", "backend"}` 一组真实超分控件。
- `register_superres_widget(enabled, scale, backend)`：登记一组控件。
- `register_superres_handles(h: RepairParamHandles)`：批量 / 媒体页（走 `build_repair_params`）
  的便捷入口；`build_repair_params._body` 在返回句柄前自动登记。
- `get_superres_widgets()` / `clear_superres_widgets()`：读取 / 清空（测试与重建用）。
- 单图页 `tab_single`、自动页 `tab_auto` 的控件是**内联构建**（绕过 `build_repair_params`），
  在构造后显式调用 `register_superres_widget(...)` 登记。

### 2.3 应用逻辑（ui/tab_settings.py）

- `apply_superres_config(enabled, scale, backend, save_default)`：
  1. 改写 `config.REAL_SUPERRES_*`（try/except 保护，失败仅提示不崩）。
  2. 若 `save_default`：`config.save_user_overrides(...)` 持久化（失败仅警告）。
  3. 用 `_superres_refresh_updates()` 为注册表中每组控件生成 `gr.update(value=...)`。
  4. 重建配置快照 Markdown（`build_snapshot_md` 实时读配置），拼出信息文案。
  5. 返回扁平列表：`[每组 enabled/scale/backend 更新 ...] + [快照, 信息]`，
     与 `sr_apply.click` 的 `outputs` 顺序严格对齐。
- `build_settings_tab()` 中：设置页在功能页之后构建，遍历 `get_superres_widgets()`
  把每组控件按 `[enabled, scale, backend]` 顺序收集进 `sr_targets`，作为 `sr_apply.click`
  的 outputs；`inputs` 为设置页自身的 `sr_enabled/sr_scale/sr_backend/sr_save`。

### 2.4 用户覆盖持久化（config.py）

- `USER_OVERRIDES_PATH = <项目根>/config.user_overrides.json`。
- `load_user_overrides()`：读 JSON；**仅白名单三键**（`REAL_SUPERRES_ENABLED/SCALE/BACKEND`）
  被读回，值经校验器过滤（倍数 1–8、后端 ∈ {auto,esrgan,realesrgan}），其余键忽略；
  文件缺失 / 损坏 / 非 dict → 返回 `{}`（静默）。
- `save_user_overrides(enabled, scale, backend)`：仅写白名单三键；失败返回 `False`（不抛）。
- `_apply_user_overrides()`：启动时调用，应用持久化值；**环境变量 `WME_*` 显式设置时
  优先级最高，对应键跳过 JSON 覆盖**（env > json > default）。

### 2.5 配置快照扩展（ui/tab_settings.py + utils/i18n.py）

- `build_snapshot_md()` 增加「真实超分」小节：标题 + 总开关 + 放大倍数 + 后端（实时读配置）。
- i18n 新增键：
  - `settings.real_superres.*`：`title` / `enabled_label`+`info` / `scale_label`+`info` /
    `backend_label`+`info` / `save_label`+`info` / `apply`（zh + en）。
  - `settings.snap.real_superres_title` / `enabled` / `scale` / `backend`。
  - `settings.snap.msg.superres_applied`。
  - 全部经 i18n 自检验证（zh-CN / en-US 双语齐全）。

## 4. 兼容性 / 安全

- **纯标准库**：覆盖读写仅用 `json` / `os`，无 torch 依赖，沙箱无 torch 亦可完整测试。
- **白名单 + 校验**：外部 JSON 无法篡改白名单外配置，非法值回退安全默认。
- **静默容错**：文件缺失 / 损坏 / 无写权限均不抛异常、不拖垮启动。
- **优先级清晰**：环境变量 > 用户覆盖 JSON > 代码默认，符合项目既有 `.env` 覆盖模型。
- **分层约束**：`config` 不依赖 gradio；`ui` 单向依赖 `config` / `services`；注册表在 `ui` 层，
  不反向渗透到 `core` / `services`。

## 6. 已知边界（延续）

- 沙箱无 torch：真实超分后端在运行时回退轻量超分；`config.user_overrides.json` 持久化与
  跨页刷新逻辑与 torch 无关，均可在无 torch 环境完整工作。
- 设置页「应用」改写的是运行时 `config` 属性与四页控件值；功能页运行函数以各自控件当前值
  为输入，因此应用后四页控件已被 `gr.update` 刷新，后续处理自动采用新值。
