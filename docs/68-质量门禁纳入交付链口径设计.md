# 阶段 68 · 质量门禁纳入「交付链」口径设计

> 目标：把经验第 6 条「**质量评估口径必须等于用户实际交付链路**」从一条单测约束升级为
> **常驻门禁红线**，让阶段 60 那类「只影响成品、不影响裸修复」的缺陷再也无法静默通过。
> 交付：`scripts/quality_gate.py`（交付链臂 + 掩码区 PSNR + 新红线）、
> `tests/test_delivery_chain_gate.py`（14 例）、刷新 `docs/assets/quality_baseline.json`。

---

## 1. 动机（一个已被记录、却始终没落地的缺口）

阶段 60 的真值审计发现：门禁与 benchmark 评估的是**裸 inpaint**，而用户实际拿到的是
「裸修复 + 后处理默认链」的成品。三个缺陷因此长期隐藏——边缘融合把**原图（仍带水印）的
像素**按软掩码混回掩码边界、色彩还原用全图外部统计 + 标准差重缩放、锐化放大掩码内残留；
其中最严重的角标用例**掩码区 PSNR 38.4 → 11.5 dB**，而门禁当时全绿。

阶段 60 修复了缺陷，但门禁口径没变——问题依然存在：**只要有人重新打开这三类操作，门禁
仍然看不见**（阶段 60 只留了 6 例单测，覆盖面仅限固定合成用例，且不经过门禁的完整矩阵）。
本阶段把它补齐。

## 2. 现状核实

`scripts/quality_gate.py` 的逐引擎循环里只有一行修复调用（原第 182 行）：

```python
out = inpaint(marked, pred, engine=engine)     # ← 到此为止，没有 postprocess
```

即：门禁矩阵（3 底图 × 4 用例 × 引擎）**完全没有碰过后处理链**。

## 3. 实施：交付链臂

在每个 (kind, case, engine) 单元里额外计算一次成品：

```python
delivery = postprocess(out, original_rgb=marked, mask=pred,
                       superres=False, real_superres=False)
```

**必须显式关闭可选超分**：`config.user_overrides.json` 可能把真实超分设为默认开启，那样
交付结果会变成 1280²、与 base 不可比（阶段 60 踩过这个坑：`pp` 突然变成 1280×1280）。
交付链臂只评估**标称默认增强链**（边界柔化 + 掩码外锐化 + 色彩还原[默认关]）；若后处理
抛异常或尺寸不一致，则记为 `None` 而不阻断门禁（但会被下面的红线抓到）。

## 4. 两个新口径

### 4.1 掩码区 PSNR（回答「擦干净了没」）

全图 PSNR/ΔPSNR 按面积加权，会被大片未改动区域稀释——阶段 65 的裁决经验已证明这一点。
新增 `_psnr_region(out, base, pred > 0)`：只统计**被擦除区域**内的 PSNR。两臂各算一次：

- `psnr_masked_bare`：裸修复的掩码区 PSNR；
- `psnr_masked_delivery`：交付成品的掩码区 PSNR；
- `masked_drop = bare − delivery`（正数 = 交付链更差）。

### 4.2 交付链保真红线（新增，与基线无关）

```python
DELIVERY_MASKED_MAX_DROP = 0.01     # 仅吸收浮点误差
# 任一单元 masked_drop > 该值 → 门禁失败
```

同时把交付链的**全图** ΔPSNR（`delta_psnr_delivery`）纳入聚合与基线漂移监控。
**不为全图设红线**：全图指标的下降来自「内容区锐化」这一**刻意保留的观感取舍**（见 §6），
属于设计决定而非缺陷——把它设成红线会逼着未来的人关掉锐化。红线只锁「该擦干净的区域」。

## 5. 量化结果（640 全量，OpenCV 引擎）

| 底图 | 用例 | 掩码区（裸→交付） | 全图 ΔPSNR（裸→交付） |
|---|---|---|---|
| gradient | 角落 LOGO | 37.46 → **37.49** | +28.30 → +28.31 |
| gradient | 底部小字 | 43.77 → **44.82** | +23.12 → +20.85 |
| gradient | 网格点阵 | 47.22 → **49.25** | +21.18 → +20.45 |
| textured | 角落 LOGO | 25.10 → **25.11** | +14.81 → +14.36 |
| textured | 底部小字 | 28.36 → **28.55** | +15.87 → +14.12 |
| textured | 网格点阵 | 26.75 → **27.05** | +1.92 → +1.42 |
| photo | 角落 LOGO | 22.91 → **22.92** | +10.41 → +9.96 |
| photo | 底部小字 | 30.12 → **30.27** | +17.72 → +14.05 |
| photo | 网格点阵 | 29.87 → **30.17** | +6.82 → +4.86 |
| 聚合 | — | **掩码区最差劣化 −0.01 dB（全部持平或略升）** | **+12.60 → +11.44 dB** |

**解读**：默认后处理链在**掩码区**零劣化（12/12 持平或小幅提升，最差 −0.01 dB 即改善
0.01 dB），与阶段 60 的结论一致；全图 ΔPSNR 下降 **1.16 dB** 全部来自内容区锐化
（`POSTPROCESS_SHARPEN`）——这是刻意保留的观感取舍，且阶段 60 已判定合成噪点图会放大该代价。

## 6. 护栏有效性验证（不是"写在纸上"）

`tests/test_delivery_chain_gate.py` 分三层：

1. **区域 PSNR 语义**（4 例）：相同图 → 100 dB、空区域 → None、**区域外改动不影响分数**、
   区域内改动被正确计入；
2. **红线判定**（5 例）：零劣化通过 / 交付链更优通过 / 38.4→11.5 dB 形态必须失败 /
   容差收紧（0.02 dB 劣化不得放过）/ 缺字段容错；
3. **端到端与"护栏咬得住"**（5 例，slow）：极小配置真跑（交付链字段齐全、掩码区零劣化）；
   **注入阶段 60 的缺陷形态**（把原图像素按软掩码混回交付结果）后，`masked_drop` 必须
   触发红线、`evaluate()` 必须失败——若这条不成立，说明红线形同虚设。

## 8. 边界（诚实声明）

- 交付链臂只覆盖**默认增强链**；可选增强（纹理重建/Poisson/伪影抑制/轻量超分）由部署级
  放行闸默认关闭，不在门禁矩阵内（阶段 61 已单独审计）；
- 只跑 OpenCV 引擎臂（LaMa 需 `--with-lama`，CPU 单图 3~4 s）；LaMa 的交付链未纳入常驻门禁；
- 视频 / PDF 链路的成品质量仍未纳入门禁（各自管线独立）；
- 全图 ΔPSNR 的 1.16 dB 下降属刻意取舍，**只监控不设红线**——若未来认为观感收益不足，
  应在阶段文档里显式裁决，而不是悄悄调阈值。
