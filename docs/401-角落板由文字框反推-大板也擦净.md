# 401 · 角落「板」由文字框反推：大板也擦净，几何覆盖 4/4（2026-11-08）

> 收掉挑战集最后一个缺口 **B2（358×67 大板）** ⇒ 承诺类的角标**几何覆盖 4/4**。

## 一、为什么大板擦不干净（阶段 398 已定位到一半）

白底板块判据靠「亮块连通域」⇒ 而大板的亮区**与照片里相邻的亮背景连成一片**
（实测连通域 371×144、实心度 0.53、触碰搜索区边界）⇒
板与背景被一起收（或一起丢）⇒ 白底判据对它无效。

已否证的三条旋钮路线（都逐位无效）：面积上限 2%→5%、长宽比上限 3.2→6、
角落搜索区 0.2→0.45 短边（后者还让单图耗时 5.9s→10.9s）。

## 二、换判据：角标 = 「字 + 板」⇒ 用文字框反推板

角标本来就是字站在板上 ⇒ 用角落里的 **OCR 文字框**当种子，按放大系数反推板的范围：

1. 把同一块板的多个文字框并成一组（竖向重叠 ≥50%、横向间隙 ≤25% 短边）；
2. 以文字并集为中心放大 `DETECT_CORNER_BADGE_EXPAND`（默认 1.3）；
3. **只在"文字确实坐在一块亮板上"时适用**（判据在**文字并集框**上做）：
   - 亮像素占比 ≥ `DETECT_CORNER_BADGE_MIN_BRIGHT`（0.55）
   - 最大亮连通块占比 ≥ `DETECT_CORNER_BADGE_MIN_SOLID`（0.40）
   实测：白板（B2）0.705 / 0.646 ⇒ 通过；深底文字或泡沫背景（B4）0.376 / 0.218 ⇒ 不适用
   ⇒ **深底纯文字不会被当成板放大**（否则会误伤周围）。
4. 面积占比 ≤ 5%（角标不会占满图）。

## 三、还差一步：填充分区要**外扩**（板自身的亮边会变成填充来源）

第一次实现后 B2 目视仍剩一块**白板残影**（比周围亮）⇒ 实测板区亮度比 **1.48**。
根因：板自身的亮边留在掩码外 ⇒ 成了 inpaint 的填充来源 ⇒ 填出一块比周围更亮的板。
⇒ 填充分区额外外扩 `DETECT_CORNER_BADGE_MARGIN`（默认 8px），让边界落在照片上
⇒ 板区亮度比回到 **1.04**，目视只剩与夜色接近的淡痕。

## 四、判定指标补第二道口径（阶段 399/400 的延续）

锐边指标看不见「残留的平整白块」⇒ 补**板/字亮度比**（足迹区 vs 周边环）：

| 样本 | 修前亮度比 | 修后 | 锐边残留 | 判定 |
| --- | --- | --- | --- | --- |
| B1 左下小板 | 1.92 | 0.952 | 0.083 | 擦净 ✓ |
| B2 大板 | 1.80 | **1.060** | 0.036 | 擦净 ✓ |
| B3 半透明板 | 1.89 | 0.971 | 0.122 | 擦净 ✓ |
| B4 深底纯文字 | 0.69 | 0.979 | 0.320 | 擦净 ✓ |

⇒ 几何门禁的参考样本判定 = **锐边残留 < 0.5 且 亮度比 ≤ 1.15**（两道口径都要过）。

## 六、诚实的边界

- **天生的歧义**：照片角落里"亮底招牌"与平台角标在像素上难分 ⇒ 放大系数保持小（1.3），
  且只在"文字坐在**连成一块**的亮区上"时才生效。
- 真阳性样本仍是**合成夹具**（真实"纯文字角标"样本本项目没有）⇒ 阈值可经环境变量回退
  （`WME_DETECT_CORNER_BADGE_EXPAND` / `_MARGIN` / `_MIN_BRIGHT` / `_MIN_SOLID` / 开关）。
- 挑战集是**合成**的（几何参数照豆包 manifest 复刻）⇒ 覆盖 4/4 是"几何维度"的覆盖，
  不等于"真实生成器全覆盖"（真实 50 张豆包图仍单列另一条红线：擦净 98.0%）。
