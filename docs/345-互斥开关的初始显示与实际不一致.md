# 阶段 345 · 视频页两个互斥开关：界面显示勾选，实际却被服务层强制关闭

> 日期 2026-10-26 · 性质：**默认值/交互语义的判决 + 修**（第二轮审计 F4，本轮最后一条）

## 一、判决先行：语义是对的，错的是**初始显示**

服务层（`services/video_service.py:493`）：

```python
detect_auto = bool(auto_preset) and not reuse     # 复用掩码 ⇒ 逐帧推荐无意义
```

这条**语义本身是对的**（阶段 27 的注释说得很清楚：复用掩码 = 固定水印位置，整段共用一个预设更合理）。
所以不改它，也不改 `config` 的默认值。**错的只是 UI 初始状态**：

| 控件 | 初始值 | 实际 |
|---|---|---|
| 「复用水印位置」`v_reuse` | `config.VIDEO_REUSE_MASK` = **True** | 复用**开着** |
| 「逐帧智能推荐」`video_auto_preset` | 写死 **`True`** | 服务层 `and not reuse` ⇒ **强制关闭** |

⇒ **界面显示是勾上的，功能却是关的**；检测模式下拉照常可点，但选了会被 `preset=None` 忽略
（「选了又没用」）；而这个复选框自己的 info 写着「勾选『复用水印位置』时自动关闭」——
**文案与实际相反**。唯一能纠正它的 `.change` 处理器（`v_reuse.change`）**只在用户动手时触发**，
构建期不会跑。

## 二、修法：初始状态按同一套语义推出来

新增纯函数 `video_recommend_defaults(reuse=None)`：

```python
r = bool(config.VIDEO_REUSE_MASK if reuse is None else reuse)
on = not r
return {"reuse": r, "auto_preset": on, "auto_preset_interactive": not r}
```

UI 构造处用它：`v_reuse.value = _vd["reuse"]`、
`video_auto_preset.value = _vd["auto_preset"]` 且 `interactive=_vd["auto_preset_interactive"]`，
检测模式下拉 `interactive=not _vd["auto_preset"]`（推荐开着时下拉本就会被忽略 ⇒ 构建期就置灰）。
**不新增任何控件、不改判定逻辑、不改 config 默认值、不改用户手动勾选后的行为**——
只是把「显示」对齐到「实际」。

## 三、守卫

`tests/test_video_recommend_defaults345.py`（4 例）：

1. 两个方向都符合服务层规则；
2. **核心不变量**：把显示出来的初始状态代入服务层公式，结果必须与显示一致
   （显示勾选 ⇒ 实际生效；显示未勾 ⇒ 实际不生效），且「复用开着 ⇒ 推荐关」这条承诺成立；
3. 按**本机真实默认值**验：`VIDEO_REUSE_MASK=True` 时界面不得把推荐显示成勾选；
4. **接线守卫**（比运行时更早失败）：复选框初值必须来自 helper，不许再写死 `value=True`
   ——写死的初值就是本缺陷的形状本身。

HEAD 上 **4 条全红**，修复后连同 `test_tab_media_audit112` / `test_ui_tab_seams` 全绿。
