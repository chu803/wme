# 阶段 57 · 端到端质量门禁 + 分辨率鲁棒性收敛

> 一句话：把阶段 49~56 的质量成果固化成「可复现基线 + 双层机器判定」的门禁，让劣化
> 无法再被静默放行；门禁首跑即在 320² 触发红线，当场暴露出检测器此前从未被测出的
> **分辨率依赖缺陷**（小图干净误报率飙升）——顺藤摸瓜定位根因（面积门限纯相对、
> 随图像变小趋近 0），并用「绝对像素下限锚定参考分辨率」修复，全尺寸档误报收敛到
> ≤2%、640 基准逐位不变。

---

## 1. 背景与动机：质量成果没有护栏

阶段 49~56 把检测器与修复引擎都推到了「有 benchmark 证据支撑」的状态：干净图误报率
69.7% → 0.8%，精确率 7.9% → 47.7%，IoU 46.0%；修复引擎 `auto` 默认收敛到 OpenCV。
但这些成果**只由手工脚本与文档维系**：

- `detector_diag.py` 要人工跑，数字人工抄进 README；
- `run_benchmark.py` 的 ΔPSNR 结论躺在 `docs/51-*` 里；
- `tests/test_benchmark.py` 只用**假数据**校验聚合逻辑，从不跑真实检测/修复。

也就是说：任何人改坏检测器常量或修复参数，全量测试依然全绿。阶段 57 的第一要务就是
把「检测 + 修复」的端到端结果固化成**机器可判定的门禁**。

## 2. 门禁设计：`scripts/quality_gate.py`

### 2.1 双层约束

| 层 | 内容 | 意义 |
|---|---|---|
| ① 绝对红线 | 干净图误报 ≤2% · 平均精确率 ≥35% · 平均 IoU ≥35% · corner_logo/edge_text 的 ΔPSNR > 0 | 与基线无关；防止劣化结果"刷新"基线 |
| ② 基线漂移 | 与 `docs/assets/quality_baseline.json` 比对；precision/recall/iou 相对容差 20%、ΔPSNR 35%、clean_fpr 绝对上浮 0.01 | 捕捉"红线之内但明显变差"的慢性劣化 |

判定逻辑刻意做成**纯函数** `evaluate(summary, baseline)`：不吃文件、不跑计算，只喂
数据结构，越线即产出机器可读的违规说明——便于单测锁死判定语义。

### 2.2 与既有脚本的边界

`detector_diag.py`（纯检测诊断，3 底图 × 4 用例 × 4 预设）和 `make_demo_assets.py`
（修复 benchmark，合成 ground truth）继续各司其职；**门禁在两者之上做聚合与判定**：
复用 `detector_diag.BASE_KINDS/gt_mask/metrics` 与 `make_demo_assets.CASES` 生成端到端
数据（检测掩码 + OpenCV 修复 + ΔPSNR + 无参考质量分），避免再造一套合成器。

### 2.3 CLI

```
python scripts/quality_gate.py            # 跑门禁并与基线比对（越线 exit 1）
python scripts/quality_gate.py --update   # 刷新基线快照
python scripts/quality_gate.py --quick    # 只跑 photo × corner_logo/edge_text，快速迭代
python scripts/quality_gate.py --sweep    # 尺寸鲁棒性扫描（见 §4）
python scripts/quality_gate.py --size 320 # 换尺寸（会与基线 size 不一致而显式报警）
```

### 2.4 首跑即触红：门禁的第一次"逮捕"

门禁刚写完，`--quick --size 320` 立即触发红线：

```
❌ [红线] clean_fpr=0.0414 越界（要求 max 0.02）
```

同一种子同一底图，640² 时干净误报仅 0.53%，320² 竟达 4.14%。门禁只用了五分钟就抓到
了一个手工维护时代永远发现不了的缺陷——**检测器误报率强依赖输入分辨率**。

## 3. 分辨率依赖缺陷：定位

### 3.1 尺寸扫描（修复前）

| 尺寸 | gradient | textured | photo |
|---|---|---|---|
| 256 | 0.00 | **16.97** | **7.89** |
| 320 | 0.58 | **11.37** | **4.14** |
| 448 | 0.88 | 4.09 | 2.09 |
| 640 | 0.96 | 1.01 | 0.53 |
| 896 | 0.89 | 0.39 | 0.28 |

（干净图四预设平均误报率 %。gradient 底图无纹理挑战性不大；textured/photo 随尺寸单调恶化。）

### 3.2 策略隔离：元凶是谁

把 `detect_watermark_mask` 的 enable 开关逐条单独打开（preset=general），干净底图上：

| 尺寸 | translucent | corner | edge |
|---|---|---|---|
| 256 textured | **10.06** | 0.00 | 0.00 |
| 320 textured | **4.88** | 0.00 | 1.30 |
| 448 textured | 0.36 | 0.00 | 0.00 |
| 640 textured | 0.00 | 0.00 | 0.00 |

**元凶是半透明通路 `detect_translucent`**；corner/edge 几乎零贡献。

### 3.3 preset 拆分：不止一条通路

门禁口径对 4 个 preset 平均，按 preset 拆开看（textured）：

| 尺寸 | general | ai_faint_tiled | ai_grid | ai_logo |
|---|---|---|---|---|
| 256 | 10.06 | **29.98** | **17.76** | 10.06 |
| 320 | 6.14 | **22.45** | **12.01** | 4.88 |
| 448 | 0.36 | **10.08** | **5.56** | 0.36 |
| 640 | 0.00 | 2.41 | 1.63 | 0.00 |

结论：translucent（general/ai_logo 触发）、tiled 增强（ai_faint_tiled 触发）、
grid 通路（ai_grid 触发）三者在**小图上**全部制造误报；越小的图越严重。

### 3.4 根因：相对门限 vs 绝对噪点

各策略的最小连通域门限都是相对量：

```
min_area = int(整图面积 × min_area_ratio[× relax])
```

面积随分辨率平方缩放，于是门限随图像变小**急剧缩水**：

| 门限(px) | 256² | 320² | 640² |
|---|---|---|---|
| translucent（relax=1, ratio=0.0002） | 13 | 20 | 82 |
| tiled/grid（relax=0.25） | 3 | 5 | 20 |

而纹理噪点是**绝对像素尺寸**（与分辨率无关：合成纹理最细颗粒固定 ~8px、最粗倍频程
固定 ~128px）。小图上绝对噪点尺寸 ≥ 缩水后的相对门限，成群通过 → 再经 4px 形态学
膨胀放大 → 误报率飙升。大图门限大（82px+），绝对噪点够不着，误报自然趋零。
这条曲线与"输入分辨率"直接相关，是检测器**本身**的性质，不是合成底图的巧合。

## 4. 修复：把面积门限锚定到参考分辨率

### 4.1 思路

min_area 门限不该随输入分辨率缩水到"能放行绝对尺寸噪点"的程度。做法：给门限加一个
**绝对像素下限 = 参考边长图像上、同一占比对应的像素数**：

```
min_area = max( 绝对下限, int(整图面积 × ratio × relax) )
绝对下限 = int( DETECT_MIN_AREA_REF² × ratio × relax )
```

- 输入边长 ≥ 锚点（默认 640，与 benchmark/门禁口径一致）：相对值已 ≥ 下限 →
  **行为逐位不变**（translucent 640 相对=下限=81，tiled/grid =20=20）；
- 输入边长 < 锚点：被钳到同一绝对门限 → 等效于"先把小图放大到 640 再按比例过滤"，
  绝对尺寸噪点不再有机可乘。

### 4.2 落地

- `config.py` 新增 `DETECT_MIN_AREA_REF`（`_env_int`，默认 640，128~4096，可环境变量调）；
- `core/detector.py` 新增纯函数 `_min_area_px_floor(min_area_ratio, relax=1.0)`，并接入
  3 处 min_area 计算点：`detect_translucent`(relax=1)、`detect_tiled_translucent`
  (relax=0.25)、`detect_logo_watermark`(relax=1)。

**网格通路例外（重要）**：`detect_grid_watermark` 的 min_area **保持纯相对、不加锚点**。
原因是网格一旦被 ACF 周期判据确认，就是"结构化的强证据"，与散斑噪声性质不同；
且证据相交（阶段 53）后的网格掩码呈碎片状，单个碎片常小于 20px——按 speck 口径加
绝对下限会把真网格全部滤掉（实测 360²/12px 单元的强网格从检出直接变空）。实测证实
ai_grid 预设在小图上的误报本就来自该预设下并发的 translucent/tiled 通路（二者已锚定），
网格自身在阶段 53 的 evidence-AND 下已自收敛，故回退后误报扫描结果逐位不变。

## 5. 结果

### 5.1 干净图误报率 vs 尺寸（修复后）

| 尺寸 | gradient | textured | photo | 备注 |
|---|---|---|---|---|
| 256 | 0.00 | **0.80** | **0.14** | 修复前 16.97 / 7.89 |
| 320 | 0.58 | **1.96** | **0.37** | 修复前 11.37 / 4.14 |
| 448 | 0.88 | **1.30** | **0.72** | 修复前 4.09 / 2.09 |
| 640 | 0.96 | 1.01 | 0.53 | **与修复前完全一致** |
| 896 | 0.89 | 0.39 | 0.28 | 与修复前一致 |

全尺寸档 ≤ 2% 红线（`--sweep` 实测最大 1.96% @ 320 textured）。

### 5.2 对检测质量（带水印用例）的影响

640 基准上 corner_logo/grid 的精确率与召回**逐位不变**（门禁基线比对通过；
grid 三底图 38.6% / 33.3% / 42.7% 与阶段 54 发布值完全一致）。小图上 corner_logo
精确率随噪声组件被滤除而提升，召回不变：

| 尺寸·底图 | corner_logo 精确率（前→后） |
|---|---|
| 256 textured | 22.6 → **100.0** |
| 256 photo | 40.0 → **100.0** |
| 256 gradient | 100（召回 ~33-37%，合成 LOGO 绝对像素绘制、相对面积过大所致，见 §8.2） |

**grid 小图口径诚实声明**：ai_grid preset 是"多策略合并"口径（translucent/tiled/grid
并集），小图上各策略相互影响，合并精确率对配置敏感、数值不稳定（实测 4.8% → 35% →
34% 随 translucent 门限变动大幅跳动），**本阶段不对 grid 小图合并精确率做结论**；
已确认的是 640 口径零回归（gate 基线比对）且干净误报收敛不依赖 grid 自身（§4.2 网格例外）。

### 5.3 640 质量门禁基线比对

全量门禁（3 底图 × 4 用例 × opencv）对基线 `docs/assets/quality_baseline.json` 比对
**通过**：干净误报 0.83% · 精确率 47.7% · 召回 82.3% · IoU 46.0% · 平均 ΔPSNR +9.76 dB
（与阶段 54/56 公布的 README 数字一致，证明修复零扰动）。

## 6. 尺寸扫描护栏（常驻）

质量门禁新增 `--sweep` 模式：对 textured/photo × {256, 320, 448, 640} 四档扫描干净图
误报率，红线 `SWEEP_MAX_FPR = 2%`，把"分辨率依赖不许复发"固化为机器判定（纯函数
`evaluate_sweep`）。实测通过（最大 1.96%）。

## 7. 测试（tests/test_quality_gate.py，15 例）

- 判定逻辑（纯函数，零计算开销）：健康通过 / clean_fpr 越红线 / 精确率越红线 /
  ΔPSNR≤0 / 必赢用例缺失 / 基线漂移 / 变好不报警 / 配置不一致 / clean_fpr 用绝对容差 /
  多引擎去重 / None delta 不污染均值；
- 尺寸扫描判定：健康通过 / 小图误报反弹报警；
- 绝对下限语义：translucent relax=1 → 81px、tiled relax=0.25 → 20px、占比 0 → ≥1；
- 集成冒烟（slow，size=320 gradient × corner_logo）：真实链路跑通、ΔPSNR>0、
  精确率>0.5、缺必赢用例会报警。

全部 15 例通过。

## 8. 已知边界（诚实声明）

1. **896² 及以上 grid 召回归零**（修复前已存在、修复后未变）：合成网格点阵以**绝对
   像素**绘制（step=56/r=3），不随底图尺寸缩放；≥896 时相对证据太弱 + 折叠模板周期
   假设失效。真实 AI 图通常 512~1024，此边界需另立课题（配合"水印几何随分辨率缩放"
   的合成口径）单独收敛，本阶段不做。
2. **256² corner_logo 召回低**（~33-37%，修复前后一致）：角落 LOGO 是绝对像素绘制
   （34px 字 + 大内边距），在 256² 上相对面积过大，接近/超出检测器的 max_cross 与
   形状约束。属合成口径与真实场景不符的假象（真实角标在缩略图上同样不可辨认），
   非检测器回退。
3. tiled/grid 通路在 640 上仍有 ~1~2.4% 的"既有容忍"误报（faint_tiled 信息论极限
   附近），是 0.83% 均值预算的一部分，未因本阶段改变。
