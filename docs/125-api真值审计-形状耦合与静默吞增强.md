## 2. 三处真缺陷

### 缺陷 A（Stage 122 铁律，当前 live）
- **症状**：`api.py` `__main__` 自检用例 2 `assert out_a.shape == arr.shape` 未显式钉死环境敏感参数，在 `REAL_SUPERRES_ENABLED=True` 时输出被 2× 放大，形状断言失败。此前**无任何子进程守卫测试**能发现此崩溃。
- **定性**：真缺陷（非 by-design）。兄弟模块 `postprocess_service` 的 `__main__` 自检已因同因在 580–584 行显式 `config.REAL_SUPERRES_ENABLED = False` 修复（注释明言"会让下面每一条形状不变断言失败"），证明该耦合真实存在。
- **最小修复**：用例 2 调用显式传 `real_superres=False, superres=False`，使形状不变量与环境解耦（Stage 122 铁律"断言形状/行为不变必须显式入参"）。

### 缺陷 B（Stage 122 未修登记，静默契约背离）
- **症状**：`remove_watermark(poisson_blend=True / texture_transfer=True)` 透传到 `postprocess_service`，但部署闸 `POSTPROCESS_*_ALLOW=False` 默认会**静默跳过**（仅 INFO 日志），api 层零可观测信号——既无异常、也无警告，`RemoveResult` 无字段承载该信息。
- **最小修复**：`RemoveResult` 增 `warnings: list[str]` 字段（默认工厂，向后兼容）；`remove_watermark` 在"显式请求某增强但对应闸关闭"时，写入 `warnings` 并打 `WARNING` 级日志。

### 缺陷 C（预存 NameError，被 A 掩盖）
- **症状**：`remove_watermark_pdf` 的 `process_pdf(...)` 调用引用了未定义的 `preset`（814 行）与 `auto_preset`（815 行）——两者都不是该函数形参，运行即 `NameError`。此前因用例 2 先崩，掩盖了该 bug。
- **最小修复**：给 `remove_watermark_pdf` 补 `preset: Optional[str] = None` 与 `auto_preset: bool = True` 形参并透传（与 `process_pdf` 及其他 api 函数一致）。
