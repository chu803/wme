# 阶段 320c · 输出格式跟随输入（能力已就位，默认仍关）

> 日期 2026-10-23 · 产物 `config.OUTPUT_FMT_FOLLOW_INPUT`、`services/auto_pipeline._resolve_out_fmt`、
> `api.get_capabilities`、`tests/test_output_fmt_follow_input320c.py`（13 例）

## 一、为什么只做「能力」不改默认

阶段 319 实测：同一张 2048² 真图（输入 JPEG 1.65MB），输出 **PNG 7.68MB = 4.65×**、
JPG 1.86MB = 1.13×、WebP 1.65MB = **1.00×**；17 文件混合批量整批 62.4MB → 84.0MB（×1.35）。
「去个水印顺手把体积翻四倍」是交付面最容易被感知的负担。

但**默认值属于观感/无损承诺**：PNG 无损、JPG/WebP 有损。按项目既有约定
（318 的 `preserve_untouched` 同款处理），先把能力做成**默认关**，等产品拍板再翻。

## 二、实现

```
OUTPUT_FMT_FOLLOW_INPUT = False        # 默认关 = 与之前逐字节一致
```

解析优先级（`_resolve_out_fmt`）：

1. **显式 `out_fmt`**（用户 `-f` / API 参数）——永远最高；
2. 开关打开 ⇒ 按输入扩展名映射：
   `png→PNG`、`jpg/jpeg→JPG`、`webp→WEBP`、`tif/tiff→TIFF`、`avif→AVIF`、
   **`bmp→PNG`**（BMP 无对应输出格式，落无损 PNG）；
3. 未知扩展名 / 无扩展名 / 开关关闭 ⇒ **返回 None**，交给 `save_image` 既有的
   `DEFAULT_OUTPUT_FORMAT` 分支（这是「不偷偷改默认」的关键：None 不是"随便选"，
   而是"照旧"）。

能力经 `api.get_capabilities()["output_fmt_follow_input"]` 暴露，REST 客户端可先问后调。

## 三、验证（13 例）

- 映射表 10 例（含 `BMP→PNG`、未知→None、无扩展名→None）；
- **关闭时对任意扩展名都返回 None**——这条专门防「偷偷改了默认」；
- 显式 `out_fmt` 优先；
- **端到端真跑** `process_file`：同一张 JPEG 输入，开关关 → 输出 `*.png`；
  开关开 → 输出 `*.jpg` 且文件非空。

## 四、诚实边界

- **JPEG/WebP 输出会再经历一次有损编码**（处理本身已重编码一次，无代际叠加）。
- 只覆盖**图片**路径；PDF/视频的输出格式由各自服务决定，不受此开关影响。
- 默认仍为 **PNG**：要不要翻默认（或做成设置页选项）仍需拍板——翻默认会让老用户
  拿到的文件从 PNG 变成 JPG，是可见的产品行为变化。
- 未在 UI 暴露；目前只能经 `WME_OUTPUT_FMT_FOLLOW_INPUT=true` 或配置文件开启。
