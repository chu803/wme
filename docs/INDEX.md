### 320e · 设备选择惰性化：OpenCV 引擎不再为不用的 GPU 付钱（2026-10-23）

守卫 4 例（OpenCV 不选 / 模型仍选 / 显式 device 不再选 / 逐字节等价）。

### 323 · R2b 贴地飞行：三条路的实测取舍 + 单图最坏净伤害红线（2026-10-25）

322a 的 R2b 余量只有 **0.010 / 0.002**，而中位数的结构性缺陷是「15 例里 6 例被擦坏、中位仍可为正」

### 324 · 平铺类修复上界 spike：一类值得做、一类结构性没戏（2026-10-25，取证 + 一句文案）

323 只剩一句待验证的归因：「平铺效果差是因为检测没找到墨迹」。本 spike 量**反过来的那一半**——
把构造真值掩码当「检测完美」喂给同一条管线（判读规则开跑前写死：<0.30 关线 / ≥0.50 值得做）。
30 用例双臂同轮（369s）结果**两类分开**：
`grid` oracle 中位 **0.749**（15/15 ≥0.571）而自动路径只有 0.002 ⇒ **纯检测瓶颈**，值得做；
`faint_tiled` oracle 中位只有 **0.026**、6/15 张被**擦得更差**（最差 −0.691）⇒ **修复瓶颈且结构性**：
α≈8.6% 的平铺文字自身误差仅 10~14，而修复要换掉 6% 画面，重绘差异与之同量级，
「擦掉它」在误差上不可能净赚 ⇒ 划进「别再试」。
真正的门槛在**数据不在代码**：真实图集 57 条 GT **100% 是角标**，平铺没有任何真实真值，
现在去做召回只能拿合成点自证（322b 刚付过学费）⇒ `grid` 那条标注**阻塞在采集**（P0 清单）。
诚实边界：oracle 走 manual 默认参数、与臂 A 预设不同，所以 0.749 读作「本管线内上界」而非理论上限；
3.2 的**符号**比数值更硬（负残留与预设无关）；两类水印都是合成的，数值只用于「值不值得投」的判断。
