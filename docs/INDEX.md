### 346 · 门禁那 94.9% 是重编码噪声：给「改动占比」加容差，并让 `outside_diff` 名副其实（2026-10-26）

欠账兑现：上一轮我说「看不懂的数字不当作通过」，这轮查了。用 `media_gate` 自己的构件复现同一场景，
把非水印区 |差| 直方图打出来：**48.8% 的像素只差 1~3 级、45.6% 差 4~8 级、≥17 级只有 0.3%**，
均值差 **3.83/255**（肉眼不可见）⇒ 视频/PDF **必须重新编码**，压缩让几乎每个像素动 ±1~3；
而门禁判「改动占比」用的是「差 > 0 即算改动」⇒ 这个数**必然接近 100%**。**那是指标失真，不是损伤。**
顺带发现那个名字本来也不准：`outside` 是「整幅图把 bbox 区置零」，`outside_diff` 其实是
**全图均值被稀释后的值**而不是「非水印区均值」⇒ 改成用掩码取真正的非水印区像素统计，同名同义。
改法（**红线一条没动**，只修诊断可信度）：新增 `DIFF_TOLERANCE=8`，改动占比按 `>8` 判定；
docstring 补容差与实测依据。同一场景修前 vs 修后：视频非水印区改动 **94.9% → 3.0%**、
全图改动 97.5% → 3.7%；PDF 第 2 页 61.8% → 1.5%。**把失真指标当真去改产品会走偏**（同 #308 的教训）。
守卫 4 例，关键是「容差不许把真损伤藏起来」：bbox 内 ±30 仍必须被算成改动、bbox_diff>20；
另有「容差常量在范围内且 diff_stats 真的用它、没有 >0 残留」的接线守卫。`media_gate` 修后 rc=0。
写测试踩两坑（已写进注释）：① 桩返回 int16 被 `cv2.absdiff` 拒（OpenCV 要求显式输出类型）；
② 画布 64px 时 `BBOX_DILATE=48` 把整幅图罩进 bbox 区 ⇒「非水印区」零像素、指标恒 0
⇒ **测区域类指标前先确认那个区域真的有像素**。
