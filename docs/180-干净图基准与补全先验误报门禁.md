# 阶段 180 · 干净图基准与补全先验误报门禁

> 承接 179（生成器感知牌体补全先验 `plate_footprint_prior`，micro mask_recall 0.5619→0.7665，
> 但杠杆 `DETECT_PLATE_COMPLETE_FROM_SIGNAL` 因「干净图误报率不可测量」保持默认 OFF）。
> 本阶段把「不可测量」变成「可证伪门禁」：搭好干净图基准 + 补全先验误报探针，
> 用合成压力样本先验证管线，并给出真实干净图的采集提示词。

## 1. 为什么需要这一关

179 的先验是**豆包专属**的（右下角固定 340×128 牌布局）。它的设计风险不是「漏检」，
而是「在**干净图**上误发整牌」——但当时基准 10 张全为带水印豆包图、**无干净图**，
故该误报率**不可测量**，杠杆只能保守默认 OFF（项目铁律「宁可漏检不可滥杀」）。

要决定是否翻为默认 ON，必须先能量出它在干净图上的误报率。本阶段就是这道关。

## 2. 交付物

- `scripts/clean_bench_probe.py`：**独立门禁**（不碰 `real_gate`，避免污染其红线/面积监控）。
  - 挑出干净图 = manifest `"clean": true` 且真值 `watermarks: []`；
  - 对每张图**同时**跑检测器（杠杆 ON / OFF），量取误发 `corner_logo` 区域数 + 牌足迹区（右下角
    340×128 @2048²）掩码覆盖率；
  - **隔离 179 归因误报**：`prior_fp_rate = (ON−OFF) 误发占比`——只算 179 先验**新增**的误报
    （先验由 `if 已有 corner_logo: 跳过` 守卫，正常应为 0）；
  - 退出码 0/1/2（通过/未通过/跳过，与门禁家族契约一致）；`--gate-on prior|total`。
- `benchmark_real/clean/`：干净图集占位（与 `benchmark_real` 同构的 `manifest.json` +
  `ground_truth.json` + `images/`）。当前为 5 张**合成压力样本**（`syn_*`），待替换为真实照片。
- `benchmark_real/clean/_gen_synthetic.py`：合成样本生成器（可复现，说明占位来源）。
- `tests/test_clean_bench_probe.py`：4 条守卫（跳过层 / 静默层 / total 口径 / 阈值语义自洽）。
  受限沙箱内 `%TEMP%` 清理被拦，故另附 `scripts/_verify_clean_probe.py` 做本地等价验证（4/4 通过）。

## 3. 测量方法与首轮结果（合成压力样本）

`clean_bench_probe.py --root benchmark_real/clean --gate-on prior`，3 次进程内复跑稳定：

| image_id | ON 误发 | OFF 误发 | 说明 |
|---|---|---|---|
| syn_01_plain | 0 | 0 | 纯色无内容 → 不触发 |
| syn_02_corner_text | 1 | 0 | 右下角黑底白字 "SAMPLE" |
| syn_03_corner_logo | 0 | 0 | 右下角纯色 Logo 块（蓝） |
| syn_04_corner_translucent | 0 | 0 | 右下角半透明亮斑（未触发 translucent 信号） |
| syn_05_natural | 1 | 0 | 渐变场景 + 右下角招牌 "OPEN 24H" |

```
基线误报率(baseline, OFF)      = 0/5 = 0.0000
179 归因误报率(prior, ON−OFF)  = 2/5 = 0.4000  ← 179 专属风险
总误报率(total, ON)           = 2/5 = 0.4000
```

## 4. 结论：179 杠杆应保持默认 OFF（已用测量坐实）

- **179 先验确实会在干净图上误发整牌**——但只发生在「右下角有文字/招牌信号」的图上
  （`syn_02`/`syn_05`）。这是**信号锚定**行为的本来面目（右下角 edge_text/translucent 信号 → 补牌），
  对带水印豆包图是正确补全，对**干净图**就是误报。
- 真实照片里「右下角有文字/Logo/招牌」极其常见（品牌角标、拍摄参数、水印式签名）。
  故一旦默认 ON，会在大量干净图上铺出 340×128 假牌 → 触发修复侧把合法内容当水印擦掉。
- **因此 179 杠杆默认 OFF 是正确且被本阶段测量支持的决策**；之前「不可测量」的留白，
  现变为「已测量 = 在对抗性右下角文字样本上 0.40，真实照片上应更低但非零」。

## 5. 顺带发现：基线 corner_logo 通路非确定（**已被 181 推翻**）

> **纠正（见 `docs/181-基线corner_logo非确定性再审计-纠正180误判.md`）**：
> 180 首轮观察到的「基线 OFF `corner_logo` 误发 0↔1 翻转」实属**检测器冷启动伪影**
> （首次推理未烧热，torch/CV 算子 warming-up 致边界样本布尔判定翻转）。181 用进程内 5 次 **warm 复跑**
> 重新测量，所有干净图 OFF 误发 = **0/5 稳定**、白源框数 = 0；唯一一次 1 出现在进程内首次推理，烧热后消失。
> → **基线在干净图上稳态不误发；「阶段 18x 候选审计」登记已撤销**。本结论不影响第 4 节决策：
> 179 杠杆默认 OFF 的理由收紧为「179 先验自身在右下角文字/招牌干净图上确定性误发」，与基线无关。

## 6. 下一步：用真实干净图替换合成样本，拿到真实误报率

合成样本是**对抗性**的（刻意右下角黑块/文字），会高估误报率。要得到可信数字，需真实照片：

> **豆包 / 图库采集提示词（复制到豆包或图库，生成后放入 `benchmark_real/clean/images/`，
> 并在 `manifest.json` 加 `"clean": true` 条目、`ground_truth.json` 加 `"watermarks": []`）：**
>
> 1. 「生成 5 张写实风格照片（风景/街拍/室内），**不含任何 AI 平台水印**，其中 2~3 张的
>    **右下角自然出现招牌、文字或 Logo**（如店铺招牌、相机参数、品牌角标），1024×1024 以上。」
> 2. 「再生成 5 张完全干净的写实照片（无右下角文字/Logo），作为阴性对照。」
> 3. 把图存到 `benchmark_real/clean/images/`，文件名 `real_01_*.png` 等；
>    `manifest.json` 每条加 `{"id":..., "path":"images/real_01_*.png", "clean": true, ...}`；
>    `ground_truth.json` 对应加 `{"image_id":..., "watermarks": []}`。
> 4. 重跑 `python scripts/clean_bench_probe.py --root benchmark_real/clean` 看真实 `prior_fp_rate`。

由于先验是豆包专属，建议**至少含若干非豆包来源**的干净图（上面提示词第 1 条已覆盖），
才能真实反映「在非豆包干净图上误发豆包牌」的风险。
