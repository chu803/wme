# 382 · 界面说「auto=有模型用 LaMa」，代码却是 auto 永远走 OpenCV（2026-11-05）

## 怎么发现的

做安装态巡检时，顺手看了修复完成后的状态栏，发现两处**承诺与实际不一致**：

1. 状态栏写「✅ 处理完成（**引擎：AUTO**）」——"AUTO" 是用户**选的标签**，
   不是**实际用的引擎**；用户无法知道这次到底跑的是 OpenCV 还是 LaMa。
2. 「修复引擎」控件下的说明写「auto=**有模型用 LaMa**，否则降级 OpenCV」。

而代码那边（`config.py` / `core/inpainter.py`）：

- `INPAINT_AUTO_PREFER` 默认 **opencv**；
- `_resolve_auto_engine()` 只有在偏好是 `lama` 且模型就绪时才返回 `lama`；
  ⇒ **auto 实际永远走 OpenCV**，哪怕 205 MB 权重已经下载好。

阶段 55 当年正是**主动**把默认从 LaMa 改成 OpenCV 的（合成数据上 OpenCV 更稳、
更快、不幻觉），README §2 也照实写了；**只有界面文案没跟上**。
于是用户看到"有模型用 LaMa"的说明、装好权重后期待更好的效果，实际拿到的却是 OpenCV。

## 修法（改文案 + 显示实际引擎，不改行为）

行为是阶段 55 依实测定下的取舍，不动它；改的是**让界面说真话**：

1. `core/inpainter.resolve_effective_engine(requested)`：公开「实际会用哪个引擎」的解析，
   与 `inpaint()` 的选择逻辑**同源**（`inpaint()` 改为调用它，避免两处逻辑漂移）。
2. 新增 `ui/engine_display.py`：返回 `(展示用引擎名, 补充说明)`。
   - 展示的是**实际引擎**（auto 落到 OpenCV 就显示 `OPENCV`）；
   - 落回 OpenCV 时追加一句原因：
     权重未就绪 →「LaMa 权重尚未就绪，效果弱于 LaMa」；
     权重已就绪但按配置默认 →「auto 按配置默认用 OpenCV…想要 LaMa 请显式选 lama」。
3. 文案订正（zh/en 各两处）：「auto=按配置偏好选择（默认 OpenCV…）」，
   并给出 `WME_INPAINT_AUTO_PREFER=lama` 这条可切换的路径。

## 验证

- 新增守卫 `tests/test_engine_honesty382.py`（6 条）：auto 的解析随配置偏好（默认 opencv、
  偏好 lama 且模型就绪才 lama、模型缺失回退 opencv）；显式引擎原样返回；
  展示层给出实际引擎与对应说明；单图页完成文案含 `OPENCV`、**不含** `AUTO`；
  中英文案不得再出现「有模型用 LaMa / LaMa if model present」。
- 真机（源码态 7894）：引擎说明已显示新文案；走完「示例 → 检测 → 修复」，
  状态栏变为
  `✅ 处理完成（引擎：OPENCV）…（auto 按配置默认用 OpenCV：更快、更保守、不脑补内容；想要 LaMa 请在「修复引擎」里显式选 lama。）`。

## 边界

- 没有改变任何修复行为或质量指标；纯文案与展示层修正。
- 显式选 `lama` 且权重缺失时，引擎 setup 仍会**显式报错**（不静默换引擎），本轮未改这条。
- 「auto 默认 OpenCV」对期待 LaMa 的大水印用户仍是能力上的短板——那是阶段 55 的取舍，
  要改需另开一轮基准，不在本次范围。
