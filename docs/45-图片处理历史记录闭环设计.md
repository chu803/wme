# 阶段 45：图片处理历史记录闭环（单图 / 自动页接入历史）

## 1. 动机与定位

阶段 1–44 已把「历史记录」做成了全站级的「浏览 / 对比 / 下载 / 重新处理 / 删除」中枢，但**历史数据的来源并不对称**：

| 处理入口 | 是否登记历史 | 落盘原图 | 可重新处理 |
|---------|------------|---------|-----------|
| 批量页（tab_batch） | ✅ `add_success` | ✅ 上传文件复制 | ✅ |
| 媒体页 · 视频（tab_media） | ✅ `add_video_record` | ✅ | 引导回视频页 |
| 媒体页 · PDF（tab_media） | ✅ `add_pdf_record` | ✅ | 引导回媒体页 |
| **单图页（tab_single）** | ❌ **从未登记** | — | — |
| **自动页（tab_auto）** | ❌ **从未登记** | — | — |

单图、自动是**最高频**的两个图片处理入口，它们的成功结果此前**处理完即丢失**，既无法在历史页回访、对比、下载，也无法「重新处理」。这与「保存近期处理记录，不用重复上传图片」的缓存设计初衷相悖。

阶段 45 的目标：把 `tab_single` / `tab_auto` 的成功结果**闭环进历史记录**，与批量页共用 `add_success` 同一套基础设施（缩略图、哈希去重、重新处理），消除图片处理的历史缺口。

## 2. 核心难点

批量 / 媒体页处理的输入是**文件路径**（`File` 组件 / `fitz` 文档 / 视频文件），`add_success` 通过 `save_upload(original_path, ...)` 把源文件复制进 `UPLOAD_DIR` 即可供「重新处理」读取。

但单图 / 自动页用的是 **`ImageEditor`（`type="numpy"`）**——用户涂涂抹抹后拿到的是**内存中的 RGB numpy 数组，没有文件路径**。因此历史记录的 `original_path` 必须先把数组**落盘**才能得到。

解决思路：扩展 `add_success`，新增 `original_arr` 关键字参数；传入数组时由缓存层负责把它落盘到 `UPLOAD_DIR`，与原文件复制路径**语义一致**。

## 3. 设计

### 3.1 `services/cache_service.py` —— 扩展 `add_success` 支持内存原图

- 导入 `make_unique_path`（来自 `utils.path_helper`）。
- 新增模块级函数 `_materialize_original(arr, original_name)`：
  - `ensure_dirs()` 后，把 RGB 数组 `cv2.cvtColor(arr, RGB2BGR)` 写盘到 `UPLOAD_DIR` 下唯一化 `.png`；
  - 返回稳定路径，供「重新处理」直接读取。
- `add_success` 签名变更（**保持向后兼容**）：
  ```python
  def add_success(
      self,
      original_path: Optional[str | os.PathLike],   # 改为 Optional
      result_arr: np.ndarray,
      *,
      original_name: str,
      mode: str = "auto",
      engine: str = "auto",
      params: str = "",
      file_hash: Optional[str] = None,
      original_arr: Optional[np.ndarray] = None,     # 新增：内存原图
  ) -> Optional[HistoryRecord]:
  ```
  - `original_arr is not None` → 优先走 `_materialize_original` 落盘内存数组；
  - 否则维持既有 `save_upload(str(original_path), ...)` 行为（批量页不受影响）；
  - `file_hash` 为空时自动从落盘后的原图 `compute_file_hash(saved_src)`，保证去重一致；
  - 缩略图仍由 `result_arr` 生成，原图 `kind` 默认 `"image"`。

### 3.2 `ui/tab_single.py` —— 单图处理登记历史

- 导入 `from services.cache_service import get_cache`，模块级 `_CACHE = get_cache()`。
- `process_single` 新增 `record: bool = True` 形参（默认登记）。
- 在「保存成功（`out_path` 已知）」之后、生成拼接对比图之前，插入登记块：
  ```python
  if record:
      try:
          params = f"引擎={engine} 力度={strength} 降噪={denoise} 膨胀={dilate} 平滑={feather} 阈值={threshold}"
          rec = _CACHE.add_success(
              None, result,
              original_name=f"single_{ts}",
              mode="manual", engine=engine, params=params,
              original_arr=image,
          )
          if rec is not None:
              _CACHE.update_result_path(rec, out_path)
      except Exception as exc:  # 历史失败不影响主流程
          log.warning("单图历史记录登记失败（不影响主流程）：%s", exc)
  ```
- 返回形状不变（5 元组）。

### 3.3 `ui/tab_auto.py` —— 自动页处理登记历史

- 同样导入 `_CACHE = get_cache()`。
- `process_auto_repair` 新增 `record: bool = True` 形参。
- 在「保存成功」之后插入与单图同构的登记块，`original_name=f"auto_{ts}"`、`mode="auto"`。

### 3.4 `ui/tab_history.py` —— 重新处理禁止重复登记

- `reprocess` 内部调用 `process_auto_repair(...)` 时显式传入 `record=False`。
- 原因：历史页「重新处理」已经**就地更新既有记录**（`update_record(rec)`），若 `process_auto_repair` 仍走登记分支，会造成「一次重处理 = 一条新历史 + 更新旧记录」的重复数据。通过 `record=False` 复用既有记录，零冗余。

## 4. 接线关系

```
tab_single.process_single  ─┐
                           ├─► _CACHE.add_success(None, result, original_arr=image)
tab_auto.process_auto_repair ─┘        │
                                       ├─► _materialize_original(image) → UPLOAD_DIR/<name>.png
                                       ├─► make_thumbnail(result) → THUMB_DIR/<name>.png
                                       └─► HistoryRecord(kind="image", file_hash=auto)
                                       _CACHE.update_result_path(rec, out_path)

tab_history.reprocess ─► process_auto_repair(..., record=False)  # 仅更新既有记录
```

## 5. 测试

`tests/test_image_history_record.py`（零 torch，全部落盘指向临时目录）：

- 服务层（6 例）：`add_success` 含 `original_arr` 的落盘 / 哈希自动计算 / 缩略图落地 / `original_arr` 优先于 `original_path` / 关闭缓存返回 `None` / 既有 `original_path` 调用兼容。
- 界面层（3 例）：`process_single` 与 `process_auto_repair` 在成功路径调用 `add_success` 并传入 `original_arr`（`mode` 分别为 `manual` / `auto`，`original_name` 前缀 `single_` / `auto_`），`record=False` 时不登记。

## 6. 影响面与边界

- **仅新增**图片处理的历史登记能力，不改动批量 / 媒体既有登记逻辑；`add_success` 旧调用方式完全兼容。
- 单图 / 自动页历史记录的 `original_name` 为合成名（`single_<时分秒>` / `auto_<时分秒>`），因为 `ImageEditor` 不携带原始文件名；缩略图与对比预览足以辨识内容。
- 历史页已有的「图片记录对比查看器 / 重新处理 / 删除 / 筛选 / 批量导出」对单图 / 自动记录**天然生效**（均按 `kind="image"` 处理），无需额外 UI 工作。
- 单图 / 自动的 `add_success` 失败仅记日志、不影响主处理流程（与批量页一致）。
