# 阶段 41 设计文档 · 历史记录分类筛选与按类型批量导出

> 项目：AI 智能水印擦除工作台
> 日期：2026-08-13
> 目标：补齐「多类型历史」的管理闭环——历史页已能归档 image/video/pdf 三类结果（阶段 37/38/40），
>       但画廊无类型筛选、打包导出不支持按类型过滤。本阶段新增「类型筛选」与「按当前筛选打包下载」。

---

## 1. 背景与动机

- 阶段 37 落地**视频**历史记录（首帧缩略图 / 元信息 / 预览）。
- 阶段 38 落地**图片**前后对比查看器（批量页 + 历史页）。
- 阶段 40 落地 **PDF** 历史记录（首页缩略图 / 页数 / 体积 / 下载）。
- 现状：历史页画廊把三类混排，且「导出 ZIP」（`export_history_as_zip`）一次性打包**全部**成功结果，
  用户无法只挑出所有 PDF 或所有视频带走。

**核心缺口**：历史记录缺乏「按类型浏览」与「按类型批量导出」能力。

---

## 2. 设计目标

1. 历史页提供**类型筛选下拉**（全部 / 图片 / 视频 / PDF），即时过滤画廊与统计。
2. 提供**按筛选打包下载**按钮：仅把当前筛选类型下的成功结果打包为 ZIP。
3. 全程零 torch、零 gradio 依赖（服务层 / 缓存层），UI 仅做接线。
4. 不改既有 `list_records()` / `export_history_as_zip()` 的默认行为（默认 = 全部），保证旧调用兼容。

## 3. 改动清单

### 3.1 `services/cache_service.py`
- `HistoryRecord.list_records(self, kind: Optional[str] = None)`
  - 旧签名 `list_records()` → 新增可选 `kind` 参数（默认 `None`）。
  - 实现：先按时间倒序，再在 `kind is not None` 时按 `getattr(r, "kind", "image") == kind` 过滤。
  - 既有调用方（不含 kind）行为不变。

### 3.2 `services/export_service.py`
- `export_history_as_zip(cache, *, fmt=None, quality=None, out_zip=None, kind: Optional[str] = None)`

  - 过滤逻辑下沉到缓存层，导出层仅消费已过滤记录，零额外依赖。

### 3.3 `ui/tab_history.py`

## 4. 关键决策与边界

- **筛选与画廊/导出强绑定**：筛选只影响「看什么」与「打包什么」；「修复报告（HTML/PDF）」保持全量叙述，
  避免一次改动面过大。后续若需报告也按类型，可同样透传 `kind`。
- **`"all"` 语义**：UI 下拉值为 `"all"`，到服务层统一映射为 `kind=None`（即不过滤），避免到处判断字符串。
- **缩略图缺失保护**：`load_gallery` 仍按 `thumb_path or result_path` 且校验存在性，过滤不影响该逻辑。
- **导出空结果**：`export_history_as_zip` 在无有效文件时抛 `FileNotFoundError`，UI 捕获后给出友好提示而非报错。
