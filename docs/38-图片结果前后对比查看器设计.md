# 阶段 38 · 图片结果前后对比查看器设计文档

> 目标：把阶段 31 的「拼接 / 滑块 / 热图」三模式对比从单图页、自动页**下沉为全站通用能力**，
> 并落地到**批量页**与**历史页**——这两个此前只有静态拼接缩略图的入口，如今也能逐条点选、
> 切换模式、看客观差异摘要、一键导出原始分辨率对比图。
> 约束：服务层零 gradio/torch 依赖、可完整测试；分层铁律不变（`ui → services → core → utils → config`）。

---

## 1. 背景与缺口

阶段 31 已把三模式对比（拼接 / 滑块 / 热图）落到单图页与自动页，但其渲染逻辑直接写在界面回调里
（`tab_single.on_enhance` / `tab_auto.on_enhance` / `tab_media.run_video_compare` 三份近重复代码）。
阶段 31 文档的「已知边界」明确写下：

> 批量/历史页未加交互滑块：两页以画廊缩略图（静态 `make_compare_array`）为主，
> 无独立 `orig_view`/`result_view` Image 组件；强行加交互需重构画廊 UX，故保留静态拼接。

这导致一个明显短板：**跑完一整批、或翻历史记录时，想逐张核查修复质量，只能把结果文件翻出来自己比**。
本阶段解决该缺口，且**不重构画廊 UX**——做法是把「查看器」做成一份可复用组件（Accordion），
放在画廊下方，由画廊点选事件驱动，因此单图/批量/历史三处行为完全一致。

## 2. 改动清单

### 2.1 `config.py`（复用既有参数，无新增）
阶段 31/导出已存在、本阶段直接复用：
- `UI_COMPARE_DEFAULT_MODE: Final[str]`（默认 `concat`）——查看器初始模式。
- `UI_COMPARE_MAX_SIDE: Final[int]`（默认 1280）——网页内嵌预览的等比缩放上限，避免超大图 base64 拖卡浏览器。
- `EXPORT_COMPARE_GAP: Final[int]` / `EXPORT_COMPARE_LABEL: Final[bool]`——落盘对比图的白边与标注开关。

### 2.2 新增 `services/compare_service.py`（纯服务层，零 gradio/torch）
把三模式渲染从界面回调**下沉为全站唯一实现**：
- `MODE_CONCAT / MODE_SLIDER / MODE_HEATMAP` 与界面 Radio 稳定 value 一一对应。
- `normalize_mode(mode)`：把任意输入规整为合法模式（非法/空回退 `UI_COMPARE_DEFAULT_MODE`，其本身非法最终落 `concat`）。
- `shrink_for_view(arr, max_side)`：长边等比缩到 `≤ max_side` 供网页预览；仅影响「看」，导出走原始分辨率。
- `align_pair(orig, result)`：以**原图尺寸**为基准把结果缩回，保证滑块揭示与热图像素级对齐（真实超分放大结果也归一）。
- `load_pair(orig_path, result_path, *, align=True)`：按路径加载并可选对齐；任一缺失/解码失败返回 `None`（界面据此提示而非炸）。
- `render_compare_html(orig_arr, result_arr, mode, *, before_label, after_label, heatmap_caption, max_side)`：三模式渲染唯一实现。
- `render_pair_html(orig_path, result_path, mode, **kwargs)`：画廊点选主入口（路径 → HTML）。
- `summarize_pair(orig_path, result_path, *, changed_threshold=8)`：差异摘要（改动像素占比 / 平均差异 / 峰值 / 是否超分放大），给查看器客观数字依据。
- `export_pair_compare(orig_path, result_path, *, gap, label)`：落盘拼接对比图（PNG，原始分辨率）到 `EXPORT_DIR`，复用 `export_service.export_compare`。
- 依赖仅 `core` / `utils` / `config` / 同层 `export_service`，**严禁 import ui 与 gradio**（与 `export_service`/`video_export` 一致）。
- `__main__` 自检：模式规整 / 配对加载与对齐 / 三模式渲染 / 差异摘要 / 落盘导出 全部通过。

### 2.3 新增 `ui/compare_view.py`（界面层，唯一允许 import gradio 处）
- `CompareViewer` dataclass：一套查看器组件句柄集合（`pair_state` / `mode` / `html` / `summary` / `refresh_btn` / `export_btn` / `file`）。
- `build_compare_viewer(elem_prefix, *, open_, show_title)`：构建一套查看器，返回句柄；`elem_prefix`（`"batch"`/`"history"`）保证同页多份不撞 DOM id；模式切换/手动刷新/导出均在此接线（`mode.change` 与 `refresh_btn.click` → `render_pair`；`export_btn.click` → `export_pair`）。
- `render_pair(pair, mode) -> (html, summary)`：查看器核心回调；未选中 → 提示先点选；缺原图/结果 → 提示文件缺失；渲染失败 → 提示切拼接重试。
- `export_pair(pair) -> (path, msg)`：导出当前选中条目对比图。
- `format_summary(name, orig_path, result_path)`：组装「条目名 + 差异摘要」Markdown（含超分放大提示）。
- 选中状态由调用方持有（各页自己的「索引 → 配对」映射），本模块只通过 `gr.State` 接收 `(原图, 结果, 名称)` 三元组，故同页可建多份互不干扰。
- 不 import 任何 `tab_*` 模块，避免循环依赖。
- `__main__` 自检：未选中 / 缺文件 / 三模式+摘要 / 导出 全部通过。

### 2.4 `ui/tab_batch.py`（批量页 · 接入查看器）
- 模块级 `_batch_pairs: list = []`：批量运行成功后按画廊同序登记 `(原图, 结果, 名称)` 三元组（`run_batch` 末尾 `append`，`clear` 时 `.clear()`）。
- `on_gallery_select(evt)`：索引规整（兼容 `(row, col)` 元组）→ 越界/无产出复位；否则从 `_batch_pairs` 取配对 → `render_pair` → 返回 `(pair_state, html, summary)` 三元组。
- `on_gallery_select_with_mode(evt, mode)`：同上但沿用用户当前所选模式（供查看器 Radio `.change` 联动）。
- `build_batch_tab` 结果区新增 `batch_viewer = build_compare_viewer("batch", open_=False)`；画廊 `.select` 输出 `batch_viewer.pair_state/html/summary`。

### 2.5 `ui/tab_history.py`（历史页 · 接入查看器）
- `on_select(evt, mode=None)`：六元组（前三项与阶段 37 语义一致，后三项为阶段 38 新增）——`(详情, 下载路径, 视频路径 or None, 对比配对 or None, 对比 HTML, 摘要)`；图片记录取 `(original_path, result_path, original_name)` 渲染，视频记录返回 `None` 并引导到媒体页抽帧对比。
- `reprocess_and_refresh(rec_id, engine, strength, denoise, compare, mode)`：五元组 `(信息, 画廊, 对比配对 or None, 对比 HTML, 摘要)`；**重处理失败 / 记录为视频 / 原图或结果文件缺失 → 查看器复位为「未选择」态**（详见 §6 修复点 2）。
- `build_history_tab` 详情区新增 `hist_viewer = build_compare_viewer("history", open_=False)`；`gallery.select` 与 `reprocess` 按钮均输出 `hist_viewer.pair_state/html/summary`。

### 2.6 `utils/i18n.py`

## 3. 数据流（图片结果闭环）

```
批量页 run_batch 成功
  └─ _batch_pairs.append((原图, 结果, 名称))（与画廊同序）
        └─ 画廊.select → on_gallery_select[_with_mode] → pair_state + 对比 HTML + 摘要

历史页 load_gallery（缩略图入画廊）
  └─ gallery.select → on_select（六元组）→ 详情 + 下载 + 对比配对 + HTML + 摘要
        └─ 重新处理 → reprocess_and_refresh（五元组）→ 新结果刷进查看器 / 异常复位
```

查看器内部：`pair_state` 变更（点选 / 模式切换 / 刷新）→ `render_pair` → `compare_service.render_pair_html` → `load_pair`（对齐）→ `render_compare_html`（三模式）→ `gr.HTML`；导出 → `export_pair_compare` → `gr.File`。

## 5. 兼容性 & 风险

- **不破坏既有单图/自动页**：原 `tab_single.on_enhance` / `tab_auto.on_enhance` 仍独立工作；本阶段新增的是**通用查看器组件**，与它们的交互滑块并存不冲突。
- **零 torch**：渲染走 OpenCV + NumPy，沙箱无 torch 完全可测；真实超分仅影响结果尺寸（查看器已对齐缩回）。
- **旧数据兼容**：历史记录 `original_path`/`result_path` 缺失时查看器安全复位（见 §6 修复点 2），旧图片记录照常展示。
- **性能**：查看器按需渲染（点选/切模式才生成），预览走 `UI_COMPARE_MAX_SIDE` 缩放，导出才用原始分辨率，开销可控。

## 6. 本阶段修复的两个缺陷（实现收尾）

阶段 38 的实现代码在「下一阶段」接续时已基本就位，但存在两个缺陷，本阶段一并修复：

1. **测试辅助函数 `_make_upscaled_pair` 的类型错误**：原实现用 `tmp_path / "原图.png"`，但被测调用处传入的是 `str`（`tempfile.mkdtemp()` 或 `str(tmp_path)`），触发 `TypeError: unsupported operand type(s) for /: 'str' and 'str'`，导致 4 个用例恒失败。改为 `os.path.join(str(tmp_path), ...)`，与同文件 `_make_pair_local` 保持一致。
2. **`tab_history.reprocess_and_refresh` 缺失文件不复位**：原实现仅当 `original_path` 为**空字符串**时复位查看器，未覆盖「路径存在但文件已被移动/删除」的真实场景，与其 docstring「原图缺失时复位」相悖，导致 1 个用例失败。改为同时校验 `_os.path.isfile(original_path)` 与 `_os.path.isfile(result_path)`，缺失即复位为「未选择」。

修复后 `tests/test_compare_viewer.py` 由 5 失败转为 **17/17 通过**。
