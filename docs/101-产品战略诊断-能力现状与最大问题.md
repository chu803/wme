# 产品战略诊断：能力现状、最大问题与解决办法

> **不是开发阶段**——这是一次对「产品离可用还有多远」的取证式评估（对应 `docs/92` 的同类文档）。
> 所有数字取自**现场复算**（`config.py` / `README.md` / 两条门禁的实测输出），不是记忆或推断。
> 复算日期：2026-09-19。

## §1 先回答「它能干啥」（已建成的事实）

### 1.1 端到端链路（已跑通）

| 环节 | 现状 |
|---|---|
| 输入格式 | PNG / JPG / JPEG / JPE / JFIF / WEBP / BMP / TIF / TIFF（白名单准入） |
| 媒体类型 | 图片 + **视频** + **PDF** |
| 检测预设 | **10 个**：`general` / `ai_tiled` / `ai_signature` / `ai_corner` / `ai_text_heavy` / `ai_faint_tiled` / `ai_grid` / `ai_gradient` / `ai_logo` / `ai_multi` |
| 预设选择 | 手动选 + **自动推荐**（`core/preset_recommender`，按残差/周期性/角标轮廓/文字密度归因） |
| 修复引擎 | **2 个可切换**：OpenCV 局部扩散、LaMa 深度模型；**插件机制**可挂自定义引擎 |
| 掩码 | 自动掩码 + **手动掩码编辑** + 掩码文件夹批量 |
| 输出格式 | PNG / JPG / WEBP / TIFF / AVIF；保留 alpha、ICC；JPG 合成背景；**不写回 EXIF** |
| 管理 | 历史记录、前后对比、批量队列、保留策略、磁盘清理 |
| 界面 | **7 个标签页**：单图 / 自动 / 批量 / 媒体 / 历史 / 模型 / 设置；中英双语 |
| 运行形态 | **本地离线**，处理不出本机 |
| 工程质量 | 约 **32,000 行**源码 + 18,000 行测试（92 文件 / **1346 用例**）；**103 份**设计文档；**两条质量门禁**（合成线 + 真实线） |

**结论**：作为**工具**，功能面是完整的——从输入到修复到导出到管理的闭环都在，且有多媒体与插件扩展。

### 1.2 但「功能完整」≠「能力已验证」

产品对外**承诺**的能力，与**有真实证据**的能力，目前是两回事：

| 类型 | 预设名 | 承诺级别 | 真实证据 |
|---|---|---|---|
| 角落 LOGO | `ai_logo` | ✅ **承诺处理** | **30 张真实图 / 60 个标注已验证**，受门禁红线约束 |
| 半透明平铺文字 | `ai_faint_tiled` | ⚪ 不承诺 | 合成用例已验证；真实图**未验证**，且属信息论极限区 |
| 底部/边缘小字 | `ai_text_heavy` | ⚪ 不承诺 | 合成用例已验证；真实图**未验证** |
| 网格点阵 | `ai_grid` | ⚪ 不承诺 | 合成用例已验证；真实图**未验证** |
| 全局渐变叠层 | `ai_gradient` | ⚪ 不承诺 | **无合成用例、无真实标注** |

**承诺面 = 1 / 5 类**（`config.WATERMARK_TYPE_COMMITTED = {ai_logo}`，由 `WATERMARK_TYPE_SCOPE` 派生）。

## §2 最大问题（按「是否挡住你现在用它」排序）

### 🔴 P0：整条评测链的「未知」，只能由**你自己的真实图**消除——但至今没有

这是**唯一一个我无法代劳、且一旦解决就会改变全部结论**的问题。

- 真实基准 30 张图的 60 个标注**全部是 `corner_logo`**；另外 4 类的真实表现**不是 100%，是未知**。
- 更尖锐的是：这 4 类里已经有**两类在合成数据上就露出问题**——
  - `ai_faint_tiled` 在**纹理/照片底图**上召回仅 **2.3% / 3.9%**（α≈0.09 的信息论极限，"擦不掉"是物理性的）；
  - `ai_grid` 在纹理/照片上精确率仅 **0.34 / 0.44**（检出 100 个区域里 56~66 个是误报）。
- 后果：如果你拖进来一张带「AI生成」**平铺字**的图，工具大概率擦不掉，而**两条门禁依然全绿**——
  因为该类型不在承诺面内、不计入指标。**"没标"会被结构性读成"没问题"**。

> **这不是"没测"，而是"已经知道其中一类在常见底图上做不成"**——它是已知的坏消息，只是没有前置到你面前。

### 🟠 P1：过检（滥杀）仍是最短板——**被擦的像素里约 87% 不是水印**

真实图实测（阶段 100 收敛后）：

| 指标 | 值 | 含义 |
|---|---|---|
| `mask_coverage` | **7.45%** | 平均每张图擦了 7.45% 的面积 |
| `coverage_ratio` | **7.65×** | 是"该擦的"7.65 倍 |
| `mask_iou` | 0.1163 | 整幅掩码只有 12% 对得上 |
| `precision` | **0.1382** | 检出区域里 **86.2% 是误报** |

**与设计原则直接冲突**：项目铁律写「**宁可漏检，不可滥杀**」，而这个数字说明实际行为是**宁可滥杀**。

**体验后果**：擦除会在**没有水印的地方**（人脸、文字、纹理）留下修复痕迹——这是最可能让你放弃它的那一类问题。
**阶段 93 登记的目标 `coverage ≤ 0.05` 至今未达成**（现 7.45%，差约 1.5×）。

### 🟠 P2：只有「检测」有真实证据，「修复」没有

- 真实门禁 `real_gate.py` **只测检测侧**（recall / precision / IoU / 覆盖率），**不测修得好看不好看**。
- 合成数据显示：在**类自然纹理底图**上，两引擎都出现「修完反而更差」（OpenCV ΔPSNR **−5.83 ~ −7.31 dB**）。
- 也就是说：**「擦掉了吗」有一半证据，「擦得干净吗」几乎没有真实证据。**

### 🟡 P3：质量分（无参考）辨析力 ≈ 随机（阶段 85 已判定，未作为红线）

⇒ 产品**无法自动回答「这张修好了没有」**，只能靠你看。

### 🟡 P4：产品化形态单一——本地单机、无多端、无托管

README 明确定位「本地离线运行，所有处理不出本机」。若你需要在手机/平板上用，是另一个工程量级。

## §3 解决办法（可执行，按性价比排序）

### ★ 第一步（只有你能做，10 分钟，决定后面所有事）

**拿 5~10 张你自己真实带水印的 AI 图跑一遍，并记录「水印属于哪一类」。**

```bash
python main.py          # 打开界面 → 「自动」标签页 → 拖入图片
```

要点：

1. **先看检测框对不对齐**——不对齐就不用往下看（那是过检/漏检问题，不是修复问题）。
2. 若自动推荐不对，去「单图」页手动选预设试 2~3 个（`ai_logo` / `ai_text_heavy` / `ai_grid`）。
3. 记录三件事：**水印类别 / 是否擦掉 / 是否擦到不该擦的地方**。

**判断规则（据此决定要不要继续投入）**：

| 你的观测 | 结论 | 下一步 |
|---|---|---|
| 多数是**角标/平台 LOGO** | **产品现在就能用** | 直接量产；只需修 P1（过检） |
| 多数是**底部文字条** | 合成召回 98%、但真实未验证 | 按第二步补真值，1 个阶段可升级为承诺类 |
| 有**平铺重复文字/网格** | 已知在纹理照片上做不成 | 别在它上面投入（信息论极限），或改用"手动掩码"兜底 |
| 擦到脸上/主体上 | P1 过检 | 优先做下面的"收敛过检" |

### 第二步：把结论固化（若你愿意标注 3~5 张）

把 bbox 填进 `benchmark_real/ground_truth.json` 对应的 `style`，再把 `config.WATERMARK_TYPE_SCOPE` 里该类型改为 `committed: True`——
**该类型立刻自动升级为承诺类型**，真实门禁开始为它守门（缺证据将直接判失败）。
（注意：**必须是你自己拍的/自己生成的图**；用 AI 再生成的图会污染真值。）

### 第三步：我能继续做的三项（你只需说"做哪个"）

| 编号 | 工作 | 直接收益 | 前置 |
|---|---|---|---|
| **A** | **收敛过检 7.45% → ≤5%** | 减少"擦到不该擦的地方"——**最影响体感的一项** | 无（残余 = `edge_text` 67.97% + `translucent` 31.69%，需**形貌判据**；抬阈值路线已被阶段 99 实测否决） |
| **B** | **给真实门禁补「修复侧」结论级红线** | 让"擦得干净吗"也进入守卫，不再只有检测侧有证据 | 无（30 张真实图已有真值掩码） |
| **C** | **把已知坏消息前置到界面** | 选中 `ai_faint_tiled` 等类型时直接提示「该类在纹理照片上召回约 2~4%」，避免你踩坑后才发现 | 无 |

### 第四步（可选，与擦除质量无关）

多端 / 云端部署——当前架构是本地单机，属于独立工程量级，**建议在 A/B 之后再谈**。

## §4 一句话总结

> **工具是完整的，能力是"一角标已证明 + 四类未知"。**
> 挡住你的不是功能缺失，而是**缺一次用你自己的图做的实测**；
> 其次是**过检会让它在无水印处留痕**（被擦像素约 87% 不是水印，与"宁可漏检不可滥杀"的设计原则相反）。
> 好消息：**角标恰恰是消费级 AI 工具最常见的可见水印形态**——若你的图正是这一类，**产品现在就能用**。
