## 一、这次到底测什么

之前跑的都是**门禁**：挑好的样本、按预设、只判一条指标。门禁全绿不等于**用户真的把一堆东西扔进去能用**。
所以这次刻意还原最粗糙的用法——建一个目录，里面混着放：

| 放了什么 | 数量 | 细节 |
|---|---|---|
| 真实带水印图 | 12 | 金标准集里前 12 张**原分辨率**（2048²、1728×2416、2720×1520），不缩放 |
| PDF | 1 份 4 页 | 用其中 4 张真图合成 |
| 视频 | 1 段 24 帧 | 1024²、8fps、固定水印 |
| 坏文件 | 3 个 | 0 字节 jpg／截断 PNG／**把 PNG 改名成 .pdf**（内容根本不是 PDF） |

共 17 个文件 62.7MB，一条命令吞下：

```
python cli.py -i 演练目录 -o 输出目录 --include-media -e
```

然后逐份核对输出：文件在不在、尺寸变没变、**水印那一块到底改没改**、水印之外改了多少、坏文件怎么交代的、进程退出码能不能给脚本用。

## 二、总账

```
EXIT=0（⚠ 见第四节缺陷 1）   总耗时 141.6s   输入 17 → 输出 15
CLI 自报：成功 15 / 跳过 0 / 失败 2 / 共 17      质量评估：良好 12 · 需复核 0 · 告警 0
PDF 4 页 → 4 页（不丢页）    视频 24 帧 → 24 帧（不丢帧，1024×1024×3 可解码）

```

**计数是诚实的**：CLI 自报「成功 15」与输出目录里真实的 15 个文件**一致**，「失败 2」正好是那 2 个坏图片。没有静默丢件、没有虚报。

**耗时结构**（单张图的间隔由输出文件 mtime 反推，串行模式即处理顺序）：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 冷启动 | ≈9s | 首次 import + 选卡 + EasyOCR 初始化，整批只付一次 |
| 每张 2048²~2720×1520 图 | 5.0–7.1s | `--engine auto` 实际选了 **OpenCV** 通路（日志 `修复引擎：OPENCV`），9 次触发分块 |
| PDF | 4.2–4.7s/页 | 150 DPI，页宽 2134px |
| 视频 | 34.4s / 24 帧 ≈1.4s/帧 | `抽帧步长=1` ⇒ 每帧独立检测（复用掩码 0 帧）；固定水印可用 `--frame-step 5` 省掉约 4/5 检测 |
| 坏文件 | ≈0s | 读图阶段即判死，不进模型 |

对照：同一批若强制 LaMa（REST 那次），1024² 单图 18.8s ⇒ **auto 选 OpenCV 是这批快起来的主因**，不是图小。

## 三、水印到底擦没擦（核心判据）

判据同 `media_gate` R2：标注 bbox 内缩 4px，取平均绝对差 ≥ 2.0 才算「这块动手了」。

| 图 | bbox 内差 | 全图改动 | 水印外改动 | 结论 |
|---|---|---|---|---|
| ai_logo_05 | 49.61 | 87.5% | 85.6% | 改了 |
| 1 | 30.00 | 67.6% | 66.0% | 改了 |
| 2 | 18.84 | 76.4% | 75.0% | 改了 |
| 3 | 18.27 | 78.0% | 76.7% | 改了 |
| 4 | 12.63 | 47.9% | 46.9% | 改了 |
| a1 | 5.08 | 74.0% | 70.1% | 改了（擦边，见下） |
| **a2** | **1.06** | 73.2% | 67.8% | **跑完没干活** |
| **a3** | **0.74** | 77.9% | 75.1% | **跑完没干活** |
| a4 | 4.13 | 94.9% | 88.4% | 改了（擦边） |
| q1 | 49.92 | 82.8% | 81.9% | 改了 |
| q2 | 32.93 | 86.2% | 85.2% | 改了 |
| q3 | 22.39 | 67.7% | 66.9% | 改了 |

三点要讲清楚，别把这张表读错：

1. **a2/a3 不是新 bug**，是已登记的图像级缺口 `WATERMARK_KNOWN_GAP_IMAGES={a1..a4}`（大宝石角标与背景在像素域不可分）。
   **`bbox_diff` 过 2.0 也不等于擦干净**，逐图看修复包围盒就清楚了：a1 的包围盒是 **2720×1520（占图 100.0%）**
   ——水印那块是「整图重绘被顺手动到」；a4 的包围盒只有 **530×349（4.5%）**，bbox 差 4.13 只是勉强过线；
   而 a2/a3 同样是 4.5% 的小框，bbox 差只有 1.06/0.74，基本等于后处理带来的全图扰动。
   演练判据只能回答「这块**动没动手**」，回答不了「擦得对不对」——后者是 `real_gate` 的 mask_recall 在管。
   逐图包围盒占比（同批）：`1`=30.4%、`2`=86.7%、`3`=93.6%、`4`=45.6%、`ai_logo_05`=74.0%、`q1`/`q2`=100.0%、`q3`=78.8%。
2. **a2/a3 拿到的却是「质量分 100 · good」**。无参考质量分只看修出来的图糊不糊、接缝自不自然，**不看水印还在不在**。所以「良好 12」这句别当成「12 张都擦成功了」。
3. **最扎眼的一列是「水印外改动」：46.9%–88.4%**。用户只圈了角上那块，但将近八成画面被改动了。成因在阶段 314b 已定位——默认后处理（降噪 + 锐化 + 边缘融合）是**全图作用**的，关掉后处理改动降到 5%。这是既有产品决策（设置页有滑杆），演练的作用是**把它在原分辨率真实图上量化出来**：不再是「关掉后处理差 30 个百分点」这种开关级数字，而是「每一张都有约 3/4 的画面被动过」。

## 四、坏文件与「宽容」的边界

| 文件 | CLI 结局 | 文案 |
|---|---|---|
| `broken_empty.jpg`（0 字节） | ❌ 失败（不进模型） | 【图片文件已损坏】原因：图片文件为空（0 字节）…建议：重新导出或重新下载该图片 |
| `broken_trunc.png`（PNG 头在、数据截断） | ❌ 失败 | 【图片文件已损坏】原因：图片解码失败，文件可能已损坏…（并附 3 条通用建议） |
| `fake_doc.pdf`（**内容是 PNG，扩展名 .pdf**） | 📄 **成功** | MuPDF 把这张 PNG 当「1 页文档」打开，照样渲染、检测、修复、写出 1 页 PDF |

坏文件的失败文案这次是**给人看的中文、带原因带建议**（阶段 314b 的成果），且不中断整批 —— 这两条是合格的。

`fake_doc.pdf` 值得单独说一句，它同时暴露两件事：

- **扩展名与内容不符没有任何提示**。这里是「宽容」而不是崩溃，结果也算可用（MuPDF 真能读 PNG），但用户如果以为处理了一份 PDF，就被误导了。**判据**：宽容可以，**静默不行**——至少该在汇总里提示「该 PDF 内容按图片解析」。
- 它的自动预设是 **`general`，置信度 0.01，触发特征「无」**，也就是系统自认为「没看见水印」，**却仍然修复了 12228 像素**。低置信度门槛该不该拦，是产品决策：拦了会漏掉真水印，不拦就在无信号图上乱改。演练把它记成待决项，不擅自动阈值。

## 五、当场修掉的缺陷（阶段 316）

**缺陷 1（P2，已修）：整批有失败，进程退出码仍是 0。**

实测就是上面这条命令：`成功 15 / 失败 2`，`EXIT=0`。后果很实际——任何脚本、CI、批处理 bat 都没法判断这批有没有踩雷，只能去**解析中文汇总文本**（`grep 失败 [1-9]`），那是脆且随时会因文案改动而失效的判据。

修法（`cli.py`）：抽出判据函数，把口径与门禁家族对齐——

```python
def _batch_exit_code(summary: dict) -> int:
    """0 = 全部成功（「跳过」是正常裁决，不计失败）/ 1 = 存在处理失败。"""
    return 1 if summary.get("failed", 0) else 0
```

`2` 保留给「参数或输入缺失」（原有行为不变）。顶层文档同步写了退出码契约。

守卫落在 `tests/test_cli.py`（+4 例）：判据映射 2 例（含**「全部跳过」必须为 0**，否则一批干净图全红）、真实子进程 2 例（只有 1 个 0 字节图 ⇒ `rc=1`；只有一张干净渐变图 ⇒ `rc=0`）。
**反例证明守卫不是哑巴**：进程内把 `_batch_exit_code` 摘成恒 0（等价于改回旧行为）⇒ `rc` 由 1 变 0，判据失效即变红；工作树 `cli.py` 未被改动（`git diff` 仅本特性的 21 行增补）。
