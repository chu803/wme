# 阶段 117 · 交图作战包：用豆包生成「真实水印图」的提示词

> 目的：把项目**唯一未消除的 P0**（真实水印图覆盖）变成你能在**两个平台之间来回对话**就能推进的事。
> 依据：`docs/108`（交图规格）+ `benchmark_real/inbox/README.md`（收件箱规格）。
> 本文件只提供**提示词与流程**，不改任何算法。

---

## 0. 你要做的只有三步

1. 把下面的**提示词**贴给豆包（豆包/即梦），让它生成图片；
2. 把生成好的图**下载原图**，丢进 `benchmark_real/inbox/`（或直接把路径/附件发我）；
3. 我用 `collect_real_assets.py` 收编、按目视给**标注草案**逐张请你确认 → 预检 → 升级承诺类型 → 出**该类的真实 precision/recall**。

---

## 1. 规格（务必照做，否则收编会失败或被预检拦下）

| 项 | 要求 |
|---|---|
| 目标类型 | ① `ai_text_heavy`（边缘小字，**最高优先级**）② `ai_grid`（网格点阵）③ `ai_faint_tiled`（平铺淡文字）④ `ai_gradient`（全局渐变） |
| 数量 | **每类 3~5 张**（够 3 张即可升级；5 张更稳） |
| 格式 | `.png` / `.jpg` |
| 尺寸 | **长边 ≥ 1024**（项目有按绝对像素标定的判据） |
| 命名 | 任意，但**避开 `01_…`~`30_…`**；建议 `txt_01_城市夜景.png` 这样带类名前缀 |
| 放置 | `benchmark_real/inbox/`（暂存区） |

**⚠ 一条红线（`docs/108` 明文）**：**不得拿现有图去 AI 重生成 / 放大后充数** ——
那会让「真实水印」退化成「合成水印」，污染 `benchmark_real` 的立身之本。
**你必须是「新生成」的图**，不是「改造」现有的图。

---

## 2. 合规边界（先读这段，再决定用哪条路）

项目要的是**「真实水印 × 真实底图」**。按水印的来源，有两条路：

- **路 A（最佳·平台原生水印）**：让豆包/即梦生成图，下载时**不要选「去水印/无水印」导出**，
  直接下载**带平台原生水印的原图**。这是 100% 合规的「平台导出的原图」。
  ⚠ 代价：豆包/即梦的原生水印多为角标或底部小字，**只能覆盖 `ai_logo` / `ai_text_heavy`**。
- **路 B（补类型·让豆包把水印"画进"图里）**：用提示词让模型在生成时**把指定水印渲染成像素**。
  这能覆盖 `ai_grid` / `ai_faint_tiled` / `ai_gradient`（这些平台原生未必有）。
  ⚠ 代价：严格说这是「AI 生成的水印」，不是「平台原生」。**交付时请注明**，
  由项目的标注口径判定它算不算 `benchmark_real` 的覆盖（若判为合成水印，会归到 `docs/105–107` 那条线）。

**建议**：两类都做 —— 路 A 拿平台原生（稳），路 B 补类型（全）。**哪条都别改造旧图。**

## 3. 提示词包（直接复制粘贴给豆包）

### 3.0 母提示词（每次对话开头先发这一条）

```
接下来请你帮我生成一批【用于软件测试的图片素材】，请严格遵守以下规矩：
1. 每张图分辨率 1024×1024 或更大，输出 .png；
2. 画面要像真实拍摄的照片（写实摄影质感），细节丰富、不是卡通简笔画；
3. 水印必须是【真实画进图片像素里的内容】，不是你在对话框里附带的文字说明；
4. 每次生成后请告诉我你能提供"带水印版"和"无水印干净版"两张。
明白请回复"明白"，然后等我发具体需求。
```

### 3.1 `ai_text_heavy`（边缘小字）—— 最高优先级，先做这个

```
请生成一张写实摄影风格的图片，主题：<场景>。
要求：1024×1024，画面干净、细节丰富。

生成后，请在图片【最底部居中】用像素真实渲染一行白色小字水印：
「AI 生成 · 仅供学习交流」
- 字号要小（字高约占画面高度的 2%），半透明（约 60% 不透明度），紧贴底边；
- 看起来要像 AI 绘图平台导出的署名水印；
- 必须真正画进图片里，是图像内容。
```

### 3.2 `ai_grid`（网格点阵）

```
请生成一张写实摄影风格的图片，主题：<场景>。
要求：1024×1024，画面干净、细节丰富。

生成后，请在整张图上叠加一层【规律排布的点阵网格】水印：
- 每隔约 80 像素重复一个小圆点（或小方块），横竖成行成列，铺满整张画面；
- 半透明（约 15% 不透明度），颜色用浅灰或白色；
- 覆盖全图但不遮挡主体，像防伪网点 / 平台网格水印。
必须真正画进图片像素里。
```

### 3.3 `ai_faint_tiled`（平铺淡文字）

```
请生成一张写实摄影风格的图片，主题：<场景>。
要求：1024×1024，画面干净、细节丰富。

生成后，请在整张图上【平铺重复】一层极淡的文字水印：
- 文字用「SAMPLE」或「AI」，倾斜约 30°，每隔约 150 像素重复一次，铺满全图；
- 非常淡（约 8% 不透明度），浅灰或浅白，像防伪底纹一样若隐若现，不抢主体。
必须真正画进图片像素里。
```

### 3.4 `ai_gradient`（全局渐变署名层）—— **v2 修正版（必用）**

> ⚠ v1 失败原因：只说了"叠加渐变"，**没禁止别的** ⇒ 豆包画成了大号 LOGO（实测见 `docs/118` §1）。
> v2 加了**强否定约束**，务必用这一版。

```
请生成一张写实摄影风格的图片，主题：<场景>。1024×1024 或更大，画面干净、细节丰富。

生成后，请在整张图上叠加一层【纯线性渐变遮罩】：
- 从画面左上角到右下角，由「半透明青色」平滑过渡到「半透明品红」，整体不透明度约 12%；
- 只允许是平滑的颜色渐变（像给整张图盖了一层彩色玻璃）；
- 【绝对不要出现】任何文字、字母、数字、圆圈、LOGO、图案、网点、边框或水印字样；
- 渐变要覆盖整张画面（四个角都要受影响），平滑过渡、无肉眼可见的分界线。

必须真正把它画进图片像素里（是图像内容，不是文字说明）。
```

**生成后自检（3 秒判断能不能用）**：
- ✅ 整张图四个角都带一点青 / 品红**色调**，中间平滑过渡 → 合格；
- ❌ 只要看到**任何文字 / 圆圈 / LOGO / 图案** → 不合格，**重新生成**（或换一张场景重来）。

### 3.5 金标增强（**强烈建议**，能让真值精确到像素）

```
另外，请再生成一张【与上面完全相同的画面、但没有任何水印】的干净版本。
两张分别命名：
  <类名>_<序号>_<场景>.png        ← 带水印版
  <类名>_<序号>_<场景>_clean.png  ← 无水印版
```

> 为什么值钱：有了「干净版」，项目的真值 `bbox` 可以用**两张图相减**自动导出，
> **零目视误差**（`docs/108` §2.3 明说这是最优路径）。

## 5. 交付

**方式一（推荐）**：把图片文件直接放进 `benchmark_real/inbox/`。
**方式二**：在对话里把**文件路径**或**附件**发我，我来收编。

我收到后会执行（你只需在标注草案上确认）：

```
1. python scripts/collect_real_assets.py add <路径> --ai-source other --style <style> --copy
2. 按目视给 bbox 草案（labeled_by="manual:assistant"），逐张请你确认/修正
3. python scripts/real_asset_preflight.py        # 来源与结构预检
4. 你确认后翻转 committed:True → 刷新基线 → 取该类【真实】precision/recall
```

`--style` 取值对照（**注意与类型名不同**）：

| 目标类型 | 传的 `--style` |
|---|---|
| `ai_text_heavy` | `edge_text` |
| `ai_grid` | `grid_watermark` |
| `ai_faint_tiled` | `translucent` |
| `ai_gradient` | `gradient_watermark` |
| （平台原生角标） | `corner_logo` / `logo_watermark` |

`--ai-source`：豆包一律用 **`other`**。

## 6. 我会替你做的（你不用管）

- 收编 + `sha256` 查重（防同一张图重复入库）；
- 目视标注草案（**不用检测器预填**，避免 `auto:` 循环论证）；
- 预检三态判定（已承诺 / 可升级 / 不可升级，附「还差什么」）；
- 你确认后：翻 `committed` → 同步 README/测试夹具（5 处守卫会强制机械同步）→ 刷新基线 → 出**该类的真实指标**并写入 `docs/`。
