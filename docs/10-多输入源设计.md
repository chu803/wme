# 阶段 10 设计文档 · 更多输入源（PDF 文档 / 视频）

> 项目名称：AI 智能水印擦除工作台（AI Watermark Eraser Workbench）
> 阶段目标：在「单图 / 批量 / 自动 / 历史 / 设置」五入口之外，新增 **PDF 文档** 与 **视频** 两类输入源，
>          复用阶段 9 沉淀的 `services.auto_pipeline.process_image` 原子核心，做到「拆 → 修 → 拼」三步走。
> 合规声明：本工具专用于去除使用者本人生成的 AI 图片上的可见水印 / 署名标识；严禁用于擦除他人享有著作权作品上的水印、署名或版权标识；亦不建议用于去除 AI 绘图平台第三方署名水印（通常违反其服务条款）。

---

## 1. 设计原则

本阶段严格遵守项目既有的分层铁律：

```
ui  →  services  →  core  →  utils  →  config
```

- **零反向依赖**：`core`、`services` 层不允许 import `gradio` 或任何 UI 组件。
- **四入口共用核心**：GUI（Gradio）、CLI（`cli.py`）、程序库（`api.py`）、REST（`server.py`）
  四类入口最终都汇聚到同一个原子函数 `auto_pipeline.process_image(rgb, ...)`。
- **薄封装**：PDF / 视频的「拆分 / 拼接 / 抽帧 / 写回」逻辑全部封装在 `services/pdf_service.py`
  与 `services/video_service.py`，界面、CLI、库层只做参数透传与进度转发，不写业务细节。
- **优雅降级**：PDF 依赖 `PyMuPDF`（可选安装）；未安装时图片与视频功能照常可用，
  仅在上传 PDF 时给出友好提示，绝不拖垮启动。

## 2. 总体架构与数据流

```
┌─────────────────────────── 四类调用入口 ───────────────────────────┐
│  ui/tab_media.py   │   cli.py --include-media   │   api.py   │  server.py  │
└─────────┬───────────────┬──────────────────────┬────────────┬───────────┘
          │               │                      │            │
          ▼               ▼                      ▼            ▼
   services/pdf_service          services/video_service        （图片走原 auto_pipeline）
          │                              │
          │  逐页渲染为 RGB 数组          │  逐帧解码为 RGB 数组
          ▼                              ▼
   for each page / frame:
        auto_pipeline.process_image(rgb, mode, engine, 修复参数, on_progress)
          → dict(result_rgb, status, mask, ...)
          ▼
   重新拼回 PDF / 写回视频容器
```

关键事实：**PDF 与视频不引入新的修复算法**，它们只是把「多页 / 多帧」拆成一张张图片，
复用与单图完全一致的去水印能力。因此任何引擎（LaMa / OpenCV）、任何修复参数（力度 / 膨胀 /
羽化 / 阈值 / 降噪 / 敏感度）都天然对 PDF 与视频生效。

## 3. PDF 文档处理（services/pdf_service.py）

### 3.1 处理流程

1. **能力探测**：`is_pdf_available()` 检测 PyMuPDF 是否安装；未安装则 `is_pdf_file()` 仍可按扩展名识别，
   但 `process_pdf` 会直接抛出明确异常（由上层提示用户安装 `pymupdf`）。
2. **页码解析**：`get_pdf_info(src)` 先用 `fitz.open` 取总页数，再 `_parse_pages(spec, total)` 解析页码范围。
   支持语法：`"1-5"`（区间）、`"1,3,7"`（离散）、`"3-1"`（自动反转，等价于 1-3）、
   越界页码（如 `"99"` 但文档只有 3 页）自动过滤并告警。缺省为全部页。
3. **逐页渲染**：`_page_to_array(page, dpi)` 用 `page.get_pixmap(matrix=zoom)` 将页渲染为位图，
   `zoom = dpi / 72`（默认 150 DPI → zoom≈2.08）。位图默认 RGB，内部转 BGR 供 OpenCV 链路使用。
4. **逐页去水印**：对每一页调用 `auto_pipeline.process_image(rgb, ...)`，得到修复后的 RGB 数组。
5. **重新拼装**：
   - 命中的页：用 `_encode_page_image(bgr)` 编码回图片字节（JPEG 默认质量 92，失败时回退 PNG），
     通过 `out_doc.new_page(width, height) + insert_image(rect, stream=...)` 写回。
   - **未选中的页**：原样 `out_doc.insert_pdf(src_doc, from_page=i, to_page=i)` 保留，不重渲染、不丢内容。
6. **失败 / 跳过处理**：当某页修复异常或判定「无水印」时：
   - 若 `PDF_KEEP_FAILED_PAGE=True`（默认）：把**原始页**（未处理）原样保留进输出，保证页数不减少；
   - 若 `PDF_KEEP_FAILED_PAGE=False`：该页缺失，并整体标记 PDF 处理为失败。
7. **资源释放**：`finally` 块中释放 `out_doc` / `src_doc` 句柄，避免文件锁。

### 3.2 关键设计点

| 关注点 | 处理方式 |
|--------|----------|
| 渲染清晰度 | `PDF_RENDER_DPI=150`（范围 36~600；72 快而糊，300 印刷级但很慢） |
| 页数上限 | `PDF_MAX_PAGES=100`，超出给出告警并截断，防止超长文档卡死 |
| 页图像格式 | `PDF_PAGE_IMAGE_FMT="JPEG"`，`PDF_JPEG_QUALITY=92`（再大肉眼难分，徒增体积） |
| 失败页 | `PDF_KEEP_FAILED_PAGE=True`：保留原页，绝不丢页 |
| 掩码复用 | PDF 页间水印位置通常**不固定**，故不启用视频那种跨页掩码复用；每页独立检测 |

### 3.3 对外接口

```python
# 同步阻塞，on_progress(frac, desc) 用于 UI 进度条 / CLI 进度行
def process_pdf(src, out_path, pages=None, dpi=None,
                mode="auto", engine="auto", strength=..., dilate=...,
                feather=..., threshold=..., denoise=..., sensitivity=...,
                on_progress=None) -> PdfResult: ...

# 数据类
class PageResult:
    index: int
    status: str          # "ok" | "skip" | "failed"
    mask_pixels: int
    note: str

class PdfResult:
    out_path: str
    total: int           # 输出文档总页数
    processed: int       # 实际修复页数
    skipped: int         # 跳过/失败保留页数
    pages: list[PageResult]
    elapsed: float
```

## 4. 视频处理（services/video_service.py）

### 4.1 处理流程

1. **能力探测**：`is_video_available()` 恒为 True（依赖已安装的 `opencv-python`），`is_video_file()` 按扩展名识别；
   `get_video_info(src)` 读取帧数、FPS、宽高、编码器，供 UI 预览与异常兜底。
2. **逐帧解码**：`cv2.VideoCapture(src)` 逐帧 `read()`，得到 BGR 帧，转 RGB 后送修复核心。
3. **检测策略（核心提速点）**：
   - **检测帧**：当 `idx % frame_step == 0`，或尚未缓存到可用掩码时，跑**完整检测 + 修复**，
     并把得到的 `mask` 数组缓存下来。
   - **中间帧**（`frame_step > 1` 且复用开启）：跳过检测，直接以 `mode="manual", mask=cached_mask`
     复用上一检测帧的掩码位置修复。固定水印场景下检测次数从 N 降到 N/`step`（实测 12 帧 → 仅检测 4 次）。
   - **失败帧 / 无水印帧**：原样写出（不丢帧、不报错中断）。
4. **编码写回**：`_open_writer(dst, fps, w, h)` 逐个尝试 `mp4v / avc1 / XVID` 编码器
   （不同环境对 `avc1` 支持不一，依次回退），`VideoWriter` 写入修复后的帧。
   **必须在所有帧写完后调用 `writer.release()`**，再 `finally` 释放 `VideoCapture`。
5. **音频处理**：OpenCV **不处理音频**。若用户希望保留原音轨，`build_audio_merge_command(src, processed, final)`
   会生成一条 `ffmpeg -i 原视频 -i 修复视频 -c copy -map 0:a? -map 1:v 输出`
   的合并命令（输出为 `*.with_audio.mp4`），用户自行执行即可。该命令字符串会在 UI 与 CLI 中展示。

### 4.2 关键设计点

| 关注点 | 处理方式 |
|--------|----------|
| 抽帧步长 | `VIDEO_FRAME_STEP=1`（范围 1~60）；固定水印设 3~5 可数倍提速 |
| 掩码复用 | `VIDEO_REUSE_MASK=True`；滚动字幕 / 飘动水印请关闭（加 `--no-reuse-mask`） |
| 帧数上限 | `VIDEO_MAX_FRAMES=900`，超出截断并标记 `truncated=True`，防止超长视频卡死 |
| 编码器 | `VIDEO_CODEC_CANDIDATES=("mp4v","avc1","XVID")`，逐个尝试回退 |
| 输出格式 | `VIDEO_OUTPUT_EXT=".mp4"` |
| 帧率异常 | FPS ≤0 或 >240 → 回退 25fps 并告警 |
| 输出校验 | 写出后若为 0 字节 → 报错，提示编码器失败 |
| 矛盾参数 | `step>1` 且 `reuse_mask=False` → 自动纠正为逐帧检测并记 warning（语义矛盾） |

### 4.3 对外接口

```python
def process_video(src, out_path=None, frame_step=None, max_frames=None, reuse_mask=None,
                  mode="auto", engine="auto", 各修复参数..., on_progress=None) -> VideoResult:

class VideoResult:
    out_path: str
    total_frames: int       # 源视频总帧数
    processed_frames: int   # 实际写回帧数（=总帧数，除非被 max_frames 截断）
    detected_frames: int    # 真正跑过检测的帧数（≤ processed_frames）
    truncated: bool
    fps: float
    audio_merge_cmd: str    # 非空时提示可用 ffmpeg 合并音轨
    elapsed: float
```

## 5. 配置项一览（config.py 第 8.5 节）

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `SUPPORTED_DOC_FORMATS` | `(".pdf",)` | 文档类输入扩展名 |

| `PDF_JPEG_QUALITY` | `92` | JPEG 页质量 |
| `PDF_KEEP_FAILED_PAGE` | `True` | 失败/跳过页是否保留原页 |
| `VIDEO_MAX_FRAMES` | `900` | 视频最大处理帧数 |
| `VIDEO_FRAME_STEP` | `1` | 抽帧步长（1~60） |
| `VIDEO_REUSE_MASK` | `True` | 是否复用相邻帧掩码 |

## 7. 命令行入口（cli.py 扩展）

新增开关（与图片处理完全兼容，按扩展名自动分派）：

| 参数 | 说明 |
|------|------|
| `--include-media` | 处理**文件夹**时，连同其中的 PDF 与视频一起处理（单文件无需此开关，按扩展名自动识别） |
| `--pages` | PDF 专用：页码范围，如 `1-5` 或 `1,3,7`（缺省全部页） |
| `--dpi` | PDF 专用：渲染清晰度（默认 150） |
| `--frame-step` | 视频专用：每隔几帧重新检测一次水印（默认 1；固定水印设 3~5 可提速） |
| `--max-frames` | 视频专用：最多处理多少帧（默认 900） |
| `--no-reuse-mask` | 视频专用：关闭掩码复用，每帧独立检测（滚动字幕、飘动水印必须加） |

内部实现：`_kind_of(path)` 判定类型 → `_collect_inputs` 新增 `include_media` 参数 →
`_dispatch` 统一分派到 `_run_pdf` / `_run_video` / `_run_one`（图片）→ `_print_result` 按 `kind`
打印 📄 / 🎬 图标与 `note`（如「音轨需 ffmpeg 合并」「第 3 页原样保留」）。

示例：

```bash
# 一次性处理一个混合目录（图片 + PDF + 视频）
python cli.py -i 素材目录 -o 结果目录 --include-media --evaluate

# 仅处理某个 PDF 的第 1~3 页，印刷级清晰度
python cli.py -i 报告.pdf -o 结果.pdf --pages 1-3 --dpi 300

# 固定水印视频，跳帧检测提速，并保留音轨
python cli.py -i 宣传片.mp4 -o 宣传片_clean.mp4 --frame-step 4
# 处理完毕后按提示执行输出的 ffmpeg 命令合并音轨
```

## 9. 边界与健壮性

1. **未安装 PyMuPDF**：图片 / 视频功能照常；上传 PDF 时界面提示「请 pip install pymupdf」，
   CLI 给出明确异常，`get_capabilities()["pdf_available"]=False`。
2. **视频音轨**：OpenCV 写回的视频**不含声音**，这是框架限制而非缺陷；通过 `audio_merge_cmd` 引导用户用 ffmpeg 补回。
3. **矛盾参数**（步长>1 且关闭复用）：自动纠正为逐帧检测并记 warning，不抛错。
4. **帧率异常**（≤0 或 >240）：回退 25fps 并告警。
5. **0 字节输出**：检测并报错，提示编码器失败，便于用户切换候选编码器。
6. **资源释放**：PDF `finally` 释放文档句柄；视频 `writer.release()` 先于 `finally` 释放 `VideoCapture`，避免文件锁。
