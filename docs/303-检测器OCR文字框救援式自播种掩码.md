# 303 · 检测器 OCR 文字框救援式自播种掩码（阶段 P0-4，2026-10-19）

> 审计链（`audit_selector.py --unaudited`）已耗尽 45/45 模块后，在 `real_gate`
> 真值体检中暴露的**漏网分支**修复：真实豆包成对图 pair_04「海边礁石」静默漏检。
> 修复链路：`probe → classify → fix → regress → validate → real_gate(通过) →
> 注入式反例守卫 → 更广回归(全绿) → 文档 → 记忆`。

## 1. 结论（TL;DR）

- **缺陷**：OCR 已读到角标文字 `(2506,1434,187,51)`，但 `_refine_regions_to_mask`
  在该框内只找到**少量偏中心的弱残差证据** ⇒ 框被裁空 ⇒ `kept_regions` 的
  「中心须在掩码内」把该区域一并丢弃 ⇒ **整图返空掩码（静默漏检）**。
- **修复**：新增 `_ocr_box_rescue_mask()`（救援式，非无条件信任）。对每个
  `ocr_text` 区域：先跑框内证据 refine；**仅当该区域中心点未被证据覆盖时**，
  才退化为整框填充。语义是「救援静默漏检」而非「填满所有 OCR 框」。
- **配置**：`config.DETECT_OCR_BOX_TRUST`（默认 `True`，env 可关）。
- **守卫**：`tests/test_ocr_agreement.py::test_ocr_box_trust_rescues_empty_refine`
  （OFF 复现 pair_04 丢框；ON 必救回）。

## 2. 归因（为什么是无条件信任的坑）

第一直觉是「OCR 读到文字就整框信任」。但**全开版实测**（P0-4 v1）令 real_gate：
- mask_coverage 0.0162 → 0.0182（红线 0.020），**覆盖率余量从 19% 蚀到 9.9%**；
- 触发 **3 处面积漂移守卫**（ai_faint_tiled / ai_text_heavy / ai_grid 面积突胖）。

根因：无条件信任把所有 OCR 框（含非水印文字、招牌、标语）都填满，在真实照片上
不可控地放大掩码。

第二版（「框内无任何证据才救援」）不触发——因为 pair_04 框内**仍有少量证据像素**
（非空），只是偏不到中心 ⇒ 条件不命中 ⇒ 仍丢框。故第三版改为按**中心点**判定，
与 `kept_regions` 的「中心须在掩码内」逐字对齐，才真正救回。
