## 2. P0：GPU 镜像解释器错配（确定性启动失败）

`Dockerfile.gpu` 的三条事实叠加成必失败：

1. runtime 装的是 `python3.11`（apt），依赖用 `python3.11 -m pip install --prefix=/install`
   装到 `/usr/local/lib/python3.11/site-packages`；
2. 基础镜像 `nvidia/cuda:12.8.1-runtime-ubuntu22.04` 自带的 `/usr/bin/python3`是 **Python 3.10**，
   它只搜索 `python3.10` 的 dist-packages ⇒ **看不到 3.11 的包**；
3. 旧 `ENTRYPOINT ["python3", "main.py"]` / `HEALTHCHECK CMD python3 -c ...` 用的正是这个 `python3`。

⇒ 容器一起来就 `No module named 'torch'`（gradio/opencv 同理）。**本机无 docker 也能静态判定**。

**修法（两件事，缺一不可）**：
- `RUN update-alternatives --install /usr/bin/python3 python3 /usr/bin/python3.11 1`
  `+ ln -sf /usr/bin/python3.11 /usr/local/bin/python3` ⇒让 `python3`/`python` 也指向 3.11，
  这样用户 `docker exec` 进去手工跑 `python3 xxx` 的行为与镜像内一致；
- `ENTRYPOINT ["python3.11", "main.py"]` + `HEALTHCHECK CMD python3.11 -c ...` ⇒
  **不依赖 symlink** 即正确。

> CPU 镜像无此问题：它用官方 `python:3.11-slim`，`python3` 本就是 3.11（E1 规则已区分）。

## 3. 依赖统一（用户 2026-10-07 拍板：统一 2.9.1 + 删 torchvision）

**改前的事实**（记忆里「仍钉 cu121」是过期记载，实际 207 已修 GPU 侧）：

| 环境 | Python | torch |
|---|---|---|
| CPU 镜像 | 3.11 | **2.3.1** |
| GPU 镜像 | 3.11 | 2.9.1+cu128 |
| 开发机 | 3.13.14 | 2.9.1+cu128 |

即 **三套 torch**；而 `requirements-gpu.txt` 曾写「与 requirements.txt 同版本（单一真值来源）」
——这句在改前是**失实宣称**。另：`torchvision==0.18.1` 代码**零 import**（全库实测），
纯「必须与 torch 严格配套」的耦合负担（旧 torch 2.3.1 正是被它拖住无法升级）。

**改后**：`torch==2.9.1` 单一真相 + 无 torchvision ⇒ 声明终于成立，且由 W1 守卫机器核验。

**wheel 可用性实证**（我在选项里承诺过要验）：

| 源 | torch 2.9.1 / cp311 | 判读 |
|---|---|---|
| 官方 PyPI | ✅ `Would install torch-2.9.1` | CPU 镜像的 torch **可获取** |
| 清华源 | ❌ `from versions: none` | ⚠ 见下|

⚠ **诚实登记**：清华源在本机**整体不可达**——对照实验中连 `numpy==1.26.4` 也返回
`none`（而官方 PyPI 的 torch 2.3.1/2.9.1 均 OK），且直接 fetch 该源返回 **403**。
所以**这是本机网络环境问题，不是 torch 版本问题**；但也意味着我**无法验证镜像构建时
清华源能否拉到 torch**（构建发生在用户侧）。若用户侧构建时清华源同步滞后或被限流，
可临时把 `Dockerfile` 的 `-i https://pypi.tuna.tsinghua.edu.cn/simple` 改为官方 PyPI。

## 5. 审计脚本自身的首版 bug（4 处假阳性，值得记）

首版跑出 4 个**假 ERROR**：

1. `E1[Dockerfile] ENTRYPOINT 用 python` —— `python3.11` 匹配到的是我**注释里**写的参考配方；
2. `E1[Dockerfile] HEALTHCHECK 用 python` —— 同上，注释里出现 `python3.11`；
3. `E1[Dockerfile.gpu] HEALTHCHECK 用 的解释器必须与装依赖的解释器**同一个**。` —— HEALTHCHECK
   正则 `[\s\S]*?CMD\s+(\S+)` 跨到了**注释说明文字**；
4. `E2 期望 1.8` —— `cu128 → 12.8` 的换算写错（`f"{s[:-2]}.{s[-1]}"`）。

**根因只有一个**：**没有先剥离 Dockerfile 注释**。⇒ 沉淀为解析铁律：
**任何 Dockerfile 匹配前必须先剥离注释**（整行 + 行尾，引号感知）。
这条与 LESSONS 227「环境假设可能是错的·从未执行的路径=未验证」同源——
**守卫上线前先让它在已知坏输入上跑一遍**。

## 6. 用户侧 Docker 验收清单（本机无法替代）

> 静态审计只能保证「不犯确定性错误」，**不能替代真构建**。请在有 docker 的机器上执行：

```bash
# 0) 先跑静态审计（本机就能跑，秒级）
python scripts/docker_consistency_check.py        # 期望：退出码 0

# 1) CPU 镜像
docker build -t wme:cpu -f Dockerfile .
docker run --rm -p 7860:7860 wme:cpu# 期望：能打开 http://localhost:7860

# 2) GPU 镜像（**250 修P0 的重点验收项**）
docker build -t wme:gpu -f Dockerfile.gpu .
docker run --rm --gpus all -p 7860:7860 wme:gpu \
    -e WME_SERVER_HOST=0.0.0.0
# 关键验证：解释器与 torch 都正确（应输出 3.11.x 与 2.9.1+cu128，且 sm_120 在 arch 列表里）
docker run --rm --gpus all wme:gpu python3.11 -c \
  "import sys,torch;print(sys.version.split()[0], torch.__version__, torch.cuda.is_available(), torch.cuda.get_arch_list()[-1:])"
docker exec -it <容器> python3 -c "import torch;print('exec 里的 python3 也能 import torch')"

# 3) REST 模式
docker run --rm --gpus all -p 7861:7861 -e WME_SERVER_HOST=0.0.0.0 \
    wme:gpu python3.11 main.py --api
curl http://localhost:7861/health

# 4) 若构建卡在下载 torch（清华源 403/不同步），改用官方源：
#    Dockerfile 的 pip -i 换成 https://pypi.org/simple 后重建
```
