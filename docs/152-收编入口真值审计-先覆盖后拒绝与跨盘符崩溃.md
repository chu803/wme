# 阶段 152 · 收编入口真值审计：`add --copy` 先覆盖后拒绝 & 跨盘符崩溃

## 动机（为什么审这个模块）

阶段 151 已端到端证明：`scripts/collect_real_assets.py` 是**闭合项目唯一 P0
（`ai_logo` 红灯）的入口**。但审计选点器显示「未审榜已空」（44 个模块全登记），
且该模块**只有 `scan` 有测试、`cmd_add` 零测试** —— 一个从未被审、又承载 P0 闭合的
入口，是典型的「覆盖荒漠」。据此刻意选点为审计对象。

## 探针与量化

在隔离目录（`WME_BENCH_DIR` 指向拷贝）用真实 CLI 跑两次 `add`，A/B 对照。

### 缺陷 1（P0 · 静默数据损坏）

`add --copy` 收编一张**同名但内容不同**的图：

```
第一次(红图) rc=0  [add] dup  images/dup.png
  收编后 images/dup.png sha = 6e35e4c2d632
第二次(蓝图) rc=0
  stderr = [error] 路径已存在但哈希变化：images/dup.png（文件被覆盖？）拒绝登记。
  >> 拒绝后 images/dup.png sha = e9da449bcc3b     ← 已被换掉
  manifest.sha256 = 6e35e4c2d632  实际文件 sha = e9da449bcc3b  一致? False
```

**守卫拒绝了「登记」，却已经完成了「覆盖」。** 提示说没登记，磁盘却变了：
manifest 里的 `sha256` 从此与磁盘文件不一致，而**没有任何后续信号**会再报这件事
（`audit_manifest` 只查清单内部的 sha 重复，不校验清单 vs 磁盘）。
对整个基准而言这是**可信度静默归零**——`benchmark_real/` 的立身之本就是可信。

### 缺陷 2（P1 · 未捕获崩溃）

`add`（无 `--copy`）且源与数据集不在同一盘符：

```
ValueError: path is on mount 'D:', start on mount 'C:'
  File "scripts/collect_real_assets.py", line 223, in cmd_add
    entry["path"] = os.path.relpath(src, BENCH_DIR)
```

未捕获，直接抛 traceback（rc=1，无友好提示）。

## 归因

两者是**同一个根因的两面**：`_build_entry` 固定从 `BENCH_DIR/rel_path` 读文件算哈希，
于是 `--copy` 被迫**先复制才能算哈希**，把破坏性写排在了守卫判定之前
（顺序错误 → 缺陷 1）；而 `relpath` 缺少平台边界处理（边界缺失 → 缺陷 2）。

## 最小修复

1. `_build_entry` 增加可选参数 `abs_src`：**哈希/尺寸取自源文件**，`rel_path` 只决定
   `filename`/`path`。有了它，`--copy` 就能**先判定、通过后再落盘**。
2. `cmd_add` 的 `--copy` 分支改为：`_build_entry(abs_src=src)` → `_upsert` 判定 →
   **仅当接受**才 `makedirs + copy2 + save_manifest`。
3. `relpath` 包 `try/except ValueError`：跨盘符退化成绝对路径并 `[warn]` 提示
   （与非 `--copy` 分支「path 用绝对」的原有语义一致）。

## 守卫（新增 `tests/test_collect_real_assets.py`，4 例）

| 用例 | 守什么 |
|---|---|
| `test_add_copy_rejects_without_overwriting_dataset_file` | **P0**：拒绝登记时数据集文件字节级不变，且 manifest sha 与磁盘一致 |
| `test_add_copy_same_content_is_idempotent` | 同内容重复收编幂等跳过、不产生重复条目 |
| `test_build_entry_hashes_abs_src_not_destination` | 契约：`abs_src` 决定哈希来源（「先判定后落盘」的前提） |
| `test_add_cross_drive_falls_back_to_absolute_path` | **P1**：跨盘符不崩溃，退化为绝对路径并告警 |

**守卫口径**：断言**磁盘上的字节**，不是函数返回值——缺陷的本质正是
「返回值说成功/拒绝，磁盘却是另一回事」。

## 经验（同步进 `LESSONS.md`）

- **守卫拒绝 ≠ 无副作用**：凡「先写后判」的顺序，拒绝的只是**登记**，不是**写入**。
  判定必须排在**一切破坏性写之前**；守卫要断言**磁盘字节**，不能只断言返回值。
- **「有守卫」不等于「有覆盖」**：本模块有 `_upsert` 哈希守卫，却因 `cmd_add` 零测试
  让缺陷存活至今。审一个入口时，先问「它的每个子命令有没有测试」。
