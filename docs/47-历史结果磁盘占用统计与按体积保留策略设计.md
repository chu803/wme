# 阶段 47 · 历史结果磁盘占用统计与按体积保留策略设计文档

> 项目：AI 智能水印擦除工作台
> 依赖阶段：1–46（含阶段 35 真实超分「设置页暴露 + 保存为默认」、阶段 46 历史保留策略可配置化）
> 运行要求：零 torch 可测；Gradio 6.22

---

## 1. 动机与现状

阶段 46 已把历史保留策略从 **env-only 常量** 提升为 **GUI 可配置 + 可持久化**，但只暴露了两个维度：

- `CACHE_KEEP_DAYS`（时间维度，默认 30 天）
- `CACHE_MAX_RECORDS`（数量维度，默认 200 条）

**缺口（第三维缺失）**：

1. **体积维度空白**：`prune()` 只按「过期天数 + 数量上限」清理。一条 1080p 视频结果与一张缩略图在数量上等价、在体积上相差三个数量级——**条数上限无法阻止磁盘被占满**。
2. **`HistoryRecord.file_size` 长期空置**：该字段早已存在，但仅阶段 37（视频）/ 阶段 40（PDF）回填；**图片结果从未回填**，导致任何基于体积的统计/清理都无从下手。
3. **无磁盘占用可见性**：用户无法回答「历史记录现在占了多少空间」，只能去文件管理器里翻 `cache/` 目录。
4. **无按体积的清理入口**：即便知道占满，也只能手动清空或提高条数上限，缺少「按体积上限自动收敛」的手段。

> 取舍说明：阶段 43 曾留下「清理孤儿成品图」的待办。本阶段选择 **按体积保留（删旧留新、保留成品图）** 而非「删孤儿文件」，理由是与阶段 46 的保留策略主线同构（同属「保留策略」家族、同一套确认守卫、同一处 UI 位置），且**不误删用户资产**——清理只清缩略图与索引条目，结果成品图一律保留。

---

## 2. 设计目标

- 补齐保留策略第三维：`CACHE_MAX_BYTES`（默认 5 GB，区间 100 MB ~ 100 GB），与既有两维构成「时间 / 条数 / 体积」三维。
- 让 `HistoryRecord.file_size` 对**图片**结果也回填，使体积成为一等公民数据。
- 新增 `get_stats()`：聚合历史结果磁盘占用（总量 + 按类型拆分），供历史页展示。
- 新增 `prune_by_size()`：**从最旧记录开始删除**，直至剩余总体积 ≤ 上限；只清缩略图，结果与成品图保留。
- 历史页新增「💽 磁盘占用」面板（5 秒定时刷新）与「💽 按体积上限清理」按钮，复用 `confirm_cb` 二次确认守卫。
- 设置页保留策略面板新增体积上限滑块，应用时**先按天数/条数清理、再按体积清理**。
- 全程零 torch，分层无反向依赖（`ui→services→core→utils→config`）。

## 3. 关键改动

### 3.1 config.py（第三维常量 + 白名单 + 校验器）

- 新增常量（紧随 `CACHE_KEEP_DAYS` 之后）：

  ```python
  CACHE_MAX_BYTES: Final[int] = _env_int(
      "CACHE_MAX_BYTES", 5 * 1024 * 1024 * 1024, 100 * 1024 * 1024, 100 * 1024 * 1024 * 1024
  )
  ```

  默认 5 GB，合法区间 **100 MB ~ 100 GB**，支持环境变量 `WME_CACHE_MAX_BYTES` 覆盖。
- `_USER_OVERRIDABLE_KEYS` 新增 `CACHE_MAX_BYTES`（白名单由 5 键扩为 **6 键**）。
- `_USER_OVERRIDE_VALIDATORS` 新增越界回退校验器：

  ```python
  "CACHE_MAX_BYTES": (
      lambda v: int(v)
      if int(v) in range(100 * 1024 * 1024, 100 * 1024 * 1024 * 1024 + 1)
      else 5 * 1024 * 1024 * 1024
  ),
  ```

  越上界（如 200 GB）或越下界（如 50 MB）均回退默认 5 GB，避免一个手滑的极端值把历史清空或形同虚设。
- 第 9.6 节 docstring 与 `_apply_user_overrides` 注释同步补充第三维说明。
- **沿用阶段 46 的时序加固**：`_apply_user_overrides()` 调用点仍位于 `config.py` **文件末尾**（全部常量定义之后），确保 JSON 读回值不被默认值覆盖。

### 3.2 services/cache_service.py（体积回填 + 统计 + 按体积清理）

- **`update_result_path(record, result_path, file_size=None)` 增强**：
  - 传 `file_size` → 直接采用（`int()` 失败记 0）；
  - 否则若 `result_path` 存在 → 现场 `os.path.getsize()`；
  - 均不可得 → 记 `0`，**不影响其它记录**（体积统计是尽力而为，不因单条失败中断）。
- **新增 `get_stats() -> dict`**：

  ```python
  {"total_bytes": int, "total_count": int,
   "by_kind": {kind: {"count": int, "bytes": int}}}
  ```

  体积取值优先级：`r.file_size > 0` → 现场 `getsize(result_path)` → `0`。遍历 `self._records` 一次性聚合，不做额外 IO 放大。
- **新增 `prune_by_size(max_bytes) -> int`**：
  - `max_bytes <= 0` 直接返回 0（防御：0 会被误读为「上限为零」而清空全部）；
  - 按 `ts` 升序（**最旧在前**）遍历，逐条扣减体积直至 `total <= max_bytes`；
  - 索引更新与 `_persist()` 在**锁内**完成；缩略图删除在**锁外**执行（`os.remove` + `OSError` 吞异常），与 `delete` / `prune` 既有范式一致；
  - **只清缩略图，结果成品图一律保留**；返回实际删除条数。

### 3.3 ui/tab_history.py（磁盘占用面板 + 按体积清理）

- 新增 `_fmt_bytes(n)`：B / KB / MB / GB / TB 人类可读格式化。
- 新增 `build_disk_usage_md()`：调 `_CACHE.get_stats()`，按 `image` / `video` / `pdf` 三类拼接 `history.disk_usage.*` 文案。
- `_record_detail` 对 `kind in ("image", "video")` 追加 `history.detail.size`（优先 `file_size`，否则现场 `getsize(result_path)`）。
- 新增 `prune_by_size_policy(compare, confirm)`：
  - `confirm=False` → 返回 `history.msg.confirm_needed`，**不调用清理**；
  - `confirm=True` → `_CACHE.prune_by_size(config.CACHE_MAX_BYTES)`，反馈 `prune_size_ok`（含 `{n}`）或 `prune_size_none`；
  - 返回**六元组** `(msg, gallery, pair, html, summary, gr.update(value=False))`，与 `prune_by_policy` / `delete_filtered` 完全对齐，可直接复用同一组 `outputs`。
- `build_history_tab`：在 `search_box` 后新增 `disk_usage` Markdown；在 `prune_policy_btn` 同 `Row` 新增 `prune_size_btn`（`variant="secondary"`）；接线 `prune_size_btn.click(...)`。
- **刷新策略（关键设计）**：新增 `gr.Timer(5.0).tick(fn=build_disk_usage_md, outputs=[disk_usage])`。

  > 为何用定时器而非在每个 handler 返回值里追加第 7 个元素：历史页已有 6 个 handler 返回六元组（`delete_selected` / `delete_filtered` / `clear_all` / `prune_by_policy` / `reprocess` / 筛选 / 搜索），逐个扩成七元组会**放大回归面**。定时器把「占用面板刷新」与各清理/删除 handler **解耦**，零侵入。

### 3.4 ui/tab_settings.py（三维应用）

- `apply_cache_config` 签名扩为 `(keep_days, max_records, max_bytes_gb, save_default)`：
  - 内部 `config.CACHE_MAX_BYTES = int(max_bytes_gb) * 1024 * 1024 * 1024`（滑块以 GB 为单位，避免用户直接面对字节数）；
  - 持久化 patch 增 `CACHE_MAX_BYTES`（合并式写入，不抹超分默认）；
  - 应用后**依次**执行 `_CACHE.prune()` 与 `_CACHE.prune_by_size(config.CACHE_MAX_BYTES)`，清理条数 `n = n_keep + n_size`；
  - 返回 `(快照 Markdown, 信息文案)`，信息文案用 `bytes="{cap} GB"` 填充占位。
- `build_snapshot_md` 调 `t("settings.snap.cache", ..., cap_gb=round(CACHE_MAX_BYTES / 1024**3))`。
- `cache_policy` Accordion 在 `cp_max_records` 后新增 `cp_max_bytes`（`gr.Slider(minimum=1, maximum=100, step=1)`），`cp_apply.click` 的 `inputs` 同步追加。

### 3.5 utils/i18n.py（中英双语键 + 自检）

- `settings.cache_policy` 增 `max_bytes_label` / `max_bytes_info`。
- `settings.snap.cache` 模板增 `{cap_gb}`；`settings.snap.msg.cache_applied` 增 `{bytes}`。
- `history` 增 `disk_usage.{title,total,kind}`、`prune_size_{btn,ok,none}`；`history.detail` 增 `size`。
- 自检区（`__main__`）循环键同步扩充，并新增占位渲染断言（`assert "GB" in t("settings.snap.cache", ...)`、`assert "MB" in t("history.detail.size", size="1.2 MB")`），中英双语各一组。

## 5. 测试（零 torch，全隔离）

`tests/test_cache_disk.py`（13 例），隔离范式镜像 `test_history_batch_delete.py`：
服务层用 `enabled_cache` fixture（重定向 `INDEX_PATH` 到临时文件 + 临时 `CacheService`），
UI 层用 `patched_cache` fixture（`monkeypatch.setattr(th, "_CACHE", fake)`，避免触碰真实历史索引）。

**1. 服务层**
1. `update_result_path` 传入 `file_size` 优先采用（不依赖文件存在）；
2. `update_result_path` 未传时从 `result_path` 现场 `getsize` 回填；
3. 缓存禁用时 `update_result_path` 为 no-op；
4. `get_stats` 聚合总量 + 按类型拆分（覆盖 `file_size` 分支与现场 `getsize` 分支）；
5. `prune_by_size` 体积收敛：3×100 B、上限 150 B → 删最旧 2 条、留最新 1 条；
6. `prune_by_size` 清理缩略图但**保留结果成品图**；
7. `prune_by_size` 未超上限时返回 0 且不动记录；
8. `prune_by_size(0)` / 负值返回 0（防「上限为零」误清空）。

**2. 配置层**
9. `CACHE_MAX_BYTES` 在 `_USER_OVERRIDABLE_KEYS` 白名单内；
10. 校验器越界回退（200 GB → 5 GB、50 MB → 5 GB；10 GB 原值通过）。

**3. UI 层**
11. `apply_cache_config(30, 200, 10, True)` 三维实时写入 + 先 `prune()` 再 `prune_by_size()`；
12. `prune_by_size_policy` 未确认拒绝执行且**不调用** `prune_by_size`；
13. `prune_by_size_policy` 确认后以 `config.CACHE_MAX_BYTES` 为上限调用清理并返回条数文案。

**4. i18n**：阶段 47 新键中英双语齐全（含 `disk_usage.*` / `prune_size_*` / `detail.size` 占位渲染）。

> 踩坑记录：UI 层用例若用 `try/finally` 手动还原 `config.*`，`finally` 会在**断言之前**执行，导致断言读到旧值而假失败；应改用 `monkeypatch.setattr(cfg, KEY, cfg.KEY)` 登记原值，由 pytest 在 teardown 自动还原。

## 6. 影响面与兼容性

- `prune()` 既有行为**完全不变**，体积维度是纯新增能力；
- `update_result_path` 新增**可选**第三参 `file_size=None`，既有调用方（阶段 37/40/45）无需改动；
- `apply_cache_config` 签名由 3 参扩为 4 参，唯一调用方是 `tab_settings` 内的 `cp_apply.click`，已同步 `inputs`；
- 历史页 6 个既有 handler 的返回值结构**未改动**（靠 `gr.Timer` 刷新占用面板），回归面最小；
- `config.user_overrides.json` 向后兼容：旧文件无 `CACHE_MAX_BYTES` 时走默认 5 GB，新保存自动合并；
- 沙箱约束：`prune_by_size` 缩略图清理沿用 `os.remove` + `OSError` 守卫（不使用 `shutil.rmtree`），与既有删除路径一致。
