# 阶段 49 —— 检测器过度检测修复设计

> 本阶段不是一个新功能，而是一次**缺陷修复 + 测试基线补齐**。
> 它修掉的是一个潜伏了 48 个阶段、能直接毁掉用户照片的严重缺陷。

---

## 一、缺陷描述

**现象**：把一张**没有任何水印**的照片交给自动检测，检测器会把大半个画面标记为「水印」，
随后修复算法把这片区域整体重绘——照片被彻底毁掉。

**量化基线**（`scripts/detector_diag.py`，三种合成底图 × 四个预设）：

| 底图 | 修复前误报率 |
|---|---|
| 纯渐变（无纹理） | 2.3% ~ 46.1% |
| 渐变 + 分形纹理 | **93.9% ~ 100%** |
| 类照片（纹理+光斑+暗角+噪点） | **87.3% ~ 99.9%** |

**根因不是某个参数调错了，而是判定逻辑本身不成立。**

---

## 二、根因分析

### 2.1 根因一：分位数阈值（主要）

半透明 / 平铺 / 网格三条通路的阈值都是这样取的：

```python
q   = 100.0 * (1.0 - 0.85 * sensitivity)
thr = np.percentile(score, q)
cand = score > thr
```

这是**分位数**，不是阈值。它恒定选中固定比例的像素，与图上到底有没有水印**完全无关**：

| sensitivity | 选中比例 |
|---|---|
| 0.55（多数预设） | 46.8% |
| 0.72（ai_faint_tiled） | 61.2% |

于是检测器**丧失了输出「无水印」的能力**——它永远会找出一片"分数最高的像素"。
这根本不是检测，是投降。

实测干净类照片底图的 score 中位数为 0.549、p99 为 2.077，分布几乎整个落进阈值下方。

### 2.2 根因二：包围盒填充掩码（放大约 2 倍）

`_regions_to_mask()` 用区域**包围盒**填充掩码。一条斜向文字笔画的包围盒面积
可达其自身的数十倍。实测候选密度 46.8% 时，最终覆盖率被放大到 **93.8%**。

更隐蔽的是：合并阶段（第 1508 行）**只保留区域列表、丢弃各策略算好的掩码**，
用包围盒重新生成——即使某个策略内部算出了精确形状，也在合并时被重新糊成矩形。

### 2.3 根因三：合并阶段的膨胀（再放大约 3 倍）

合并时对掩码做 `(5,5)` 椭圆核膨胀 **2 次**，即每个区域向四周各涨约 10px。
"膨胀一点点"在区域数很少时无妨，但平铺策略会产生数百个小连通域
（干净纹理图实测 746 个），这点"一点点"被成百次重复叠加，
实测把 11.9% 的候选密度推高到 28%。

### 2.4 根因四：边缘小字策略输出了不可能的框

`_projection_boxes()` 对每个投影命中段生成一个**横跨整条带**的包围盒。
实测产出 `640×6`（整幅宽的细条）与 `8×640`（整幅高的竖条）——绝不可能是文字。
在干净图上造成 0.8%~3.4% 误报；而真正的底部小字水印**反而没被这条策略命中**
（类照片底图上 edge_text 召回仅 14%，主要来自半透明通路）。

### 2.5 为什么这个缺陷能潜伏 48 个阶段

**唯一的理由是缺少基线测试。** 此前的检测器测试只验证「不报错、流程通、
覆盖率在 0~1 之间」，从未断言过一句最该断言的话：

> **一张没有水印的图，检测器应该输出空掩码。**

没有基线，缺陷就无法被测出来。本阶段的第一要务是补上这条基线
（`tests/test_detector_overdetection.py::test_clean_image_yields_near_empty_mask`）。

## 三、修复方案

### 3.1 绝对证据门限（替换分位数）

新判据是**两个绝对条件的交集**：

```
通过 = (|中值残差| ≥ DETECT_MIN_DELTA)  ∧  (|归一化残差| ≥ DETECT_SIGMA_K × σ稳健)
```

两个条件各堵一类失效模式，缺一不可：

| 条件 | 堵住的失效模式 |
|---|---|
| 绝对幅度（灰阶） | 平滑图 σ≈0 时，任何微小浮点涨落都算"多倍 σ" |
| 相对显著（×σ） | 纹理图的残差天然很大，必须用图自身的噪声尺度衡量 |

σ 用 **MAD 稳健估计**（`1.4826 × MAD`）。这一点很关键：若用标准差，
水印像素本身会抬高 σ，形成**自我 masking**——水印越强门槛越高，最终反而检测不到。
MAD 基于中位数，可容忍接近 50% 的污染，σ 始终反映背景噪声。实测在 10% 强污染下
MAD 给出 1.0（真实噪声）,而标准差给出 15+。

同时，`sensitivity` 的语义被修正为**直接控制统计门限**：

```
k_sigma = DETECT_SIGMA_K × (1.5 − sensitivity)
```

修复前它控制的是分位数，语义扭曲（调低敏感度不是"更严格"，而是"只保留分数最高的前 X%"）。

**参数扫描**（`k_sigma` 单一变量，min_delta 影响很小）：

| k_sigma | 误报率 | 召回率 |
|---|---|---|
| 1.5 | 8.83% | 60.46% |
| 2.0 | 2.91% | 56.17% |
| **2.5** | **0.78%** | **52.44%** |
| 3.0 | 0.18% | 47.12% |
| 4.0 | 0.00% | 33.07% |

取 **2.5** 为默认：误报率进入 <1% 的安全带，同时保住约一半召回。

### 3.2 形状感知掩码（替换包围盒填充）

新增 `_components_mask()`，只填连通域**自身像素**，再按需膨胀。
各策略的掩码现在会一路透传到合并阶段（`mask_parts` + `_collect()`），
不再被重建为包围盒。`DETECT_SHAPE_AWARE_MASK=False` 可一键回退旧行为，便于排查对比。

### 3.3 网格周期性判据重写

修复前用「阈值化二值图 → 行/列投影 → 一维自相关」判周期。实测该判据的区分度不足：

| 图 | 行列投影自相关 | 阈值 |
|---|---|---|
| 干净纹理图（应为"无周期"） | **0.55 ~ 0.60** | 0.35 |
| 真实网格水印 | 0.59 ~ 0.60 | 0.35 |

几乎无区分度——阈值化丢掉了幅度信息，随机散点的投影同样给出高相关。

改为在**连续残差场**上做二维 FFT 自相关（`_periodic_strength`）：

| 图 | 二维 FFT 自相关峰值 |
|---|---|
| 干净渐变 / 纹理 / 照片 | 0.211 / **0.052** / **0.043** |
| 网格水印（渐变 / 纹理 / 照片） | 0.833 / **0.119** / **0.188** |

纹理与照片两档（真实场景代表）分离度约 **2.3 ~ 4.4 倍**。阈值 `DETECT_GRID_MIN_ACF`
取 0.09，落在两簇之间。

**两个易错点（都踩过）**：

1. **可分离图案的二维峰落在坐标轴上。** 若 `g(x,y)=f(x)·f(y)`，则自相关也可分离，
   `acf(56,0)=a` 而 `acf(56,56)=a²`，因 `a<1`，峰必然在轴上（实测规则网格的峰是
   `(0,56)` 而非 `(56,56)`）。因此：
   - 判定"是否有周期"用二维峰（正确）；
   - 但**取周期必须沿两轴分别求**（`acf[:,0]` 与 `acf[0,:]`），否则只能折出一维。

2. **只要求一个方向有周期即可。** 要求两方向同时非零会把最常见的可分离网格全部漏掉。

### 3.4 周期折叠模板（提升网格掩码精度）

判定为网格后，修复前的做法是把所有通过门限的候选像素原样标记。问题在于门限在
纹理图上总会漏过 1%~2% 的噪声，它们与真正的网格单元混在一起被一并标记——
实测类照片底图误报率达 13.3%，IoU 反而比"不启用网格策略"时更低。

改为**按周期折叠**：把 N 个 tile 对齐叠加求平均，信号相干叠加（幅度不变）、
噪声随机相消（降为 1/√N），模板信噪比提升 √N 倍。再用模板自身的稳健 σ 作门限。

> **踩过的坑**：门限**不能**再除以折叠增益 `√N`。`_robust_sigma(template)` 测到的
> 已经是"平均之后的噪声"σ_field/√N，再除一次等于双重折扣，实测会让门限形同虚设、
> 模板处处超标，覆盖率被推到 28%。

折叠效果（网格用例 IoU）：

| 底图 | 无折叠 | 单轴折叠 | **双轴折叠** |
|---|---|---|---|
| 渐变 | 8.5% | 8.5% | **30.9%** |
| 纹理 | 14.0% | 14.0% | 11.6% |
| 照片 | 18.3% | 18.3% | **29.9%** |

### 3.5 边缘小字几何约束

`_projection_boxes()` 加两道约束：

1. **收缩**：在命中段内做交叉轴投影，把框收缩到墨迹的**实际横向范围**，而非铺满整条带；
2. **尺度**：文字行高需在合理区间内。尺度参照**带的长边**（横带长边≈图宽、竖带长边≈图高），
   不能用短边——640px 图的横带短边仅约 77px，会让上限小到 13px，连真实 22px 高的水印都被拒掉。

### 3.6 全局覆盖率上限（最后一道闸）

若合并后的掩码覆盖整图超过 `DETECT_MAX_COVERAGE_RATIO`（默认 30%），
按区域面积**从小到大**保留，直到覆盖率回落（小区域更像水印，大区域更像误报）。

**设计依据（产品层面的非对称风险）**：把大半个画面交给修复算法重绘 = 照片被彻底毁掉、
不可逆；而漏掉一小块水印只是残留瑕疵，用户还能手动补掩码。
**宁可漏检，不可滥杀。**

例外：全局渐变水印（`KIND_GRADIENT`）按设计整图标记，是用户在预设里主动选择的，
不做裁剪，否则 `ai_gradient` 会被这道闸彻底清空。

### 3.7 平铺增强通路的下限保护

`ai_faint_tiled` 等预设把敏感度拉到 0.72（k≈1.95），实测不划算：

| 门限下限 | 干净图误报 | 极淡平铺召回 |
|---|---|---|
| 1.95 | 3.81% | 7.39% |
| **2.20** | **1.52%** | **3.13%** |
| 2.50 | 0.48% | 1.15% |

放松到 1.95 要多付 2.3 个百分点的误报，只换来 4.3 个百分点的召回。
且该水印的绝对召回**在任何配置下都超不过 7.4%**——它的扰动只有约 9 个灰阶
（α≈0.09），在高纹理背景上本就低于本特征的检测极限。

**这是信息论限制，不是调参能解决的。** 默认取 2.2 作为下限。

## 四、被评估后否决的方案（留档）

### 4.1 带符号残差的空间相干性

**思路**：水印是加性叠加，残差符号在区域内一致；纹理是零均值噪声，符号交替相消。
定义 `coh = |boxFilter(signed)| / boxFilter(|signed|)`，期望水印区接近 1、纹理区接近 0。

**实测结果**（k 为相干性统计的窗口边长，分离度 = 水印区中位数 − 背景区中位数）：

| k | corner_logo | edge_text | grid | faint_tiled |
|---|---|---|---|---|
| 9 | −0.005 | −0.008 | −0.007 | −0.001 |
| 15 | +0.330 | +0.401 | +0.039 | −0.056 |
| 25 | +0.460 | +0.500 | −0.009 | −0.011 |

**结论**：对**实体水印**（corner_logo / edge_text）分离度良好（+0.33~+0.50），
但对**平铺/网格类**几乎无效（≈0）——此类水印极淡且平铺不规则，残差远低于纹理噪声。
而实体水印已由角落/LOGO 策略稳定处理（0.0% 误报）。
**故不引入**：收益已被覆盖，却要增加一条需要真实图回归的复杂通路。

### 4.2 直接实现 FFT 周期性检测（在绝对门限之前）

最初评估时，绝对证据门限尚未落地，曾考虑直接上 FFT 周期性检测。
实测它对 grid 有效（峰值 0.119~0.188 vs 干净图 0.043~0.052），
但对 faint_tiled 完全无效（峰值 0.041~0.045，与干净图的 0.043~0.052 无法区分）——
因为该水印的平铺经 30° 旋转后以 50% 步进重叠，破坏了严格周期性，无可增益可用。

**最终结论一致**：faint_tiled 类水印超出本特征表示的检测极限，诚实的失败方式是
"什么都没检测到"，而不是"把画面重绘三分之一"。

## 七、测试

新增 `tests/test_detector_overdetection.py`（23 例）：

1. **干净图基线**（3 底图 × 4 预设）：误报率必须 < 5%
2. **响应性**：加水印后覆盖率必须显著高于干净图（防止"恒返回空"蒙混过关）
3. **质量下限**：角落 LOGO / 网格的召回与精确率下限
4. `_evidence_gate`：双条件交集、纯噪声拒绝、MAD 抗污染
5. `_components_mask`：形状 vs 包围盒、面积过滤、膨胀
6. `_periodic_strength`：真周期 vs 随机纹理、退化输入、双轴周期
7. `_fold_template` / `_tile_out`：折叠降噪、退化周期
8. `_projection_boxes`：拒绝整幅暗带、定位文字行
9. 覆盖率上限：裁剪生效、渐变预设豁免
10. 配置自检与默认值区间
11. `DETECT_SHAPE_AWARE_MASK` 开关可回退

新增诊断工具 `scripts/detector_diag.py`：三种底图 × 四类水印，
输出误报率 / 召回率 / 精确率 / IoU，可导出 JSON。这是本阶段的**度量基础设施**——
没有它，缺陷既无法量化、修复也无法验证。

全量回归：**413 passed，6 skipped，0 failed**（修复前 396）。

## 八、遗留与下一步

1. **真实图片验证（最高优先级，待用户提供素材）**
   本阶段全部结论基于合成数据。合成纹理是刻意构造的高频噪声，可能比真实照片更恶劣，
   也可能在某些维度上不够真实。需 3~5 张真实带水印的 AI 生成图回归确认。
2. **极淡平铺水印仍是未解难题**
   召回上限约 7%，且代价不成比例。若要攻克，需要换特征表示
   （例如多尺度方向滤波、或引入学习型检测器），而非继续调阈值。
3. **`edge_text` 在类照片底图上召回仅 14%**
   边缘小字水印目前主要靠半透明通路兜底。若真实图回归确认这是短板，
   可考虑把绝对证据门限也引入边缘策略（当前仅用几何约束）。
