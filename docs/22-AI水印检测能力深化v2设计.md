# 阶段 22 · AI 水印检测能力深化 v2 设计

> 项目定位：本工具为**去除 AI 生成图片上的水印**（AI 绘图平台给出的可见水印/署名标识）专用。
> 合规底线：只处理用户**自己有权处理**的 AI 生成内容；去除第三方平台署名水印通常违反其服务条款，工具不鼓励该用途。

---

## 1. 阶段定位与范围

阶段 20 建立了「检测预设体系 + 平铺增强 + 底部搜索 + 四入口透传」；阶段 21 打通了「检测模式」下拉的四入口统一并新增 `ai_text_heavy` / `ai_faint_tiled` 两预设。

但检测**策略库本身**仍只有四类（半透明 / 角落 LOGO / 边缘小字 / 平铺增强衍生），对两类典型 AI 水印样式覆盖不足：

1. **网格状平铺水印**：规则排布的网格 / 点阵 logo（repeated lattice），低频、半透明、靠「周期性」才能稳定识别，普通残差阈值容易漏。
2. **全局渐变署名层**：整图叠加的平滑渐变（如整图轻微变亮 / 变暗的署名层），遍布全图、低频，无法用「局部连通域」定位。
3. **OCR 文字识别精度**：原 `EasyOCR` 取框后**不做置信度过滤**，且小字在低分辨率裁剪块上召回偏低。

**本阶段目标（用户选定方向：检测能力深化 v2）：**
1. 新增两类检测策略：**网格状平铺水水印**（`detect_grid_watermark`）、**全局渐变叠加水印**（`detect_gradient_watermark`），由 config 开关门控，默认关闭，不破坏既有默认行为。
2. **OCR 识别精度提升**：预处理放大（小图 2x 立方插值）+ 置信度过滤（`DETECT_OCR_MIN_CONFIDENCE`，默认 0.25）。
3. **检测命中率统计**：`DetectionStats` 数据结构（覆盖率 / 区域数 / 按类别计数 / 是否启用 OCR），UI 实时展示。
4. 新增两预设：`ai_grid`、`ai_gradient`，把新策略一键暴露给用户。
5. **修复合并逻辑缺陷**：多策略并行时小区域会被大区域「吞并」后误删（见 §6）。

**分层铁律严守**：`core` / `services` / `utils` 零 gradio 依赖；新策略与统计全在 `core.detector.py`，UI 仅调用并展示。

## 2. 新增检测策略

### 2.1 网格状平铺水印（`detect_grid_watermark`）
- 接口与 `detect_translucent` 一致：`(rgb, sensitivity, area_total, min_area_ratio, max_area_ratio) → (mask, regions)`。
- 残差计算沿用「中值背景估计 + 局部归一化」（`score = |gray - medianBlur| / local_std`）。
- **周期检测**：对 `marks` 行/列投影做自相关（`_dominant_period`），要求行、列方向都找到稳定周期（`6 ≤ period ≤ 0.6*边长`）且自相关强度 `min(sy, sx) > 0.3` 才判定为网格。
- 命中后把网格单元用 `KIND_GRID`（`"grid_watermark"`）标注，轻微膨胀覆盖单元边缘。
- 合成图验证：360×360 规则方块网格 → 检出 81 个 `grid_watermark` 区域，覆盖率约 0.20（仅单元，不含误报边框）。

### 2.2 全局渐变叠加水印（`detect_gradient_watermark`）
- 把灰度图粗采样到 256×256，对全体像素最小二乘拟合双线性平面 `z = a·x + b·y + c`。
- 判据（三者同时满足）：平面幅度 `√(a²+b²) > 12`、解释率 `explained = 1 - var_res/var_gray > 0.6`、残差标准差 `res_std < 32`。
- 命中后**整图标记**一个 `KIND_GRADIENT`（`"gradient_watermark"`）区域（置信度 = `explained`）。
- ⚠️ 该策略会整图修复，误触发风险高（普通带渐变照片也可能命中），**默认关闭**，仅由 `ai_gradient` 预设主动开启，且 UI 文案已提示「仅建议用于确认有渐变水印的图」。

### 2.3 门控与默认行为
- `detect_watermark_mask` 新增 `enable_grid: bool = config.DETECT_GRID_ENABLED`、`enable_gradient: bool = config.DETECT_GRADIENT_ENABLED`。
- 两开关默认 `False`（config `DETECT_GRID_ENABLED` / `DETECT_GRADIENT_ENABLED` 默认 `False`），**默认检测行为完全不变**。
- 预设 `ai_grid` / `ai_gradient` 经 `DetectionPreset.resolve()` 把对应开关透传，实现「预设开、默认关」。

## 3. OCR 文字识别精度提升

`_ocr_boxes_in_patch(rgb_patch, px, py)` 增强：
1. **预处理放大**：当 `config.DETECT_OCR_UPSCALE` 为真且裁剪块长边 `< 640` 时，先把 `bgr` 2x 立方插值放大再识别，识别框除以 `scale` 映射回原块坐标，提升小字召回。
2. **置信度过滤**：丢弃 `item[2] < config.DETECT_OCR_MIN_CONFIDENCE`（默认 0.25）的低置信框，抑制背景误报。
3. 失败安全不变：reader 为 `None` 或无 OCR 时返回 `[]`，沙箱缺 EasyOCR 路径不受影响。

## 4. 检测命中率统计（`DetectionStats`）

- 新增 `@dataclass DetectionStats`：`mask_pixels / coverage_ratio / region_count / by_kind(Dict[str,int]) / used_ocr`。
- `compute_detection_stats(mask, regions, area_total, used_ocr)`：纯 numpy，零 gradio 依赖。
- `DetectionResult` 新增 `stats: Optional[DetectionStats]`（合并阶段末尾统一计算并附上）。
- **类别保留**：合并后区域保留各自 `kind`，可视化按 `_REGION_COLORS` 着色，统计按类细分（`translucent / corner_logo / edge_text / ocr_text / grid_watermark / gradient_watermark`）。

### 4.1 UI 展示
- `ui/components.build_detection_stats_markdown(stats)`：把 `DetectionStats` 渲染为 Markdown（含「🔍 检测命中率」标题 + 覆盖率 / 区域数 / 按类别命中 / OCR 状态）。
- `ui/tab_auto`：新增 `detect_stats_md = gr.Markdown`（注册 `detect.stats.placeholder`），`process_auto_detect` 返回四元组 `(preview, editor, status, detect_stats_md)`，`detect_btn.click` 的 `outputs` 增加该组件。
- `ui/tab_batch`：`on_progress(0.35, ...)` 进度日志补充覆盖率百分比。
- i18n：`detect.stats.*`（label/placeholder/coverage/regions/by_kind/kind_sep/ocr_on/ocr_off/none）与 `detect.kind.*`（六类标签）双语；`_kind_label()` 通用映射任意 `KIND_*`。

## 5. 新增预设

内置预设数由 6 → 8（`core/detection_presets._BUILTIN_PRESETS`）：

| 预设名 | 展示名 | sensitivity | enable_grid | enable_gradient | 其余策略 | 适用场景 |
|---|---|---|---|---|---|---|
| `ai_grid` | AI 网格水印 | 0.6 | **True** | False | 全策略 + 平铺增强 | 规则网格 / 点阵水印，专治 repeated lattice |
| `ai_gradient` | AI 渐变水印 | None | False | **True** | 其余全部关闭 | 整图平滑渐变署名层（整图修复，慎用） |

> `resolve_preset` 仅透传非 None 字段；`ai_gradient` 显式关闭 `translucent/corner/edge/enhance_tiled`，仅留渐变，避免多策略互相干扰。

## 6. 合并逻辑缺陷修复（重要行为修正）

### 6.1 问题
原合并块对「合并后掩码」做连通域分析，再按组件面积 `[min_area, max_area]` 过滤，保留「中心落在保留组件内」的区域。
当**多策略并行**（如 `ai_grid` 预设同时开启 半透明/角落/边缘/网格）时，角落或边缘策略可能在网格图上误标出**一块大连通域**（如整圈边框），把众多小网格单元**吞并**进同一巨型组件；该巨型组件面积超过 `max_area_ratio` 被整体丢弃，导致**所有网格小区域一并被删**——即便 `enable_grid=True` 也检不出网格（`detect_watermark_mask(grid, preset="ai_grid")` 返回空集）。

### 6.2 修复
改为**逐区域判定**，依据区域自身（按类别放宽的）包围盒面积：
- 区域中心必须落在掩码内；
- `KIND_GRADIENT` 直接保留（整图标记，不受 `max_area` 约束）；
- 其余类别：`kind_min ≤ (w·h) ≤ kind_max` 才保留（`KIND_GRID` 的 `kind_min` 放宽到 `area_total * min_area_ratio * 0.25`，与 `detect_grid_watermark` 一致）；
- 最终掩码 = **仅取保留区域 bbox 内的合并掩码**（`final_mask[y0:y1,x0:x1] |= mask[...]`），既保留精确形状，又**丢弃被大块吞并的误报区域**（如边缘误标的整圈边框）。

修复后：`detect_watermark_mask(grid, preset="ai_grid")` 正常返回 81 个 `grid_watermark` 区域，覆盖率约 0.20（仅单元，误报边框被剔除）。

## 10. 坑点记录

1. **i18n 重复键陷阱**：首次向 `utils/i18n.py` 追加 `detect.kind` / `detect.stats` 时误写成**第二个顶层 `"detect"` 键**，Python dict 字面量后键覆盖前键，导致原有 `detect.preset` 整个丢失、所有预设标题解析回退为 key。已合并进首个 `detect` 块修复（zh-CN / en-US 双语言各修一处），并扩充 `__main__` 自检断言覆盖全部 8 预设与 `detect.kind` / `detect.stats` 各键。
2. **合并吸收误删**：见 §6，多策略并行下小区域被大连通域吞并后随 `max_area` 过滤整体丢失；必须以区域自身面积判定 + 仅取保留区域 bbox 掩码解决。
3. **OCR 坐标映射**：放大识别后 `EasyOCR` 返回坐标处于放大空间，必须除以 `scale` 映射回原块坐标，否则框错位。
4. **默认行为保护**：新策略默认 `False`，仅靠预设开启；既有默认 `detect_watermark_mask`（无 `enable_grid/gradient`）返回结果与阶段 21 完全一致（测试 `test_detect_backward_compat_default` 守护）。
