# 阶段 23 · AI 水印检测能力深化 v3 设计

> 项目定位：本工具为**去除 AI 生成图片上的水印**（AI 绘图平台给出的可见水印/署名标识）专用。
> 合规底线：只处理用户**自己有权处理**的 AI 生成内容；去除第三方平台署名水印通常违反其服务条款，工具不鼓励该用途。

---

## 1. 阶段定位与范围

阶段 20 建立「检测预设体系 + 平铺增强 + 底部搜索 + 四入口透传」；阶段 21 打通「检测模式」下拉四入口统一；阶段 22 新增网格 / 渐变两类策略 + OCR 精度提升 + 命中率统计（`DetectionStats`）。

但检测能力仍有两类缺口：

1. **实体 LOGO 轮廓水印无覆盖**：很多 AI 平台在图角放**实心品牌标识**（实心图标 / 字母组合），它不是半透明、不是文本、也不是规则网格，而是「高实心率的闭合实心形状」——既有四类策略（半透明 / 角落 LOGO/文字 / 边缘小字 / 网格 / 渐变）都无法稳定命中。
2. **网格 / 渐变策略误报偏高**：阶段 22 的网格检测在「随机噪声」下虽靠周期判据大抵不触发，但缺乏覆盖占比带约束，对稀疏噪点 / 近整图纹理仍可能误判；渐变判据用硬编码 `0.6`，无法按环境调参。

**本阶段目标（用户选定方向：检测能力深化 v3）：**
1. 新增检测策略 **实体 LOGO 轮廓水印**（`detect_logo_watermark`），由 `enable_logo` 门控，**默认关闭**，不破坏既有默认行为。
2. **网格 / 渐变误报抑制**：以 config 驱动阈值，网格加「覆盖占比带」约束，渐变硬编码 `0.6` 改为 config 项，提升可调性、降低误报。
3. **批量页 / 媒体页命中率统计聚合**：在阶段 22 单图 `DetectionStats` 基础上，UI 层新增聚合助手，把多图统计合并展示；服务层 `pdf_service` / `video_service` 透传每页 / 每帧 `stats`。
4. 新增预设 `ai_logo`，把 LOGO 检测 + 角落 + 半透明 + 底部搜索一键暴露。
5. 全部新行为**默认关闭 / 仅预设开启**，严守「默认检测向后兼容」铁律。

**分层铁律严守**：`core` / `services` / `utils` 零 gradio 依赖；新策略与统计聚合全在 `core.detector.py` 与 `ui/components.py`，UI 仅调用并展示。

## 2. 新增检测策略：实体 LOGO 轮廓水印

### 2.1 算法（`detect_logo_watermark`）
- 同 `detect_translucent` 接口：`(rgb, area_total, min_area_ratio, max_area_ratio, solidity_threshold=…, max_aspect=…) → (mask, regions)`。
- 流程：
  1. 灰度化 → `Canny(gray, 50, 150)` 取闭合边界 → `dilate(3×3, 1)` 把断口连起来，避免轮廓破碎导致实心率失真。
  2. `findContours(RETR_EXTERNAL, CHAIN_APPROX_SIMPLE)` 取外轮廓。
  3. 对每个轮廓：`area = contourArea(cnt)`；`min_area ≤ area ≤ max_area` 过滤（面积上下限由 `min_area_ratio`/`max_area_ratio` × `area_total` 推出）。
  4. `hull = convexHull(cnt)`，`solidity = area / contourArea(hull)`；`solidity < solidity_threshold` 丢弃（实心形保留，空心环 / 镂空字丢弃）。
  5. 包围盒宽高比 `aspect = max(bw,bh)/min(bw,bh)`；`aspect > max_aspect` 丢弃（细长条不判为 LOGO）。
  6. 命中后登记 `DetectionRegion(kind=KIND_LOGO, confidence=solidity)`，并用**原始轮廓** `fillPoly` 填进掩码，保留 LOGO 精确形状（而非仅包围盒）。
- 合成图验证：300×300 浅灰底 + 角落实心圆(半径35) + 角落实心方块 → 检出 2 个 `logo_watermark` 区域；纯色 / 平滑图返回空；细长实心条(5×260, aspect≈52) 被宽高比过滤拒掉。

### 2.2 门控与默认行为
- `detect_watermark_mask` 新增 `enable_logo: bool = config.DETECT_LOGO_ENABLED`（默认 `False`）。
- 预设解析：若 `DetectionPreset.enable_logo is not None`，`resolve()` 透传 `kw["enable_logo"]`；否则走 `enable_logo` 字面量。
- 默认 `DETECT_LOGO_ENABLED=False` → 既有 `detect_watermark_mask()`（不传 `enable_logo`）返回结果与阶段 22 完全一致，**不出现 `KIND_LOGO`** 区域（测试 `test_logo_gating_default_off` 守护）。

### 2.3 合并块面积上下限（与阶段 22 修复一致）
阶段 22 已把「合并后按大连通域过滤」改为「逐区域按类别放宽的包围盒面积判定」。`KIND_LOGO` 使用**专属**上下限：
- `kind_min`：`area_total * config.DETECT_LOGO_MIN_AREA_RATIO`（默认 0.0003，比通用的更宽松，允许小角标）。
- `kind_max`：`area_total * config.DETECT_LOGO_MAX_AREA_RATIO`（默认 0.15，比通用的更紧，抑制整块误报）。
- `KIND_GRID` 维持阶段 22 的 `min_area_ratio * 0.25` 放宽。
- 最终掩码 = 仅取保留区域 bbox 内的合并掩码，既保留精确形状，又丢弃被大块吞并的误报。

### 2.4 误报风险与抑制
该策略对「实心大块物体」（人脸色块、纯色衬衫、图标状装饰）也可能误报；通过三重抑制兜底：
- 默认关闭（仅 `ai_logo` 预设开启）；
- 面积上限（默认整图 15%）+ 宽高比上限（默认 8×）；
- 实心率阈值（默认 0.85）过滤镂空 / 文字类。

## 3. 网格 / 渐变误报抑制（config 驱动阈值）

### 3.1 网格覆盖占比带（阶段 23 新增）
`detect_grid_watermark` 在形态学开运算后、周期检测前新增覆盖占比带检查：
```python
cov = float(np.count_nonzero(marks > 0)) / float(max(1, marks.size))
if cov < config.DETECT_GRID_MIN_COVERAGE or cov > config.DETECT_GRID_MAX_COVERAGE:
    return 空
```
- 太稀疏（`cov < 0.003`）→ 接近孤立噪点，不像规则平铺；
- 太密集（`cov > 0.6`）→ 更像全局纹理而非平铺水印；
- 周期判据 `min(sy, sx) > config.DETECT_GRID_MIN_STRENGTH`（默认 0.35，原为硬编码 0.3）。

### 3.2 渐变解释率阈值外置
`detect_gradient_watermark` 判据中 `explained > 0.6` 硬编码改为 `explained > config.DETECT_GRADIENT_MIN_EXPLAINED`（默认 0.6），可按环境调参。

### 3.3 抑制效果验证
- 随机噪声（`np.random` 整图）：网格检测返回 0 区域（无规则周期）；渐变检测返回 0 区域（残差平滑度低、`res_std` 大）。
- 纯色图：渐变检测返回 0 区域（方差不足）。
- `DETECT_GRID_MIN_STRENGTH` 调到 0.99：弱周期条纹被高阈值抑制（即便偶有周期，高阈值也兜得住，稳定不报错）。

## 4. 批量 / 媒体页命中率统计聚合（阶段 23 新增）

阶段 22 的 `DetectionStats` 只服务单图（auto 页）。批量 / 媒体页需要「多图汇总」，故在 UI 层新增聚合助手，避免各页重复逻辑、且不污染核心层。

### 4.1 UI 层聚合助手（`ui/components.py`）
- `aggregate_detection_stats(items)`：延迟 `from core.detector import DetectionStats`，累加 `mask_pixels` / `region_count` / 各类别命中（`by_kind`），OCR 任一为 `True` 即记为启用，覆盖率取各图均值；无任何有效统计（全 `None`）返回 `None`。
- `build_aggregate_detection_stats_markdown(items)`：`aggregate_detection_stats` → `build_detection_stats_markdown`（复用阶段 22 的渲染，标题「🔍 检测命中率」），空时显示占位。
- 延迟 import 设计：组件库**不**在导入期硬依赖 `core`，仅在运行时按需加载，守住「组件库零核心期依赖」边界。

### 4.2 服务层 stats 透传
- `services/auto_pipeline.process_image`：自动模式捕获 `det_stats = result.stats`，在 `skipped` 与 `success` 返回 dict 均加 `"stats"` 键（manual 模式为 `None`）；对既有调用方无影响。
- `services/pdf_service`：`PageResult` 增加 `coverage_ratio / by_kind / used_ocr / stats`；`process_pdf` 循环里 `pr.stats = core.get("stats")` 并填充前三项。
- `services/video_service`：`VideoResult.frame_stats: List[object]`；检测帧 / 复用帧分支均 `result.frame_stats.append(core.get("stats"))`。

### 4.3 页面接线
- `ui/tab_batch`：新增 `batch_detect_stats = gr.Markdown`（占位 `build_detection_stats_markdown(None)`，注册 `detect.stats.label`）；`_process_one` 把 `res.stats` 写入 `detect_stats` 并返回 dict 携带；`run_batch` 维护 `_agg_stats` 列表，DONE 分支追加，3 个 `yield` 改为 5 元组（追加 `_agg_stats_md()`），2 个提前 return 改为 5 元组（追加 `build_detection_stats_markdown(None)`）；`run_btn.click` 的 `outputs` 增加该组件。
- `ui/tab_media`：`run_pdf` 返回 2→3 元组（追加 `stats_md`，成功路径 `build_aggregate_detection_stats_markdown([pr.stats for pr in res.pages])`，失败/异常/无文件返回 `build_detection_stats_markdown(None)`）；`run_video` 返回 3→4 元组（追加 `stats_md`，成功路径 `build_aggregate_detection_stats_markdown(res.frame_stats)`）；新增 `pdf_detect_stats` / `video_detect_stats` 两个 `gr.Markdown` 并接入对应 `click` 的 `outputs`。

## 9. 坑点记录

1. **i18n 默认语言与测试断言**：单测下 `utils.i18n` 默认语言可能为 `en-US`（受 `config.UI_LANGUAGE` 或持久化状态影响），`build_detection_stats_markdown(None)` 会返回英文「Detection Hit-Rate」占位。聚合 Markdown 测试须先 `set_language("zh-CN")` 再断言中文标签，否则 `in md` 失败。
2. **浮点均值容差**：聚合覆盖率取各图均值，`(0.1+0.2)/2 = 0.15000000000000002`，断言须用 `pytest.approx(0.15)`，否则 `== 0.15` 因浮点误差失败。
3. **默认行为保护**：`enable_logo` 默认 `False`，仅靠 `ai_logo` 预设开启；既有 `detect_watermark_mask()`（无 `enable_logo`）返回结果与阶段 22 完全一致（测试 `test_logo_gating_default_off` 守护）。
4. **组件库零核心期依赖**：`ui/components` 聚合助手用延迟 `from core.detector import DetectionStats`，避免在导入 `ui/components` 时就把检测核心拉进来（模块导入顺序 / gradio 上下文无关的考量）。
5. **服务层 stats 透传向后兼容**：`process_image` 仅在返回 dict 加 `"stats"` 键、对既有调用方无影响；批量页独立维护 `_agg_stats` 列表，媒体页从 `PageResult.stats` / `VideoResult.frame_stats` 取数，各页互不影响。
