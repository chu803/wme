# 阶段 71 · 导出侧透明通道保真与往返保真审计设计

> 目标：审计「**输出/保存侧**」——阶段 60/68 已把「内存里的修复结果」纳入真值审计，但内存结果
> 与用户最终拿到的文件之间还有**一次编码**（`save_image`），这一层从未被审视。
> 交付：透明通道跨格式策略统一（保留/合成）、AVIF 路径一致化、
> `tests/test_output_fidelity.py`（15 例）、2 个新配置常量。

---

## 1. 动机：输出文件是用户真正拿到的东西

用户旅程的最后一步是把内存里的 `result_rgb`（+ 可选 alpha）经 `save_image` 编码写盘。此前
阶段 60/68 审的是**像素**（修复保真、交付链保真），本阶段审的是**编码**：格式能力、透明通道、
往返损耗。触发点是一个真实的用户可见症状：**导出 JPG 后，原图透明区域出现彩色色块**。

## 2. 审计发现

### 2.1 透明通道被静默丢弃并「显形」（缺陷）

`save_image` 原实现：**只在** `out_fmt == "PNG" and PNG_KEEP_ALPHA` 时写 4 通道，
其余情况把原始 RGB **原样**写出。而真实 PNG 的透明区域往往驻留不可见 RGB（例如被擦掉的
Logo 原色、图层合成前的底色）。实测（透明区隐藏 RGB = 红块）：

| 导出格式 | 修复前 | 用户看到 |
|---|---|---|
| PNG | 4 通道（alpha 保留） | ✅ 正常 |
| **JPG** | 3 通道，透明区 = **隐藏红块原样显形** | ❌ 凭空多出彩色块 |
| **WEBP** | 3 通道，同上 | ❌ 同上（**本可携带 alpha**） |
| **TIFF** | 3 通道，同上 | ❌ 同上（**本可携带 alpha**） |

**关键事实**：实测 OpenCV 的 `.png` / `.webp` / `.tiff` 编码器都能写 4 通道并原样保留 alpha
——即 WebP/TIFF 的 alpha 丢失是**不必要的**。

### 2.2 「声明 ≠ 实现」（与阶段 70 同族）

`PNG_KEEP_ALPHA` 的配置注释早先写着「**False：透明区域统一填充为白色**」，但实现从未如此——
关掉开关后同样只是丢 alpha、暴露隐藏 RGB。`requirements.txt` 承诺的 EXIF 校正（阶段 70）+
这里的白底合成，两处「依赖声明里的承诺」都落空了。

### 2.3 AVIF 路径不一致

`_save_avif` 先试 cv2（**不携带 alpha**）再回退 Pillow（携带）——有透明通道时若 cv2 成功，
alpha 就丢了，与主路径的语义相悖。

## 3. 修复

### 3.1 透明通道策略（`save_image`）

```
alpha 可用（尺寸匹配）？
  ├─ 是 且 PNG_KEEP_ALPHA 且 目标格式 ∈ OUTPUT_ALPHA_FORMATS（PNG/WEBP/TIFF）
  │      → 写出 4 通道，alpha 逐位保留
  └─ 否 → 若确有 alpha：先按 out = rgb×a + bg×(1−a) 合成到 OUTPUT_FLATTEN_BG_COLOR（默认白）
          再写出（**绝不直接丢弃 alpha**）
```

- **WebP/TIFF 升级为保留 alpha**（cv2 实测支持）——不仅是 JPG 的合成修复；
- `PNG_KEEP_ALPHA=False` 的语义**落实为配置注释承诺的"合成到背景色"**（原先 = 丢弃并显形）；
- alpha 尺寸不匹配 → 告警并忽略（不误用、不崩溃）。

### 3.2 AVIF 路径一致化

`_save_avif` 重构为三级回退：**有透明通道时优先走 Pillow（RGBA）**；cv2 路径仅在无 alpha
（或 Pillow 不可用）时使用；最终降级 PNG 时同样先合成（`_save_avif_via_pillow` 抽出为独立
函数，三级回退共用）。

### 3.3 新增配置（2 个）

- `OUTPUT_ALPHA_FORMATS = ("PNG", "WEBP", "TIFF")`——支持透明的导出格式清单
  （以「cv2 编码器实测能写 4 通道」为准，而非拍脑袋）；
- `OUTPUT_FLATTEN_BG_COLOR = (255, 255, 255)`——合成背景色。

## 4. 验证

| 检查 | 结果 |
|---|---|
| alpha 保留（PNG/WEBP/TIFF） | `mode == RGBA`，alpha 通道**逐位等于输入**；隐藏 RGB 仍在原位（被 alpha 遮蔽，属正常存储） |
| JPG 合成 | 透明区 = 白底（±2 编码噪声）；**隐藏 RGB 不得显形**（缺陷护栏：全图搜索隐藏色的不透明像素，一个都不允许） |
| `PNG_KEEP_ALPHA=False` | PNG 也合成到背景（落实声明语义） |
| 往返保真 | **PNG/TIFF 逐位无损（100 dB）**；JPG/WebP q95 = 44.5~51.8 dB（测试下限 40 dB，留 4.5 dB 余量） |
| 尺寸 | 4 种格式输出尺寸均与输入一致 |
| AVIF | 有 alpha 时优先 Pillow（RGBA）；两级回退均不暴露隐藏 RGB |
| alpha 尺寸不匹配 | 告警并忽略，不崩溃 |

护栏 `tests/test_output_fidelity.py` **15 例**。

## 5. 边界（诚实声明）

- **ICC 色彩配置不保留**（延续阶段 70 的边界）：Display-P3 等宽色域输入导出后可能偏色；
  正确修法需要色彩管理（`ImageCms` 转换），留待有真实宽色域样本时再评估；
- WebP 为有损编码：透明区的隐藏 RGB 存在 ±1 量化噪声（该区域被 alpha 遮蔽，视觉无关，
  测试已按此放宽）；
- 动图导出不适用（输入侧已在阶段 70 拒绝动图）。

## 6. 经验沉淀（已并入 MEMORY 第 16 条）

16. **「保存」也是一条要审计的转换链（71）**：像素层面的正确性 ≠ 文件层面的正确性。
    输出编码至少要回答三个问题：① **格式能力**（它支持透明吗？实测，别背书）；
    ② **隐藏信息**（透明区的 RGB 常驻留不可见内容，丢 alpha 就是把它公之于众）；
    ③ **往返损耗**（无损格式必须逐位相等，有损格式要设 PSNR 下限）。
    本阶段与阶段 70 再次印证：**「配置注释/依赖声明里承诺的行为」是最便宜的审计入口**
    （PNG_KEEP_ALPHA 声称"填白底"实为"丢 alpha"）。
