# 阶段 326 · 对外数字据实核一遍，并给它们装上防腐守卫

> 日期 2026-10-25 · 产物 `tests/test_scorecard_fresh326.py`（6 例）、
> `docs/quality/product_scorecard.json`（scale + engineering 两处数字刷新）、`CHANGELOG.md` 头部

## 一、为什么做

325 之后顺手想核对一件事：「我们对外说的项目规模，还是真的吗？」
一查就是三处脱节，而且**没有任何东西在管**（`tests` 里原先没有一个测试引用过记分卡）：

| 声明处 | 写着 | 实测 |
|---|---|---|
| `CHANGELOG.md` 第 3 行 | 逐阶段文档「共 118 份」 | `ls docs/*.md \| wc -l` = **284**（含 INDEX） |
| 记分卡 `scale.docs` | 246 | 284 |
| 记分卡 `scale.test_cases` / `dimensions[4].metrics.test_cases` | **2504**（两处同值） | `pytest --collect-only -q` 求和 = **3359** |
| 记分卡 `scale.test_files` | 219 | **242**（`ls tests/test_*.py \| wc -l`） |
| 记分卡 `scale.src_loc` | 33200 | **36382**（core+services+ui+utils+cli+api+config+main） |
| 记分卡 `scale.test_loc_approx` | 26000 | **48257**（`tests/test_*.py`；含 conftest 则 48368） |
| 记分卡 `scale.scripts` | 32 | **49** |

更要紧的是：**同一个事实存了两份副本**，而且两份已经互相打脸——
`scale.docs=246` 与 `dimensions[engineering].metrics.docs=280` 不一致。

## 二、为什么这些数字值得单独管

`purpose` 字段自己写着「供每个阶段后刷新」，`grades`/`dimensions` 是要给机器读的对外承诺。
数字烂掉比虚报更糟的地方在于：**读的人无法判断哪一条是真的**，于是整张记分卡失去效力。
而它烂掉的方式很安静——没有人改它，只是每次新增都不再顺手更新。

## 三、守卫的形态（刻意不写死等号）

`tests/test_scorecard_fresh326.py` 6 例：

1. **两处副本必须一致**（`scale` vs `dimensions[engineering].metrics`）——先把「各说各话」钉死；
2. `docs` 声明值 ≤ 实测 +1，且不得落后实测 **25%** 以上；
3. `test_files` 同上（严格 ≤ 实测）；
4. `test_cases` 夹在 **`def test_` 条数** 与 **该条数 ×2** 之间。
   为什么不直接用真实收集数：`pytest --collect-only -q` 要 1~2 分钟，不该塞进单测。
   实测比值 **3359 / 2565 = 1.31** ⇒ 上界取 ×2 有充足余量，而下界正好能抓住过期值
   （旧的 2504 < 2565，**余量仅 61**，注释里写明这条下界是紧的）；
5. `CHANGELOG` 头部那句「共 N 份」与实测同数量级（±25%）；
6. 结构前提断言（`dimensions` 里必须有 `id=engineering`，字段齐备）——结构变了数字比较就没意义。

**为什么不写死等号**：文档数每加一篇就动。等号会让每个阶段无谓地红一次，
然后被人调高容差或直接删掉守卫——那才是真正的损失。方向（不许虚报）+ 量级（不许腐烂）
双断言才留得住。

## 四、诚实边界

- 守卫用的是**代理量**（`def test_` 条数）而非真实收集数，所以它只能证明「声明值没低于下界 /
  没高过上界」，不能保证 `test_cases` 精确。要精确值仍须跑 `--collect-only`。
- LOC 的口径我在 JSON 里写清了**含哪些文件**（`src_loc` 不含 `scripts/` 与 `tests/`）。
  没写清口径的 LOC 数字没有意义——同一棵树换个口径能差 30%。
- `audited_modules=45` 这次**没动**：它没有可机械复测的定义（AUDITED_SINCE 表的口径另说），
  与其编一个数，不如留着不动并知道它没被验证。
- **`test_cases` 下界是紧的**：实测 `def test_` = 2565，而真实收集 = 3359（比值 1.31）。
  被抓住的那个过期值 2504 距下界只有 **61**——所以将来若有人大量删除参数化，
  这条会先红；正确反应是**去重跑 `--collect-only` 校正口径**，不是把下界调低（LESSONS #309）。
