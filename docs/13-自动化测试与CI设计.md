# 阶段 13：自动化测试与 CI 设计文档

> 目标：把前 12 个阶段分散在各模块 `__main__` 的自检，整合为一套可重复运行的 **pytest 测试套件 + 本地 CI 脚本**，防止后续改动造成回归。
> 核心理念：**离线可用、零 torch 依赖、四入口（GUI/CLI/库/REST）共用同一份动态清单的回归护栏**。

---

## 一、为什么需要

前 12 阶段已建立完整功能，但校验手段是「各自 `python xxx.py` 跑自检」，存在三点隐患：

1. **分散**：9+ 个模块自检互不关联，CI 无法一键跑全。
2. **人工**：没有统一入口与通过/失败判定，新人接手无从验证。
3. **依赖盲区**：自检默认假设 torch 已装、模型已下载；离线环境（如本开发沙箱）下 LaMa 路径不可测，但 OpenCV 引擎、插件、模型管理、API/CLI/UI 装配**完全可测**。

阶段 13 用 pytest 把这些能力固化下来，并明确标注「需要 torch / 需要网络」的用例以便 CI 跳过。

---

## 二、测试分层架构

```
tests/
├── test_config.py          单元测试：配置校验 + env 辅助函数
├── test_plugins.py         单元测试：插件注册表（动态引擎清单 / 边界）
├── test_model_manager.py   单元测试：模型管理（注册/切换/校验/回滚，零文件）
├── test_inpainter.py      端到端：OpenCV / demo_model / auto 引擎真实修复
├── test_cli.py            集成：CLI 模型子命令（子进程调用）
├── test_api.py            集成：REST/库层 get_capabilities / 模型管理函数
├── test_ui.py             集成：build_app 装配 + 引擎下拉一致性
└── test_legacy_selfcheck.py  遗留收敛：逐模块运行 __main__ 自检（子进程）

conftest.py                 fixtures：合成图/掩码、active 还原、cli_run 子进程
pytest.ini                 标记(torch_required/network/slow) + 超时 + testpaths
requirements-dev.txt       测试依赖（pytest / pytest-timeout / pytest-cov）

test.bat / test.sh         本地 CI 脚本（离线跑全套，安装依赖→pytest→汇总）
```

**三层**：单元（纯函数/类）→ 集成（CLI/API/UI 真实入口）→ 遗留收敛（复用既有 `__main__` 自检，避免重复造轮子）。

## 三、覆盖范围与「不依赖 torch/网络」策略

| 测试对象 | 覆盖点 | 不依赖 torch 的做法 |
|---------|-------|-------------------|
| config | validate_config / snapshot / `_env_bool`·`_env_list`·`_env_json` | 纯 Python，离线直接测 |
| plugins | 动态清单含 demo_model、has_engine 边界、注册/清理隔离 | 纯 Python 注册表 |
| model_manager | 注册/列出/active 切换/缺失判定/校验/回滚 | **monkeypatch 模拟文件存在性**，全程不创建真实权重文件（详见第四节坑点） |
| inpainter | opencv / demo_model / auto 引擎端到端修复、空掩码报错 | 走 OpenCV 引擎（CPU 可用），用纯 numpy 合成图，不碰 LaMa |
| cli | --list-engines / --list-models / --verify-model(失败码) / --set-model(成功+失败码) | 子进程跑 CLI，不触发下载 |
| api | get_capabilities 含 engines+models、list/verify/set_active 模型函数 | 内存态调用 |
| ui | build_app 装配 >0 块、UI 下拉与注册表/API 同源 | gradio 装配，不加载模型 |
| 遗留自检 | config/plugins/model_manager/inpainter/image_utils/mask_generator/detector/theme/components | 子进程运行既有 `__main__`，离线可用者全收 |

**被门控跳过的用例**：`test_inpainter::test_lama_engine_end_to_end` 标记 `torch_required`，离线 CI 用 `-m "not torch_required and not network"` 自动排除（共 1 例，装好 torch 后才会运行）。

**实测分布**：46 个用例总数，其中 1 个 torch 门控 → **离线实际运行 45，全绿**。

## 四、关键设计决策与坑点

### 4.1 沙箱 safe-delete：测试一律「零文件删除」
本环境 Python 的 `os.remove` / `shutil.rmtree` 被 safe-delete 钩子拦截（recycle-bin 不可用），会直接抛异常。因此：
- **端到端测试用纯 numpy**，不落盘；
- **model_manager 测试不创建真实权重文件**，改用 `monkeypatch.setattr(mm._os.path, "exists"/"getsize", ...)` 模拟「文件存在且体积足够」，从而验证 `verify_model` 的 `ok` 判定逻辑；`rollback_model` 用 monkeypatch 劫持 `shutil.copy2` + 模拟备份存在来验证成功分支；
- 所有注册都发生在内存 `_SLOTS` 字典，测试结束 `pop` 掉即可，**无需删除任何文件**。

### 4.2 端到端修复只走「无需 torch」的引擎
- `engine="opencv"`：OpenCV 传统算法，CPU 即可跑通真实修复管线（掩码预处理→引擎→后处理）。
- `engine="demo_model"`：示例插件无自定义权重时降级为 cv2 TELEA，同样无需 torch。
- `engine="auto"`：无 LaMa 权重时自动降级为 opencv，验证降级链路。

三者共同证明「修复引擎 = 唯一可扩展入口」的端到端闭环，不依赖缺省的 torch。

### 4.3 四入口一致性护栏
`test_ui` 断言 UI 引擎下拉 `get_engine_choices()` 与 `core.plugins.get_engine_choices()` 完全一致，且 API `get_capabilities()["engines"]` 包含同一组引擎——固化「GUI/CLI/库/REST 共用同一份动态引擎清单」的铁律。

### 4.4 CLI 用子进程、贴近真实
`cli_run` fixture 以 `sys.executable cli.py <args>` 子进程方式调用，与用户真实使用一致，同时天然隔离副作用（如 `--set-model` 改写的状态文件不影响测试进程内存）。

## 五、pytest 配置与标记

`pytest.ini`：
```ini
[pytest]
testpaths = tests
markers =
    torch_required: 需要 PyTorch 的用例（离线 CI 跳过）
    network: 需要网络的用例（离线 CI 跳过，如下载模型）
    slow: 耗时较长的用例（如运行模块 __main__ 自检）
addopts = -ra -q --timeout=300
```
超时 300s 防止 detector 等自检卡死。

## 六、本地 CI 脚本用法

**Windows**：
```bat
test.bat            # 用默认 python
test.bat "C:\path\to\python.exe"   # 指定解释器
```

**Linux / macOS**：
```sh
chmod +x test.sh
./test.sh                 # 用默认 python3
./test.sh /path/to/python # 指定解释器
```

脚本流程：`安装 requirements-dev.txt` → `pytest -m "not torch_required and not network"` → 打印 ✅/❌ 汇总并以退出码反映结果，可直接接入 GitHub Actions / GitLab CI 的 `script` 段。

接入 CI 的最小示例（GitHub Actions）：
```yaml
- name: Test
  run: python -m pip install -r requirements-dev.txt && python -m pytest -m "not torch_required and not network" -q
```

## 七、验证结论

| 验证项 | 命令 | 结果 |
|-------|------|------|
| 全量离线测试 | `pytest -m "not torch_required and not network"` | ✅ 45 用例全过 |
| 门控跳过 | 同上（1 个 torch 用例被排除） | ✅ 符合预期 |
| CLI 子命令 | `--list-engines` / `--list-models` / `--verify-model` / `--set-model` | ✅ 退出码与输出正确 |
| API 能力接口 | `get_capabilities` 含 engines+models | ✅ |
| UI 装配 | `build_app()` 不抛异常、blocks>0 | ✅ |
| 遗留自检收敛 | 9 个模块 `__main__` 子进程运行 | ✅ 全过 |
| 本地 CI 脚本 | `test.bat` / `test.sh` 同口径 | ✅ |

**结论**：阶段 13 把分散自检固化为可一键运行的回归网，覆盖插件/模型管理/CLI/API/UI/端到端修复；离线零 torch 依赖即可全绿；torch/网络用例被标记门控，装好环境后自动纳入。修复核心算法（detector / image_utils / inpainter 算法）本阶段零改动，风险隔离在测试层。
