# 385 · 承诺能力（角标 LOGO）在真实图上到底擦掉了多少（2026-11-05）

## 为什么要做这件事

用户只有一个问题：**"我的水印擦掉了吗？"**。
而项目里已有的两道门禁答的都不是这个问题：
`corner_signal_gate` 量的是"这张图有没有被**路由**到 ai_logo"（策略选对没），
`removal_truth_probe` 量的是"合成图上的**掩码**对不对"（像素真值）。
**"真实角标图跑完检测+修复之后，角标还剩多少"从来没被量过。**

## 探针（`scripts/corner_removal_probe.py`）

逐张跑**生产路径**：`detect_watermark_mask(preset="ai_logo")` → `inpaint(engine="auto")`
（参数取界面默认：力度 1 / 膨胀 0 / 羽化 5 / 阈值 127 / 降噪 3）。

三个量：
- **检出**：修复掩码与人工标注的 GT 外接框有交集；
- **角标可见度**：按**路由器的同一套几何**（右下/中右 ROI → 48x64 → 9 张角标模板最大 NCC）
  取值，修复前高说明角标在，修复后掉到阈值以下说明擦净了
  （阈值直接读 `config.RECOMMEND_CORNER_WATERMARK_NCC_MIN`，不另写一份）；
- **误伤**：GT 外接框**之外**发生变化的像素占比。

## 实测结果（51 张真实标注角标图，本机无 LaMa 权重 ⇒ 走 OpenCV 引擎）

> ⚠ 下面是**改前**口径（膨胀下限生效前）。阶段 388 加入「角标 LOGO 预设专属 12 像素膨胀下限」后，
> 同样口径下 **完全擦净率 62.7% → 78.4%**、可见度 0.235 → 0.193、框外变化 0.75% → 1.30%，
> 详见 `docs/388`。

| 指标 | 数值 |
| --- | --- |
| 检出率 | **86.3%** |
| 完全擦净率（全部图） | **62.7%** |
| 完全擦净率（已检出的图） | **61.4%** |
| 角标可见度 NCC（修复前 → 后，中位数） | **0.821 → 0.235** |
| 框外变化像素占比（中位数） | 0.75% |
| 框内变化像素占比（中位数） | 44.5% |

⇒ **一句话结论**：承诺的角标类，**约 86% 能找到、约 61% 能擦干净**；
剩下 39% 的已检出图里角标仍有残留（NCC 仍在阈值之上）。

## 顺带测出的一个可改进点：掩码覆盖不足

同一批图（24 张子集）上只改"掩码膨胀"这一个参数：

| 膨胀 | 完全擦净率（已检出） | 框外变化占比 |
| --- | --- | --- |
| 0（界面默认） | 60% | 0.83% |
| 12 px | **70%** | 1.30% |
| 24 px | **75%** | 2.11% |

⇒ 角标是**半透明板块**，检测框常只咬住实心笔画、漏掉羽化边缘 ⇒ 残留来自**覆盖不足**，
不是修复算法本身不行。扩大掩码能换 +10~15pp 的擦净率，代价是框外变化从 0.83% 升到 1.3~2.1%。

**本轮不改默认参数**（膨胀是全局旋钮，会影响其它水印类型），而是把数据与结论留下：
是否给 `ai_logo` 预设单独加"最小膨胀"，需要另跑一轮全量门禁（`run_all_checks --gates`）
确认不影响其它类，属下一步。

## 能不能把膨胀调大当默认？——门禁说不行（阶段 386 的前置实验）

既然膨胀能换 +10~15pp 的擦净率，就试了"把默认从 0 调到 12"（只改环境变量
`WME_MASK_DILATE_DEFAULT=12`，不改代码），跑全量门禁：

- `pytest` **rc=1**，5 条守卫变红：
  `test_default_dilate_calibrated`、`test_default_beats_legacy_8_on_grid`、
  `test_default_feather_does_not_attenuate_thin_text`、
  `test_H6_changed_pixels_stay_within_feather_support`、
  `test_H6_spill_ratio_under_five_percent_on_large_mask`；
- `clean_bench_probe` / `quality_gate` / `corner_signal_gate` 仍 ✅。

⇒ **默认膨胀是"按类标定"出来的**（阶段 105 的校准）：网格类用 0 更好，而且膨胀会让改动
**溢出到水印区之外**（那两条 H6 就是"只动水印区"的误伤红线）。
所以**不能改全局默认**；要做只能做成**按预设的最小膨胀**（只作用于 `ai_logo`），
并为它补一条自己的标定守卫（角标类受益 + 其它类不受影响）。

⚠ 本轮门禁里 `real_gate` rc=3（子进程未给结论）、`removal_truth_gate` 与 `media_gate`
rc=2（缺 EasyOCR / PyMuPDF）⇒ **不能**据此断言"ai_logo 专属膨胀"安全，必须在**完整环境**
里复跑这两道门禁再定。

## 边界

- 只覆盖**角标 LOGO** 这一类（承诺类），其它类不在本轮口径内。
- 本机**没有 LaMa 权重**，全部走 OpenCV 引擎 ⇒ 装了权重的用户应当更好，但**本轮没有测过**
  （不能把 61% 当成上限）。
- 可见度是**模板相关度**，不是"人眼看还有没有"；NCC 0.235 仍可能肉眼可见弱痕迹。
- 误伤按"像素是否变化"计，不区分变化是否可察觉；且包含修复区外扩/后处理的连带影响。
