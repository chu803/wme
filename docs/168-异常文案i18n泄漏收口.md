覆盖度荒漠榜已在阶段 145 收口（`audit_selector --unaudited` 零输出），审计方向转「质量盲区」中的 **i18n 整类泄漏**。该整类分 4 子类：

| 全角标点 | ✅ | 162（`tab_models`：`｜`→`models.status_device_line`） |

## 2. 根因探针（量化）

`WatermarkEraserError` 三个渲染方法（`to_text` / `to_markdown` / `to_dict`）与全部子类（`~30` 个）的默认文案存在两层硬编码：

1. **结构标签层**：`【{title}】` / `原因：` / `诊断：` / `建议：` / `底层异常：`、Markdown 的 `### ❌` / `**原因**` / `**诊断信息**` / `**解决建议**`、字典键 `异常类型`/`标题`/`原因`/`诊断`/`建议`/`底层异常` —— 全部写死中文。
2. **默认内容层**：每个子类的 `default_title` 与 `default_suggestions` 全是中文字面量。

泄漏链路：
```
UI: t("single.msg.fail", exc=format_exception_for_ui(exc))
  → format_exception_for_ui: exc.to_markdown()        # 中文结构标签 + 中文标题/建议
  → 拼进 en-US 界面                                # 外层模板是英文，内层异常仍是中文
```
这正对应 #197：外层 `t()` 模板翻译了，但 `{reason}`/`exc=` 带入的内层异常文案仍是中文。

**量化结论**：en-US 下 `OutOfVRAMError().to_markdown()` 输出含 `显卡显存不足` / `**解决建议**` / `：` 等中文，100% 泄漏（无任何英文降级）。`validate_i18n_parity` 抓不到——异常模块从未接入 i18n。

## 3. 最小修复（等价方案）

> 等价「经 i18n 路由」但**不重构 30 个子类**，风险最低、零破坏 `self.__main__` 自检。

在 `utils/exceptions.py` 顶层新增：

- `_PHRASE_EN: dict` —— 标题 + 建议译文表，键与各异常类 `default_title` / `default_suggestions` 的中文原文**逐字对应**（~121 条）。
- `_STRUCT_LABELS: dict` —— `zh-CN` / `en-US` 双语结构标签表；**en-US 侧零 CJK、零全角标点**（含经 `❌` 符号，非 CJK，保留为语言中立）。
- 辅助：`_effective_lang(lang)`（默认取全局 `get_language()`）、`_localize_phrase(text, lang)`、`_labels(lang)`。

改动点：
- `from utils.i18n import get_language`（包在 `try/except` 内，i18n 不可用时兜底 `zh-CN`；无循环依赖：config/i18n/logger 均不反向 import exceptions）。
- `to_text` / `to_markdown` / `to_dict` 增加 `lang: str | None = None` 形参；标题/建议经 `_localize_phrase` 路由，结构标签经 `_labels(lang)` 路由。**`self.title` / `self.suggestions` 仍为中文字面量**（保持既有契约与自检 `assert _err1.title == "显卡显存不足"` 不变）。
- `format_exception_for_ui` **不改**——它调用 `to_markdown()`，依赖全局语言即自动英文化。

关键修复细节（守卫抓到的真 bug）：初版 `to_markdown` 在英文标签后**硬编码了全角冒号 `：`**（`f"{L['md_suggest']}："`），导致 en-US 每条仍是 `**Suggested fix**：`。改为统一使用本地化分隔符 `L['kv_sep']`（zh `：` / en `: `）后闭合。

## 4. 守卫（`tests/test_exceptions_i18n.py`）

覆盖 24 个代表类（资源/配置/模型/图片/媒体/网络/任务/服务各子树）× 3 个渲染方法 + `format_exception_for_ui`：

- **覆盖契约**：所有子类 `default_title` 与 `default_suggestions` 每一条都必须在 `_PHRASE_EN` 有键；漏翻（新增异常忘登记 EN）立即红。
- **零泄漏契约**：`reason`/`detail`/`cause` 全空时，en-US 渲染（md/text/dict）不得含任何 CJK / 全角标点；且须含英文标签（`GPU out of memory` / `**Suggested fix**`）、不得含中文结构标签（`原因` / `**解决建议**`）。
- **动态内容透传契约**：`reason` 若为中文（调用方传入）须原样保留（设计如此）。
- **结构标签表契约**：`_STRUCT_LABELS['en-US']` 零 CJK；`['zh-CN']` 仍含中文（确保没把原文清空）。
- **zh-CN 不被破坏**：默认（zh-CN）渲染仍含 `显卡显存不足` / `**解决建议**`。

## 6. 诚实边界

- `reason` / `detail` / `cause` 是**调用方传入的动态内容**；en-US 下若调用方传中文仍原样透传——本阶段只收口异常**自身**硬编码文案，动态内容本地化由调用方负责（属合理边界，已在守卫中显式验证透传行为）。
- i18n 整类第 4 子类 **报告类交付物**（`report_service` 中文单语）仍待收口（166 登记），未在本阶段处理。
- 未做注入式反例：本次为**纯增量**（新增表 + 渲染方法加 `lang` 形参），未改动既有逻辑分支，回归风险低；守卫已直接钉住「漏翻即红 / 零中文泄漏」两条契约，等价覆盖反例意图。
