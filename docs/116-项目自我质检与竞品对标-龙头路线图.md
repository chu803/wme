## 0. 结论（结论先行）

| 维度 | 评级 | 一句话 |
|---|---|---|
| 工程与质量体系 | **A** | 注入式反例 + 三线门禁 + 真值审计，标准高于 99% 的同类开源项目 |
| 核心去痕质量 | **B-** | 合成/合同类场景已达标；真实场景**精确率 0.155 / 掩码 IoU 0.170**（过检 3.75×）是硬伤 |

| 产品化 | **D** | 有 Service/API/CLI/UI/插件五入口，但**无账号/计费/鉴权/托管** |

**总评：B —— 一个工程质量顶级、但「还不是一件商品」的技术内核。**

**龙头差距的根因只有两条**：
1. **数据**：真实水印图覆盖不足，导致「另外 4 类能不能用」无法证明（**最大且唯一的外部阻塞**）；
2. **商品化**：技术内核没有套上账号/计费/托管/性能这三层商业外壳。

**路径**：`数据 → 质量 → 产品化 → 生态` 四步走，见 §4。

## 1. 自评记分卡（量化）

记分卡已固化为机器可读文件 `docs/quality/product_scorecard.json`，每个阶段后可刷新追踪。

### 1.1 检测质量（B-）

| 指标 | 合成 | 真实 | 判读 |
|---|---|---|---|
| 误报率 | **0.36%** | — | 合成场景极干净 |
| 精确率 P | **66.1%** | **0.1552** | 真实场景**过检严重** |
| 召回 R | **79.8%** | 1.0000（**仅角标**） | 真实召回只对承诺类型成立 |
| IoU | **60.2%** | mask_iou **0.1705** | 掩码级偏低，区域级 0.7518 |
| 掩码覆盖 | — | **3.65%**，覆盖比 **3.75×** | 「不是框偏了，是框太多了」 |

**结论**：合成场景（合同/角标/平铺）已可用；**真实照片上过检近 4 倍**，且这一残余已被前序阶段证明是「半透明通路的固有误报，受连通域守卫保护，不宜再砍」。**想真正提升真实精确率，唯一的路是拿到真实图后重标判据** —— 回到数据问题。

### 1.2 去痕质量（A-）

| 指标 | 值 |
|---|---|
| 合成 ΔPSNR | **+13.21 dB**（交付链 +11.37） |
| e2e `corner_logo` removal / spill | **0.3555** / **0.7%** |
| e2e `edge_text` / `grid` | 0.2415 / 0.5063；spill 1.2% / 0.7% |
| 外溢（spill）红线 | ≤0.05，实测全部 ≤1.2% |

**结论**：**修复侧是项目的强项**；双引擎 + 相位一致掩码预处理，外溢控制良好。唯一弱点是 `faint_tiled`（极淡平铺）去痕率偏低。

### 1.3 真值覆盖（D）

```
真实基准：30 张 1024²、60 个真值水印 —— 全部 corner_logo
manifest：30 张全写 mixed（信息量为零）
8 类预设中，仅 1 类有真实真值；另 4 类真实召回【未知，不是 100%】
```

**这是全项目唯一未消除的 P0。** 代码侧已无阻塞（升级规格/预检/交图口 `benchmark_real/inbox/` 均已备，见 `docs/108`）。

### 1.4 性能（C-）

| 项 | 现状 | 竞品宣称 |
|---|---|---|
| 设备 | 默认 CPU-only | 云端 GPU |
| 单图 | LaMa 3~4 s | WatermarkRemover.io 称 ~2 s / 2K |
| 视频 | 逐帧，30 s@30fps ≈ 900 帧/min 级 | 多数竞品视频能力弱 |

**结论**：隐私（本地）是卖点，但**速度是短板**；Dockerfile 有 CUDA recipe 注释却未集成基准/CI。

### 1.5 工程与质量体系（A）

- 107 测试文件 / ~1516 用例 / 118 份文档；层架构零反向依赖。
- **四条门禁**：`quality_gate.py`（合成）+ `real_gate.py`（真实，三层判定）+ `e2e_real_probe.py --gate`（修复侧，退出码三分）+ `mask_param_audit.py`（掩码标定）。
- **注入式反例**强制：每处修复都验证「守卫真会失败」（115 阶段复现 `out.mean=1.45`）。
- **真值审计体系**：`audit_selector.py` 按「行数 ÷ 测试引用」选点，已连续审 19 个模块（88→115）。
- 差距：**无 CI**（116 已补）、**无 LICENSE**（116 已补）、无 `pyproject.toml`、无 CHANGELOG（116 已补）、仓库根有残留物。

### 2.3 不可替代的差异化（护城河候选）

1. **全本地离线**：竞品清一色云端 SaaS ⇒ 隐私敏感场景（律师/医疗/内部素材）只有本项目可选。
2. **免手涂 + 8 类 AI 水印预设**：竞品多是「通用抠除」或要求手涂，本项目对 AI 生成图的**类型化检测**更贴场景。
3. **PDF / 视频 / 图片全输入源**：多数竞品只做图片。
4. **合规标签**：「仅去除本人生成内容」是一枚**信任徽章**，在监管趋严下反而是入场券。

**结论**：本项目不缺「技术独特性」，缺的是**把独特性包装成商品**（托管、性能、账号、计费）。

## 4. 龙头路线图（3 阶段 · 可量化）

### Phase 1（0–3 月）「数据与质量」— 解掉 P0
- **动作**：交付真实图（每类 3~5 张 × 5 类，规格见 `docs/108`）→ 重标真实门禁为**全类型红线**。
- **目标（可验收）**：真实 `precision ≥ 0.35`、`mask_iou ≥ 0.35`、5 类真实 `recall ≥ 0.85`。
- **里程碑**：`docs/quality/product_scorecard.json` 的 `coverage` 从 D → B。

### Phase 2（3–6 月）「产品化与性能」— 补上商品外壳
- **动作**：GPU 后端（CUDA/ONNX）+ tile 批推理；`server.py` 加 **API Key / 限流 / 配额**；`docker-compose.yml` 一键部署；发布桌面端（`build.spec` 已备）。
- **目标**：单图 **P95 < 1.5 s**（GPU）；API 具备鉴权与配额；发布 **v1.0 正式版**。
- **里程碑**：`productization` 从 D → B。

### Phase 3（6–12 月）「生态与商业化」— 做护城河
- **动作**：插件市场（`plugins/` 已有地基）+ 模型市场；多语言站点 + 定价页 + 账号体系；可选**扩散式细化后端**追平复杂背景。
- **目标**：可计费、可分发、可扩展。
- **里程碑**：`ecosystem` 从 F → C。

> 现实提醒：以上是**多季度产品化工程**，不是一次代码提交能完成的。本轮（116）先把**地基**（CI/许可/打包元数据/记分卡）与**战略清晰度**补齐。

## 6. 唯一的硬阻塞

**我需要你给我真实水印图。** 没有它，「另外 4 类」的真实召回永远是「未知」——
无法证明、无法对客户承诺、无法写进宣传页。这是通往龙头的**第一块石头**，且**只有你能搬**。

交付口：把图拖进 `benchmark_real/inbox/` 即可（自动收编、sha256 查重、只列目录不动文件）。
规格：`.jpg/.png`、真实来源、长边 ≥ 640；优先级 `ai_text_heavy` > `ai_grid` > `ai_faint_tiled` > `ai_gradient`。

## 7. 本报告的诚实边界

1. **竞品数据未经受控横评**：全部为第三方评测/厂商宣称，不能作为「我们更强/更弱」的最终判据；Phase 1 补一场同条件横评才算数。
2. **自家数据全部可复跑**：均来自 `scripts/` 下的门禁脚本，任何人可核。
3. **「龙头」是结果不是声明**：本文只给路径与量化目标，不做「我们已经领先」的结论 —— 现在的真实位置是「**技术内核强、商品外壳缺**」。
