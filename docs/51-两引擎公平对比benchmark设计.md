## 1. 为什么还需要这个 benchmark

阶段 49 之前，检测器在干净图上会产出 90%+ 的误报掩码，导致：
- 覆盖率数字完全失真（真实水印只占 5%，检测却标 60%）；
- 修复引擎被迫在「整图都是水印」的掩码上重建，两种引擎都会被拖垮，对比无意义。

检测器修好后，掩码回到「只覆盖真实水印区域」，此时再跑两引擎对比，得到的
ΔPSNR（修复后 − 带水印）才是公平的。

## 2. 方法论

### 2.1 数据构造
- **底图两类**（分别检验两个引擎的舒适区）：
  - `gradient` 纯渐变（OpenCV 局部扩散的最优点，LaMa 生成式重建的最差点）；
  - `textured` 类自然纹理（多倍频程值噪声，更接近真实照片的统计特征）。
- **水印四类**（来自 `CASES`）：`corner_logo` 角落 LOGO、`edge_text` 底部边缘小字、
  `faint_tiled` 极淡平铺文字、`grid` 网格点阵。
- **种子**：默认 4 个（1/2/3/4），取均值与标准差，结论稳健。

### 2.2 度量
- **ΔPSNR = PSNR(修复后, 原图) − PSNR(带水印, 原图)**（dB）。
  正值越多 = 修复越接近原图；负值 = 修完反而更差。
- **覆盖率** = 掩码像素占比（%）。
- **MAE** = 修复后相对原图的平均绝对误差（0~255）。

### 2.3 公平性原则
- 同一张合成图，先用**同一份检测掩码**喂给两个引擎，排除「检测差异」干扰，只比修复本身；
- 两引擎用完全相同的 `inpaint()` 入口（`core/inpainter.py`），仅 `engine=` 不同；
- 多种子取均值，避免单张图的偶然性。

### 2.4 复现
```bash
python scripts/run_benchmark.py --save-samples
# 产出：
#   docs/assets/benchmark.json         逐条（data,case,engine,seed）
#   docs/assets/benchmark_summary.json 聚合（均值/标准差 + LaMa−OpenCV 差值）
#   docs/assets/bench_*.png            代表性四联对比图（opencv 上 / lama 下）
```

## 4. 结论与对真实数据的预测

### 4.1 合成数据上的确定结论

1. **OpenCV 全面优于 LaMa（8/8 用例）**，且在大面积 / 渐变用例上 LaMa 严重负向
   （ΔPSNR 低至 **−25.19 dB**，即修完比不修还差）。这与阶段 50 的直觉一致：
   - 纯渐变是局部扩散的最优解（扩散填充即可近似完美），却是 LaMa 生成式重建的最不舒适区；
   - LaMa 在纯色底图上实测 PSNR 65 dB、未掩码区 100% 保留（管线本身无 bug），
     但一旦遇到渐变 / 半透明叠层，它会"补出幻觉纹理"引入误差。
2. **类自然纹理底图上，两引擎都没有把水印完全修掉**（ΔPSNR 多为负或接近 0）。
   这说明合成纹理图的统计特征仍不足以让 LaMa 发挥生成式补全优势——它更接近信息论边界，
   而非"LaMa 擅长"的真实照片分布。

### 4.2 对真实数据的预测

- LaMa 的强项（生成式纹理补全、保持语义连贯）**只有在真实照片上才能体现**。合成数据上
  LaMa 因幻觉纹理反而吃亏，这恰恰印证：**真实图是 LaMa 翻案的唯一场景**。
- 检测器（阶段 49 修好）已经能给出诚实掩码，因此无论未来默认切到哪个引擎，掩码都可靠；
  benchmark 也采用"同一份掩码喂两引擎"的设计，排除了检测差异干扰。

### 4.3 工程建议

- **当前默认引擎保持 OpenCV**：在合成与已验证的纯色 / 渐变场景上它稳定且更快、零依赖。
- **LaMa 作为可选引擎保留**，并标记为"建议用于高纹理真实照片"；其价值需经 P0 真实图验证后才能定论。
- **P0 真实图验证仍是最高优先级**：把 3~5 张真实带水印 AI 图放进目录，跑
  `python scripts/make_demo_assets.py --input-dir <dir> --compare` 即可得到真实场景的 LaMa vs OpenCV 对比。
