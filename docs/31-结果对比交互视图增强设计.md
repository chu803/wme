# 阶段 31 · 结果对比交互视图增强设计

> 日期：2026-08-06｜目标：在既有「结果对比视图」（静态 Before|After 拼接）基础上，新增三种可交互/更直观的对比模式——**拼接对比 / 拖动滑块 / 差异热图**，落地于「自动检测修复」与「单图处理」两个拥有独立原图/结果查看器的入口。

## 1. 背景与定位

- 项目在阶段 6 已通过 `config.UI_COMPARE_VIEW` + `services.export_service.make_compare_array` 提供**静态** Before|After 拼接图（单图/自动页展示，批量/历史页切换缩略图）。
- 静态拼接只能「并排看」，无法直观判断修复痕迹残留、过渡不自然区在哪。本阶段在不破坏既有静态视图的前提下，**叠加一层增强对比视图**，提供三种模式：
  1. `concat`（拼接对比）：复用 `make_compare_array`，编码为 data URI 内嵌 `<img>`——与旧视图等价，但改为按需生成、可被滑块/热图无缝切换。
  2. `slider`（拖动滑块）：自包含 HTML/CSS 滑动对比控件，底层放结果与图、上层裁剪揭示原图，拖动分割线实时对比。
  3. `heatmap`（差异热图）：像素级 `|orig - result|` 均值，99 百分位拉伸后套 `COLORMAP_JET`，越亮表示该处改动越大，用于定位残留水印/修复痕迹。
- 设计原则：**纯 numpy + cv2（零 gradio/torch 依赖）**，所有构建器放在 `services/export_service`；UI 层只做接线，直接复用修复回调已输出的 `orig_view`/`result_view` 作为增强视图输入，**不改 repair 的 outputs**，规避阶段 29 的接线错位坑。

## 2. 改动清单

### 2.1 `services/export_service.py`（零 gradio）
- 新增 `import base64`。
- `_to_rgb3(arr)`：规整为 H×W×3 uint8 RGB（丢弃 alpha、容错 shape）。
- `_array_to_data_uri(rgb_arr, ext=".jpg", quality=88)`：RGB→BGR→`cv2.imencode`→base64 `data:image/jpeg;base64,...`，供 `gr.HTML` 内嵌、免落盘。
- `make_diff_heatmap(orig_arr, result_arr, percentile=99.0)`：
  - 尺寸不一致时 `cv2.resize` 结果到原图尺寸；
  - 三通道取绝对差均值 → `np.clip` → 99 百分位拉伸 → `cv2.applyColorMap(..., COLORMAP_JET)`→RGB；
  - 完全相同返回全黑；空维度返回 1×1 黑图（防御）。
- `make_before_after_html(orig_arr, result_arr, before_label, after_label)`：
  - 自包含 HTML/CSS，**无 `<script>`**（Gradio `gr.HTML` 兼容关键）；
  - 底层 After `<img>` 全宽，上层 Before `<img>` 置于 `.ba-before`（width:50% + overflow:hidden），透明 `range` 覆盖全图、`oninput` 实时调整 `.ba-before` 宽度与 `.ba-divider` 位置；
  - 用模块全局 `_BA_COUNTER` 避免多实例 DOM id 冲突；编码异常返回 `<p>` 错误段而非抛异常。

### 2.2 `utils/i18n.py`
- 新增 `compare` 块（中英各 10 键）：`enh_title`/`enh_mode_label`/`enh_mode_info`/`mode_concat`/`mode_slider`/`mode_heatmap`/`enh_btn`/`no_result`/`slider_label`/`heatmap_label`。
- `__main__` 自检：循环断言 10 键均非裸 key（先 `set_language("zh-CN")` 再跑，修正顺序坑）；追加 zh 断言（`enh_title=="### 🔬 增强对比视图"`、`mode_slider=="拖动滑块"`）与 en 断言后恢复 zh-CN。

### 2.3 `ui/tab_auto.py` / `ui/tab_single.py`
- 导入由 `from services.export_service import make_compare_array` 改为 `from services import export_service as _es`（既有修复路径的 `make_compare_array` 调用同步改为 `_es.make_compare_array`，修复一处替换导入导致的 NameError 回归）。
- 新增 `on_enhance(orig_arr, result_arr, mode) -> str`：
  - `orig/result` 任一为 `None` → 返回 `t("compare.no_result")`；
  - `mode=="slider"` → `_es.make_before_after_html`（auto 用 `auto.orig_label`/`auto.result_label`，single 用 `single.orig_label`/`single.result_label`）；
  - `mode=="heatmap"` → `_es.make_diff_heatmap` + `_array_to_data_uri` 包 `<img>` + `heatmap_label` 说明段；
  - 默认 concat → `_es.make_compare_array` + `<img>`；
  - 异常兜底返回 `no_result`。
- `build_*_tab` 右列结果区新增：`enh_title`(Markdown) + `enh_mode`(Radio: 三模式, value="concat") + `enh_btn`(Button) + `enh_view`(gr.HTML)。
- 接线：`enh_btn.click` 与 `enh_mode.change` 均以 `[orig_view, result_view, enh_mode]` 为 inputs、`[enh_view]` 为 outputs 调 `on_enhance`——**不触碰 repair 的 `.click` outputs**，零接线风险。

## 5. 已知边界与决策

- **批量/历史页未加交互滑块**：两页以画廊缩略图（静态 `make_compare_array`）为主，无独立 `orig_view`/`result_view` Image 组件；强行加交互需重构画廊 UX，故保留静态拼接（与既有设计一致），交互增强聚焦于拥有专属前后查看器的自动/单图页。
- 滑块控件依赖内联 `oninput`（无 `<script>`），最大化兼容 Gradio `gr.HTML` 渲染；若后续 Gradio 版本对内联事件收紧，可改为挂载一次性 `<script>` 初始化（需评估沙箱 CSP）。
- 差异热图基于 99 百分位拉伸，对「大面积均匀改写」（如整图去噪）会整体偏暗——属预期行为，热图用于定位**局部**改动。
- 增强视图为纯前端内存生成（data URI），不落盘、不进报告，避免与 `export_compare` 落盘对比图功能重叠。
