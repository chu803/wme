## 1. 目标与范围

为全部 Gradio 界面接入中英文双语切换能力：

- 建立纯翻译层 `utils/i18n.py`（**严禁 import gradio / ui / services**，保持零界面依赖，便于单元测试）。
- 建立界面层运行时注册表 `ui/i18n_rt.py`（**仅界面层**可 import gradio），支撑「实时切换」——切换语言时一次性刷新所有已注册组件，无需重载页面。
- 把 7 个主标签页 + 媒体页 2 个子标签页的全部静态文案（标题 / 折叠面板 / 按钮 / 滑块 / 文本框占位符 / Markdown）接入 `t()` 并注册。
- 顶部提供语言切换下拉框，切换即生效；运行时生成的消息（状态日志 / 报错）在回调内直接调用 `t()` 反映当前语言。
- 标签页标题（Gradio 6 的 `TabItem` 不支持运行时 `update`）由注入 JS 在切换时重命名。

## 3. 翻译键命名规范

采用「点号分层」键，便于归属与缺失排查：

```
app.tab.single / app.tab.auto / ...       顶层标签页标题
app.compliance                            顶部合规声明
params.engine_label / params.sensitivity_*  修复参数面板
single.* / auto.* / batch.* / media.* /     各标签页文案
       history.* / settings.* / models.*
common.on / common.off / common.unknown_title  通用词
lang.label / lang.zh / lang.en / lang.applied  语言切换器
```

取词函数：

```python
def t(key: str, **kwargs) -> str:
    """按当前语言取译；缺失键回退 zh-CN，再回退为 key 本身（绝不抛异常）。"""
```

含占位符的译文（如 `{name}`、`{error}`），中英文**占位符必须同名**，代码用 `t("x.y", name=...)` 统一填充。

## 4. 语言优先级

`load_language()` 按以下顺序决定生效语言（进程内缓存于模块级 `_LANG`）：

1. 环境变量 `WME_UI_LANGUAGE`（便于容器/CI 预置）；
2. 持久化文件 `cache/i18n_state.json`（用户上次在界面中的选择，切换即写回）；
3. `config.UI_LANGUAGE`（默认 `zh-CN`）；
4. 兜底 `zh-CN`。

## 5. 实时切换机制

### 5.1 注册表（ui/i18n_rt.py）

```python
register(component, resolver)        # resolver() -> dict（gr.update 的 kwargs）
reg_value(comp, key, **fmt)          # 刷新 value（Markdown / 文本展示）
reg_label(comp, key)                 # 刷新 label
reg_info(comp, key)                  # 刷新 info
reg_label_info(comp, label_key, info_key)  # 同时刷新 label + info
reg_textbox(comp, label_key, placeholder_key=None)  # 刷新 label + 占位符

apply_language(lang) -> [gr.update(...), ...]   # 与注册表同序
registered_components() -> [comp, ...]          # 作为事件 outputs
```

`resolver` 必须是**无参可调用对象**，内部调用 `t(key)`。这样在 `apply_language` 遍历注册表时，`t()` 会按已切到的语言重新取词——**文案不会在构建时被冻结**。

### 5.2 切换事件接线（ui/app.py）

```python
lang_dropdown.change(
    fn=_on_lang,
    inputs=[lang_dropdown],
    outputs=registered_components() + [lang_status],
    js=_build_lang_js(),
)
```

- `_on_lang(lang)`：`apply_language(lang)` 返回全部组件更新列表，末尾追加一条语言状态 Markdown。
- `outputs` 与返回值**顺序、长度严格一致**（注册表序 + 状态框），否则 Gradio 报错。

### 5.3 标签页标题的特殊处理

Gradio 6.22.0 的 `TabItem` / `Tabs` **没有运行时 `update` 能力**（实测 `gr.TabItem.update` 抛 `AttributeError`）。因此：

- 构建时为每个 `TabItem` 设置 `elem_id`（如 `single`、`media_pdf`），Gradle 会把标签**按钮**的 DOM `id` 设为 `<elem_id>-button`（见 `gradio/layouts/tabs.py` 文档）。
- 切换语言时，由 `change` 事件的 `js` 参数先行在**前端**重命名这些按钮：

```js
(lang) => {
  const MAP = {"single": {"zh-CN": "...", "en-US": "..."}, ...};
  for (const id in MAP) {
    const btn = document.getElementById(id + '-button');
    if (btn) btn.textContent = (MAP[id][lang] || btn.textContent);
  }
  return lang;   // 把语言代码透传给后端 fn
}
```

`MAP` 由 `_build_tab_rename_js()` 在 Python 端**直接读取 `TRANSLATIONS` 双语文案**生成 JSON，保证标签页标题与翻译包单一来源一致，不重复维护。

> 备注：Gradio 事件的 `js` 参数在 `fn` 之前于前端执行，并接收 inputs 值（已核对 `gradio/events.py` 注释）。`js` 返回 `lang` 即作为 `fn` 的输入，二者无缝衔接。

## 6. 运行时消息

状态日志、报错、进度提示等动态文本**不进注册表**，直接在回调内调用 `t()`，天然反映当前语言。例如：

```python
def on_pdf_uploaded(file_value):
    if not path:
        return t("media.pdf.info_init")          # 随当前语言
    ...
    return t("media.pdf.loaded", name=..., pages=..., ...)
```
