# 阶段 263 · full 基线标定法：超分口径纳入 + 标定就绪

> 目的：把「③ full 基线标定法」这个待决项从模糊 worry 变成**已落地的口径修复 + 一键建立命令**。
> 本文档只做分析与实现，不擅自写 full 基线、不改超分配置（那属 ① 用户决策）。

---

## 一、执行摘要（结论先行）

- **perf_baseline.json 现状**：仅 `detect` 阶段（v3，p95 0.679s）。**`full` 阶段基线从未建立**——
  MEMORY 里的「full P95 9.846s」是一次**历史探针数字**，不是入库基线（见第四节自反证伪）。
- ③ 的真问题（full 标定口径）定位为：**full 阶段标定口径遗漏了「真实超分」状态**。
  阶段 262 实测超分开启令 full 链路耗时 **+2.6s**；若不纳入口径维度，「超分开」与「超分关」的
  full 测量会被误判为同口径 ⇒ 护栏失准（LESSONS 230 重演）。
- **修复**：在 `baseline_comparable` 增加 **full 阶段专属**超分可比性检查
  （`real_superres_enabled` / `real_superres_scale` / `real_superres_backend`），
  **不进全局 `COMPARABILITY_KEYS`**——避免让现有 v3 detect 基线被判「结构过旧」失效。
- **守卫**：`tests/test_perf_full_caliber263.py` **7 例全绿**；连同既有 `test_perf_probe.py` 共 **27 例全绿**。
- **派生发现（独立）**：detect 阶段 P95 自 2026-10-06 的 0.679s 升至当前 ~1.545s
  （同图、同码、同尺寸、测量干净）→ **未归因的机器环境漂移**，已据向下刷新护栏拒绝静默植入，列为开放项待归因。

---

## 二、full 标定口径决策（决策就绪）

- **标定方法**：复用 `perf_probe` 已有的成熟方法，无需新方法论——
  min-of-k=3、硬件指纹闸门、噪声比/锚点比瞬态闸门、向下刷新护栏、结构版本化。
- **唯一待决的口径选择**：超分状态必须与基线绑定（**本阶段已落地**）。
- **实际建立 full 基线的命令**（门禁家族契约，退出码 0/1/2）：
  ```bash
  python scripts/perf_probe.py --stage full --update
  ```
  ⚠ 该命令写入的基线会记录**当前超分口径**。鉴于 ①（超分开/关）尚未由你拍板，
  建议**先定 ① 再跑**；或现在用「超分关」跑出干净基线（见 262 建议 A）。
- full 基线建立后，`perf` 门禁方能对**全链路时延**做回归护栏——
  路线图的「P95<1.5s」目标必须 `--stage full` 才验得到（detect 阶段是 CPU 绑定，永远不吃 GPU）。

---

## 三、归因（detect 2.3× 漂移——独立发现）

| 证据 | 结果 |
|---|---|
| 旧基线 measured_at | 2026-10-06 |
| `core/detector.py` / `preset_recommender.py` / `detector_service.py` 自 10-06 起提交 | **0 次**（代码未变） |
| 基准图 `ai_logo_02` 最后提交 / mtime | 2026-10-03 / 2026-09-30（文件未变） |
| 同图 `ai_logo_02` 实测 | 2048²，单图 min 1.27s |
| 本次测量噪声比 / 锚点比 | 0.029 / 0.978（排除瞬态 run 内方差） |

⇒ 排除 **代码 / 工作负载 / 瞬态负载** ⇒ 属**持续性机器环境漂移**（后台进程 / 散热降频 / 运行时库）。

**处置**：向下刷新护栏正确拒绝把 1.545s 植入基线；**不 `--force-update` 掩盖**。
列为开放项：在干净的空闲机器上复测 detect P95，确认是否本机环境偶发；若回到 ~0.7s 则属偶发、
届时 `--force-update` 重标定 detect 基线是合理的。

## 四、验证

- `tests/test_perf_full_caliber263.py`（7 例）：
  超分开 vs 超分关不可比 / 同口径可比 / scale 不匹配不可比 / detect 不受超分维度影响 /
  `measure(stage="full")` 真实记录超分口径 / 缺超分键的旧 full 基线不可比 / 超分检查仅作用于 full。
- `tests/test_perf_probe.py`（20 例）：辅助函数补键后不受影响。
- **合计 27 例全绿**。

## 五、自反证伪

- 超分口径检查**仅作用于 full 阶段**；若将来 detect 基线也被超分维度误判不可比 ⇒
  说明检查作用域写错（守卫 `test_superres_is_full_stage_scoped_not_detect` 已覆盖）。
- detect 2.3× 漂移若在某台空闲机器复测回到 ~0.7s ⇒ 证明确属本机环境偶发，应重标定 detect 基线。
- MEMORY 中「full P95 9.846s」**非入库基线**，只是一次性历史探针数字；同理「detect P95 0.681s」
  已被本次复测推翻为 ~1.545s（环境漂移），**二者都不能当作承诺值**。
- 本阶段**未执行** `perf_probe --stage full --update`（不擅自写基线，等 ① 拍板）；
  **未改** `config.user_overrides.json` 超分配置（维持 262 决策：待你拍板）。
