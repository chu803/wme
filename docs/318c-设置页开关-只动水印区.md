# 阶段 318c · 设置页开关：让普通用户也能开「只动水印区」

> 日期 2026-10-23 · 产物 `ui/tab_settings.py`、`config.py`（user_overrides 双清单）、`utils/i18n.py`、
> `tests/test_processing_prefs.py`（+3 例）

## 一、动机

318 有引擎能力，318b 有 CLI / api / REST 三个入口——但**打开网页的用户仍然用不到**：
他们不会写 `--preserve-untouched`，也不知道环境变量。这正是我给自己写的
LESSONS #298「能力存在但对调用方不可达」的第三种形态：**门面都接了，界面没接**。

## 二、做法（收窄过的范围）

没有给自动/单图/批量/媒体四个页签各加一个复选框（那要改 4 处位置参数接线，风险高、收益重复），
而是加在**设置页 → 处理偏好**里做**全局默认**：

- 一个复选框「只动水印区（推荐追求保真时开启）」，与「双跑择优 / 透明通道 / EXIF / 位深」并列；
- 点「应用处理偏好」⇒ 写运行时 `config.POSTPROCESS_PRESERVE_UNTOUCHED`（**立即生效**，
  因为 `postprocess()` 每次调用都读 config）；
- 勾「保存为默认」⇒ 写入 `config.user_overrides.json`，下次启动仍生效；
- 确认文案补一项「只动水印区：{preserve}」——**实测发现**：不加这一句，用户点完「应用」也看不出
  自己勾的那项到底生效没有（原文案只报四项）。

`config.user_overrides.json` 的**两份清单必须同时登记**（`_USER_OVERRIDABLE_KEYS` +
`_USER_OVERRIDE_VALIDATORS`）——我只加了后者，`test_config_parse::test_override_lists_are_consistent`
当场抓红（它存在的理由就是「分叉会导致某键永久静默失效」）。

## 三、验证：不是只跑单测，是真开界面点了一遍

1. `WME_SERVER_PORT=7899 main.py` 起界面 → 打开「设置与导出」；
2. 截图确认新复选框渲染正常（与其余偏好项同款样式、默认未勾）；
3. 勾选 → 点「应用处理偏好」→ 页面文案返回：
   `已应用处理偏好 —— 双跑择优：关闭；透明通道：开启；EXIF 方向：开启；位深规范化：开启；只动水印区：开启`
   ⇒ 位置参数顺序、handler 写入、文案渲染三处同时被证。
4. 全程**没有**勾「保存为默认」，未改动 `config.user_overrides.json`。

单测侧：`tests/test_processing_prefs.py` +3 例——
白名单往返（`"true"`/`"关"` 经 `parse_bool`）、`apply_processing_prefs` 的**三态**
（`None` 不动这项、不写覆盖文件；显式 True 才写入并持久化）、i18n 双语键。

## 四、诚实边界

- **没有**给四个处理页签加「逐次开关」：目前是「全局默认 + CLI/REST 逐请求覆盖」两层。
  逐页签开关要做的话，得走 `RepairParamHandles` 扩展 + 4 处位置参数接线，属独立阶段。
- 只验证了**渲染与写入**，没有在浏览器里跑一次真实修复来肉眼确认「水印外确实没变」——
  那条链路由阶段 318 的 A/B（60 用例）与 `test_array_facade_is_actually_effective` 覆盖。
- 设置页文案说「推荐追求保真时开启」，默认仍是**关**：翻默认会改变所有用户的成片观感，
  这个决定没有在代码里替用户做（见 `docs/318` §五 的三选项对照）。
