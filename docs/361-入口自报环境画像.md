# 阶段 361 · 入口开头必须说出「这次量的是哪个环境」（把 4 次「本地绿、CI 红」的共同沉默收掉）

> 日期 2026-10-31 · 性质：**验证层可观测性**（347/351/358/360 的根因收口）

## 一、问题：门禁量的是哪个环境，取决于谁的 `sys.executable`——但没人打印过这句话

`run_all_checks.py` 的步骤一律用 `sys.executable` 调用（本仓库的既有纪律）。
于是「用哪个解释器启动入口」就**决定了门禁量的是哪个环境**。而入口原来只打印步骤清单：

```
验证入口 run_all_checks · 步骤清单
  · pytest ...
```

⇒ 本地跑的是 `D:\wme-1.0.3\venv`（3.13，装了 torch / PyMuPDF / easyocr），
CI 跑的是 runner（3.11，只装 min+dev）。**两份代码路径不一样**，
于是「本地 3400+ 项全绿」与「CI 红」可以同时为真——347（cp311 轮子）、351（镜像包名改名）、
358（收集期 ImportError）、360（自检把缺依赖判成失败）**四次都是这个形状**。
其中 360 那次最刺眼：探针当时报 `rc=0`，因为它只在**本进程**屏蔽模块，而自检守卫是子进程。

## 二、做法：`scripts/env_profile.py`＝环境画像的单一真值来源

判据只认两份清单，不认回忆：

- `CI_REQUIRED`（CI 应当能给出的 import 名）：`cv2 / gradio / numpy / PIL / pytest`
  ⇒ 缺任何一个 = **这台机不是 CI 那种环境**（连"能不能等价"都谈不上）。
- `CI_FORBIDDEN`（CI **刻意不装**的可选增强）：`torch / fitz(PyMuPDF) / easyocr`
  ⇒ 装了 = 本地会走 **CI 永远不会走**的分支 ⇒「本地全绿」**不能外推**成「CI 绿」。这一侧才是红因来源。

退出码沿用门禁家族口径：`0` 等价 / `1` 必装都缺（失败）/ `2` 本机更强（**告知，不是失败**）。
**不改判定**：画像只自报，不参与入口的退出码——把"非等价环境"判红属判定口径变更，与任务 #24 同类，等用户拍。

入口输出（`--list` 也打印，零成本就能看到）：

```
验证入口 run_all_checks · 环境画像
  解释器   : D:\qoder\ci311venv\Scripts\python.exe  (Python 3.11.4)
  判定     : [ci_equivalent] 与 CI 等价 ⇒ 这个解释器跑出来的入口结果**就是** runner 会看到的结果。
```

本机完整环境则报 `[full_dev] 本机多装了 easyocr, fitz, torch …` 并直接给两条下一步
（① `ci_env_probe.py` 约 10 分钟；② 用 min+dev 的 3.11 等价 venv 跑同一条入口，约 7 分钟，建法见 docs/360）。

## 三、探测方式：走元数据，**不走 `find_spec`**

`importlib.metadata.packages_distributions()` 只读已装包的元数据：不 import 被测模块、不碰 `find_spec`、毫秒级。
这不是风格偏好——`ci_env_probe.py` **正是钩 `find_spec`** 来模拟"CI 上没有这个模块"，
画像若用它判定就会与假点共用一层，**在被模拟的环境里自己先炸**（LESSONS #334 原样复发）。

## 四、守卫与两个自打的脸

`tests/test_env_profile361.py`（9 例，两环境各跑一遍全绿）：
① 三种判定 + 退出码口径；② 文案必须 actionable（点名多装了谁 + 给两条下一步）；
③ 探测不许走 `find_spec`；④ `CI_REQUIRED` 的分发名必须真的在 `requirements-min/dev` 里（防漂移）；
⑤ 入口 `--list` 开头必须有画像；⑥ 脚本单独跑与入口内嵌判定同源。

**写守卫时自己踩了两个老坑**（都按既有教训当场改掉）：
- 第一版用「文本里不许出现 `find_spec`」判 ⇒ **把说明文里那句"别用 find_spec"判成了违规**。
  ⇒ 改 `ast` 判定（#316 的同类：文本判据看不见"这行是给人读的还是给机器执行的"）。
- 第一版把 helper 写在测试中间、还留了一条恒真断言（`assert set(...) <= ... or True`）⇒ 删。

## 五、登记纪律当场生效（这条守卫证明了自己还活着）

新增 `scripts/env_profile.py`（带 `__main__`）后，**CI 等价环境的完整入口立刻变红**：
`tests/test_legacy_selfcheck.py::test_selfcheck_coverage_is_accounted_for`
——磁盘上每个含 `__main__` 的模块必须**要么登记为子进程自检、要么显式豁免**（阶段 147 的台账）。
处置：加进 `NOT_REGISTERED_BY_DESIGN` 的 **S 类**并写明理由——
`env_profile.py` 的退出码**是判定**（0 等价 / 1 环境不对 / 2 本机更强），
不是「自检通过=0」那种语义；把它塞进 `MODULES` 会把「本机环境比 CI 强」读成"自检失败"（新的假红）。
它的端到端覆盖在 `tests/test_env_profile361.py`（子进程真跑 + 两个环境各一遍）。

⇒ 顺带说明画像为什么**故意**没有参与入口判定：如果入口因为 `[full_dev]` 就判红，
本地全量门禁（需要 torch/PyMuPDF 的那些步）就永远跑不了——判定口径属任务 #24/#35，等用户拍。

## 六、诚实边界

- **它只报告，不阻止**：非等价环境照样能跑入口（这正是今天的需要——本地全量门禁必须用完整环境跑）。
  要变成红线属判定口径变更（同 #24）。
- 画像判的是「包在不在」，**不判版本对不对**：cp311 轮子（347）与镜像系统包名（351）两类
  由各自的守卫钉；OS 维度（Windows vs Ubuntu）仍不在射程内。
- 子进程仍然看不见画像：`test_module_selfcheck` 那类派生进程用的是同一个解释器，所以画像对它们**有效**；
  真正跨不过的是 `ci_env_probe` 那种**进程内注入**（360 已记录，未做进程边界传递）。
