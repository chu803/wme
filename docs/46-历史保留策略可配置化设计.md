# 阶段 46 · 历史保留策略可配置化设计文档

> 项目：AI 智能水印擦除工作台
> 依赖阶段：1–45（含阶段 35 真实超分「设置页暴露 + 保存为默认」、阶段 40–43 历史记录管理闭环）
> 运行要求：零 torch 可测；Gradio 6.22

---

## 1. 动机与现状

历史记录的保留策略（`CACHE_MAX_RECORDS` / `CACHE_KEEP_DAYS`）底层早已实现：

- `config.py`：`CACHE_MAX_RECORDS`（默认 200，区间 10–5000）、`CACHE_KEEP_DAYS`（默认 30，区间 1–3650）常量 + 环境变量 `WME_*` 覆盖；
- `services/cache_service.py`：`CacheService.prune()` 按「过期天数 + 数量上限」自动清理，并在 `add_success` 写入时自动调用；
- `ui/tab_settings.py`：`on_prune_cache` 提供手动「清理过期记录」按钮；快照 `build_snapshot_md` 展示保留天数/条数。

**缺口（不对称）**：

1. 保留策略是 **env-only 常量**——用户无法在 GUI 配置/持久化，只能改 `.env`/重启，与阶段 35 真实超分「设置页暴露 + 保存为默认」不对称。
2. 历史页只有手动 `prune` 按钮（且位于设置页），无内联「按策略清理」入口。
3. 用户覆盖持久化 `save_user_overrides` 为**整体覆盖式**，若直接加保留策略键会**抹掉已保存的真实超分默认**。

---

## 2. 设计目标

- 在设置页暴露「历史保留策略」面板：保留天数 / 最大条数滑块 + 保存为默认 + 应用按钮。
- 应用即写运行时配置 + 可选持久化到 `config.user_overrides.json` + 立即按新策略清理一次 + 刷新快照。
- 历史页提供内联「按策略清理过期记录」按钮，复用既有的 `confirm_cb` 二次确认守卫。
- 重构 `save_user_overrides` 为**合并式**字典写入，保证「保存超分默认」与「保存保留策略」互不覆盖。
- 全程零 torch，分层无反向依赖。

---

## 3. 关键改动

### 3.1 config.py（白名单 + 合并式保存 + 调用时序加固）

- `_USER_OVERRIDABLE_KEYS` 新增 `CACHE_KEEP_DAYS` / `CACHE_MAX_RECORDS`。
- `_USER_OVERRIDE_VALIDATORS` 新增两键校验器：
  - `CACHE_KEEP_DAYS`：`lambda v: int(v) if int(v) in range(1, 3651) else 30`
  - `CACHE_MAX_RECORDS`：`lambda v: int(v) if int(v) in range(10, 5001) else 200`
- `save_user_overrides(enabled, scale, backend)` → **`save_user_overrides(patch: dict)`**：
  - 读回已有覆盖 JSON → 仅合并白名单内且校验通过的键 → 写回；
  - 非 dict / 空 dict 直接返回 `False`；写失败返回 `False`，不抛异常。
- **时序加固（关键）**：原 `_apply_user_overrides()` 调用位于模块中部（第 9.6 节后），而 `CACHE_KEEP_DAYS` / `CACHE_MAX_RECORDS` 定义于第 10 节（更靠后）。若在该调用点应用覆盖，随后常量定义会**用默认值覆盖掉 JSON 读回值**，导致持久化失效。
  - 修复：将 `_apply_user_overrides()` 实际调用点移至 **`config.py` 文件末尾**（全部常量定义之后），确保覆盖在默认值之后生效。环境变量（`WME_*`）优先于 JSON 的逻辑不变。

### 3.2 ui/tab_settings.py（保留策略面板 + apply_cache_config）

- 新增 `apply_cache_config(keep_days, max_records, save_default)`：
  - 实时写 `config.CACHE_KEEP_DAYS` / `config.CACHE_MAX_RECORDS`；
  - 若 `save_default`：合并式 `config.save_user_overrides({CACHE_KEEP_DAYS, CACHE_MAX_RECORDS})`（不抹超分默认）；
  - 立即 `_CACHE.prune()` 反馈清理条数；
  - 返回 `(快照 Markdown, 信息文案)`，与 `cache_apply.click` 的 `outputs=[snapshot, info]` 对齐。
- `build_settings_tab` 在真实超分面板后新增「历史保留策略」`Accordion`（`cp_keep_days` 1~3650 / `cp_max_records` 10~5000 / `cp_save` / `cp_apply`），并接线；`apply_superres_config` 的 `save_user_overrides` 调用同步改为字典形式。

### 3.3 ui/tab_history.py（内联按策略清理）

- 新增模块级 `prune_by_policy(compare, confirm)`：未确认返回 `history.msg.confirm_needed` 且**不调用 prune**；确认后 `_CACHE.prune()` 并刷新画廊，返回六元组（与 `delete_filtered` 对齐，便于复用 `confirm_cb` 守卫与 outputs 结构）。
- 在 `delete_filtered_btn` 同 `Row` 下新增 `prune_policy_btn`，复用 `confirm_cb`，接线 `outputs=[detail, gallery, hist_viewer.pair_state, hist_viewer.html, hist_viewer.summary, confirm_cb]`。

### 3.4 utils/i18n.py（中英双语键 + 自检）

新增：
- `settings.cache_policy.*`（`title` / `keep_days_label` / `keep_days_info` / `max_records_label` / `max_records_info` / `save_label` / `save_info` / `apply`）；
- `settings.snap.msg.cache_applied`（含 `days` / `max` / `n` 占位）；
- `history.prune_policy_{btn,confirm,ok,none}`。
- 自检（`__main__`）补相应断言。

## 5. 测试（零 torch，全隔离）

10. i18n 键中英齐全。

## 6. 影响面与兼容性

- 仅新增保留策略的可配置入口，不改变 `prune()` 既有行为；
- `save_user_overrides` 签名变更（`(enabled, scale, backend)` → `(patch: dict)`），唯一调用方 `apply_superres_config` 已同步；既有测试已更新；
- `_apply_user_overrides()` 调用点后移不影响其它模块导入（仅函数定义顺序调整，无新增导入期副作用）；
- 用户覆盖文件 `config.user_overrides.json` 向后兼容：旧文件只有超分三键，新保存会自动合并新增两键。
