# 阶段 181 · 基线 corner_logo「非确定性」再审计 —— 纠正 180 误判

> 承接 180（干净图基准与补全先验误报门禁，测得 `prior_fp_rate = 2/5 = 0.40`，
> 坐实 179 杠杆默认 OFF）。180 第 5 节报告「基线 corner_logo 通路对右下角深块**非确定**
> （跨进程 OFF 误发 0↔1 翻转）」，并把该现象登记为候选审计目标（阶段 18x）。
> 本阶段用进程内热复跑重新审计该论断，结论：**180 的「基线非确定」是冷启动伪影，并非基线缺陷**。
> 据此撤销 180 第 5 节的误判登记，并加固探针避免再生此类伪影。

## 1. 触发与动机

180 首轮运行时，`syn_02_corner_text` / `syn_05_natural` 在杠杆 OFF 下的 `corner_logo` 误发数
先是 **1**、后续 3 次复跑变成 **0**——跨进程的 0↔1 翻转被解读为「基线 corner_logo 通路非确定」。

但这与 179 正交（179 先验被 `if 已有 corner_logo: 跳过` 守卫挡住，不会贡献 OFF 误发），
若真为基线缺陷，意味着**基线本身会在干净图上误发整牌**——这是比 179 误报更严重的问题，
必须查清，不能留在「候选审计」里悬而未决。

## 2. 探针与测量方法（`.probe181.py`）

关键改进：**同一进程内、每张图测量前都先烧热检测器**，并做 5 次 warm 复跑：

- 在每次 `detect_watermark_mask` 调用前，先做一次 1×1 废图推理（等价 `_warmup()`），吸收冷启动离群点；
- 对 5 张合成样本各跑 5 次（OFF 杠杆），统计 `corner_logo` 误发数 + 白源框数（`_plate_boxes_in_patch` 命中）；
- 另跑一张带水印豆包目标图 `ai_logo_02` 作为「白源框应正确命中」的对照。

### 2.1 测量结果

| image_id | OFF corner_logo（5 次 warm 复跑） | 白源框数 | 结论 |
|---|---|---|---|
| syn_01_plain | 0 / 0 / 0 / 0 / 0 | 0 | 不触发 |
| syn_02_corner_text | 0 / 0 / 0 / 0 / 0 | 0 | **稳定不误发**（180 原报 0↔1） |
| syn_03_corner_logo | 0 / 0 / 0 / 0 / 0 | 0 | 不触发 |
| syn_04_corner_translucent | 0 / 0 / 0 / 0 / 0 | 0 | 不触发 |
| syn_05_natural | 0 / 0 / 0 / 0 / 0 | 0 | **稳定不误发**（180 原报 0↔1） |
| ai_logo_02（对照） | n/a | 1 | 白源框**正确命中**（验证探针本身灵敏） |

### 2.2 归因：是冷启动伪影，不是基线缺陷

- 所有干净图在稳态下 OFF `corner_logo` 误发 = **0（5/5 稳定）**，白源框数 = **0**；
- 唯一一次「误发=1」出现在**进程内第一次推理**（未烧热检测器时），复跑前先烧热即消失；
- 机制：torch 算子 / OpenCV 线程池 warming-up，首次推理与后续推理在边界样本上差之毫厘，
  可能翻转「是否误发 corner_logo」的布尔判定——纯属**冷启动离群点**，非基线逻辑非确定。

→ **180 第 5 节「基线 corner_logo 非确定」论断被推翻**；基线在干净图上稳态不误发。

## 3. 加固：把「烧热」固化进探针

既然冷启动伪影会让任何「首次推理即量」的门禁漂绿/漂红，就把消除动作写死：

- `scripts/clean_bench_probe.py` 新增 `_warmup()`：正式测量前用 1×1 废图做一次推理，
  临时把 `DETECT_PLATE_COMPLETE_FROM_SIGNAL` 置 False（避免烧热本身改面积），结束后还原；
- `run_clean_probe` 新增形参 `warmup: bool = True`，默认在测量循环前调用 `_warmup()`；
- `tests/test_clean_bench_probe.py` 新增 `test_probe_deterministic_within_process`：
  同进程两次测量（prior/baseline/total 三率）应完全一致；
- `scripts/_verify_clean_probe.py` 扩展第 ⑤ 条确定性断言 → 由 4/4 升到 **5/5**。

本地独立验证（绕过沙箱 `%TEMP%` 限制）：

## 4. 修正后的真实指标（稳态，可复现）

`clean_bench_probe.py --root benchmark_real/clean --gate-on prior`，进程内复跑稳定：

```
基线误报率(baseline, OFF)      = 0/5 = 0.0000   ← 180 误报的 0↔1 已澄清，稳态=0
179 归因误报率(prior, ON−OFF)  = 2/5 = 0.4000   ← 179 专属风险（稳态可复现）
总误报率(total, ON)           = 2/5 = 0.4000
```

注意：`prior_fp_rate = 0.40` 与 180 数值相同，但**含义已变**——
180 把它混在「基线噪声」语境里，181 澄清它是 **179 先验在稳态下对右下角文字/招牌信号干净图的确定性误发**，
不再有「基线也抽风」的干扰项。

## 5. 结论：决策不变，但理由收紧

- **179 杠杆保持默认 OFF** —— 决策与 180 一致，**理由更新为**：
  179 先验是信号锚定的，右下角有文字/招牌信号的干净图**必**被误铺整牌（稳态测量已证实，
  `syn_02`/`syn_05` 稳定命中）；基线在干净图上稳态不误发，风险**全部**来自 179 先验本身。
- 撤销 180 第 5 节「基线 corner_logo 非确定 → 候选审计（阶段 18x）」登记：已查清为冷启动伪影，非缺陷。
- 诚实披露边界不变：合成样本是对抗性（刻意右下角文字/招牌），会高估误报率；
  真实照片复测仍待用户按 180 提示词补 ~10 张真实干净图（含非豆包）后执行。
