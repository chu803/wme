## 1. 背景与动机

阶段 32 已实现真实的 AI 模型超分（`core/superres.py`），并通过 `postprocess` 接入单图 / 批量 / 自动 / 媒体页的逐帧修复。但 **`remove_watermark_video` / `process_video` 当时未透传真实超分参数**（阶段 32 已知边界之一）。

视频是「拆 → 修 → 拼」流程：逐帧调 `process_image`，再把修复帧写回新视频。真实超分会**改变画布尺寸**（如 4×），而 `video_service` 原有逻辑在第 530 行有「尺寸兜底，强制 resize 回原尺寸」——若直接透传真实超分，放大帧会被拉回原尺寸，**等于白做**，且视频 Writer 要求所有帧同尺寸，否则写出失败。

因此本阶段的核心难点是：**真实放大时，整段输出视频的尺寸必须整体放大且每一帧同尺寸**。

---

## 2. 设计要点

### 2.1 一次性探测后端，整段复用同一实例

`process_video` 在打开视频、读到源尺寸（`width`/`height`）后，**一次性探测**真实超分后端：

```python
_real_enabled = config.REAL_SUPERRES_ENABLED if real_superres is None else real_superres
_real_scale   = clamp(real_scale or config.REAL_SUPERRES_SCALE, 1, 8)
backend       = _resolve_video_backend(real_backend, real_model_path, real_model_dir, _real_enabled)
out_w, out_h  = (width*_real_scale, height*_real_scale) if backend is not None else (width, height)
```

- 后端可用（`backend is not None`）→ 输出视频尺寸 = 源 × scale，且把**同一后端实例**复用给每一帧；
- 后端不可用 → `out_w/out_h` 等于源尺寸，行为与旧版完全一致（回退轻量超分）。

复用实例避免了「逐帧重复 `import torch` / 加载模型」的开销（视频常 900 帧以上）。

### 2.2 输出 Writer 与尺寸兜底统一用输出尺寸

- `_open_writer(dst, fps, out_w, out_h)` 用输出尺寸创建 Writer；
- 逐帧写出前的尺寸兜底目标改为 `(out_w, out_h)`：放大场景下，原样输出 / 处理失败的帧也会被放大到同一尺寸，保证所有帧尺寸一致；非放大场景 `out_w/out_h == 源尺寸`，行为不变。

### 2.3 `real_backend` 同时兼容「实例」与「kind 字符串」

为支持视频复用实例，阶段 32 的 `postprocess` 的 `real_backend` 参数从「仅 kind 字符串」扩展为「`SuperResBackend` 实例 / kind 字符串 / None 均可」：

```python
def _resolve_backend(real_backend, model_path, model_dir):
    if isinstance(real_backend, SuperResBackend):
        return real_backend                      # 视频：直接复用探测好的实例
    kind = real_backend if isinstance(real_backend, str) and real_backend else config.REAL_SUPERRES_BACKEND
    return get_superres_backend(kind, model_path=model_path, model_dir=model_dir)
```

向后兼容：单图 / 批量 / 自动 / API 等原有调用仍传 `None` 或 kind，行为不变。

### 2.4 结果标记与回退警告

`VideoResult` 新增 `upscaled: bool` 与 `real_scale_used: int`。当 `_real_enabled` 为真但后端探测为 `None`（缺 torch / 权重）时，写入警告「已开启真实超分，但当前环境缺少 torch/权重，已自动回退轻量超分（同分辨率）」，用户可见。

### 2.5 视频抽帧对比查看（处理体验增强）

阶段 31 已在自动页 / 单图页提供「拼接 / 滑块 / 热图」三模式对比视图。本阶段在媒体页视频结果区新增**抽帧对比查看**：

- 帧序号滑块（`0 … VIDEO_MAX_FRAMES`）+ 三模式 Radio（复用 `compare.*` 键）+ 「生成增强对比」按钮；
- `run_video_compare(src, out, frame_idx, mode)`：用 OpenCV 从源视频与结果视频各抽同一帧（越界 clamp），结果帧若已被真实超分放大则缩回源尺寸以对齐，再调用 `export_service` 渲染：
  - `concat` → `make_compare_array` + data URI `<img>`；
  - `slider` → `make_before_after_html`（无 `<script>` 拖动控件）；
  - `heatmap` → `make_diff_heatmap` + data URI `<img>`；
- 缺源 / 结果视频时返回提示段落（语言无关，以 `⚠` 开头）。

对比聚焦「去水印效果」，故放大结果会缩回源尺寸对齐，不展示放大本身。

## 6. 已知边界 / 后续可扩展

1. **沙箱无 torch**：真实超分后端默认探测为 `None`，视频真实放大端到端仍需装 `torch` + 权重（`REAL_SUPERRES_MODEL_PATH`）后生效；代码路径已验证（假后端 2× 上行链路通过）。
2. **真实放大改变输出尺寸**：已正确处理（输出视频整体放大、所有帧同尺寸），但抽帧对比查看为对齐会把放大结果缩回源尺寸，对比聚焦去水印效果而非放大倍率。
3. **逐帧真实超分开销**：视频逐帧放大 + 写更大帧，整体更慢且产物体积更大；固定水印场景建议配合「复用水印位置」减少检测次数（真实超分仍逐帧应用）。
4. **音频**：输出视频仍无音轨，需 ffmpeg 合并（视频处理结果区已给出命令）。
5. **UI 未暴露 `real_backend` 选择器**：沿用 `config.REAL_SUPERRES_BACKEND`（auto），与单图 / 批量一致。
