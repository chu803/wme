# 398 · 角标几何覆盖率红线门禁（2026-11-07）

> 把「承诺类的擦净率对**角标长什么样**敏感」从一句提醒，变成**可跟踪、可拦截的数字**。

## 一、为什么要这道门禁

阶段 395–396 的诊断结论：挑战集 4 种角标几何，检出 4/4 但**完全擦净只有 1/4**；
阶段 396 把填充改成"足迹自适应"后升到 **2/4**。剩下的 2/4 是真实缺口，
但此前**没有任何门禁盯着它** ⇒ 下次有人改检测器、几何覆盖悄悄退化，没人知道。

## 二、B2（大板）的精确定位（阶段 397 否证、阶段 398 定位）

| 猜测 | 实验 | 结果 |
| --- | --- | --- |
| 面积上限 2% 挡的（B2 占 2.29%） | 放宽到 5% | **逐位无效** ❌ |
| 长宽比上限 3.2 挡的（B2 是 5.34） | 放宽到 6.0 | **逐位无效** ❌ |
| 角落搜索区太小（B2 的板被切掉） | 0.2 → 0.45 短边 | **逐位无效**，且单图耗时 5.9s→10.9s（翻倍）❌ |

**真因**（逐判据实测）：**白底板块判据的最小边长门槛**
（`DETECT_PLATE_MIN_SIDE` 换算后 19px）——板越大 ⇒ 文字越大 ⇒ 文字上下的**白边越薄**
⇒ 358×67 的板只剩 ~15px 白边 ⇒ 判据不认它。
B1/B3（174×59、小字）白边 ~19px 刚好过线 ⇒ **"板越大反而越难认"**。
B4（无底板纯文字）没有板可填 ⇒ 需要另一条判据（文字层定位）。

⇒ 要吃下这两类几何，得给板块判据补一条**"整块亮板"**通路（新的几何判据），
工程量大一档；在那之前，先把缺口**量化并守住**。

**最后一组否定实验（闭运算核扫描）**：板块判据里本来就有为"被板上深色字形切开的亮块"
准备的闭运算（阶段 173），核大小按长边比例 `DETECT_PLATE_CLOSE_FRAC`——
若把核放大到能跨过 B2 的 48px 文字，板就会和周围亮背景并成一片 ⇒ 触发
"触碰搜索区边界 ⇒ 整块丢弃"。实测三档（0.02 / 0.035 / 0.05，已是配置上限）：

| 闭运算比例 | B2 的角标区域数 |
| --- | --- |
| 0.010（默认） | 0 |
| 0.020 | 0 |
| 0.035 | 0 |
| 0.050（上限） | 0 |

⇒ **核大小不是旋钮**：小了跨不过文字，大了并掉背景 ⇒ B2 必须走**新判据**
（"整块亮板"：把被文字切开的白条按 x 对齐 + 竖向相邻**合并**成整块板）。
本阶段到此为止，缺口已量化并被门禁守住。

## 三、做法

- `scripts/build_challenge_set.py`：按豆包 manifest 的**精确几何参数**
  （174×59 / 358×67 / alpha=128 / 无底板 / 边距 20px）从干净图集**确定性生成** 12 张挑战图
  （**不入库**，干净 checkout 上门禁也能跑）。
- `scripts/challenge_probe.py --gate`：走生产链（检测 → 按预设膨胀下限 → 修复）量
  **检出率**与**完全擦净率**，按 config 红线判定：
  `CORNER_GEOMETRY_MIN_DETECTED`（默认 1.0）、`CORNER_GEOMETRY_MIN_ERASED`（默认 0.5）。
- 接进 `run_all_checks --gates`（`corner_geometry_gate`）。

## 四、当前数字与含义

| 指标 | 实测 | 红线 |
| --- | --- | --- |
| 4 种几何的检出率 | **4/4** | ≥100% |
| 4 种几何的完全擦净率 | **2/4**（左下小板 ✅、半透明板 ✅；大板 ❌、无底板纯文字 ❌） | ≥50% |
| 无水印组改动（顺带量） | 平均 0.20%、最大 0.74% | — |

⇒ 这道门禁现在的作用是：**守住 2/4 不许退**（几何覆盖退化会直接踩红），
同时把"还差哪两种"钉在文档与报告里（下一轮做几何判据时，它就是验收线）。
