# 阶段 186 · 性能探针与时间预算门禁（优化清单 A5）

> 起因：`docs/185` 侦察发现全仓 `p95` / `latency` / `time_budget` 命中 **0 处**——
> 四个门禁都只 `time.time()` **打印**耗时，**没有任何时间红线** ⇒ 战略目标
> 「P95 < 1.5s」**无法判定是否达标**，性能回退无人发现。
> 本阶段把「耗时」从日志变成**门禁**，并首次量出真实数字。

## 1. 交付

- **`scripts/perf_probe.py`**（新门禁，退出码家族契约 0/1/2）：
  - 工作量默认 = **真实基准图**（`benchmark_real/images/`，优先 10 张 `ai_logo_*`）；
  - **逐图 min-of-k**（`--repeat`，默认 3）取样，汇总 min / P50 / P95 / max / 均值；
  - **回归护栏**（默认生效）：`P95 ≤ 基线 P95 × (1 + --tol)`，`tol` 默认 30%；
  - **绝对目标**（默认只报告差距、不判红）：`--target`（默认 1.5s，来自路线图）；
    `--enforce-target` 才升级为硬红线（GPU/CI 环境用）；
  - **可比性裁决**：`source` / `stage` / `repeat` / 结构版本任一不一致 ⇒ **判跳过(2)**，
    杜绝「拿合成图基线判真实照片」或「拿跑 1 次的时间判跑 3 次的」；
  - 无基线 ⇒ **2（跳过，绝不假装通过）**；`--update` 测量并写基线
    `benchmark_real/perf_baseline.json`。
- **`utils/stats.py`**（新共用件）：`nearest_rank_percentile` —— 分位数的**唯一实现**
  （最近秩、无插值，口径与 `real_gate` 阶段 93 起沿用的一致）。`scripts/real_gate.py`
  的面积画像 P90 由本地嵌套 `_pct` 改为调用它（**取值逐位不变**，有回归测试钉住）。
  抽出的理由：本项目反复吃过「同一判据两处实现 ⇒ 慢慢漂移」的亏（LESSONS 187/195）。
- **`tests/test_perf_probe.py`**（15 例）：工作量确定性 / 真实图优先 / 分位口径 /
  可比性裁决 / 退出码语义 / real_gate P90 抽取后不变。
- 接入 `scripts/run_all_checks.py --gates`（第 6 步）；按 **S** 登记进自检登记表。

## 2. 两个测量教训（本阶段的真正价值）

### 教训一：**工作量若用合成素材，会系统性低估真实成本**
首版用「固定 seed 合成图」当工作量：P95 = **0.113s**。
而同一探针改用**真实基准图**：P50 = **1.427s**、P95 = **3.209s** —— **差约 9~28 倍**。
原因是合成底太平滑（纹理/边缘极少），检测器的多数通路几乎不干活。
⇒ 若拿它做门禁，会**掩盖真实回退**（正是「量错对象」的陷阱）。故默认工作量改为真实图，
且基线记录 `source`、跨源**拒绝对比**。

### 教训二：**统计量必须先证明它高于噪声地板，否则门禁会「常红失效」**
首版「每图只跑一次」，连续两次同批测量的 P95 是 **1.558s → 4.037s**（同一张图
1.558s → 4.036s）——**机器负载噪声约 150%**，远超 30% 的护栏 ⇒ 这种门禁会**一直红**，
等价于没有门禁（本项目「红旗常亮=红旗失效」的同族问题）。
⇒ 改为**逐图 min-of-k**：min 是**能力度量**（该机「至少能做到多快」），天然滤掉负载尖峰。
实测：连续两次 P50 **1.427s → 1.479s**（+3.6%）、P95 **3.209s → 3.302s**（+2.9%）——
噪声被压到可判定水平。

## 3. 首次真实性能数据（CPU，10 张真实基准图，min-of-3）

| 指标 | 实测 |
|---|---|
| min | 0.810 s |
| **P50（中位）** | **1.427 s** |
| **P95** | **3.209 s** |
| max | 3.209 s（= P95，n=10 时最近秩取到最大样本） |
| 均值 | 1.677 s |
| 逐图重复内极差均值 | 0.113 s（噪声参考） |

**读法（诚实）**：
- 这是**检测阶段**（不含 LaMa 修复）在 **CPU** 上的成绩；
- 对照路线图 **P95 < 1.5s**：CPU 上 P95 是目标的 **2.1 倍** ⇒ 该目标隐含**GPU 或进一步优化**
  （与 `docs/185` A5 的判断一致：目标只在生产环境可强制，故默认只报告差距）；
- 单张最慢是 `ai_logo_10_lavender_hot_air_balloon`（3.2s）、最快 `ai_logo_07_glass_curtain`（0.8s）
  —— 与图像纹理密度相关（检测器在复杂纹理上通路更多），这本身解释了为何不能用合成底。

## 4. 边界与后续

- **门禁默认只守回归**（不许变慢），不守绝对目标 ⇒ 不会在 CPU 机器上常红；
  上 GPU/CI 时用 `--enforce-target --target 1.5` 即可把目标变红线。
- 基线已入库（`benchmark_real/perf_baseline.json`），随 `real_gate` 基线同一惯例管理；
  **换了机器/CPU 核数**后若整体变慢，应视为「环境变化」→ 用 `--update` 重标并记录原因。
- 未覆盖：**修复阶段（LaMa）延迟**、**GPU 路径**、**并发吞吐**（`docs/185` D1）——
  待有 GPU 环境或并发需求时扩展 `stage` 维度（基线的 `stage` 字段已为此预留）。
- 本阶段产物：`scripts/perf_probe.py`、`utils/stats.py`、`tests/test_perf_probe.py`、
  `benchmark_real/perf_baseline.json`、`run_all_checks` 接入、本文件、LESSONS 199–200。
