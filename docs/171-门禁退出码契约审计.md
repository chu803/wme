# 阶段 171 · 门禁退出码契约审计

> 类型：评测装置盲区审计（承 170）· 探针 3 同族「自述 vs 实际」
> 关联阶段：170（门禁编码/空真值崩溃）、146（刷新护栏）、95（恒红=哑巴）、
> 经验 185（判据不对称即 bug）、经验「静默通过是缺陷温床」

## 1. 选点背景

阶段 170 的教训之一是「**自述的裁决分支可能是死代码**」（文档说会报 X，
实际在更早处崩溃）。本阶段沿同一条线，把门禁家族的**退出码契约**
（`0 通过 / 1 未通过 / 2 跳过`）逐条与其实现比对——「自述 vs 实际」是否一致。

## 2. 契约表（文档 vs 实现）

| 门禁 | 文档声称 | 实现 | 一致 |
|---|---|---|---|
| `quality_gate` | 0 通过 / 1 越线 | 0 / 1 | ✅ |
| `real_gate` | 0 / 1 / 2（2 = 数据集缺失） | 0 / 1 / 2（2 = manifest/truth 缺失） | ✅（**文档 line 112 自相矛盾**，见 S2） |
| `prompted_area_gate` | 0 / 1 / 2（2 = 数据集**或基线**缺失） | 0 / 1 / 2（manifest / 空 / 无图 / 基线缺失） | ✅ |
| `mask_param_audit` | 0 / 1 | 0 / 1 | ✅ |
| **`e2e_real_probe`** | `--gate` help：「0 通过 / 1 失败 / 2 跳过」；`evaluate_gate` doc：「skipped 计入退出码 2 的依据」 | 2 仅用于「图片缺失」；**基线缺失 → 0** | ❌ **S1** |

## 3. 缺口清单（四段）

### S1 · `e2e_real_probe` 的 `skipped` 不参与退出码（P1）

**证据**：`scripts/e2e_real_probe.py:503`（`--gate` help 文本「退出码 0 通过 / 1 失败
/ 2 跳过」）+ `:419`（`evaluate_gate` docstring「skipped … **计入退出码 2 的依据**」）
vs `:587-608`（`main` 只把 `fails` 变成 1，其余**一律返回 0**；`skipped` 仅
`:598` 打印）。`skipped` 的唯一来源是 `:427`「无基线快照：只判定红线，漂移层跳过」。

**机制**：`evaluate_gate` 产出三元组 `(fails, notes, skipped)`，但 `main` 的退出码
只消费 `fails`；`skipped` 被打印成 `⚠` 却不进 `return`。于是「**漂移层根本没跑**」
被压成 `exit 0`。

**后果**：CI 把「只跑了红线、漂移层未判」读成「真的通过了」（假绿）；
且与同族 `prompted_area_gate`（基线缺失返回 **2**）**不对称**——同一情形两个退出码，
正是经验 185「判据不对称即 bug」。

**动作**：抽出纯函数 `gate_exit_code(fails, skipped)`（`fails`→1、`skipped`→2、
否则→0，失败优先），`main` 改用它；并让 `skipped` 分支打印「跳过（未完成全部判定层）」。

### S2 · `real_gate` 退出码文档自相矛盾（P2）

**证据**：`scripts/real_gate.py:112` 写
「`0 = 通过（含「数据集缺失 → 跳过」，见下）`」，而 `:114` 同时写
「`2 = 跳过：manifest 或 ground_truth 缺失`」，实现（`:986-992`）对数据集缺失
返回 **2**。同一段文档里「0 含数据集缺失」与「2 是数据集缺失」直接冲突。

**机制**：`:112` 的括号注释与真实语义相反（「含」应为「不含/另有」），属笔误残留。

**后果**：读者据 `:112` 会以为「数据集缺失也算通过（0）」，与 CI 实际读到的 2 相反
——正是本阶段要消灭的「自述 ≠ 实际」。

**动作**：改 `:112` 为「`0 = 通过`」，并加一行勘误说明。

## 4. 什么情况算完备（可判定验收线）

1. `e2e_real_probe --gate` 三种情形的退出码 = 文档：**无基线 → 2 / 红线越界 → 1 / 全过 → 0**
   （由 `gate_exit_code` 守卫钉住）。
2. 契约表五行「文档 = 实现」成立（本阶段后全 ✅）。
3. 注入式反例：把退出码映射改回「只认 fails」⇒ 守卫应变红（已验）。
4. 祖先缺陷回归：`evaluate_gate(agg, None)` 必产生 `skipped` 且映射到 2（非 0）。

## 5. 修复

- `scripts/e2e_real_probe.py`：新增 `gate_exit_code()`；`main` 尾部改为
  `fails`→打印未通过 / `skipped`→打印跳过 / 否则打印通过，最后 `return gate_exit_code(...)`。
- `scripts/real_gate.py`：修正退出码文档 `:112`。

## 6. 守卫

`tests/test_e2e_real_probe_exit_codes.py`（4 用例）：
映射基础（含失败优先）/ 无基线→2（回归）/ 有基线合规→0 / 红线越界→1。

## 7. 验证

- 守卫直跑：**PASSED=4 FAILED=0**。
- 注入式反例：把 `gate_exit_code` 改回「只认 fails（skipped 不返码）」⇒ 守卫
  `test_missing_baseline_is_skip_not_pass` 变红；还原后 sha256 逐字节一致 ⇒ 复绿。
- 端到端：`e2e_real_probe.py --gate`（基线在位）EXIT=0 不变（skipped 为空，
  修复不改变基线在位时的行为）。

## 8. 诚实边界

- **潜伏而非活跃**：`benchmark_real/e2e_baseline.json` 已提交，`--gate` 正常运行时
  `skipped` 为空 ⇒ 本修复闭合的是「有图但基线被删/未就位」这一**潜伏**契约漏洞，
  非当前活跃红（当前 `e2e --gate` 实测 EXIT=0）。
- **家族口径差异（已登记，本阶段不改）**：对「**基线缺失**」，`real_gate` /
  `quality_gate` 走「只跑红线 → 0」，`prompted_area_gate` / `e2e_real_probe` 走
  「跳过 → 2」。二者**各自的文档是自洽的**（real_gate 的 2 只声明给数据集缺失）。
  是否统一（按经验 185 应统一）属口径决策，且改动主门禁退出码影响面较大，
  故登记为显式边界，留待后续按需收敛。
- 未跑全量 pytest（沙箱拒删 basetemp）；本阶段守卫已用直调核验。
