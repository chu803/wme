# 阶段 154 · 真实对决决策基线守卫（real_benchmark_decision）

## 动机
顺延审 `scripts/` 入口，继 152（收编入口）、153（校验工具一致性）之后，本轮审计
`scripts/real_benchmark_decision.py` 的胜者判定。`audit_selector` 未审榜已空，故按
「刻意选点」原则挑薄弱入口：该脚本只被 `test_real_benchmark_smoke.py` 的 `_repair_one`
接线测试覆盖，**整个 `main()` 的胜者统计逻辑零测试**。

## 抓到（P0 · 契约失效 / 假胜出）
`_run_image` 计算 `baseline_seam_delta`（第 234 行，原图未修复的接缝色差下界），文档第 233 行
明确写：「修复到不劣于此才算『真的擦掉了水印』」。但 `main()` 第 333–352 行只拿 `ocv`/`lam`
比较，**`baseline` 仅传给打印格式化器 `_f(base)`**，决策完全忽略它。

⇒ 当两引擎都**劣于「留着水印不修复」**时，脚本仍会判出一个 winner：
- `ocv=50, lam=60, baseline=10` → 历史逻辑判 `opencv` 胜（假胜出）；
- 两引擎都劣但差值 <3.0 → 判 `tie`（同样误导，因为根本没有任何一方「真擦掉」）。

这是**静默契约违背**：文档承诺了下界，代码却没强制。

## 修法（纯函数固化契约）
抽纯函数 `_decide_winner(ocv, lam, baseline, tol=3.0)`，返回 5 态：
- 非双数值 → `"n/a"`；
- 两引擎都 ≥ `baseline` → `"inconclusive"`（**不构成胜出**，核心修复）；
- 否则按 seam_delta 越低越好，`|差|<tol` → `"tie"`，否则小者胜（`"opencv"`/`"lama"`）。

`main()` 改用它，`tally` 新增 `inconclusive` 桶并在末尾统计输出
（「inconclusive N（两引擎都不如不修复）」）。

## 守卫
新增 `tests/test_real_benchmark_decision.py`（12 例）：
- 纯函数五态参数化覆盖（inconclusive/opencv/lama/tie/n/a，含「恰好等于 baseline」
  「平手区但都劣于 baseline」边界）；
- `test_false_winner_regression`：历史假胜出 `ocv=50,lam=60,base=10` 必须 ≠ opencv
  且 = inconclusive；
- 集成守卫 `test_main_tally_reports_inconclusive_when_both_worse`：`WME_BENCH_DIR` 指向 tmp
  + `importlib.reload` 让模块常量解析到 tmp，注入合成结果（两引擎都劣于 baseline）并
  monkeypatch `_run_image`，断言 `main()` 标准输出记 `inconclusive 1` 且
  `opencv 0`/`lama 0`（不得假胜出）。

## 诚实边界
- 本修复只约束「对决胜负判定」的契约；`seam_delta` 作为无参考代理本身的质量上限未变
  （真实图无「未加水印原图」仍是开放问题，见脚本头部文档）。
- `main()` 现在会如实把「两引擎都擦不干净」标记为 `inconclusive` 而非误导性的
  winner/tie——这会让历史对决统计里出现 inconclusive 桶，属**诚实收紧**，不是指标劣化。
