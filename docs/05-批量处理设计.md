> 项目：AI 智能水印擦除工作台（AI Watermark Eraser Workbench）
> 阶段目标：在「单图处理 / 智能自动检测」两个入口之外，补齐 **批量处理能力**，

## 2. 任务队列引擎（services/queue_worker.py）

### 2.1 核心数据结构

```python
class TaskStatus(str, Enum):
    PENDING   = "pending"    # 已入队，等待执行
    RUNNING   = "running"    # 正在执行
    DONE      = "done"       # 执行成功
    FAILED    = "failed"     # 失败（含重试后仍失败）
    CANCELLED = "cancelled"  # 被用户取消

@dataclass
class Task:
    id: str                      # uuid4 前 8 位，便于日志阅读
    name: str                    # 展示名（文件名）
    path: str                    # 原图绝对路径（支持中文）
    status: TaskStatus = PENDING
    progress: float = 0.0        # 0~1
    message: str = ""
    result: Optional[dict] = None
    error: Optional[str] = None
    retries: int = 0
    _cancelled: bool = False     # 任务级取消标记（与队列级联动）

    def to_dict(self) -> dict:   # 可 JSON 序列化，用于界面/日志
        ...
```

### 2.2 BatchQueue 公开接口

| 方法 | 签名 | 说明 |
| :--- | :--- | :--- |
| `__init__` | `(max_concurrency=None, max_size=None, retry=None, timeout=None)` | 参数缺省时全部取 `config` 默认值 |
| `submit` | `(name: str, path: str) -> Task` | 入队；队列满抛 `QueueFullError` |
| `reset` | `() -> None` | 清空队列与取消标志（无进行中任务时调用） |
| `cancel` | `() -> None` | 设置队列级取消标志，中断剩余任务 |
| `is_cancelled` | `() -> bool` | 读取取消标志（线程安全） |
| `run` | `(processor, on_update=None) -> Iterator[Task]` | **生成器**：并发执行，逐个 yield 完成的 Task |
| `summary` | `() -> dict` | 聚合快照 `{total,done,failed,cancelled,running,pending,finished,progress}` |
| `count_done` / `count_failed` / `count_cancelled` | `() -> int` | 各类计数 |
| `tasks` | `() -> list[Task]` | 任务列表浅拷贝（线程安全读取） |

**类型别名**：

```python
ProgressCallback = Callable[[float, str], None]        # on_progress(progress, message)
Processor       = Callable[[Task, ProgressCallback], dict]  # 成功返回结果 dict，失败抛异常
```

### 2.3 并发与流式进度的实现

`run()` 是生成器，内部用 `ThreadPoolExecutor(max_workers=max_concurrency)` 提交所有任务，
再用 `as_completed(futures)` 迭代：

- **谁先完成谁先 yield** —— 进度条与日志能实时滚动，不用等整批结束。
- `on_update(task)` 回调在每次 yield 前触发，供界面层汇总日志、收集画廊项。
- Gradio 的 generator 回调天然支持这种「逐项流式输出」，因此 `run_batch` 直接把
  `queue.run(...)` 包在生成器里，每次 `yield (进度比例, 日志文本, 画廊列表)`。

### 2.4 单任务执行状态机（_execute）

```
PENDING ──submit──▶ （进入线程池）
   │
   ▼
RUNNING ──processor 抛 _CancelSignal──▶ CANCELLED
   │
   │ processor 抛普通异常 → 重试（retry 次）
   ▼
DONE  （status="done", result=结果 dict, progress=1.0）
   │
   ▼ （重试耗尽）
FAILED （status="failed", error=str(exc), progress=0.0）
```

- **重试**：尝试次数 = `retry + 1`；偶发失败 `sleep(0.5*(attempt+1))` 后重试，
  重试耗尽才标记 `FAILED`，**单个任务失败不拖垮整批**。
- **取消感知**：`_on_progress` 检查点是取消信号的捕获点。一旦 `self._cancelled`
  或 `task._cancelled` 为 True，`_on_progress` 抛出内部 `_CancelSignal`，
  processor 立即中断，任务标记为 `CANCELLED`。未开始的任务在提交前被直接标记取消。
- **线程安全**：所有共享状态（`_tasks / _index / _cancelled / task.progress`）
  都经 `threading.RLock()` 保护；`_CancelSignal` 是内部异常，不会泄漏到队列之外。

### 2.5 配置项（config.py 复核均已存在）

| 常量 | 默认值 | 含义 | 范围 |
| :--- | :--- | :--- | :--- |
| `BATCH_CONCURRENCY` | 1 | 批量并发线程数 | 1–16（CUDA 模式 >2 时警告） |
| `QUEUE_MAX_SIZE` | 500 | 队列最大长度 | 1–10000 |
| `QUEUE_TASK_RETRY` | 1 | 单任务失败重试次数 | 0–5 |
| `QUEUE_TASK_TIMEOUT` | 600 | 单任务超时秒数（预留） | 30–7200 |

## 3. 历史记录缓存（services/cache_service.py）

### 3.1 数据结构

```python
@dataclass
class HistoryRecord:
    id: str
    ts: float                       # 处理完成时间戳
    original_name: str
    original_path: Optional[str]    # 原图落盘路径（重处理免重复上传）
    result_path: Optional[str]      # 修复结果图路径（下载用）
    thumb_path: Optional[str]       # 缩略图路径（画廊展示）
    mode: str = "auto"              # auto / manual
    engine: str = "auto"            # lama / opencv / auto
    status: str = "success"         # success / failed
    file_hash: Optional[str] = None # 原图内容哈希（去重）
    params: str = ""                # 参数摘要（回溯用）
```

### 3.2 文件落盘布局

```
CACHE_DIR/
├── history_index.json          # 索引（HistoryRecord 列表）
├── uploads/                     # 原图落盘（reuse file_service.save_upload）
├── thumbs/                      # 缩略图（make_thumbnail + save_thumbnail）
└── outputs/                     # 修复结果成品图（由上层 save_result 写出）
```

### 3.3 关键方法

| 方法 | 说明 |
| :--- | :--- |
| `compute_file_hash(path, algo="md5")` | 分块读取计算内容哈希，用于去重判定 |
| `add_success(...)` | 落盘原图 + 生成缩略图 + 追加索引并持久化，返回 `HistoryRecord` |
| `update_result_path(record, result_path)` | 结果成品写出后回填路径（去重命中需 `result_path` 非空） |
| `add_failure(name, error, ...)` | 仅登记失败日志，不含结果/缩略图 |
| `list_records()` | 全部记录按时间倒序（最新在前） |
| `find_by_hash(file_hash)` | 找最近一条「成功 + 哈希一致 + 有结果」的记录（去重命中） |
| `get(record_id)` / `update_record(record)` | 按 id 取 / 替换（重处理后回填缩略图与结果，供历史页「重新处理」） |
| `delete(record_id)` | 删记录 + 清缩略图（**保留 outputs 成品图，不误删用户资产**） |
| `clear()` | 清空全部记录与缩略图（保留 outputs），返回删除数 |
| `prune()` | 自动清理：超 `CACHE_KEEP_DAYS` 天或超 `CACHE_MAX_RECORDS` 条，返回删除数 |

### 3.4 缓存配置项（config.py）

| 常量 | 默认值 | 含义 |
| :--- | :--- | :--- |
| `CACHE_ENABLED` | True | 总开关 |
| `CACHE_MAX_RECORDS` | 200 | 记录数上限 |
| `CACHE_KEEP_DAYS` | 30 | 过期天数 |
| `CACHE_INDEX_FILE` | `"history_index.json"` | 索引文件名 |
| `CACHE_THUMBNAIL_SIZE` | 256 | 缩略图边长 |

### 3.5 健壮性细节

- **加载时过滤死链**：`_load()` 会丢弃 `result_path` 已不存在的记录（如被手动删除），避免界面显示死链。
- **失败容错**：`add_success` 内部异常被捕获并记日志，返回 `None`，不中断批量流程。
- **IO 不持锁**：删除/清理缩略图在锁外执行，避免持有 `RLock` 做磁盘 IO。
- **自动清理时机**：构造时与每次 `add_success` 后（`__init__` 调 `prune()`）触发，磁盘不会无限膨胀。

## 4. 批量处理界面（ui/tab_batch.py）

### 4.1 布局

- **左列**：文件夹导入 / 多文件导入 → 模式 Radio（auto / manual）→ 手动掩码文件夹（仅 manual 显示）→ 参数 Accordion（引擎、敏感度、力度、降噪、膨胀、平滑、阈值）→ 开始 / 取消按钮。
- **右列**：总体进度条 + 处理日志框 + 结果画廊（点击放大、右键另存）。

### 4.2 核心辅助函数

| 函数 | 作用 |
| :--- | :--- |
| `_normalize_file_value(value)` | 把 Gradio 多版本返回值（None / str / list / dict）规整为纯路径列表，去重保序 |
| `_mask_path_for(mask_folder, image_path)` | 在掩码文件夹找与原图同名的灰度掩码（按 stem 匹配） |
| `_build_editor_value(image, mask)` | 组装 Gradio 6.x 的 `ImageEditor` dict：`{background, layers:[红色 RGBA], composite:None}` |
| `_cv2_threshold(gray)` | 掩码文件夹模式做 Otsu 二值化（延迟 import cv2） |
| `_process_one(task, on_progress, ...)` | **单图原子单元**，复用 `process_auto_repair`，含缓存去重 |

### 4.3 单图原子单元 `_process_one` 流程

```
task.path
  └─ validate_image_file(path)          # 损坏/超大/格式非法 → 抛 ValueError（不拖垮批次）
  └─ compute_file_hash(path)
       └─ _CACHE.find_by_hash(hit)      # 命中且结果存在 → 直接复用，标记 skipped
  └─ load_image(path)
  └─ mode=="manual"?
       是 → _mask_path_for 找同名掩码 → 灰度 → Otsu 二值
       否 → detect_watermark_mask(image, sensitivity, use_ocr)
  └─ mask 全空? → 抛 ValueError("未检测到水印区域")
  └─ _build_editor_value(image, mask)
  └─ process_auto_repair(...)           # 与阶段 4「智能自动检测」页签同一条修复路径
       → (_, result, status, out_path)
  └─ _CACHE.add_success(...) + update_result_path(rec, out_path)
  └─ return {status, out_path, result_path, thumb, skipped}
```

> 设计要点：批量入口与单图/自动入口**复用同一修复路径**，保证两种入口行为完全一致，
> 不出现「单图效果好、批量效果差」的分裂。

### 4.4 生成器 `run_batch`（Gradio 6.x 适配）

```python
def run_batch(
    folder_value, files_value, mask_folder_value,
    mode, engine, strength, dilate, feather, threshold, denoise, sensitivity,
    progress: "gr.Progress" = gr.Progress(),   # 必须置于所有普通输入之后，默认值实例
):
    ...
    for _t in queue.run(_processor, on_update=_on_update):
        s = queue.summary()
        yield s["progress"], "\n".join(log_lines[-200:]), list(gallery)
    ...
```

- `progress` 参数按 Gradio 6.x 约定放在**所有输入之后**，默认值为 `gr.Progress()` 实例，
  由 Gradio 自动注入，不占用 `inputs` 列表位置（阶段 4 已踩坑修正）。
- 无文件 / 手动模式缺掩码文件夹时，直接 `yield (0.0, 提示, [])` 提前返回。

### 4.5 取消

`cancel_batch()` 调用 `_CURRENT_QUEUE.cancel()`（模块级队列引用，由 `run_batch` 写入）。
进行中任务在下一个 `_on_progress` 检查点感知取消并安全退出。

## 5. 历史记录界面（ui/tab_history.py）

### 5.1 布局

- 顶部：刷新 / 清空全部按钮。
- 画廊（左，3 列）+ 详情 Markdown / 下载 File / 重处理参数 Accordion（右）。

### 5.2 关键函数与机制

| 函数 | 作用 |
| :--- | :--- |
| `load_gallery()` | 读缓存 → 组装 `(缩略图, 标题)` 画廊值 + 统计文本；重建 `_HISTORY_ID_MAP` |
| `on_select(evt)` | 画廊选中事件，按 `evt.index` 从 `_HISTORY_ID_MAP` 定位记录 → 详情 + 下载文件，写入 `_LAST_SELECTED_ID` |
| `delete_selected(rec_id)` | 删除单条 + 刷新画廊 |
| `clear_all()` | 清空全部 + 刷新画廊 |
| `reprocess(rec_id, engine, strength, denoise)` | 重新检测 + 修复原图 → 更新缩略图/结果路径 → `update_record` 持久化 |

- **选中定位机制**：`_HISTORY_ID_MAP`（画廊顺序→记录 id）解决 Gradio Gallery `select`
  只给 index 不给 id 的问题；`_LAST_SELECTED_ID` 供删除/重处理按钮复用。
- **重新处理闭环**：读取 `rec.original_path`（原图已落盘缓存）→ 重新检测 → 修复 →
  生成新缩略图 → `update_record` 覆盖旧记录，结果即时在画廊刷新。
- **统一返回二元组**：所有回调返回 `(str, list)`（详情/信息文本 + 画廊值），与组件绑定一致。

## 7. 使用说明（零基础）

1. 进入「批量处理队列」标签页。
2. 点「导入整个文件夹」选一个全是带水印图片的目录，或拖入多张图片。
3. 模式选「智能自动检测」（默认）；若你已有同名灰度掩码，选「手工掩码文件夹」并指定掩码目录。
4. 按需调整参数（敏感度、力度、降噪等），点「④ 开始批量处理」。
5. 右侧实时滚动：进度条 + 成功/失败日志 + 结果画廊。随时可点「取消」。
6. 去「历史记录」标签页：浏览缩略图、点选看详情、下载结果、或「重新处理」改参数再跑一次；重复导入同一张图会命中缓存直接复用。

## 8. 已知限制与后续优化点

- `BATCH_CONCURRENCY` 默认 1（CPU/OpenCV 降级安全）；若部署机有 GPU 且 LaMa 可用，可调高并发。
- `_process_one` 的缓存去重按「原图内容哈希」命中即复用——若想用**不同参数**重跑同一张图，
  当前会复用旧结果；如需「参数变化即重算」，可在 `find_by_hash` 命中后比较 `params`（后续增强）。
- 失败记录目前只留日志、不入画廊；可后续在画廊中特殊标记失败项便于复查。
- 阶段 6+ 规划：界面美化、打包部署、性能调优、拓展功能（如批量导出 ZIP、PDF 水印专模等）。
