- 这印证并**闭合**了 174（调参无效）、176 §7（lift 块过不了 whiteness 那套过滤、

## 2. 根因重定位：缺口不是 corner_logo 调参，而是"生成器感知先验"缺失

对 4 张目标图跑**真实检测器**并 dump 全部区域，发现反直觉事实：

```
### ai_logo_06_flower_field_  mask_recall=0.389  corner_logo区域数=0  ← 白牌通路 0 输出
    kind计数: {'translucent': 2, 'edge_text': 2}
    translucent (1685,1880,126,120) GT交叠=13685px
    edge_text   (1400,1914,595,56)  GT交叠=16968px
### ai_logo_07_glass_curtain  mask_recall=0.272  corner_logo区域数=0
    kind计数: {'translucent': 12}
    translucent (1686,1880,236,120) GT交叠=26450px   ← 牌几乎被 translucent 抓到
### ai_logo_08_abstract_flui  mask_recall=0.030  corner_logo区域数=0
    translucent (1795,1917,138,126) GT交叠=13110px
### ai_logo_09_vintage_typew  mask_recall=0.226  corner_logo区域数=0
    translucent (1789,1832,265,132) GT交叠=13760px
```

| 图 | mask_recall | corner_logo 区域 | 召回来源（与 GT 交叠 px） |
|---|---|---|---|
| 06 花田 | 0.389 | **0** | translucent 13685 + edge_text 16968 |
| 07 玻璃 | 0.272 | **0** | translucent 26450 |
| 08 抽象 | 0.030 | **0** | translucent 13110 |
| 09 打字机 | 0.226 | **0** | translucent 13760 |

**重定位结论**：
- `corner_logo`（白牌）通路在低对比底上**完全不触发**（0 区域）；当前那点召回
  100% 来自 `translucent`（半透明叠加层检测）+ `edge_text` 在右下角牌区的**碎片命中**。
- `translucent` 抓的是"豆包AI"文字/描边的半透明叠加，**没抓到牌的实心填充**——
  故 bbox 与 GT 交叠 1.3~2.6 万 px，但稀疏掩码只覆盖真值框 3~39%（文字≠整牌）。
- 这意味着：问题根本不是"白牌判据调参"，而是**没有任何通路在右下角重构出完整的
  340×128 牌体**。低对比牌的"实心填充"在任何绝对量/相对量亮度启发式下都不可分。

## 3. 唯一可行的下一条路径（登记，待用户授权实现）

> 174 当年即定性"需新候选模型"，176 验证 lift 不可用。178 把候选收敛到唯一方向。

**生成器感知的牌布局先验（plate_footprint_prior）**：
- 172-A 已用亮度剖面客观证实：豆包角标是固定 **340×128 圆角板**，恒在右下角、
  随图尺寸等比缩放（2048² 上即 340×128）。这是**可证伪、可复现的不变式**。
- 设计：在 `detect_watermark_mask` 装配阶段做**信号锚定的牌体补全**——
  当某角搜索区内有 `translucent`/`edge_text` 证据（**不是盲猜位置**）但无 `corner_logo`
  命中时，在该角按"规范化足迹"补发一个 `corner_logo` 区域（尺寸随图缩放）。
- **可逆杠杆** `DETECT_PLATE_COMPLETE_FROM_SIGNAL`（默认 OFF）+ 守卫测试 + 注入式反例。
- **精度风险（须诚实披露）**：当前基准 10 张全为带水印豆包图，**无干净图**，
  故"干净图上误发整牌"的误报率**不可测量**。实现后须在门禁与 README 显式标注该留白，
  待补齐干净图基准再标定红线。
