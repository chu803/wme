# 阶段 6 设计文档：界面美化 · 导出服务 · 设置页 · 复用组件

> 所属项目：AI 智能水印擦除工作台（AI Watermark Eraser Workbench）
> 阶段目标：在「功能完整」的基础上做一次体验升级 —— 统一视觉风格、补上结果「交付」能力（导出 / 对比 / 打包）、新增设置与导出页、并抽离跨标签页复用的 UI 组件，消除重复代码。
> 完成日期：2026-08-04

---

## 1. 背景与范围

前 5 个阶段已完成「单图 / 自动 / 批量 / 历史」全部功能，但存在三处体验短板：

1. **视觉不统一**：所有页签沿用 Gradio 默认外观，缺乏品牌感，且标题区、按钮、画廊间距未做打磨。
2. **结果「交付」能力缺失**：修复结果只能逐张在画廊里右键另存；没有「一键导出全部历史」「原图 vs 修复后对比图」这类用户真正需要的产出能力。
3. **参数面板重复**：批量页、自动页、单图页各自的「修复参数面板」是三份近似拷贝，改一处要同步三处，违反 DRY。

阶段 6 一次性补齐上述三项，且**不破坏任何既有功能**：修复核心路径（core / services）零改动，仅新增模块 + 接线。

---

## 2. 分层与依赖（铁律重申）

```
ui  →  services  →  core  →  utils  →  config
```

| 模块 | 层级 | 依赖方向 | 关键约束 |
| --- | --- | --- | --- |
| `ui/theme.py` | 界面层 | `gradio`, `config` | 允许 import gradio |
| `ui/components.py` | 界面层 | `gradio`, `config` | 允许 import gradio；**仅产出组件，不触发业务逻辑** |
| `ui/tab_settings.py` | 界面层 | `services.export_service`, `services.cache_service`, `ui.components`, `config` | 可 import services / 其它 ui；不反向 |
| `services/export_service.py` | 服务层 | `core.image_utils`, `utils.*`, `config` | **严禁 import ui / gradio**，进度只通过回调抛出 |
| `services/cache_service.py`（新增 `get_cache()`） | 服务层 | `core`, `utils`, `config` | 保持无 gradio |

> 要点：`export_service` 与既有 `queue_worker` / `cache_service` 同源，是「纯服务、不碰界面」的；界面层（`tab_settings` / `components` / `theme`）才允许接触 Gradio。

## 3. 新增配置段（`config.py`）

阶段 6 在 `config.py` 新增少量常量，未改动既有常量：

```python
# 【导出目录】对比图 / 打包 ZIP / 重新编码结果落盘位置。
EXPORT_DIR: Final[Path] = _resolve_dir("EXPORT_DIR", "exports")

# 【对比图间隔像素】原图与修复后之间的白色留白宽度。
EXPORT_COMPARE_GAP: Final[int] = _env_int("EXPORT_COMPARE_GAP", 24)

# 【对比图是否标注 Before/After】True 会在左右两图上叠字。
EXPORT_COMPARE_LABEL: Final[bool] = _env_bool("EXPORT_COMPARE_LABEL", True)
```

并在 `ensure_directories()` 的 `targets` 元组中加入 `EXPORT_DIR`，使程序启动时自动建好 `exports/`，无需手动创建。

## 4. 统一主题与 CSS（`ui/theme.py`）

### 4.1 主题对象 `build_app_theme()`

- 基于 `gr.themes.Soft` 定制品牌色：主色 `#2563EB`（蓝）、辅色 `#38BDF8`（天蓝），并微调 `background_fill_primary` / `block_background_fill` / `button_primary_background_fill` 等。
- **安全兜底**：整段定制放在 `try/except` 内；一旦当前 Gradio 版本不支持某字段，自动回退到 `gr.themes.Soft()`，确保 `launch_app()` 永不因主题参数崩溃。
- 模块含 `__main__` 自检：构造主题并打印主题对象类型，验证不报错。

### 4.2 自定义样式 `APP_CSS`

- 纯装饰 CSS（不影响功能），所有选择器限定在 `.gradio-container` 内，不污染页面其它部分。
- 覆盖点：标题区渐变、主按钮圆角与悬浮态、画廊卡片间距、日志框等宽字体、对比图等比例。
- 注入方式：`app.launch(css=APP_CSS)`（Gradio 6.x 约定，已从 `Blocks()` 构造移除）。

### 4.3 接线位置

`ui/app.py` 的 `launch_app()` 改为：

```python
app.launch(
    ...
    theme=build_app_theme(),   # 阶段 6 注入
    css=APP_CSS,               # 阶段 6 注入
    footer_links=footer_links,
)
```

## 5. 导出服务（`services/export_service.py`）

服务层模块，提供 4 个公开函数（含 `__main__` 自检，4 个用例全通过）：

| 函数 | 作用 | 关键参数 |
| --- | --- | --- |
| `reencode_image(src, *, fmt, quality, out_path, keep_alpha)` | 把单张结果图按格式（PNG/JPG/WEBP）与画质重新编码保存 | `fmt` 默认识别后缀；`quality` 仅对 JPG/WEBP 生效 |
| `export_compare(original, repaired, *, out_path, gap, label)` | 生成「原图 \| 修复后」左右拼接对比图 | `gap=EXPORT_COMPARE_GAP` 白色留白；`label=EXPORT_COMPARE_LABEL` 叠 Before/After |
| `export_paths_as_zip(paths, *, fmt, quality, out_path)` | 把一批图片路径打包成 ZIP | 可选重编码；自动去重文件名 |
| `export_history_as_zip(records, *, fmt, quality, out_path)` | 把历史缓存的成功记录导出为 ZIP | 直接吃 `HistoryRecord` 列表，取 `result_path` |

设计要点：

- **中文路径 / 透明通道**：读写复用 `core.image_utils.load_image_with_alpha` / `save_image`，与修复主流程一致。
- **延迟导入 cv2**：`export_compare` 才用拼接与标注，缺失时给出明确报错提示而非静默失败。
- **文件名安全**：`utils.path_helper.sanitize_filename` 处理非法字符；`make_unique_path` 避免覆盖。
- **失败隔离**：单张重编码失败不影响整包 ZIP（记录日志后跳过）。

## 6. 复用组件（`ui/components.py`）

把「修复参数面板」从各标签页抽离为单一来源，消除重复。

### 6.1 数据结构 `RepairParamHandles`

```python
@dataclass
class RepairParamHandles:
    engine: gr.Radio
    strength: gr.Slider
    dilate: gr.Slider
    feather: gr.Slider
    threshold: gr.Slider
    denoise: gr.Slider
    sensitivity: gr.Slider
```

把一组组件句柄打包，供回调 `inputs=[...]` 引用。

### 6.2 构建器

| 函数 | 返回值 | 说明 |
| --- | --- | --- |
| `build_repair_params(accordion_title, open_, sensitivity_label, sensitivity_info)` | `RepairParamHandles` | 在 `gr.Accordion` 内构建完整参数面板，默认值全部读 `config`（`INPAINT_STRENGTH_DEFAULT` 等） |
| `build_export_format_selector()` | `(format_radio, quality_slider)` | 导出格式（png/jpg/webp）+ 画质滑块（JPG/WebP 有效） |
| `param_values(h)` | `dict` | 把句柄当前值提取为字典，便于传给 `process_auto_repair` |

### 6.3 接线效果

`ui/tab_batch.py` 阶段 6 起改为：

```python
params = build_repair_params(
    accordion_title="③ 处理参数（本批次统一）",
    open_=True,
    sensitivity_label="自动检测敏感度",
    sensitivity_info="调高可揪出更淡的水印，但误判率上升",
)
...
run_btn.click(
    fn=run_batch,
    inputs=[folder_input, files_input, mask_folder, mode,
            params.engine, params.strength, params.dilate, params.feather,
            params.threshold, params.denoise, params.sensitivity],
    outputs=[batch_bar, batch_log, batch_gallery],
)
```

> `inputs` 顺序与 `run_batch(folder_value, files_value, mask_folder_value, mode, engine, strength, dilate, feather, threshold, denoise, sensitivity, progress=...)` 一一对应（11 个普通输入 + `progress` 置于最后，符合 Gradio 6.x 约定）。

## 7. 设置与导出页（`ui/tab_settings.py`）

「设置与导出」标签页，复用 `export_service` + `components` + `cache_service.get_cache()`：

1. **配置快照**（只读 Markdown）：展示当前关键配置（模型状态、设备、目录、队列/缓存参数）。
2. **导出设置**：`build_export_format_selector()` 选择格式与画质。
3. **操作按钮**：
   - 导出全部历史为 ZIP（按所选格式重编码）→ `export_history_as_zip`
   - 立即清空缓存 → `CacheService.clear()`（只删索引与缩略图，**保留 outputs 成品图**）
   - 立即清理过期记录 → `CacheService.prune()`（按 `CACHE_KEEP_DAYS` / `CACHE_MAX_RECORDS`）
   - 生成配置快照 → 把当前 config 落盘为 `exports/config_snapshot.txt`

### 7.1 缓存单例 `get_cache()`

`services/cache_service.py` 新增模块级单例：

```python
_CACHE_SINGLETON: CacheService | None = None

def get_cache() -> CacheService:
    global _CACHE_SINGLETON
    if _CACHE_SINGLETON is None:
        _CACHE_SINGLETON = CacheService()
    return _CACHE_SINGLETON
```

`tab_batch` / `tab_history` / `tab_settings` 三页改用 `get_cache()`，确保同一进程内缓存状态一致（一处清空，处处可见）。

## 9. 遗留与后续

- **界面美化范围**：阶段 6 完成了主题、CSS、导出页、复用组件。更细的视觉打磨（如每个页签的图标、空状态插画、移动端适配）可列入后续优化，但不影响功能。
- **导出格式扩展**：目前支持 PNG/JPG/WEBP；如需 TIFF/AVIF 等，在 `export_service` 增加分支即可，无需改动界面。
- **设置项持久化**：阶段 6 的设置页为「只读快照 + 即时操作」，未做「用户改设置→写回 config/.env」。若需可持久化用户偏好，需扩展 config 的写入能力（列为后续优化点）。
