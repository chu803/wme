# 阶段 169 · 报告类交付物 i18n 泄漏收口

> 类型：i18n 整类泄漏收口 · 第 4 子类（整类收口完成）
> 关联经验：#197（本地化只解外层模板·内层硬编码泄漏）/ #194（i18n 守卫须含全角标点）
> 关联阶段：162（全角标点）/ 164（任务级消息）/ 166（报告汇总口径，登记本子类）/ 168（异常文案）

## 1. 选点背景

i18n 整类泄漏分 4 子类，前三子类已于 162 / 164 / 168 收口；本阶段处理最后一个、也是 166 已登记的 **报告类交付物**：

| 子类 | 状态 | 收口阶段 |
|------|------|----------|
| 全角标点 | ✅ | 162 |
| 任务级消息 | ✅ | 164 |
| utils.exceptions 异常文案 | ✅ | 168 |
| **报告类交付物（`report_service`）** | ✅ **本阶段** | 169 |

`services/report_service.py` 生成用户**要交付/归档/打印**的 HTML/PDF 修复报告；此前报告内所有文案（标题、汇总、质量标签、逐条明细、PDF 文本行、错误提示）全部硬编码中文单语，英文界面下导出报告仍整篇中文。

## 2. 根因探针（量化）

全 606 行通读后，定位 deliverable 文案硬编码点（`t()`/i18n 零接入）：

| 位置 | 硬编码中文 | 分类 |
|------|-----------|------|
| `_encode_png` | `PNG 编码失败` | 错误 |
| `build_entries` | `报告对比图生成失败…` / `报告质量评估失败…`（log） | 日志 |
| `_quality_summary` | `本报告未包含质量评估（…）` + `良好/告警/待复核/未评估` | 汇总 |
| `_card_html` | `未评估质量` / `质量分 {s} · {level}` / `对比图`(alt) / `模式/引擎：` / `时间：` / `参数：` | 卡片 |
| `generate_html` | `{APP_NAME} 修复报告` / `共 N 条` / `平均分` / `暂无可导出的成功记录。` / `生成时间：` / `HTML 报告已生成…` | 报告头尾 |
| `generate_pdf` | `{APP_NAME} 修复报告` / `生成时间：` / `共 N 条处理结果` / `质量概况：` / `平均质量分：` / `名称：` / `模式/引擎：…时间：` / `参数：` / `智能推荐：` / `PDF 插入图片失败…` / `PDF 报告已生成…` | PDF |
| `export_report` | `没有可导出的成功记录（请先处理几张图片）。` / `未安装 PyMuPDF…` | 错误/日志 |

**量化结论**：en-US 下 `generate_html` 输出含 `修复报告`、`共 N 条`、`良好/告警/待复核` 等，100% 泄漏。`_card_html` 的 `alt="对比图"` 与 `质量分` 前缀是最隐蔽两处——前者不被文本渲染关注、后者嵌在 HTML 属性/`<span>` 内。`validate_i18n_parity` 抓不到（report_service 从未接入 i18n）。

## 3. 最小修复（经 i18n 路由，与 168 同范式）

> 复用阶段 168 的范式：**跟随全局 `get_language()`**（同 `format_exception_for_ui`），报告语言即用户所选界面语言；不加 `lang` 形参，改动面最小。

**A. `utils/i18n.py`** —— 在 `TRANSLATIONS` 的 zh-CN / en-US 各新增 `report.*` 命名空间 **29 个键**（标题/汇总/质量标签/卡片标签/PDF 文本/错误/日志），中英双侧对称、占位符同名（`{app_name}`/`{n}`/`{avg}`/`{score}`/`{level}`/`{path}`/`{exc}`）。

**B. `services/report_service.py`**：
- 顶部新增 `from utils.i18n import t, get_language`（无循环依赖：i18n 只依 config/logger）。
- 全部 deliverable 文案改经 `t("report.*")` 取用；带参键传 `**kwargs`。
- 质量标签（`良好/告警/待复核`）与动态 `level` 复用：`t("report.quality_" + q.level)`，卡片/PDF 文本用 `t("report.quality_score", score=…, level=t(f"report.quality_{q.level}"))` —— 一份标签既作汇总计数标签、又作单条 level 文案，避免孪生键。
- HTML 根元素 `lang="zh-CN"` → 跟随语言（`lang_code`）。
- 错误/日志：`raise RuntimeError(t("report.err_png_encode"))`、`raise FileNotFoundError(t("report.err_no_records"))`、`log.*(t("report.log_*", …))`（日志由 `%s` 位置参改为具名占位符，便于本地化）。

**关键修复细节（守卫抓到的真 bug）**：初版只把 `q.level` 本地化，**漏了 `质量分` 前缀**与 `alt="对比图"` 两处，en-US 报告仍含 6 个 CJK（`质量分`=3 + `对比图`=3）。补上 `report.quality_score` 与 `report.alt_compare` 后闭合。

**PDF 全角空格处理**：模式/引擎与时间之间原用全角空格 `　`(U+3000)——它**命中 CJK 正则**（`\u3000-\u303f`），故 en-US 侧改用普通半角空格（`_sep = "　" if zh else " "`）。

## 4. 守卫（`tests/test_report_service_i18n.py`，13 用例）

- **覆盖契约**：正则扫描 `report_service.py` 源码里每个静态 `t("report.*")` 键（含单/双引号），必须在 zh-CN 与 en-US 双侧存在且占位符同名——**新增引用未登记键立即红**。
- **动态键契约**：`report.quality_{good,warn,review}` 三支必须存在。
- **零泄漏契约**：en-US 下 `_card_html` 三种 level + 未评估分支、`_quality_summary` 标签与 note、完整 HTML 报告、空记录 `FileNotFoundError`——全部零 CJK / 全角标点（产品名 `APP_NAME` 在测试中替换为 ASCII 以隔离专有名词）。
- **parity 契约**：`validate_i18n_parity()` 不得有 `report.*` 问题。
- **zh-CN 回归**：zh-CN 报告仍含 `修复报告` / `共…条`（确保没清空原文）。

CJK 正则与 168 同口径：`[\u3000-\u303f\u3400-\u4dbf\u4e00-\u9fff\uff00-\uffef]`（`·` U+00B7、`—` U+2014 属语言中立，不在其中）。

## 6. 诚实边界

- **产品名 `config.APP_NAME` 仍为中文**（`AI 智能水印擦除工作台`），会随标题/页脚进入 en-US 报告——属专有名词（产品名），本阶段未提供英文译名；测试中以 ASCII 替换以隔离本地化泄漏。若需英文报告零 CJK，应由 config 提供 `APP_NAME` 英文名。
- **智能推荐理由 `reason_line()` 来自 `utils/recommend_view`**（独立模块，其 `detect.recommend.*` 键已双语），本阶段未改；其本地化依赖该模块既有 i18n 接入。守卫中的 entry 不带 `recommendation`，以聚焦 report_service 自身文案。
- **动态内容**（文件名 `original_name`、`params`）由调用方传入，en-US 下若本身含中文仍原样透传——合理边界。
- i18n 整类 4 子类**至此全部收口**；后续 i18n 相关仅剩「新增文案须同步双语」的常规维护（已由覆盖契约守卫兜底）。
