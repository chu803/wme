# 阶段 350 · 媒体服务层（视频 / PDF）的用户可见文案归入 i18n

> 日期 2026-10-27 · 性质：**i18n 补齐**（337 开放项 #29 的服务层部分）

## 一、缺口

337 把「质量诊断」那条链路的文案收归 UI（服务层产键、UI 渲染），但**媒体服务层**
（`services/video_service.py` / `services/pdf_service.py`）仍在直接产中文句子：
进度提示（"正在打开视频……" / "处理第 3/12 帧……"）、`result.warnings`、`result.error`。
⇒ **英文界面里视频与 PDF 链路全是中文**（进度、告警、错误无一例外）。

## 二、修法

* 新增 `media_svc.*` 键段（中英各 26 条），**中文文案逐字不变** ⇒ 中文用户零感知、既有断言零变化；
* 服务层改成 `t("media_svc.xxx", 参数…)`，**日志**（`log.*`）保持中文（日志不是界面文案，不进 i18n）；
* 参数化的地方用占位符：`{src}` `{formats}` `{w}/{h}` `{fps}` `{step}` `{codecs}` `{i}/{plan}`
  `{iou}/{threshold}` `{written}/{total}` `{pages}/{total}` `{n}/{msg}`。

共改 26 处（视频 17 + PDF 9），全部用**精确文本替换**（每处必须恰好命中一次，否则脚本报错退出），
不做模糊匹配。

## 三、守卫（`tests/test_media_service_i18n350.py`，6 例）

* `media_svc.*` 的**英文侧零 CJK**（漏译一眼可见）；
* 行为级：切到 en-US 后，`process_video` / `process_pdf` 返回的 `error` **不含 CJK**；
  切回 zh-CN 仍是中文（中文行为零变化）；
* 中文侧逐字回归（"正在打开视频……" / "PDF 处理完成" / "一帧都没能读出来…"）；
* `validate_i18n_parity()` 仍为空（键集与占位符两侧同名）。

## 四、边界

* **CLI 仍无 i18n 层**（`cli.py` 不 import `t`、没有 `--lang`）：CLI 的自有文案还是中文。
  本阶段只做媒体**服务层**；CLI 整体国际化属产品决策，未做。
* 服务层调用 `t()` ⇒ 文案跟随**全局语言状态**（用户在设置页切语言即生效），这与 UI 层渲染的语义一致。
* `utils/i18n.py` 的键段是**新增**（`media_svc`），不改动既有 `media.video.*` / `media.pdf.*`，
  避免动到已经在用的键。
