## 1. 动机：真实侧的全部收益只由手工脚本维系

阶段 57 起，`scripts/quality_gate.py` 把**合成图**（640²、程序生成底图）上的检测 + 修复结果
固化成机器可判定的双层契约（绝对红线 + 基线漂移）。这是阶段 49~81 所有量化结论的守卫。

但方向 A 与阶段 82 共同证明了一件更严重的事：

| 口径 | 阶段 82 前后 | 守卫 |
|---|---|---|
| 合成图 general | 精确率 51.3%、召回 82.3% | ✅ `quality_gate.py` |
| **真实图 general** | 精确率 **1.29% → 3.08%**、召回 **71.7% → 93.3%** | ❌ **无任何自动判定** |

阶段 82 的两项修复（`_merge_adjacent_fragments` 碎片聚合、`_suppress_natural_light` 自然光影守卫）
把真实图召回抬了 21.6pp、精确率翻 2.4 倍——但它**只由手工跑 `run_real_benchmark.py` 与文档维系**：

- 合成门禁不会因为真实侧退化而报警（两条分布本来就不相关）；
- 全量测试也不会（`tests/test_real_benchmark_smoke.py` 只用 1 张合成小图验证链路连通性，
  验证的是「跑得通」，不是「不掉分」）。

**结论：任何人回退掉这两项修复，合成门禁全绿、测试全绿，真实图收益被静默丢弃。**
这正是阶段 57 在合成侧已经解决过的问题，在真实侧重演了一遍。

## 2. 方法：把真实图指标固化为「第二条基线契约」

与阶段 72「双线误报契约」同范式——不是用一条线去覆盖两种分布，而是**承认两条线各自成立**：

| 分册 | 口径 | 覆盖内容 | 红线语义 |
|---|---|---|---|
| 合成线 `quality_gate.py` | 640² 程序底图 | 检测 + 修复 + **交付链** | 「算法常数不被改坏」 |
| **真实线 `real_gate.py`** | 30 张真实 1024² AI 图 | **仅检测侧** | 「真实分布上的结论不被回退」 |

**为什么真实线不测修复侧**：真实图没有「干净原图」可对齐（用户提供的是已带水印的成品），
ΔPSNR / 修复保真度在此口径下无法求真值。强行用 `no_reference_inpaint_score` 代替会把
「无参考指标不可靠」（阶段 56/61 已记录）引入门禁，得不偿失。故真实线**只做检测侧契约**。

### 2.1 单一真值来源

`real_gate.run_real_gate()` 不重写任何匹配逻辑，直接调用 `run_real_benchmark.run_all()`——
区域级 IoU≥0.3 贪心一对一匹配、聚合口径（各图均值再平均）全部复用。
（经验 24/77：同一语义不得有第二条实现。）

门禁只在其上包一层：`config`（可比性元数据）+ `aggregate`（判定所需指标）+ 判定/渲染。

### 2.2 三层判定

**第 0 层 · 数据完整性（本阶段新增的防线）**

`run_all` 对读图失败是**静默 `continue`** 的（只在 stderr 打印一行）。这意味着：
30 张里有几张读不出来时，聚合均值会照常算出来，**只看数字完全看不出来**——
如果那几张恰是最差的图，指标还会「变好」。

故强制断言 `实评图数 == manifest ∩ ground_truth 的标注图数`，不等即失败并给出
「有图被静默跳过」的明确说明。这是「容错能力会成为错误的藏身处」（经验 23）在
门禁层的直接应用：**依赖静默容错的数据管道，必须配一条「容错未被触发」的断言。**

**第 1 层 · 绝对红线（按预设登记）**

```python
REAL_PRESET_CONTRACT = {
    "general": {
        "recall":    ("min", 0.85),   # 82 前 0.717 / 82 后 0.933
        "precision": ("min", 0.025),  # 82 前 0.0129 / 82 后 0.0308
        "mean_iou":  ("min", 0.55),   # 崩溃护栏
    },
}
```

红线**直接编码阶段 82 的工程结论**：跌破召回 0.85 = 碎片聚合失效；跌破精确率 0.025 =
自然光影守卫失效。两者都是**严格夹在 82 前后实测值之间**的（有专门的标定测试锁定，
见 §4）。

只给 `general` 登记契约——它是唯一有真实语义的预设。其余预设（`ai_gradient` 设计上
恒零输出等）只做**监控 + 漂移**，不设绝对红线，避免「给不可能达标的预设加红线 =
门禁永久红灯 = 门禁被无视」。

**第 2 层 · 基线漂移**

真实图数据集是**固定文件**（同图同码 → 同结果，完全确定性），故漂移即真实回退，
容差只用来吸收依赖库版本的浮点扰动：

| 指标 | 容差 | 理由 |
|---|---|---|
| `recall` | 10% | 阶段 82 的核心收益，收紧 |
| `precision` | 25% | 真实图精确率基数低、噪声相对大 |
| `mean_iou` | 15% | — |
| `mask_iou` | 20% | 监控项（与区域级 IoU 正交，交叉验证用） |

另有两项**可比性检查**（与合成门禁的 `size`/`seed` 检查同源）：预设集合不一致、
标注图数变化 → 直接报「配置」问题，因为数字已不可比。

## 3. 基线快照与实跑

`benchmark_real/quality_baseline.json`（与合成侧 `docs/assets/quality_baseline.json` 同构，
只存 `config` + `aggregate`，不存逐图明细）：

```
真实图门禁 · benchmark_real · 标注 30 张 / 实评 30 张

| 预设    |  n | 精确率 | 召回   | 区域IoU | 掩码IoU | 契约 |
|---------|----|--------|--------|---------|---------|------|
| general | 30 | 0.0308 | 0.9333 | 0.6523  | 0.0577  | 红线 |
```

- 耗时 **14.5s**（30 图 × general 单预设，CPU）。
- 数值与 `bench_20260913_171113.json` **逐位一致** → 复用 `run_all` 未引入口径漂移。
- `mask_iou = 0.0577` 是**监控项而非红线**：它量的是「掩码像素级重合」，在
  「检测框对但形状松」（真实图正是这种形态——精确率仅 3%）时天然很低。
  记录它是为了给 F1 残余收敛提供一条**正交的**参考线（经验 27：单一指标定胜负前
  先问它奖励什么）。

默认只跑 `general`（10 预设全跑约 300 次检测，CPU 数分钟），用 `--presets` 显式扩展。

## 4. 阈值标定守卫：防止门禁被悄悄调哑

门禁最常见的失效方式不是「没写」，而是「写了一个迟早被放宽到无意义的阈值」。
故新增一条**标定层测试**：

```python
@pytest.mark.parametrize("metric", ["precision", "recall"])
def test_red_line_brackets_stage_a4_and_82(metric):
    lo, hi = _STAGE_A4_GENERAL[metric], _STAGE_82_GENERAL[metric]   # 0.0129/0.717 与 0.0308/0.9333
    assert lo < threshold < hi
```

它断言 `general` 的召回/精确率红线**严格夹在方向 A 与阶段 82 的实测值之间**：
- 若有人把召回红线从 0.85 下调到 0.70（≤ A4 的 0.717）→ 测试失败；
- 若有人把它上调到 0.94（≥ 82 的 0.9333）→ 测试失败（会让门禁一上线就红灯）。

**红线是一个「结论的编码」，不是「随手填的数」——它必须能被溯源到具体实验值。**

## 5. 顺带修复的真实缺陷：`os.path.relpath` 跨盘符崩溃

测试当场抓到一个**生产缺陷**（不是测试自身的问题）：

```
ValueError: path is on mount 'C:', start on mount 'D:'
```

`--update` 在**成功写完基线之后**，用 `os.path.relpath(args.baseline, _ROOT)` 打印确认信息。
Windows 下 `relpath` 无法对**不同盘符**求相对路径 → 抛 `ValueError`。

触发条件很现实：用户把 `--baseline` 指到项目所在盘之外（例如快照统一放到 D 盘、
项目在 C 盘）。后果是 **CLI 在基线已落盘后崩溃**——用户看到报错，会以为基线没写成，
实际已经写成了（下次 `--update` 又会覆盖，形成「报错但状态已变」的认知偏差）。

**同族扫描**（经验 23：修一处必须全局扫描）：`grep os.path.relpath` 命中 5 处，
其中 2 处是本次同一形态（`real_gate.py:305`、`quality_gate.py:569`——**合成门禁有同样的潜伏缺陷**），
另外 3 处（`collect_real_assets` / `make_demo_assets` / `run_benchmark`）的基准目录与
目标必然同盘，风险为 0。

**修复**：在 `utils/path_helper.py` 新增 `display_path(path, base)` 作为**唯一实现**
（try/except 兜底为绝对路径），两处调用点改为它。展示路径绝不该有能力让功能失败。

## 8. 通用经验（并入 MEMORY）

**34. 「手工脚本 + 文档」维持的量化结论，等于没有守卫。** 阶段 57 已为合成侧建立门禁，
但真实侧（方向 A / 82）的收益仍停留在「跑一次手工脚本、抄数字进文档」。判据是：
**改坏它，有没有任何自动化会失败？** 若答案是否，则该结论处于无保护状态，
无论它在文档里写得多详尽。

**35. 门禁的「跳过」必须与「通过」区分开。** 数据集缺失时返回 0（通过）会让 CI 在
「数据被误删」时收获一片绿。三分退出码（0/1/2）把「真的通过了」和「根本没跑」
变成机器可判定的两种状态。

**36. 数据管道的静默容错必须配「容错未被触发」的断言。** `run_all` 读图失败静默
`continue` 是合理的工程取舍，但它让「评估了 30 张」与「评估了 27 张」在输出上无法区分。
在**判定层**（而不是管道层）加一条计数一致性断言，成本极低、收益是防止整条门禁
在残缺数据上给出貌似可信的数字。

**37. 阈值要能溯源到实验值，并写成测试。** 红线夹在「修复前/修复后」实测值之间，
既可以防止被放宽到无意义，也可以防止被收紧到一上线就红灯。**「结论的编码」必须
可被验证为「确实是那个结论的编码」。**

**38. 展示路径不得有能力让功能失败。** `os.path.relpath` 在 Windows 跨盘符抛
`ValueError`，把「打印一行确认信息」变成了「基线写好后崩溃」。凡是在**成功路径尾部**
做的展示性操作（打印路径、格式化摘要、上报指标），都必须设计成**永不抛异常**——
否则报错信息会与真实状态矛盾，比不打印更糟。
