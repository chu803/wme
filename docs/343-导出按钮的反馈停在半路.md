# 阶段 343 · 导出按钮的「点了没反应」：反馈文案早就写好了，只是没人接线

> 日期 2026-10-26 · 性质：**产品缺陷修复**（第二轮审计 F5，本条收尾后 F1–F7 全部处理完）

## 一、缺陷与最扎心的那半句

`ui/tab_media.py` 的两个导出按钮（对比帧图 / 帧拼图）所有失败路径都是 `return None`，
而 `outputs` 只接一个 `gr.File` ⇒ 「点了没反应」与「成功」在界面上**完全不可区分**；
`run_video` 还会往同一个组件写 `None`（清掉上一次导出），于是连「上次导出过」这个线索都没了。

最扎心的是：`media.video.export_no_video`（"⚠️ 请先处理视频生成结果，再导出。"）与
`media.video.export_done`（"✅ 已导出：{path}"）**中英双语早就在 `utils/i18n.py` 里躺着**，
全仓 `grep` 下来没有任何代码引用过它们。⇒ 这件事不是没想到，是**停在半路**：
文案先就位、接线没人补，而「有文案」反过来让后来读 i18n 的人以为功能已经做了。

## 二、修法：把日志通道接进已有组件，不新造控件

两个处理器统一返回 `(文件或 None, 写进视频日志的一句真话)`，接线改成
`outputs=[v_export_file, video_log]`——`video_log` 是本页**已有**的结果日志框
（`:929`），复用它而不是新增一个常驻组件（观感类改动要先给用户挑，不自己加）。

四条出口都有话可说：

| 情形 | 以前 | 现在 |
|---|---|---|
| 没有结果视频 | `None`（无反应） | `export_no_video` |
| 服务层写出成功 | 只有文件组件多一个条目 | 外加 `export_done（带路径）` |
| 服务层返回 `None`（没能写出） | `None` | `export_fail` + 原因 |
| 服务层抛异常 | 直接 500/静默（视 Gradio 版本） | 捕获后 `export_fail` + 格式化原因，并 `log.exception` |

新增 i18n 键只有一个：`media.video.export_fail`（中英对称，`validate_i18n_parity()` 实测 `[]`）。

## 三、既有守卫反过来钉住了旧契约（一次教科书式的 #81 处理）

`tests/test_tab_media_audit112.py` 的接线契约表原本写着
`"export_frame_file": (4, 1)`、`"export_sheet_file": (1, 1)`——
它把「只有一个输出」当成**契约**钉住了 ⇒ 反馈缺失被永久化。
做法是**同步契约到新形态** `(4, 2)` / `(1, 2)` 并在注释里写明为什么改
（不是为了让测试变绿而放宽），同时补一条更硬的判据：
`test_return_arity_matches_outputs` 现在要求这两个函数**每条 `return` 都是 2 元组**
⇒ 以后谁再写一条「失败就 `return None`」的分支会被直接抓住。

## 四、反例与守卫

`tests/test_export_feedback343.py`（6 例）：缺视频要有话 / 成功要带路径 /
