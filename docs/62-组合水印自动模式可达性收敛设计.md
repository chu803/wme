# 阶段 62 · 组合水印（多重水印）的自动模式可达性与收敛

> 一句话：AI 平台常在**同一张图**上叠加多种水印（角落 LOGO + 底部文字、LOGO + 网格点阵…），
> 而阶段 59 收敛的推荐器只会挑**一个**单信号预设——预设只启用自己那一类策略，于是组合里的
> 另一类水印被整类漏检（**LOGO + 网格实测召回仅 71.8~72.1%，而全策略并集可达 97.1~99.9%**，
> 约 27 个百分点的丢失）。修复：新增并集预设 `ai_multi`，推荐器在多类信号同时触发时改推它，
> 组合召回升至 97.0~99.9%（≥ 全策略上界）。

---

## 1. 背景：阶段 59 只解决了"单信号"推荐

阶段 59 把推荐器在纹理/照片底图上的准确率修到 grid/corner/edge 各自 88.7~100%。
但那些用例都是**单一类型**水印。真实 AI 平台常见组合：

| 组合 | 组成 |
|---|---|
| logo+text | 角落实体 LOGO ＋ 底部说明文字（最常见） |
| logo+grid | 角落 LOGO ＋ 网格点阵水印 |
| text+grid | 底部文字 ＋ 网格点阵 |

而每个预设只启用**自己那一类**策略（`ai_logo` = translucent + corner + logo，
**edge=False、grid 未启用**；`ai_grid` = translucent + corner + edge + grid + 平铺增强）。
推错预设 = 组合中另一类水印的策略根本没跑。

## 2. 审计：组合召回 vs 全策略上界

合成组合（叠加在 gradient/textured/photo 底图上），比较「推荐预设下的召回」与
「全策略并集（上界）」：

| 底图 | 组合 | 修复前推荐 | 推荐下召回 | 全开上界 |
|---|---|---|---|---|
| textured | logo+text | ai_logo | **83.5%** | 92.3% |
| textured | logo+grid | ai_logo | **72.1%** | 97.1% |
| textured | text+grid | ai_grid | 92.8% | 91.6% |
| photo | logo+text | ai_logo | **83.5%** | 92.3% |
| photo | logo+grid | ai_logo | **72.1%** | 99.8% |
| photo | text+grid | ai_grid | 98.8% | 98.5% |

结论：**logo+grid 丢约 27pp**（网格策略未启用）、logo+text 丢约 9pp（edge 策略未启用）；
text+grid 恰好没损失——因为 `ai_grid` 本身已是超集（含 corner/edge）。

顺带修正一处文档性缺陷：`ai_logo` 的描述曾写作"开启 LOGO 轮廓检测 + 角落 + 半透明 + **网格**
四类策略"，与代码（未启用网格）不符，已改正并注明组合请用 `ai_multi`。

## 3. 修复：并集预设 + 组合感知推荐

### 3.1 新增内置预设 `ai_multi`（AI 多重水印）

策略取**并集**：`translucent + corner + edge + grid + logo + enhance_tiled + search_bottom`
（OCR 沿用默认）。它不是"更激进"，而是"不漏类"：任一类已触发信号都有对应策略在跑。

### 3.2 推荐器：信号族计数 → 组合走并集

在既有特征层（阶段 59 稳健 marks）之上统计**信号族**：

```
f_logo     = solid_logo 触发
f_periodic = grid_on 或（平铺周期 + 覆盖超网格带）
f_text     = （text 或 signature 触发）且 **无周期结构**
families   = [f_logo, f_periodic, f_text]
```

- `len(families) >= 2` → **ai_multi**；
- 否则维持阶段 59 的单信号分支链（顺序不变）。

**族互斥规则**（避免把单类水印误判为组合，是本次实现的关键细节）：

1. **周期结构抑制文字族**：填充式平铺方块的边缘密度同样高（会触发 `text_act`），若不抑制，
   普通平铺图（`ai_tiled` 用例）会被误判成组合 → 回归测试当场抓到；
2. **文字族抑制签名族**：文字密集图的底部带密度也高（会触发 `sig_act`），二者同源，
   只计一个。

实测这两条规则把 `tiled`/`text` 两个既有自检用例恢复为原推荐（`ai_tiled` / `ai_text_heavy`），
同时组合用例正确落入 `ai_multi`。

## 4. 修复后结果

| 底图 | 组合 | 推荐 | 召回 | 修复前 |
|---|---|---|---|---|
| gradient | logo+text | ai_multi | **99.9%** | ai_logo 97.5% |
| gradient | logo+grid | ai_multi | **99.9%** | ai_logo 71.8% |
| textured | logo+text | ai_multi | **97.0%** | ai_logo 83.5% |
| textured | logo+grid | ai_multi | **97.1%** | ai_logo 72.1% |
| photo | logo+text | ai_multi | **97.7%** | ai_logo 83.5% |
| photo | logo+grid | ai_multi | **99.8%** | ai_logo 72.1% |
| textured/photo | text+grid | ai_grid | 92.8 / 98.8% | 不变（ai_grid 已是超集） |

组合召回全部 ≥ 全策略上界；单信号用例（grid / corner / edge / tiled / text / clean）
推荐与召回均不变（阶段 59 的 11 例测试继续通过）。

## 6. 边界（诚实声明）

- 组合中若含**全局渐变叠加**，`ai_multi` 不含渐变策略（渐变检测会整图标记，保持 opt-in
  语义，需用户显式确认）；本阶段不改变这一点。
- 组合数 ≥3 类的超复杂场景（如 LOGO + 文字 + 网格 + 极淡平铺）由 `ai_multi` 的并集覆盖，
  但各策略的敏感度仍是单套参数，理论上存在"某一类特别淡"导致的漏检——与单类场景的
  信息论极限同源。
