## 1. 背景与范围

前 6 个阶段已完成全部功能（单图 / 自动 / 批量 / 历史 / 设置 / 导出）与界面美化。核心算法（`core`）、模型加载（`model_loader`）、设备探测（`device_manager`）已具备 GPU 自动探测、CPU 线程控制、LaMa 模型存在性/完整性校验与 OpenCV 降级能力。

阶段 7 不改动任何修复算法，聚焦**交付与运维**：

1. **依赖分层**：把一份 `requirements.txt` 拆为 `requirements-min`（无 torch）、`requirements-gpu`（CUDA torch）、完整版三档，按机器条件选择。
2. **一键启动**：`scripts/start.bat`（Windows）、`scripts/start.sh`（Linux/Mac）自动建 venv、装依赖、启动。
3. **打包部署**：`build.spec`（PyInstaller 生成 EXE）+ `Dockerfile` / `.dockerignore`（容器化）。
4. **启动期可观测性**：`main.py` 新增性能配置摘要、设备/降级提示、模型预热状态，用户启动即清楚「本次用 LaMa 还是 OpenCV、是否用上显卡」。

## 2. 依赖分层（三份清单）

| 清单 | 包含 | 适用 | 安装命令 |
| --- | --- | --- | --- |
| `requirements.txt` | 完整（CPU 版 torch + LaMa + gradio + 全部） | 默认，想用 LaMa 神经网络 | `pip install -r requirements.txt` |
| `requirements-min.txt` | 不含 torch/LaMa，仅 OpenCV 降级引擎 + 界面 | 无显卡、想最小体积 | `pip install -r requirements-min.txt` |
| `requirements-gpu.txt` | 仅 CUDA 版 torch/torchvision（覆盖完整版中的 CPU torch） | 有 NVIDIA 显卡、要 GPU 加速 | 先装完整版，再 `pip install -r requirements-gpu.txt` |

> 设计要点：完整版仍是「默认且最省心」的选择（任何机器都能跑，只是没显卡时用 CPU）；`min` 把体积最大的 torch 去掉，适合纯体验；`gpu` 在完整版基础上换 CUDA torch，启用显卡加速。**三份清单共用同一份 `config.py` 与全部业务代码，不存在功能分叉。**

## 3. 一键启动脚本

### 3.1 `scripts/start.bat`（Windows）

流程：检测 `venv` 是否存在 → 不存在则 `python -m venv` 创建 → 激活 → 升级 pip → 装 `requirements.txt`（清华镜像）→ `python main.py %*`（透传参数）。安装失败给出明确提示并 `pause`，不静默退出。

### 3.2 `scripts/start.sh`（Linux / macOS）

同款逻辑（bash，`set -euo pipefail` 稳妥退出），`source venv/bin/activate` 后用 `exec python main.py "$@"` 接管进程。已通过 `bash -n` 语法检查。

### 3.3 用法

```bash
# Windows：双击 scripts/start.bat，或命令行
scripts\start.bat            # 正常启动界面
scripts\start.bat --selftest # 仅跑核心管线自测

# Linux / macOS
chmod +x scripts/start.sh
./scripts/start.sh
```

## 4. 打包部署

### 4.1 `build.spec`（PyInstaller → EXE）

- 目标脚本 `main.py`，`one-folder` 模式产物 `dist/AIWatermarkEraser/`。
- `hiddenimports` 显式列出 `core` / `services` / `ui` / `utils` 全部子模块及 `torch` / `gradio` / `cv2` 等关键第三方库，规避打包后「缺模块」。
- `excludes` 排除 `easyocr`（可选增强，未装时减小体积）。
- 数据文件打包 `config.py` 以兼容特殊运行路径。
- 说明：模型文件 `models/big-lama.pt` 不进 EXE，需随程序分发或启动后联网下载。

```bash
pyinstaller build.spec
```

### 4.2 `Dockerfile`（容器化）

- 基础镜像 `python:3.11-slim`，安装 `libgl1` 等 OpenCV/Gradio 运行库与 `ffmpeg`。
- 先装依赖（利用层缓存）→ 复制源码 → `EXPOSE 7860`。
- 默认 `ENV SERVER_HOST=0.0.0.0 SERVER_OPEN_BROWSER=False`，容器外可访问。
- 提供 **GPU 镜像参考配方**（基于 `nvidia/cuda` + CUDA torch + `--gpus all`）。

### 4.3 `.dockerignore`

排除 `venv/`、`outputs/`、`cache/`、`models/`、`exports/`、`logs/`、`temp/`、`.git/`、`.workbuddy/`、打包产物等，减小构建上下文、避免把用户数据打进镜像。

### 4.4 容器用法

```bash
docker build -t watermark-eraser .
docker run -p 7860:7860 -e SERVER_HOST=0.0.0.0 \
  -v "$PWD/outputs:/app/outputs" -v "$PWD/models:/app/models" \
  watermark-eraser
```

## 5. 启动期性能报告与降级提示（`main.py`）

新增三个函数，在 `main()` 真正启动界面前依次执行：

| 函数 | 作用 |
| --- | --- |
| `print_performance_report()` | 打印设备模式、CPU 线程数、分块大小/重叠、批量并发、服务最大线程、半精度开关 |
| `report_device_and_gpu_hint()` | 打印当前设备（GPU 名称+显存 / CPU 原因）；若装了 torch 却没用上显卡，给出装 CUDA torch 的指引；若没装 torch，给出安装提示 |
| `warm_up_model()` | 若模型已就位则加载 LaMa 并报告「引擎就绪」；否则明确「使用 OpenCV 降级引擎」 |

新增 `config` 开关：
- `STARTUP_WARMUP_MODEL`（默认 True）：是否启动期预热模型。
- `STARTUP_GPU_HINT`（默认 True）：是否在 CPU 模式下打印 GPU 加速指引。

> 实测样例（本沙箱无 torch / 无模型）输出：
> ```
> >>> 性能配置：
>   计算设备模式   : auto
>   CPU 推理线程数 : 自动（物理核心数）
>   分块大小       : 512 px（重叠 64 px）
>   批量并发数     : 1
>   服务最大线程   : 8
>   半精度推理     : 开启
>   [设备] ℹ️  当前使用 CPU 模式：未检测到 NVIDIA 显卡，自动退回 CPU
>   [提示] 未安装 PyTorch，LaMa 引擎不可用（已自动降级为 OpenCV）。
>   [模型] ℹ️  LaMa 模型缺失，将使用 OpenCV 降级引擎（仅适合细小水印...）
> ```

## 6. 性能调优参数一览（`config.py`）

| 参数 | 默认 | 调优建议 |
| --- | --- | --- |
| `DEVICE_MODE` | `auto` | 有显卡保持 auto；老显卡驱动不稳可改 `cpu` |
| `CPU_THREADS` | `0`（自动） | 边跑图边做别的事 → 调小（如 2~4）；纯跑图 → 保持 0 |
| `TILE_SIZE` / `TILE_OVERLAP` | `512` / `64` | 大图显存不够 → 调小 TILE_SIZE；质量优先 → 调大重叠 |
| `DEVICE_USE_FP16` | `True` | 老显卡（GTX10 系前）显存异常 → 关 |
| `DEVICE_EMPTY_CACHE_AFTER_RUN` | `True` | 显存 ≥8GB 且连续批量 → 关（更快） |
| `BATCH_CONCURRENCY` | `1` | GPU 可用且 LaMa 路径 → 可上调（2~4） |
| `SERVER_MAX_THREADS` | `8` | 高并发多用户访问 → 上调 |

> 全部参数支持 `.env` 覆盖（`WME_` 前缀），无需改代码。
