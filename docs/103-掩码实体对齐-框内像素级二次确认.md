# 阶段 103 · 掩码—实体对齐：框内像素级二次确认

> 用户诉求（原文）：「直接进阶段 103」。
> 该阶段的定义来自阶段 102 的量化结论：**「检测区域框」与「水印实体」之间没有任何对齐环节**，
> 掩码面积 / 真值面积按类型在 **0.58×~11.36×** 之间双向漂移，是修复精度的第一瓶颈。
>
> 结论先行：**归因推翻了原计划的假设。** 原以为主因是「角标的框太小」（0.58×），
> 实测主因是**只有区域框、没有形状掩码的策略（边缘小字）在整框填满**——
> 该通路在 4 类水印上分别涂掉 10.0 / 6.8 / 9.0 / 7.0% 的图面，精确率只有 0.009~0.166。
> 据此实现的「框内像素级二次确认」在不损失召回的前提下把这条通路收紧，
> **三条门禁全部零回归且指标改进**：真实图侧掩码覆盖率 0.0745 → **0.0525**（−29.5%）、
> 过检倍率 7.65× → **5.39×**（−29.5%）、掩码 IoU 0.1163 → **0.1426**（+23%）、
> 合成侧精确率 54.2% → **59.2%**、IoU 52.1% → **56.9%**。

### 判读

1. **`edge`（边缘小字）的 `mask% ≈ bbox%`**（6.78/6.14、10.04/9.38、6.98/6.29、9.02/8.26）
   ⇒ 它的掩码**几乎 100% 是矩形填充**，这就是「检测框」与「实体」的差距本身。

2. **`corner` 策略在 4 类合成水印上召回全为 0.000**——它不贡献任何过检，也不贡献任何真命中。

4. **主因不是「框太小」，而是「框被填满了」。** 计划据此改向。

## 2. 前置：把 e2e 量测升格为可判定门禁

按阶段 99/75 的教训：**只改行为不标红线，改进可以静默回退**。故先标定再改。

### 三层判定（`scripts/e2e_real_probe.py --gate`）

| 层 | 内容 | 说明 |
|---|---|---|
| ① 数据完整性 | 每类 `n` 必须 > 0 | 空掩码 / 修复报错不算「通过」 |
| ② 绝对红线 | `removal ≥ 下界`、`collateral ≤ 上界`、`overdraw ≤ 上界` | **单侧**，方向 = 不许变坏 ⇒ 任何改进都不会被判失败 |
| ③ 基线漂移 | 相对容差 15%，**只查朝红线劣化方向** | 朝反侧的变化只提示「改进」，不判定 |

**为什么红线是单侧而不是区间**：`overdraw` 的目标是 0.9~1.5，但把区间写成红线会让
「把 11.74 降到 1.2」这类**目标改进**被判失败。下界方向（掩码偏小）必然压低 `removal`，
而 `removal` 已有下界红线 ⇒ 属**传递性守备**。

**为什么固定 `--limit 10`**：门禁若允许命令行改样本量，就是拿苹果比橘子。
门禁模式强制 `limit=10 / engine=lama`，并校验基线的 `engine`/`side` 与当前一致。

**优秀线与红线分两层**：`ASPIRATIONAL`（removal ≥90% / collateral ≤0.20 / overdraw ∈[0.9,1.5]）
**只打印不判定**——当前无一类达标，写成红线会让门禁恒红，而恒红的门禁与恒绿的一样是哑巴（阶段 95 教训）。

## 3. 实现：框内像素级二次确认

### 3.1 原语（`core/detector.py`）

```python
def _evidence_is_degenerate(evidence) -> bool      # 全图无证据 ⇔ 判据不可用
def _refine_regions_to_mask(regions, evidence, h, w, pad=2) -> (mask, dropped)
```

- 对每个区域框，取框内**有证据**的像素当掩码，再膨胀 `pad`；
- 框内**一点证据都没有** ⇒ 整框丢弃（不再拿「框」本身当实体）；
- 与 `_components_mask` 的分工：后者处理「策略自己有候选图」，本函数处理「策略没有候选图」。

### 3.2 接入（`_collect`）

`_collect(mask_small, regions)` 在 `mask_small is None` 时改为调用二次确认；
证据场由 `_full_evidence()` **懒算一次**（只有框型策略会用到），
判据与半透明通路**同一套**（`_residual_fields` + `_evidence_gate`）⇒
「什么算证据」在全项目只有一个定义。

### 3.3 回退守卫（宁漏不误杀）

证据场退化（全图零证据）时**回退整框填充**。理由：全图取不到证据 ⇔
证据判据在本图上不可用（水印比 `DETECT_MIN_DELTA` 还淡），**而不是「图上没有水印」**；
此时若照裁剪会把掩码裁空 = 静默漏检。

### 3.4 新增配置

| 配置 | 默认 | 作用 |
|---|---|---|
| `DETECT_BOX_EVIDENCE_REFINE` | `True` | 总开关；关闭即逐字节回到旧行为 |
| `DETECT_BOX_REFINE_PAD` | `2` | 证据外形膨胀半径 |
| `DETECT_BOX_REFINE_K_SCALE` | `0.5` | **框内相对门限的缩放**（见下节，这是本阶段的关键标定） |

## 4. 关键标定：一个被门禁抓住的坏默认值

第一次实现用**全域同一套门限**（`k_scale = 1.0`）。三件验证结果：

| 检查 | 结果 |
|---|---|
| 合成质量门禁 | ✅ EXIT=0，P 54.2→**59.3**、IoU 52.1→**57.1** |
| 真实图门禁 | ✅ EXIT=0，掩码覆盖率 0.0745→**0.0319**、掩码 IoU 0.1163→**0.2075**、过检 7.65×→**3.27×** |
| **e2e 门禁** | ❌ **EXIT=1**：`faint_tiled.removal = −0.1633 < −0.15`（红线 + 漂移双触发） |

**门禁正确地判红了**：它在确认两处大幅改进的同时，抓出一处被顺手带坏的指标。

### 定向定位（`%TEMP%/faint_probe.py`，10 图）

| 策略 | 框总面积 | 精简后 | 框内真值 | 精简后真值 | 丢真值 | 丢占比 |
|---|---|---|---|---|---|---|
| `corner` | 4 312 | 4 129 | 0 | 0 | 0 | 0.0% |
| `edge` | 304 382 | 158 780 | 17 210 | 12 933 | **4 277** | **24.9%** |

⇒ 机制完全对上：丢掉 4 277 个真值像素 ≈ 全部真值的 1.9%，
若这些像素原本被修复到 ~100%，聚合 `removal` 就掉 **0.019**——与实测的 0.022 一致。

### 阈值扫描（`%TEMP%/refine_sweep.py`）

| 相对门限缩放 | `edge_text` 框内真值保留 | `edge_text` 掩码占整图 | `faint_tiled` 真值保留 |
|---|---|---|---|
| 1.00 | **100.0%** | 2.111% | **75.1%** |
| 0.75 | 100.0% | 2.507% | 83.2% |
| **0.50** | **100.0%** | **3.033%** | **92.1%** |
| 0.25 | 100.0% | 3.529% | 98.8% |

（`edge_text` 整框填充基线 4.46% / 182 824 px；`min_delta` 从 3.0 扫到 0.5 几乎无影响
⇒ 起作用的是**相对**判据，不是绝对判据。）

### 结论与理由

**框内应使用比全域更宽的门限**，物理上说得通：**先验不同**。
框外任何像素都可能只是噪声，需要高置信；框内「这里存在水印」的先验已由策略建立，
判据只需回答「这个像素是否属于该实体」，沿用全域高门限会把**极淡水印的子集**剔掉。

取 **`k_scale = 0.5`**：`edge_text` 保真 100%、面积仍 −32%；`faint_tiled` 保真回到 92.1%。

## 5. 验证结果

### 5.1 三条门禁（`k_scale = 0.5` 最终口径）

| 检查 | 退出码 | 关键指标（基线 → 现在） |
|---|---|---|
| **e2e 修复侧门禁** | **0** | `edge_text` overdraw 6.87→**5.00**、collateral 1.657→**1.423**、removal 0.228→0.229；`faint_tiled` removal −0.142→**−0.139**、overdraw 2.61→2.58；`grid` 11.74→11.60、removal 0.475→**0.478**；`corner_logo` 三项不变 |
| **真实图门禁** | **0** | P 0.1382→**0.1478**、R 1.0000（不变）、mean_iou 0.7518（不变）、mask_iou 0.1163→**0.1426**、mask_coverage 0.0745→**0.0525**、coverage_ratio 7.65×→**5.39×** |
| **合成质量门禁** | **0** | 误报 0.78%（不变）、P 54.2→**59.2**、R 81.9%（不变）、IoU 52.1→**56.9**、ΔPSNR 12.93→**13.15** dB、交付链 11.67→**11.84** dB、掩码区最差 −0.01 dB（不变） |

**三点必须同时说清**：
1. **零回归**：三条门禁的全部既有指标都是「改进或不变」，没有任何一项劣化。
2. **召回守住了**：真实图 `recall` 1.0000 与 `mean_iou` 0.7518 **逐项不变**，
   合成侧 `recall` 81.9% **逐项不变** ⇒ 收紧面积没有换来漏检。
3. **改进的主要落点在「掩码变准」而不是「掩码变多」**：
   真实图掩码覆盖率 0.0745 → **0.0525**（−29.5%），同时掩码 IoU 0.1163 → **0.1426**（+23%）
   ⇒ 面积更小、却与真值更重合。

> 真实图门禁的 `mask_coverage` 在 30 图口径下为 **0.0525**（k=0.5），
> 略高于阶段 93 定的「≤5%」目标；若取 `k_scale = 1.0` 则为 **0.0319**，已达标——
> 但那一档会破坏 `faint_tiled`（e2e 门禁判红），故不采用。该权衡由门禁本身裁决。

  预期：`edge_text.overdraw` 回到 6.87 > 新红线 6.50，且相对新基线漂移 +37.5% > 15% ⇒ 判红。

### 5.3 守卫测试（`tests/test_detector_box_refine.py`，13 例）

| 编号 | 守什么 |
|---|---|
| K1 | 原语自检：退化判据正确；**守卫自检**——若退回整框填充，掩码面积会是证据面积的 100 倍（证明下面守的不是假问题） |
| K2 | 证据形状：掩码 == 框内证据；`pad` 膨胀但**不越出包围盒**；框外证据不被取用；越界包围盒被裁剪不崩 |
| K3 | 框内无证据 ⇒ 整框丢弃且计入 `dropped`；多框混合时互不污染 |
| K4 | 退化回退判据；关开关必须回到整框填充 |
| K5 | 端到端掩码**严格变小**且非空；二次确认**不得新增任何框外像素**（⊆ 整框填充） |
| K6 | `DETECT_BOX_REFINE_K_SCALE` 真的被读取（死配置检测）；门限放宽在**原语层**必须是超集 |

K6 的写法本身是一条经验：端到端无法断言「缩放小 ⇒ 掩码大」，因为
`DETECT_MAX_COVERAGE_RATIO` 覆盖率闸会在放宽后触发裁剪、打断集合关系 ⇒
把集合断言放到原语层、把「配置是否生效」放到端到端层。

## 6. 未达成与边界（诚实登记）

1. **`overdraw` 没有一类落进目标区间 0.9~1.5**。最佳的 `corner_logo` 为 0.89（下侧，
   欠覆盖），最差的 `grid` 为 11.60。本阶段解决的是**框填充型**过检；
   `grid`/`faint_tiled` 的过检主要来自 `tiled_enh` 与 `grid` 这两条**形状掩码**通路的
   判据过松（依次涂 13.2% / 12.1% 图面，精确率仅 0.064 / 0.131），属**检测判据**问题。
2. **`faint_tiled` 的去痕率仍为负**（−13.9%）：修完比不修更糟。本阶段未触碰其成因。
3. **`corner_logo` 的 0.89×（欠覆盖）未处理**。原计划的「向外扩到完整实体」**没有实施**——
   因为归因显示主因不是框太小；按「不写没有证据的复杂度」原则，把它留给有实测支撑的下一步。
4. **`edge` 策略在 `corner_logo` 上召回 0.506，是那一类的主要命中来源**，
   而它的形状是矩形填充。本阶段把矩形换成证据形状后 `corner_logo` 三项指标**完全不变**，
   说明该策略在真实底图上的表现恰好没被这处改动波及（阈值/证据强度不同）。
   这条**未做归因**，登记为待查。
5. 门禁样本仍是合成水印（`make_demo_assets`）。**平台真实水印图仍缺**（阶段 101 起登记，
   本阶段未消除）；未标注的 4 类真实表现仍是**未知**，不是 100%。
6. 真实图门禁的 `mask_coverage` 在 k=0.5 下为 **0.0525**，略高于阶段 93 的「≤5%」目标；
   k=1.0 可达标但会牺牲 `faint_tiled`。**两个目标当前不可同时满足**，取舍依据已写入 config 注释。
