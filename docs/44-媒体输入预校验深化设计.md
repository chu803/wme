# 阶段 44：媒体输入预校验深化（PDF / 视频校验层）

> 本文档对应代码改动：config / utils.path_helper / utils.exceptions / services.validators
> / utils.i18n / ui.tab_media，以及新增测试 `tests/test_validators_media.py`。
> 全部改动零 torch 依赖，可在无 GPU 环境完整验证。

---

## 1. 背景与动机

媒体模块（阶段 10 / 27 / 33 / 37）已支持 PDF、视频的「读取 → 修复 → 回写」，
但输入校验存在明显不对称：

- **图片**：`services/validators.validate_image_file` 在真正处理前做四道闸门
  （格式白名单 / 体积上限 / 解码 / 像素上限），非法输入被早早挡下。
- **PDF / 视频**：`run_pdf` / `run_video` 只校验了「有没有上传文件」，
  其余（格式是否合法、体积是否超限、文件是否损坏）全靠下游 `pdf_service` /
  `video_service` 在处理中才报错。一个 5GB 损坏视频会一路推进到逐帧修复阶段
  才崩溃，浪费大量算力且报错不友好。

阶段 44 补齐这道缺口：把图片已有的「预校验闸门」范式，平移到 PDF / 视频，
让明显非法的媒体在进重处理流程前就被拦截并给出贴合场景的上屏提示。

---

## 2. 目标

1. 在 `config` 层补齐媒体体积上限常量（此前只有图片 `MAX_IMAGE_FILE_MB`）。
2. 在 `path_helper` 补齐媒体格式白名单判定（此前只有图片 `is_supported_input`）。
3. 在异常体系新增独立的 `MediaError` 子树（此前只有 `ImageError` 子树）。
4. 在 `validators` 新增 `validate_pdf_file` / `validate_video_file`，
   复用上述常量与白名单，返回结构化元信息 `PdfMeta` / `VideoMeta`。
5. 在 `tab_media.run_pdf` / `run_video` 接入预校验闸门，捕获 `MediaError` 后
   返回 `media.*.invalid` 上屏文案 + 空结果组件。
6. 配套 i18n 双语键、单元测试、设计文档、全量 pytest 零回归。

---

## 3. 分层与职责（严格遵守项目铁律）

```
ui/tab_media.py        → 调用闸门、捕获 MediaError、上屏 invalid 提示（零算法）
services/validators.py → 媒体校验主逻辑（零 gradio，可独立测试）
utils/path_helper.py   → 媒体格式白名单
utils/exceptions.py    → MediaError 异常子树
config.py              → MAX_PDF_FILE_MB / MAX_VIDEO_FILE_MB
```

各层仅向下依赖，无反向依赖；`services` / `utils` 不引入 gradio。

---

## 4. 改动清单

### 4.1 config.py（媒体体积上限）
```python
MAX_PDF_FILE_MB   = _env_int("MAX_PDF_FILE_MB",   500, 1, 10240)   # 默认 500MB
MAX_VIDEO_FILE_MB = _env_int("MAX_VIDEO_FILE_MB", 2000, 1, 102400) # 默认 2GB
```
均可用环境变量 `WME_MAX_PDF_FILE_MB` / `WME_MAX_VIDEO_FILE_MB` 覆盖，
继承项目既有 `_env_int` 下界/上界保护。

### 4.2 utils/path_helper.py（媒体白名单）
```python
def is_supported_pdf_input(path) -> bool    # 比对 config.SUPPORTED_DOC_FORMATS (.pdf)
def is_supported_video_input(path) -> bool  # 比对 config.SUPPORTED_VIDEO_FORMATS
```
`__main__` 自检新增 5 条断言（用例 5）。

### 4.3 utils/exceptions.py（MediaError 子树）
新增第 4.5 节：
```python
class MediaError(WatermarkEraserError)            # 基类
class UnsupportedMediaError(MediaError)           # 格式不在白名单
class CorruptedMediaError(MediaError)             # 损坏 / 无法解码
class MediaTooLargeError(MediaError)              # 体积超限
```
每个子类带 `default_title` 与 `default_suggestions`，沿用既有三段式异常结构，
便于 UI 直接 `to_markdown()` 渲染。

### 4.4 services/validators.py（校验主逻辑）
新增：

- `PdfMeta` / `VideoMeta` dataclass（路径、体积 MB、页数 / 帧率-帧数-宽高）。
- `validate_pdf_file(path, *, max_mb=None)`：
  1. 存在性 → 2. `is_supported_pdf_input` 白名单 → 3. `size > MAX_PDF_FILE_MB`
     → 4. `fitz.open` 可打开（捕获异常转 `CorruptedMediaError`）。
- `validate_video_file(path, *, max_mb=None)`：
  1. 存在性 → 2. `is_supported_video_input` 白名单 → 3. `size > MAX_VIDEO_FILE_MB`
     → 4. `cv2.VideoCapture.isOpened()` 可解码。

缺失依赖走清晰的 `ImportError`（`fitz` / `cv2`），与图片校验一致；
体积超限 / 格式非法 / 损坏分别抛对应 `MediaError` 子类。
`__main__` 自检新增用例 4/5/6（非 PDF / 非视频 / 缺失文件）。

### 4.5 utils/i18n.py（上屏键）
```text
zh-CN / en-US 均新增：
  media.pdf.invalid   = "❌ 文件校验未通过：{exc}"
  media.video.invalid = "❌ 文件校验未通过：{exc}"
```
`{exc}` 渲染为 `MediaError.to_text()`（含标题 / 原因 / 建议），跨语言稳定。

### 4.6 ui/tab_media.py（闸门接线）
- 顶部新增 `from services.validators import validate_pdf_file, validate_video_file`
  与 `from utils.exceptions import MediaError`。
- `run_pdf`：`is_pdf_available()` 通过后、`progress()` 前插入闸门：
  ```python
  try:
      validate_pdf_file(path)
  except MediaError as exc:
      return (t("media.pdf.invalid", exc=exc),
              gr.update(value=None, visible=False),
              build_detection_stats_markdown(None))
  ```
- `run_video`：`process_video` 导入后、`progress()` 前插入同名闸门
  （返回 6 元组，含空 gallery 与空命令）。

闸门在「文件已上传」且「依赖可用」之后、`progress()` 之前触发，
因此 `progress` 不会被调用，可安全在测试中传 `progress=None`。

## 5. 接口契约（对调用方的影响）

- `validate_pdf_file` / `validate_video_file` 为**新增函数**，不改动既有
  `validate_image_file` / `validate_numpy_image` / `validate_output_format` 签名。
- `run_pdf` / `run_video` 入参与返回值形状**不变**，仅在非法输入下提前返回
  invalid 三元组 / 六元组（原失败路径返回三元组 / 六元组，形状一致）。
- 上游 `pdf_service` / `video_service` 无需改动；闸门只做「轻量预筛」。

---

## 6. 测试覆盖（`tests/test_validators_media.py`，17 例，零 torch）

| 分类 | 用例 |
| --- | --- |
| path_helper 白名单 | `is_supported_pdf_input` / `is_supported_video_input` 各类扩展名 |
| exceptions | MediaError 继承链、字段与 `to_markdown` 渲染 |
| validate_pdf_file | 合法 PDF / 不支持格式 / 缺失 / 损坏 / 体积超限 |
| validate_video_file | 合法视频（cv2 写真小视频）/ 不支持格式 / 缺失 / 损坏 / 体积超限 |
| i18n | `media.pdf.invalid` / `media.video.invalid` 双语存在 |
| 闸门接线 | `run_pdf` / `run_video` 在 MediaError 时返回 invalid 上屏文案 + 空结果 |

体积超限用例用 `monkeypatch` 把上限压到 `-1` 触发（小文件按 MB 四舍五入会成 0.0，
故不能用 0 作阈值），确保不依赖生成超大文件。

## 8. 影响面与回滚

- 仅新增媒体校验能力，不改动既有图片校验与媒体处理主链路；
  回滚即删除本节相关函数与 i18n 键，无数据迁移。
- 体积上限默认值偏保守（PDF 500MB / 视频 2GB），需要更大文件可通过
  `.env` 调大对应环境变量，异常建议文案已同步提示。
