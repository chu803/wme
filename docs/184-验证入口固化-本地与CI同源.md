# 阶段 184 · 验证入口固化（本地与 CI 同源）

> 承接 183：首次跑全库暴露 6 处跨阶段锚点腐化。183 的**根因**不是「没人写测试」，
> 而是**没有任何一个命令要求『全都跑一遍』**。本阶段把「该跑哪些检查」固化成唯一入口，
> 并让 CI 与本地跑同一套步骤。

## 2. 交付

- **`scripts/run_all_checks.py`** —— 唯一验证入口：
  - 步骤 ① `pytest`：默认跑 **CI 等价子集**（`-m "not torch_required and not network"`，
    标记名以 `pytest.ini` 为单一真值来源）；`--full` 跑全量。
  - 步骤 ② `undef_scan`：静态「引用了但从未定义」名扫描（零依赖、秒级）。
  - 步骤 ③ 三条门禁（仅 `--gates`）：`clean_bench_probe` · `quality_gate` · `real_gate --strict-scope`。
  - 退出码 `0/1/2`（**失败优先**；只有「全部跳过」才是 2），与门禁家族契约一致。
  - `--list` 只列步骤不执行（供 CI 自检与文档）。
  - **固化 183 教训**：pytest 一律用**项目内** `--basetemp`（`%TEMP%` 的清理会触发沙箱
    批量删除护栏 ⇒ 一整族「删除类」用例假失败）；所有步骤用 `sys.executable`（不依赖 PATH）。
- **`tests/test_run_all_checks.py`**（20 例）四层守卫：编排 / 环境 / 聚合 / **同源**。
  其中两条**防漂移**守卫最关键：
  1. `test_ci_workflow_calls_the_same_entry` —— CI 必须调用同一入口；
  2. `test_ci_does_not_duplicate_marker_selection` —— CI 的**可执行部分**不得再写一份
     marker 选择逻辑（否则「本地绿、CI 红」）。
  （解析 pytest 的 `-m` 需注意：`python -m pytest -m <expr>` 里有两个语义不同的 `-m`，
  故在脚本里提供单一解析助手 `marker_expr_in(argv)`，测试只断言它的结果。）
- **`.github/workflows/ci.yml`**：改为调用 `python scripts/run_all_checks.py`，
  删除重复的 marker 逻辑；头部注释记录 184 的修正理由。
- **自检登记表**：`scripts/run_all_checks.py` 按 **S** 豁免登记（理由：会递归拉起 pytest
  子进程，超出守卫的 300s 超时，且「pytest 里再跑 pytest」本是递归占用）。

## 4. 边界与后续（需用户决策）

- **CI 真正生效的前提是项目纳入版本控制**（`git init` + 首次提交 + 远端）。
  这改变项目的性质（引入版本历史、`.gitignore` 策略、提交粒度），**属用户决策**，
  本阶段**未擅自执行**——只把入口与同源守卫固化好，一旦纳管即可被机器自动拦住此类缺陷。
- 语言层面建议：纳入 git 后，把 `run_all_checks.py --gates` 作为**合并前的本地必跑**，
  CI 保持轻量（仅 fast 子集），门禁（需 torch）在带 torch 的环境单独跑（与 `pytest.ini`
  的 `torch_required` 约定一致）。
- 本阶段产物：`scripts/run_all_checks.py`、`tests/test_run_all_checks.py`、`ci.yml` 改造、
  自检登记表、本文件、MEMORY / 日志 / LESSONS 197 同步。
