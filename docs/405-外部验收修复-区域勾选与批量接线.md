## 二、复现与修复

### 1. 批量 `params` NameError

`run_batch` 的 `_processor` 写的是 `sharpen=params.sharpen.value` /
`enable_postprocess=params.postprocess.value`，但 `params` 只存在于 `build_batch_tab`
的 builder 作用域，函数签名与 `run_btn.click(inputs=...)` 都没有这两个值。

修复：
- `run_batch(..., real_backend, enable_postprocess=config.POSTPROCESS_ENABLED,
  sharpen=config.POSTPROCESS_SHARPEN_AMOUNT, evaluate, ...)`；
- `_processor` 改用形参；
- UI `inputs` 补 `params.postprocess, params.sharpen`。

**连带 bug（一修就暴露）**：`_process_one` 的解包写成
`_, result, status, _, out_path = process_auto_repair(...)`，而真实返回序是
`(orig_view, result_view, compare_view, status_text, download_file)` ⇒ `status`
拿到的是 `compare_view`（ndarray），`status or t(...)` 抛
`The truth value of an array with more than one element is ambiguous`。
每张图**首跑必失败**，队列重试后命中缓存（首次失败的产物已登记）⇒ 日志看着
「成功」，实际靠重试掩盖。已改为 `_, result, _, status, out_path`。

同一错误解包还在**历史页「重新处理」**（`ui/tab_history.reprocess`）：它会把状态
文案写进 `rec.result_path`。已一并修复，并加真实 `reprocess` 调用守卫。

守卫：`tests/test_batch_params_wiring405.py`（5 例：签名、真实调用处理器、
UI inputs 源码断言、批量解包顺序、历史重处理解包顺序）。

### 2. 橡皮越擦越多（F5）

受控探针（`.scratch/editor_eraser_probe.py`，真 Chrome + 真鼠标）：
预填一个红色 RGBA 图层，选 `Erase` 横穿红块，回传图层的红块**整体位移**
（x 200→280、y 150→310）且被撕成两条；用 RGB 预填仍复现。
结论：Gradio 6.31 的 ImageEditor 对**预填图层**的编辑命令按视口坐标重排内容，
不是我们掩码合并的错。

产品改法（不跟上游缺陷缠斗）：
- 检测后编辑框**保持空白**（只显示原图），画笔坐标实测正确；
- 新增「检测区域（取消勾选 = 本次不修复该区域）」CheckboxGroup，默认全选；
  取消勾选的区域按 bbox 外扩 12px 从检测掩码中清零
  （`ui.tab_auto.exclude_regions_from_mask`，覆盖检测填充 pad 4 + 羽化 5 + 余量）；
- 移除橡皮工具（`editor_kwargs["eraser"] = False`），保留画笔与撤销；
- merge 语义改为「检测(净) ∪ 画笔补涂」，manual 仍只取笔迹。

守卫：`tests/test_auto_regions405.py`（裁剪单元、取消后并集、全部取消、
空编辑框返回值）。

真 UI 复验（ai_logo_02，5 个区域）：
- 取消「区域 1」后修复，状态「检测命中 35,152 像素」（原始 38,068 − 区域1 的 2,916）；
- 产物 vs 原图：**取消勾选区域 0 像素改动（max 0）**；保留区域 3,579 px 改动
  （max 225）；全图实际改动 0.83%；
- 画笔补涂：44,328 px，状态栏「画笔补涂 44,328 像素」，实际改动 1.73%。

### 3. 改动比例低报（F3-b）

原状态按**掩码面积**报「本次将改动约 1.1%」，真实写入还包含
`POSTPROCESS_PRESERVE_BAND_PX=8` 的保护带（羽化/融合），2048² 上可达 3.7%。
现在改为**完工后实测**：`_actual_change_ratio(image, result, threshold=10)`
（任一通道差 >10 记为改动），显示「本次实际改动约 x% 的画面」。
`ai_logo_02` 状态 0.90%，独立逐像素测量 0.902% —— 同口径。
真·超分改变画布尺寸时返回 None，跳过该行（不硬比）。

### 4. E2「整图 34%」的根因

外部报告：合成噪声图 + 亮底招牌，检测 1 区 8,918 px，状态 1.0%，产物与原图整体
差异 34.18%，左上远区也 33.04%。

本机同构合成图直接 0 区，无法逐字复现；但用真图复现了**基线漂移**：
同一张 2048² JPEG，直接比较我们 headless（PIL 输入）产物与真 UI 产物，
保护带外 98.6% 像素有 **≤10 级**差异，部分高对比边缘 >10。进一步验证：
ImageEditor 往返后，修复底图不再是文件原像素，而是编辑器重编码后的背景；
噪声图上这种小漂移会被放大成大面积 >10（即外部看到的 34%）。
这不是修复改动了全图，也不是浏览器与 PIL 解码 JPEG 的差异
（实测 Chrome canvas 解码与 PIL 逐像素相同）。

修复：`process_auto_repair` 新增 `upload` 输入，修复底图**优先用上传原图数组**
（尺寸一致时），编辑框只提供笔迹掩码。真 UI 复验：保护带外 **0 像素**改动；
取消勾选区域 **0 像素**改动。
