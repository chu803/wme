# 阶段 368 · 把记分卡里最后一个"信我"数字接回它的真值来源

> 日期 2026-11-01 · 性质：**对外可核对性**（367 的续）

## 一、它的问题不是数值错，而是**没有复现命令**

`docs/quality/product_scorecard.json` 里 `audited_modules = 45`，而 docs/326 §四自己写着：
「audited_modules 未重测，沿用 45（**无可机械复测的定义**）」。
⇒ 一个进不了复现命令的数字，写进对外记分卡等于写了一句"信我"。
367 复算 `src_loc` 时已经证明过：写下来的口径和实际算出的数值**可以差 1500 行几个月没人发现**——
所以"没人能动它"不是稳定，是**没人能验证**。

## 二、真值来源其实一直存在

`scripts/audit_selector.py` 里的 `AUDITED_SINCE`（已审模块登记）就是这本账，条数恰好 45。
缺的只是"把它接成一条命令"：

- 新增 `python scripts/audit_selector.py --audited-count` ⇒ 打印 `len(AUDITED_SINCE)`（零副作用、毫秒级）。
- 记分卡 `scale_note` 里那句"无可机械复测的定义"换成**这条命令**。
- 该工具自己的设计原则早就写着：「决策用的登记必须与量具同源，并由脚本消费（`--unaudited`）」
  —— 本阶段只是把同一条原则补到它漏掉的那个字段上。

## 三、守卫（两份副本 + 命令本身，三层对齐）

`tests/test_scorecard_fresh326.py`：
1. `test_the_two_copies_of_the_same_numbers_agree` 的比对键从 3 个扩到 4 个
   （`test_cases / test_files / docs / **audited_modules**`）——同一事实的两份抄本**不许各说各话**；
2. 新增 `test_audited_modules_equals_the_tool_registry`：记分卡两处都必须等于 `len(AUDITED_SINCE)`；
3. 新增 `test_audited_count_cli_reports_the_registry`：**子进程真跑** `--audited-count`，
   断言它打印的数与记分卡一致（"可复现"要连命令一起验，不能只验常量）。

牙齿（反例真跑）：把 `scale.audited_modules` 改成 45+3 ⇒ **三条同时红**（含"命令报 45，记分卡写 48"），
复原后 8 例绿。

## 四、顺手清掉自己刚造的两处脏

- 生成的守卫里出现 `import os` / `import sys` **重复导入**与**函数内再导入**（脚本拼接代码的老毛病）⇒ 归位到模块级一份。
- 一处 f-string 里写 `：
{...}` 被拼成了**真换行**⇒ 语法错、收集期直接 ERROR。
  ⇒ 用脚本生成代码之后**必须立刻跑一遍**，别相信"看起来对"（361/364 也是同一课：工具第一次跑就报自己的 bug）。

## 五、边界

- 本阶段只让数字**可复现**，没有重审任何模块，也没有改登记内容（仍 45 条）。
- `AUDITED_SINCE` 的语义仍是"有专属审计的模块数"——它衡量的是**审计过**，不等于**测得厚**
  （荒漠度排名 `--unaudited` 才是后者的量具）。这句话留在 `scale_note` 里，避免下一个读的人把它当质量分。
