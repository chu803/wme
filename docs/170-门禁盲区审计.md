覆盖度荒漠榜已空（`audit_selector --unaudited` 零输出，44 个模块全登记）⇒
审计方向从「缺测试」转向「**评测装置自身的盲区**」：门禁自称的判定，

有没有「意识到了却只修了一半」的同族漏洞？

## 3. 缺口清单（每条四段，均可复现）

### S1 · `real_gate` 在「真值存在但为空」时**崩溃**，而非给出设计判定（P1）

**证据**：`benchmark_real/ground_truth.json` 的 `entries` 为空
（阶段 150 Option A 移除伪造标注后的合法状态）。
`scripts/run_real_benchmark.py:190-191` 在「manifest 非空、无任何图有真值」时
`raise RuntimeError("manifest 中没有任何图有真值；…")`；
`scripts/real_gate.py`（`run_real_gate` 直接调用 `run_all`，`main()` 无 try/except）
⇒ 进程以 traceback 结束，EXIT=1。

**机制**：`ground_truth.json` 的 `_note` 声称「real_gate 正确报
`committed_missing=['ai_logo']` 并硬失败」——但那个裁决在 `evaluate_real` 的
**0b 层**；而崩溃发生在更早的 `run_all`，
**数据完整性层（0）、承诺面层（0b）、面积监控层（3）全部被跳过**。
即：文档承诺的判定根本没走到，用户看到的是「工具自己崩了」。

**后果**：① 门禁的「可执行硬失败」退化成不可读的 traceback（无法区分
「数据集未就绪」与「代码 bug」）；② 承诺面/面积监控两层在空真值期间**结构性失明**。

**动作**：`real_gate.run_real_gate` 显式识别「有图但零标注」：
跳过评估循环、返回空聚合（`n_images=0`），把裁决交回 `evaluate_real`
（`committed_missing` 硬失败 + 「没有任何预设结果」数据层判定）。
边界：manifest **无图**（未就绪）仍由 `run_all` 报错，语义不变。

### S2 · 「输出编码决定退出码」加固**未推广同族**（P1 · 元缺陷）

**证据**：阶段 146 已在 `real_gate.py`（后加 `prompted_area_gate.py` /
`real_asset_preflight.py`）内联修复该失效模式——注释原文：
「**「输出内容」决定了「门禁退出码」**（CI 读到的"未通过"其实只是打印失败）」。
但元扫描（AST 取 `print`/`write` 实参里的 GBK 不可编码字符）显示：
**13 个脚本会打印非 GBK 字符，其中 10 个未加固**，含三条门禁：
`quality_gate.py` / `mask_param_audit.py` / `e2e_real_probe.py`。

**机制**：Windows 上 stdout 被重定向/管道时 Python 按 ANSI 代码页（GBK）编码；
`print("✅…")` 抛 `UnicodeEncodeError` ⇒ 退出码 1。
**通过的门禁被读成未通过**（假红），比假绿更贵——会诱使你去改一个没坏的模块。

**后果**：`quality_gate.py` 在重定向输出下**永远 EXIT=1**（无论质量好坏）；
`--update` 成功写盘后若收尾打印失败，会把成功动作报成失败。

**动作**：抽共用件 `scripts/console_encoding.py::force_utf8_stdio()`；
给 10 个未加固脚本加调用（`main()` 首条语句）；把 3 个既有内联实现改为调用共用件
（「同语义一处实现」）。新增元守卫把「新增脚本自动纳入」变成机器可判定。

## 4. 什么情况算完备（可判定验收线）

1. 空真值下 `real_gate.run_real_gate()` **不抛异常**，`evaluate_real` 返回
   `ok=False` 且含「承诺类型缺少真值证据」——已由 S1 守卫钉住。
2. **每个** `print`/`write` 非 GBK 字符的 `scripts/*.py` 都调用 `force_utf8_stdio`
   （或等价 `reconfigure`）——元守卫机器枚举，非手抄清单。
3. `quality_gate.py --quick` / `mask_param_audit.py` 在**重定向 stdout** 下
   EXIT 与判定一致（通过则 0）。
4. 共用件 `force_utf8_stdio` 幂等、对不支持 `reconfigure` 的流不抛。
5. 注入式反例：撤掉任一加固 ⇒ 对应用例变红（已验：撤 S1 → 4 红；撤 S2 → 1 红）。

## 8. 诚实边界

- 元守卫只覆盖**静态可枚举**的 `print`/`write` 实参；若某脚本把非 GBK 字符放在
  **被 return 出去的字符串**里再由调用方打印，静态扫描看不到（属动态构造，需运行时守卫）。
  实测本仓库这类脚本（非 GBK 字符仅在 docstring/返回值）未纳入 —— 记为已知边界。
- S1 修复后，空真值下 `real_gate` 仍 **EXIT=1**（这是阶段 150 的设计裁决：
  「承诺比证据多」= 可执行硬失败，须补图或收回承诺），**未**改成 EXIT=2
  ——刻意对齐既有裁决，不新造语义。
- 完整 pytest 套件因沙箱拒删 basetemp 未在本轮跑全量；两个守卫测试已用直调方式核验。
