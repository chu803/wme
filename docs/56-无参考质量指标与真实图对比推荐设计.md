## 1. 背景与动机

阶段 51 证明：合成数据上 **OpenCV 在 8/8 用例占优、LaMa 全负**（ΔPSNR 低至 −25.19 dB）。
阶段 55 据此把 `auto` 收敛为默认 OpenCV，消除「有模型即无脑 LaMa」的静默劣化。

但「双跑两引擎 + 无参考指标择优」仍是**更有价值的终态**：它能在真实难图上挑出 LaMa——
合成数据上 LaMa 全负，是因为本项目合成纹理非真实照片、且 LaMa 的强项（大面积遮挡、复杂内容）
在合成用例里没被触发。**阶段 55 推迟它的原因**是：①无参考 inpainting 指标在真实纹理上不可靠；
②双跑翻倍耗时（LaMa CPU 单图 3~4s）；③无真实图 ground truth 验证指标。

本阶段把这件事拆成**可验证、不阻塞热路径**的三块：

| 块 | 内容 | 是否进默认热路径 |
|---|---|---|
| 指标 | `core/quality.no_reference_inpaint_score` | 否（纯函数工具） |
| 推荐 | `make_demo_assets.run_real_case` 对每张真实图给逐引擎质量分 + 推荐 | 否（仅 `--input-dir` 诊断工具） |
| 验证 | `scripts/validate_selector.py` 用合成 ground truth 校验一致性 | 否（一次性脚本） |

**为什么不进默认热路径**：双跑使每次修复耗时翻倍，且选优效力在真实图上未经验证；故默认 `auto`
仍走 OpenCV（阶段 55），指标仅作 `--input-dir` 人工决策辅助。待 P0 真实图验证后，再把双跑择优
推进到热路径。

## 2. 指标设计：无缝一致性（seamless consistency）

### 2.1 思想

好的修复应让「被修复区域」在局部统计上与其紧邻的「未修复背景环」无缝衔接。
我们分别度量**修复区**与**背景环**在四特征上的差异，差异越小越无缝、分数越高：

- 每通道 `mean`（亮度均值）
- 每通道 `std`（亮度标准差）
- 每通道梯度 `mean`（边缘强度）
- 每通道梯度 `std`（纹理丰富度）

`score = −mean(|f_rep − f_ctx| / scale)`，越高越好（`scale` 以背景环特征幅值为尺度，下限 1.0）。

### 2.2 关键 bug 与修复（本阶段核心工程点）

初版 `_features` 把**整张图**的梯度统计当成区域梯度，导致一个隐蔽的边界偏置：

> 背景环是贴着水印块的「环」，其**内边界**正对着水印（200 vs 128 的突变）。
> 若把整图梯度算进来，环的梯度特征会包含「水印↔背景」的突变，
> 于是**即便完美修复（块内梯度 0）也与背景环（含边界突变梯度）不可比**——
> 实测完美修复分数竟为 −0.46（应≈0），单调性断言失败。

**修复**：梯度统计只取「左右/上下邻居都在区域内」的内部梯度像素：

```python
gx = np.abs(np.diff(ch, axis=1))            # (H, W-1)
gy = np.abs(np.diff(ch, axis=0))            # (H-1, W)
in_gx = (bin_mask[:, :-1] & bin_mask[:, 1:])   # 左右都在区域内
in_gy = (bin_mask[:-1, :] & bin_mask[1:, :])   # 上下都在区域内
g = np.concatenate([gx[in_gx].ravel(), gy[in_gy].ravel()])
```

这天然排除了「区域↔区域外」的边界突变梯度，无需腐蚀操作（也避开了 cv2 5.0 `erode`
在部分 dtype 上的兼容性报错），让 `_features` 回归纯 numpy。归一化 `scale` 加下限 1.0，
防止平滑区（背景环统计近 0）时差异被无限放大。

### 2.3 边界情形

- 掩码为空 / 背景环为空 → 返回 `0.0`（无法判断，不偏袒任一引擎）。
- cv2 不可用 → 抛 `RuntimeError`（由调用方决定如何处理）。

## 3. 接入真实图对比工具

`scripts/make_demo_assets.py --input-dir X` 已有真实图 LaMa vs OpenCV 对比
（`run_real_case`：自动检测 → 两引擎修复 → 输出掩码区改写量 MAE 与两引擎差异）。
本阶段在其上增加：

- 对每个成功修复的引擎算 `quality_score`（无参考质量分）；
- 取分数最高者为 `recommended`（无参考启发式推荐）；
- 四联对比图的引擎面板标注质量分，推荐项加 `★推荐`；
- 汇总 Markdown 表新增「OCV分 / LaMa分 / 推荐」三列。

这样当用户终于丢进真实图，直接得到「逐引擎质量分 + 推荐引擎」，辅助其在 LaMa / OpenCV 间
人工拍板（因为真实图无 ground truth，分数只是启发式参考，不是判决）。

## 4. 诚实验证（scripts/validate_selector.py）

用合成数据**已知的 ground truth** 校验指标方向是否正确：

- 同一用例分别用 opencv / lama 修复，得到两版结果；
- 用全参考 `ΔPSNR`（修复 vs 真值）判定「ground-truth 赢家」；
- 用 `no_reference_inpaint_score` 判定「指标推选家」；
- 统计两者一致率。

**诚实结论**：合成数据上 OpenCV 8/8 占优，本一致率主要证明「指标方向未被写反、
未被边界/归一化 bug 反向」，而**不能**证明其在真实照片上能正确挑出 LaMa
（合成纹理非真实照片，且天然偏 OpenCV）。真实选优效力仍待 **P0 真实图验证**。

> 实测一致率（详见脚本输出）：**阶段 56 修复后 1 种子 8 用例 = 8/8（100%）**；
> 修复前（含边界偏置 bug）4 种子 32 用例为 78.1%。边界偏置修复使指标方向完全正确。
> 指标在部分纹理/边缘用例会选 LaMa（合成 ΔPSNR 偏低、但视觉可能更合理）——
> 这正是我们希望它具备、且真实照片上可能翻盘的能力。

## 5. 测试（tests/test_quality.py，5 例）

1. **空掩码返回 0.0** —— 不偏袒任一引擎；
2. **完美修复优于留水印** —— 还原真值底色 vs 水印块保留，分数前者更高；
3. **常量填充单调性** —— 完美(128) ≥ 中等(160) ≥ 严重(0)，填充值单调；
4. **局部均值混合优于常量填充** —— 背景环均值填充优于常量 0；
5. **真实引擎集成** —— 与 `make_demo_assets` 真实修复结果集成不报错，且真修复优于「留着水印」。

全部 5 例通过。
