# 阶段 108 · 真实图交图规格 与 承诺类型升级预检

> **本轮没有改任何算法。** 它的交付是：把「补真实图 ⇒ 升级承诺类型」这条路的**入库规格**、
> **阻塞点清单**与**预检工具**一次性做齐，使图片到位后升级是**机械的**、且不会被循环论证污染。

## 2. 需要你提供什么（精确规格）

### 2.1 数量与类型

| 目标类型 | 需要几类图 | 每类张数 | 该类型水印的典型形态 |
|---|---|---|---|
| `ai_text_heavy`（边缘小字） | 1 类 | **3~5 张** | 图底部/边缘的说明文字、`AI生成` 字样、一行小字 |
| `ai_grid`（网格点阵） | 1 类 | **3~5 张** | 全图规律排布的点阵 / 网格 logo |
| `ai_faint_tiled`（平铺文字） | 1 类 | **3~5 张** | 全图极淡、重复出现的文字/logo |
| `ai_gradient`（全局渐变） | 1 类 | **3~5 张** | 整图叠加的平滑渐变/署名层 |

**优先级**：`ai_text_heavy` > `ai_grid` > `ai_faint_tiled` > `ai_gradient`。
理由：前两类的检测通路已有实测数据（`docs/106` 的消融分解里 `edge`/`grid` 都有明确读数），
最容易在补齐后立即产出可引用的真实指标；`ai_gradient` 的检测通路在 30 张真实图上**恒零触发**
（`docs/107` §5②），它更像一个"要么很好要么不该承诺"的类型。

### 2.2 文件规格

- **格式**：`.jpg` / `.png`（与 `collect_real_assets.py` 的收编格式一致）；
- **内容**：**必须是真实来源**（你自己生成并下载的原图，或平台导出的原图）。
  ⚠ **不得用 AI 重新生成/放大过的图充数**——那会让"真实水印"退化成合成水印，
  与 `benchmark_real` 的立身之本冲突（本项目所有"合成水印 × 真实底图"的结论都在
  `docs/105–107` 里，那个口径已单独存在，不需要再污染这个）。
- **尺寸**：不限（门禁按原尺寸跑，`real_gate` 不做缩放）；但请尽量 ≥ 640 长边，
  因为项目里有若干判据是按"绝对像素"标定的（`docs/58` 的高分辨率召回问题即源于此）。
- **命名**：任意，但请**避免与现有 `01_…` ~ `30_…` 冲突**（建议加类名前缀，如 `txt_01_说明.jpg`）。
  收编时会自动分配 `id`。
- **放置**：直接给我路径即可（放桌面/任意目录都行），我用
  `collect_real_assets.py add <path> --style <style> --copy` 收编进 `benchmark_real/images/`。

### 2.3 真值标注（**这一步最要紧**）

- 每个水印需要一个 `bbox = [x, y, w, h]`（原图像素坐标）与一个 `style`（取自 `STYLE_ENUM`）。
- **严禁用检测器输出预填**：`build_real_ground_truth.py auto` 是用**检测器自己的结果**当真值
  （`labeled_by="auto:<preset>"`）⇒ 拿它去评检测器是**循环论证**，recall/precision 会结构性偏高。
  **本阶段的预检会把任何 `auto:` 标注判为「不可升级」**（`test_auto_annotations_block_upgrade_…`）。
- **我可以代做草案**：我能直接看图，按**目视**给出 bbox 草案与 `style` 判断，
  记 `labeled_by="manual:assistant"`，并逐张列出让**你确认/修正**。
  这不是检测器预填（不构成循环论证），但**最终的正确性责任在你**——尤其"这个水印是不是
  平台原生的"只有你知道。
- 现有的 60 条是 `manual:measured`，可作为格式范例。

## 3. 升级一个类型的完整清单（工具已内置，`--class <预设>` 会打印）

```
1. 收编图片：python scripts/collect_real_assets.py add <path> --style <style> --copy
2. 人工标注：build_real_ground_truth.py list → 手写 watermarks[] → validate
             （**不要用 auto**；标注来源必须 manual:*）
3. 配置翻转：config.WATERMARK_TYPE_SCOPE[<preset>]["committed"] = True
4. 同步 README：「支持的水印类型」验证状态列 + 承诺类数量那句（两处都有测试守卫）
5. 同步测试夹具：tests/test_watermark_scope95.py 的
   test_committed_face_is_exactly_corner_logo / test_real_dataset_scope_reports_commitment_face
   （它们**故意**钉住承诺面，就是为了逼这次同步）
6. 刷新基线并取指标：real_gate.py --update → --strict-scope →
   --presets general,<新类预设>
7. 全量 pytest（承诺面守卫会连带检查 UI 文案与 README 是否同进同退）
```

**为什么清单必须这么长**：承诺面是本项目唯一一处「对外声明会处理哪些类型」的地方，
它被 5 处守卫同时钉住（config 派生 / 承诺面测试 / README 两处 / UI 文案注入）。
漏一处就会出现「配置改了但文案没改」或「文案改了但门禁没同步」——**宁可强制一次机械同步**。

## 4. 预检工具（本阶段新增）

`scripts/real_asset_preflight.py`：

| 能力 | 说明 |
|---|---|
| 逐类覆盖计数 | 按 `config.WATERMARK_TYPE_SCOPE[*]["truth_styles"]` 归并（**不另写风格映射**） |
| 标注来源审计 | `auto:` 前缀 ⇒ 判「不可升级」（循环论证守卫） |
| 结构审计 | 重复 `image_id` / 重复 `sha256`（同一张图收编两次）/ 枚举外 `style` / 孤儿条目 / 空标注 / 非法 bbox |
| 承诺面同口径 | **复用 `real_gate.annotation_scope`**（矛盾、枚举外 style、承诺类缺真值三类硬失败与门禁一致） |
| **收件箱（交图口）** | 列出 `benchmark_real/inbox/` 的待收编图片，并**查重**（与已收编 30 张比 `sha256`、以及收件箱内部自重复）；**只列目录，不动文件** |
| 三态判定 | `已承诺` / `可升级` / `不可升级`（附「差在哪」） |

退出码：`0` 通过 / `1` 发现问题 / `2` 数据集缺失（与其他门禁同约定）。

```bash
python scripts/real_asset_preflight.py                  # 全量报告
python scripts/real_asset_preflight.py --class ai_grid   # 单类：还差什么 + 升级步骤
python scripts/real_asset_preflight.py --min-images 5    # 改数量下限
python scripts/real_asset_preflight.py --json out.json   # 机器可读
```

## 5. 测试（17 例，`tests/test_real_asset_preflight.py`）

→ sitecustomize.py::_check_bulk_delete_guard → _exit_bulk_guard_control → SystemExit(1)

即**沙箱的"单轮批量删除护栏"**（第 50 次删除时要求确认）拦下了日志轮转用例的 `os.remove`。
判定依据：① 失败发生在 `logging.handlers.doRollover` 的 `os.remove`，不是任何断言；
② 与本次改动无关——本轮**只新增** `scripts/real_asset_preflight.py` 与
`tests/test_real_asset_preflight.py`，未触碰 `utils/logger.py`；
③ 本轮新增的 13 例全绿；④ 该现象在阶段 107 的全量跑中已出现并同样归因。

**未做任何"绕过护栏"的动作**（没有改写断言、没有跳过用例、没有重试同一命令）。
若需在 CI 上拿到"全绿"，正确做法是给该用例的临时目录**白名单**或降低其删除次数，
而不是把它改成 pass ——这属于环境配置决策，等你决定。
