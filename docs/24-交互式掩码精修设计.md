# 阶段 24 · 交互式掩码精修设计

> 项目定位：本工具为**去除 AI 生成图片上的水印**（AI 绘图平台给出的可见水印/署名标识）专用。
> 合规底线：只处理用户**自己有权处理**的 AI 生成内容；去除第三方平台署名水印通常违反其服务条款，工具不鼓励该用途。

---

## 1. 阶段定位与范围

阶段 20–23 把「自动检测」做得越来越强：预设体系、平铺增强、底部搜索、网格/渐变/实体 LOGO 策略、OCR 精度、命中率统计。但检测再强也有两类修不好：

1. **漏检**：检测没命中、或只命中一部分，修复后原图还留着水印残影。
2. **误报**：检测圈进了不该修的背景，修复后把背景也抹花了。

前几阶段自动页（tab_auto）其实**已经有了 ImageEditor 画笔/橡皮 + `build_mask_from_editor` 提取**（阶段 4 遗留），但**只用于「手动模式」的纯手绘**，自动模式下：
- 检测一旦跑完，结果**直接进修复**，用户没有机会补画/擦除；
- 即便在自动页用 ImageEditor 涂了，代码也没把编辑框掩码**并入最终修复掩码**（`process_image` 没有 `user_mask` 入参）。

**本阶段目标（用户选定方向：交互式掩码精修）：**
1. 新增**纯 numpy 掩码代数模块** `core/mask_editor.py`（零 gradio、可独立测试），提供 `merge_masks`（merge 合并 / manual 仅精修）与 `apply_brush` / `apply_rect` 程序化编辑原语，供脚本化 API（api.py / server.py）与自动化测试复用。
2. 自动页新增**掩码精修控制区**：精修模式（合并 / 仅精修）单选、🔄 重新加载检测掩码、🧹 清空编辑框；检测结束后把检测结果**预填进编辑框**，用户可补画补漏 / 擦除误报。
3. 修复链 `process_image` 透传可选 `user_mask`：auto 模式下按 `mask_mode` 与检测掩码合并，使「手绘补画」真正生效。
4. 维护**向后兼容铁律**：不传 `user_mask` 时行为与阶段 23 完全一致；仅新增返回键，不改函数签名位置语义。

**分层铁律严守**：`core.mask_editor` 零 gradio 依赖，仅单向依赖 `core.mask_generator`（再导 `count_mask_pixels`）+ `utils.logger`；UI 只调用核心层、不解析掩码代数。

## 2. 核心模块：`core/mask_editor.py`（掩码代数，阶段 24 新增）

### 2.1 设计约束
- 属于「算法层（core）」，**零 gradio 依赖**，纯 numpy 实现，可独立 `python core/mask_editor.py` 自检。
- 只做「掩码代数」，不解析 Gradio ImageEditor 值（那是 `core.mask_generator.build_mask_from_editor` 的职责）。两层**单向依赖**：`mask_editor → mask_generator`（无环）。
- 所有输入掩码按「**0/255 二值**」约定处理；尺寸不一致时**自动最近邻对齐**，避免边缘出现灰度中间值。

### 2.2 内部原语
- `_as_binary(mask)`：把 `None` / `(H,W)` / `(H,W,3)` / `(H,W,4)` 归一化为 `(H,W)` 0/255；RGBA 优先取 alpha（画笔图层语义），RGB 取均值亮度，`>0 → 255`。
- `_resize_binary(bin, th, tw)`：最近邻缩放到目标尺寸（尺寸一致则透传）。
- `_canonical(det, user, target_shape)`：把检测 / 用户掩码规范化为**同尺寸**二值；目标尺寸优先级 `target_shape > 非空掩码中较大者 > (0,0)`。

### 2.3 `merge_masks(det_mask, user_mask, mode, target_shape=None)`
按模式合并「检测掩码 × 用户精修掩码」，返回 `(H,W)` 0/255：

| 模式 | 常量 | 语义 | 公式 |
|---|---|---|---|
| 合并 | `MASK_MODE_MERGE="merge"` | 检测 ∪ 用户（补漏 + 擦除都生效，推荐） | `np.maximum(det, user)` |
| 仅精修 | `MASK_MODE_MANUAL="manual"` | 用户 ∩ ¬检测（剥离预填检测层，只修亲手绘制） | `np.bitwise_and(user, np.bitwise_not(det))` |

行为细节（均有 `__main__` 自检用例 + 单测守护）：
- `mode` 非法 → 记 warning 并**回退 merge**（不抛异常）。
- `det_mask` 为 `None`/空 → 直接返回 `user_mask`（用户手绘即最终掩码）。
- 尺寸不一致 → `_canonical` 最近邻对齐到 `target_shape`（缺省取两掩码较大者）。

### 2.4 `apply_brush(mask, cy, cx, radius, add=True)` / `apply_rect(mask, y0, x0, y1, x1, add=True)`
- `apply_brush`：以 `(cy, cx)` 为圆心、`radius` 为半径的**圆形画笔**增/删；返回**副本**（不修改原掩码）；圆心越界或 `radius<=0` 时返回原掩码副本。
- `apply_rect`：以 `(y0,x0)-(y1,x1)` 为对角（半开区间 `[y0,y1)×[x0,x1)`）的**矩形**增/删；自动夹取到图像范围内；退化矩形（`y1<=y0` 或 `x1<=x0`）返回副本。
- 用途：脚本化 API（api.py / server.py）与自动化测试构造用户掩码，无需走 ImageEditor 交互。

### 2.5 `count_mask_pixels` 再导出
`core.mask_editor` 直接再导出 `core.mask_generator.count_mask_pixels`（单源实现），UI / 服务层从 `mask_editor` 取数即可，避免重复定义。

## 4. 服务层透传（`services/auto_pipeline.py`）

`process_image` 签名新增 `user_mask: Optional[np.ndarray] = None, mask_mode: Optional[str] = None`（位于 `artifact_amount` 之后、既有关键字之后，向后兼容）。

**auto 模式分支逻辑（仅 auto 生效；manual 模式调用方应直接把最终掩码传给 `mask``）：**
```python
if user_mask is not None:
    used_mask_mode = str(mask_mode or config.MASK_EDIT_DEFAULT_MODE).lower()
    if used_mask_mode not in (MASK_MODE_MERGE, MASK_MODE_MANUAL):
        log.warning("未知掩码精修模式 %r，回退为 %r。", used_mask_mode, MASK_MODE_MERGE)
        used_mask_mode = MASK_MODE_MERGE
    mask = merge_masks(mask, user_mask, used_mask_mode, target_shape=rgb.shape[:2])
    user_pixels = int(count_mask_pixels(user_mask))
```
- 合并**发生在「空掩码 skipped 判定」之前**：即便检测为空（如没找到水印），只要用户手绘了，`merge_masks(空, 用户, …)` 仍返回非空掩码 → 进入修复，**手绘补漏不丢**。
- 返回字典新增 `"user_mask_pixels"`（用户精修像素数，未传为 0）与 `"mask_mode"`（实际生效模式）；`skipped` 与 `success` 两条返回路径均带这两个键，对既有调用方无影响。

## 5. 界面层接线（`ui/tab_auto.py`）

自动页已具备 ImageEditor（`brush`/`eraser` 工具）。本阶段把「检测 → 精修 → 修复」闭环补完：

### 5.1 检测后预填检测掩码进编辑框
- `process_auto_detect` 返回值由 4 元组扩展为 **5 元组**：`(detect_preview, editor_value, status_text, detect_stats_md, det_mask)`，每个 return 分支都带 `det_mask = result.mask`（无上传 / 异常时为 `None`）。
- `detect_btn.click` 的 `outputs` 追加 `det_mask_state`（`gr.State(None)`），把检测掩码暂存，供后续精修 / 重载使用。

### 5.2 精修控制区（新增组件）
- `mask_mode = gr.Radio(choices=[(t("mask_edit.mode_merge"), MASK_MODE_MERGE), (t("mask_edit.mode_manual"), MASK_MODE_MANUAL)], value=config.MASK_EDIT_DEFAULT_MODE, label=t("mask_edit.mode_label"), info=t("mask_edit.mode_info"))`。
- `reload_mask_btn = gr.Button("🔄 重新加载检测掩码", size="sm")` → `_reload_detection_mask(det_mask, upload)`：尺寸匹配时把 `det_mask` 重新预填进编辑框（擦过头 / 清空后一键恢复），否则返回 `None`。
- `clear_editor_btn = gr.Button("🧹 清空编辑框", size="sm")` → `_clear_editor(upload)`：返回空图层 dict，回到空白画布。
- ⚠️ `gr.Button` **不接受 `info=` 关键字**（gradio 会报 `unexpected keyword argument 'info'`），故按钮说明放 `mask_mode` 的 `info`，按钮仅保留 `size="sm"`。

### 5.3 修复时合并用户精修掩码
- `process_auto_repair` 签名扩展：`det_mask=None, mask_mode=None`（位于 `artifact_amount` 之后），返回值保持 5 元组。
- 逻辑：
  1. 解析 `mode`（非法回退 merge）；`det = det_mask if 2D ndarray else None`；`user_mask = build_mask_from_editor(...)`（从编辑框提取 0/255）。
  2. **merge 模式**：若 `count_mask_pixels(user_mask)==0`（编辑框为空）→ 尝试用 `det` 兜底；`det` 也为空 → 触发**自动回退** `detect_watermark_mask(image, preset=config.DETECT_PRESET_DEFAULT, use_ocr=config.DETECT_USE_OCR)`（设 `auto_fallback=True`，状态提示追加 `t("auto.msg.auto_fallback")`）；否则用编辑框掩码（已含预填检测层）。
  3. **manual 模式**：`mask = merge_masks(det, user_mask, MASK_MODE_MANUAL, target_shape=image.shape[:2])`（剥离预填检测层，只修用户笔迹）。
  4. 构建 `refine_tip`：`det` 非空时追加 `t("auto.msg.refine_stats", det=…, user=…, added=…)` 展示像素统计；状态 = 完成 + 评估 + `refine_tip`。

### 5.4 接线
- `repair_btn.click` 的 `inputs` 追加 `det_mask_state, mask_mode`；`reload_mask_btn.click(fn=_reload_detection_mask, inputs=[det_mask_state, upload], outputs=[editor])`；`clear_editor_btn.click(fn=_clear_editor, inputs=[upload], outputs=[editor])`。

## 9. 坑点记录

1. **`gr.Button` 不接受 `info=`**：gradio 6.x 的 `Button.__init__` 无 `info` 入参，传了会 `TypeError: unexpected keyword argument 'info'`。按钮说明文字统一放到同组 `Radio` 的 `info`，按钮只保留 `size` / `tooltip`（如需 hover 提示）。
2. **i18n 重复顶层键覆盖**：新增键务必并入既有块（`"auto"`），另起新顶层块用**唯一**名（`"mask_edit"`）。重复写 `\n"auto": {...}` 会让后写块**整体覆盖**前写块，导致其他 `auto.*` 键在运行时报「缺失翻译」。
3. **合并顺序先于空掩码判定**：`merge_masks` 必须在「`mask_pixels==0 → skipped`」判定**之前**执行，否则「检测为空但用户手绘了」会被误判为 skipped，补漏失效。当前代码顺序正确（先合并、后判空）。
4. **最近邻对齐保二值**：掩码缩放用 `np.ix_` 整数索引（最近邻），**不能**用 `cv2.resize`（会产生中间灰度值，破坏 0/255 约定）。`target_shape` 优先于两掩码各自尺寸，确保最终掩码与 `rgb` 同尺寸，inpaint 不报错。
5. **`process_image` 向后兼容**：不传 `user_mask` 时，`mask_mode` 仍返回（默认 `config.MASK_EDIT_DEFAULT_MODE`）、`user_mask_pixels` 返回 0，函数其余行为（检测 / 修复 / 后处理 / 返回键集合）与阶段 23 完全一致；既有 CLI / api / server / 批量 / 媒体入口调用方式不受影响（它们不传 `user_mask`）。
6. **单测环境无 torch**：`process_image` 的 auto 模式依赖 `detect_watermark_mask`，无 torch 时可能跳过检测；测试对 `status=="success"` 才严格断言统计，否则仅验证键存在，避免环境差异偶发失败。`mask_editor` 纯 numpy 单测不依赖任何模型，稳定可重复。
