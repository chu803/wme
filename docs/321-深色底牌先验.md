# 阶段 321 · 深色底牌先验：给「角标」补上另一种样式

> 日期 2026-10-23 · 产物 `config.py`（3 键）、`core/detector.py`（镜像判据 + 独立 S 上限 + 跳过闭运算）、
> `tests/test_dark_plate_prior321.py`（5 例）

## 一、动机

阶段 317 探针：真实 57 个标注水印 **100% 是角标**，但换一种板样式（**深色圆角板 + 白字**）时
`ai_logo` 检回只有 **0.267**、擦除度 0.532。根因不是推荐器，是**风格覆盖**：
原来两条候选来源都假设「牌比底亮」——

- 白色判据 `V ≥ 140 且 S ≤ 80`；
- 局部提亮 `lift = V − blur(V)`（管中低对比底上的半透明牌）。

深色板两条都不命中，只能靠 `ai_text_heavy` 的白字**误打误着**。

## 二、实现（白牌判据的镜像）

新增第三条候选来源 `mask_source="dark"`，与既有两条**各跑各的过滤、只并框**（阶段 176 的既定姿势）：

| 判据 | 白牌（原） | 深色牌（新） |
|---|---|---|
| 牌体亮度 | `V ≥ 140` | `V ≤ 90` |
| 牌体饱和度 | `S ≤ 80` | `S ≤ 140`（更宽，见下） |
| 「墨迹」方向 | 深字：`像素 ≤ 0.55 × 牌体中位亮` | **亮字**：`像素 ≥ 牌体中位亮 / 0.55` |
| 墨迹占比下限 | 0.05 | 0.05 |
| 闭运算桥接 | 开（桥接被字形切开的亮块） | **关**（见下） |
| 形状/面积/实心度/贴边 | 沿用同一套 | 沿用同一套 |

## 三、两次「零效果」的排查（都是实测，不是猜）

**第一版：指标一分没动。** 直接对一张真图逐条打印各闸门，发现：

1. **S 上限太严**：实测 alpha=150 的半透明深板压在彩色照片上，牌体 **V 中位 25–58（够暗）**，
   但 **S 中位最高 116 > 80** ⇒ 牌被整块拒掉。→ 深色通路单独用 `DARK_S_MAX=140`。
2. **闭运算把牌并没了**：`clean_08` 上 41×41 的闭运算把 177×68 的深色牌与周围暗部
   （窗框/桌面）并成跨区大块 ⇒ 触碰搜索区边界 ⇒ 整块丢弃。闭运算的用途是桥接
   「被**深色**字形切开的**亮**牌」，深色牌恰好相反（亮字切暗牌），**不需要桥接**。→ 深色通路跳过闭运算。

修完后 `clean_08` 的深色通路打出 `(1854,1963,177,68)`——真值是 `(1854,1963,176,67)`，几乎逐像素重合。

## 四、实测（阶段 317 的同一套 60 用例，逐例对比）

**中位数没动**（15 例里只有 2–3 例真正受益），所以必须逐例看：

| 用例 | 检回 | 擦除度 |
|---|---|---|
| `clean_08 + corner_logo` | **0.307 → 0.726** | 0.238 → 0.375 |
| `clean_15 + corner_logo` | 0.276 → 0.326 | 0.602 → 0.626 |
| `clean_08 + edge_text` | 0.587（不变） | 0.471 → 0.507 |
| `clean_14 + edge_text` | 0.586（不变） | 0.608 → 0.671 |

**15 例均值**：角标检回 **0.371 → 0.402**、擦除度 **0.503 → 0.518**；**无一例变差**。
（`clean_01` 仍未命中——它的板与背景对比更低，属下一轮的目标。）

## 五、诚实边界

- 只帮到 **2/15**（明显改善）——深色板只是角标样式的一种；真正要覆盖跨平台，仍需**真实样本**
  扩充模板库（当前模板库来自 9 张豆包图）。
- 判据放宽了饱和度，理论上会多收「暗且紧凑、带亮字」的物体（招牌、屏幕 UI、车牌）。
  仅靠形状/面积/实心度/贴边四项约束 + 只在**四角搜索区**内生效来抑制。
  **必须用门禁证明没有扩散**：`real_gate`（57 张真实豆包图）/ `prompted_area_gate` / `clean_bench_probe`。
- 只在 `enable_corner=True` 的预设上生效（当前所有内置预设都开）。
- 未做消融：没有单独量化「深色通路」在真实豆包图上的新增误检数（门禁只报聚合）。
