## 二、第一条：把「Windows 语义」写成了断言

`test_L0_legacy_unique_name_posix_does_not_strip_backslash` 的第一句是：

```python
assert Path("a\\b.txt").name == "b.txt", "本机应是被支持的 Windows 语义"
```

它的**本意**是证明旧实现（`Path(...).name`）的 F5 缺陷「依赖平台」——可它自己先断言了平台。
在 Linux 上 `Path("a\\b.txt").name == "a\\b.txt"`，于是这句必红。

修法不是加 `skipif`（那会把 POSIX 侧的证据永久藏起来），而是**两个平台各说各的结论**：

- Windows：旧实现侥幸正确（`== "b.txt"`）；
- POSIX：旧实现剥不掉反斜杠（`== "a\\b.txt"`）——**这才是 F5 的证据**；
- 跨平台恒真的一句单独留：`PurePosixPath("a\\b.txt").name == "a\\b.txt"`。

这样同一份测试在 runner 上跑的是 POSIX 分支，在本机跑的是 Windows 分支，两边都有断言。

## 三、第二条：把「轮子没带某个编码器」当成了环境事实

`test_avif_fallback_png_flattens` 只 patch 了 Pillow 路径，注释写着
「cv2 的 AVIF 编码器在本环境同样不可用 → 走第 ③ 级 PNG 降级」。
这条对 Windows 的 opencv wheel 成立，但 **manylinux 的 opencv 5.0.0.93 wheel 带 libavif**，
在 runner 上真的写出了 `.avif` ⇒ `assert saved.endswith(".png")` 翻红。

⇒ 这是第五类环境假设：**同一个版本号的 wheel，在不同 OS 上带的编码器/后端可以不同**
（不是版本漂移、不是 OS 路径语义、不是时区、也不是字体）。

修法：把「cv2 的 .avif 编码不可用」**显式模拟**出来（只拦 `.avif`，PNG 编码保持真实），
测试从此与「依赖构建里带不带某个编码器」解耦，两个 OS 跑同一条分支；
`try/except cv2.error: pytest.skip(...)` 一并删掉——原来那个 skip 正是这条假设的挡箭牌。

## 四、边界与收获

- 本阶段**没有改产品代码**：两条都是测试侧的环境假设。产品行为未变。
- 收获一条通用判据：**凡是「本环境没有 X」的注释，都要问一句「哪个 OS/哪个轮子没有？」**
  依赖的编译特性（编码器、后端、SIMD、字体）和 OS 语义一样，能被写进断言变成假红。
- 本地验证：CI 等价入口 `rc=0`（3409 passed / 37 skipped / 6 deselected）。
  runner 端由下一次 Actions 运行确认。
- ⚠ 仍存在的同类风险（未处理）：其余用到「可选编码器」的用例（WebP/TIFF/AVIF 家族）
  在注释里也写着"本环境"，本阶段只修了唯一翻红的那条；逐条审计留作后续。
