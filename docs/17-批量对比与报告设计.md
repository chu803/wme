# 阶段 17 · 批量对比与报告设计文档

> 项目：AI 智能水印擦除工作台 (AI Watermark Eraser Workbench)
> 阶段目标：一键把处理结果「汇总成一份可交付的修复报告」（HTML / PDF）。
> 日期：2026-08-03

---

## 1. 背景与目标

前序阶段已经具备：

- 单图 / 自动 / 批量三种入口，结果统一登记到 `cache_service`（历史缓存）；
- 批量处理完成后画廊展示 Before|After 对比图与质量分；
- `export_service.make_compare_array` 能拼「原图 | 处理后」对比数组；
- `quality_service.evaluate_quality` 能打质量分（阶段 16 已加降采样加速）。

但**缺少对外交付物**：用户处理完一批图片后，想把结果整理成一份报告发给同事 / 存档 / 打印，而不是在界面里逐张翻看。阶段 17 补上这一闭环：

- **历史记录页**：把「全部成功历史」导出为报告；
- **批量处理页**：把「本次批量运行成果」导出为报告（不依赖历史缓存，跑完即交付）。

报告支持两种格式：

| 格式 | 特点 | 用途 |
|------|------|------|
| HTML | 单文件自包含，对比图以 base64 内嵌，双击即开 | 邮件附件、网页查看、免附带图片 |
| PDF  | PyMuPDF 生成的真实 PDF，内嵌中文，可打印归档 | 正式归档、打印 |

## 3. 数据来源

报告只读取一组「来源记录」，每条需具备以下属性（因此 `HistoryRecord` 与 `ReportSource` 都可直传）：

```
status / result_path / original_path / original_name / engine / mode / params / ts
```

两个入口的数据源不同：

| 入口 | 数据源 | 含义 |
|------|--------|------|
| 历史页 | `_CACHE.list_records()` | 全部历史成功记录（含历史批量成果） |
| 批量页 | 模块级 `_batch_run_products` | **仅本次批量运行**产出的成功结果 |

批量页在 `run_batch` 每次启动时 `_batch_run_products.clear()`，并在 `_on_update` 的 `DONE` 分支把 `ReportSource` 追加进去，因此「跑完立即导出」天然成立。

### `ReportSource` 数据类

```python
@dataclass
class ReportSource:
    original_path: Optional[str] = None
    result_path:   Optional[str] = None
    original_name: str = "image"
    engine: str = "auto"
    mode:   str = "auto"
    params: str = ""
    ts: float = 0.0
    status: str = "success"
```

字段与 `HistoryRecord` 对齐，所以历史页可直接把 `list_records()` 传给 `export_report`。

## 4. `build_entries`：记录 → 报告条目

核心过滤规则（保证报告里只有「真正可交付」的结果）：

1. `status != "success"` → 跳过；
2. `result_path` 为空或文件不存在 → 跳过；
3. 原图存在 → 生成 Before|After 对比图（`make_compare_array` + `_maybe_downscale` 到 `REPORT_COMPARE_MAX_SIDE`）；
4. 原图缺失 → 退化成「仅结果图」（`img_is_compare=False`），保证历史中已删原图的记录仍可出报告；
5. `include_quality=True` 且原图存在 → 调 `evaluate_quality` 打质量分（超大图自动降采样）。

每条产物字典含：`name / engine / mode / params / time_str / img_b64 / img_w / img_h / img_is_compare / quality / result_path`。

> 任意单条对比图或质量评估失败，仅 `log.warning` 跳过该条，**不阻断整份报告**。

---

## 5. HTML 报告（`generate_html`）

- 自包含：对比图以 `data:image/png;base64,...` 内嵌，无需附带图片文件；
- 结构：标题 + 生成时间 + 汇总统计（总条数 / 良好 / 告警 / 待复核 / 平均分）+ 响应式卡片画廊；
- 每张卡片：对比图 + 文件名 + 模式/引擎 + 时间 + 参数 + 质量分徽章（`good/warn/review` 三色）；
- 样式内联在 `<style>`，无外部依赖。

---

## 6. PDF 报告（`generate_pdf`，PyMuPDF / fitz）

- 延迟 `import fitz`，避免无 PyMuPDF 时整个模块不可用；
- 中文渲染：内置 CJK 字体名 `"china-s"`（`fitz.Font("china-s")` 校验通过则用之，否则回退 `"helv"`）；
- 封面/汇总页 + 逐条记录页：
  - 每页 `REPORT_PDF_RECORDS_PER_PAGE` 条（默认 2）；
  - 单图高度上限为页面可用高度的 62%，避免一张图占满整页；
  - 本块放不下当前页时自动换页；
- 每条含对比图 + 名称 / 模式引擎 / 时间 / 参数 / 质量分文本行。

### PDF → HTML 回退

当 `fitz` 不可用时，`export_report(fmt="pdf")` 捕获 `ImportError`，回退为 HTML 输出，**并把输出路径的 `.pdf` 扩展名改写为 `.html`**（已修复「HTML 内容配 PDF 名」的 bug）。

## 7. 配置开关（config 第 8.aa 节）

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `REPORT_INCLUDE_QUALITY` | `True` | 报告是否含质量评估 |
| `REPORT_COMPARE_MAX_SIDE` | `1000` | 对比图最大边长（0=不限制），防超大图拖慢/溢出 |
| `REPORT_PDF_RECORDS_PER_PAGE` | `2` | PDF 每页记录数（1~8） |

均支持 `WME_` 前缀环境变量覆盖，并纳入 `get_config_snapshot()`。

## 8. UI 接线

两个标签页各加一组控件（`report_fmt` Radio / `report_btn` Button / `report_file` File）：

- **历史页** `export_report_from_history(fmt)`：`records = _CACHE.list_records()` → `export_report(records, fmt)`；
- **批量页** `export_report_from_batch(fmt)`：`if not _batch_run_products: 提示先运行` → `export_report(_batch_run_products, fmt)`。

两者都对 `FileNotFoundError`（无成功记录）与通用异常做了友好降级，把结果文件路径返回给 `gr.File` 供点击下载，并把提示写到状态区。

控件位于：

- 历史页：`刷新/清空` 行下方新增一行（报告格式 + 导出按钮）+ `报告文件` 下载框；
- 批量页：画廊下方新增「⑥ 导出本次批量报告」小节（同结构）。

## 10. 已知限制

- PDF 质量评估文本仅展示「质量分 + 等级」一行，未把 `detail` 诊断全文写入（避免 PDF 过长；HTML 报告同样如此，保留简版）；
- 批量页报告仅含「本次运行」成果，跨多次批量的汇总仍需走历史页；
- 无 PyMuPDF 环境下 PDF 请求会回退为 HTML（文件名 `.html`），属预期降级；
- 报告不重新执行修复，完全基于已落盘的 `result_path` 原图与结果。
