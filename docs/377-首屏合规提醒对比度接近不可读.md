# 阶段 377 · 首屏《合规提醒》对比度约 1.1:1——几乎读不清

> 日期 2026-11-04 · 性质：**真实渲染发现的可见缺陷 + 主题修复 + Quickstart 截图**

## 一、怎么发现的

为 README 的「3 分钟上手」拍真机截图时，第一屏的**合规提醒**整块看起来"糊成一片"。
用浏览器读 computed style 确认不是截图的错觉：

```
blockquote            背景 rgb(255, 251, 235)   ← 浅黄
blockquote > p/strong 文字 rgb(243, 244, 246)   ← 近白
```

对比度约 **1.1:1**（WCAG AA 正文要求 ≥ 4.5:1）——**首屏最重要的一段合规文字几乎不可读**。

## 二、根因

主题 CSS 只给 `blockquote` 本身设了 `color: #475569`，**没管子元素**；
而 Gradio 深色主题的 `.dark .prose p { color: … !important }` 把段落染成近白。
第一版尝试 `.gradio-container .prose blockquote *` **不够**：它与 `.dark .prose p`
**同权重**（0,2,1），同权重下按加载顺序后者胜出（实测刷新后 `<p>` 仍是近白）。

## 三、修法

对 `p / strong / em / a / span / li` **逐个列名**，并加 `body` 前缀把特异性抬到 **0,2,2**，
继续保留 `!important`：

```css
body .gradio-container .prose blockquote p,
body .gradio-container .prose blockquote strong,
… { color: #475569 !important; }
```

实测（同一浏览器、刷新后）：`<p>` 的 computed color = `rgb(71, 85, 105)` ⇒ 对比度约 **7.5:1**。

## 四、守卫

`tests/test_theme_branches_audit.py::test_compliance_blockquote_keeps_readable_contrast`：
- 浅黄底必须在；
- 必须存在 `blockquote p` / `blockquote strong` 的子元素规则；
- 该规则里必须带 `!important`（否则压不过主题规则）。

## 八、同一个修复在入口里被自家守卫拦了一次（值得记）

第一版 CSS 注释里写了 `⇒`。`ui/theme.py` 的整段 CSS 是**模块级字符串**、且该文件有自检入口，
于是编码守卫（GBK 编不出 `⇒`）把入口判红——**注释也是字符串**，这条对 CSS/模板同样成立。
改法：注释里的箭头换成中文词；不为此给 theme.py 加 UTF-8 加固（它没有需要打印这些字的地方）。
