# 阶段 352 · 「跳过 / 有 WARN」也要说出结论（#24 开放项的显示那一半）

> 日期 2026-10-27 · 性质：**显示改进**（不改退出码契约）

## 一、问题

门禁家族的退出码 **2** 表示「跳过」或「有 WARN 但不阻断」；统一入口在行首只印一个 `⏭`
⇒ 读的人容易理解成「这一步什么都没检查」，于是「有 2 个 WARN 待决策」被吞进绿里
（阶段 330 记录的那个开放项 #24）。

## 二、只改显示，不改契约

`run_steps()` 在 `rc == 2` 时，把子进程**最后一条非空输出**接在那一行后面：

```
⏭ docker_static       rc=2           0.2s  容器静态一致性（…）
   └─ 结论：无 ERROR，2 个 WARN（不阻断构建，但需知悉/决策）
```

**为什么不动退出码语义**：把「有 WARN」判成红（改总退出码）属**对外口径翻转**，
按项目纪律要先给判决表再动（#24 的 A/B 两个方案与代价已在 `docs/330` §六列好，等你拍）。
本阶段先把**证据摆到眼前**，让那一行自己会说话。

## 三、守卫

`tests/test_run_all_checks.py::test_skip_code_surfaces_the_child_conclusion`：
rc=2 且子进程输出「…2 个 WARN…」时，入口的行里必须出现「WARN」。
（`rc != 0` 的失败路径与 `rc == 0` 的成功路径格式都不变 ⇒ 既有断言不受影响。）

## 四、顺带记一条实现坑

`scripts/run_all_checks.py` 是 **CRLF 行尾** ⇒ 用 Edit 工具按 LF 匹配会「找不到原文」；
本阶段的改动是用**按行定位的脚本**改的（并逐行打印替换区间复核）。
这不是新坑，但值得写下来：**改 Windows 上 CRLF 文件时，先用脚本按行定位，别用文本块替换**。
