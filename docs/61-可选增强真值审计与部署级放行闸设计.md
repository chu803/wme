# 阶段 61 · 可选增强（纹理重建 / Poisson）的真值审计与处置

> 一句话：阶段 60 把"可选增强"列为待审项。用同一真值口径一测，抓到两个此前无人发现的
> 问题——**纹理细节重建是彻底的死代码**（作用域互斥，乘积恒 0，从未生效过）；**Poisson
> 无缝融合极端不稳定**且危害巨大（掩码区 PSNR −10.9 ~ −26.4 dB）。修好死代码后再测，
> 纹理重建仍是**净负收益**（−3.3 ~ −12.6 dB）。处置：两者均改为**部署级放行闸**
> （默认不通行），伪影抑制/轻量超分实测中性予以保留，并为所有可选增强加了一道
> 基于无参考质量分的**自动回退网**（best-effort）。

---

## 1. 审计口径与结果

在"默认链（阶段 60 修复后）"之上单独叠加各可选增强，测量掩码区 PSNR Δ（对 ground truth）：

| 可选增强 | 默认 | 掩码区 Δ（12 用例范围） | 判定 |
|---|---|---|---|
| 伪影抑制（双边滤波） | 关 | +0.00 ~ **+0.41** | 中性偏正，保留 |
| 纹理细节重建 | 关 | **恒 0.00**（修复前） / −3.3 ~ −12.6（修复后） | **死代码 + 净负收益** |
| Poisson 无缝融合 | 关 | −26.4 ~ **+15.9**（跳动极大） | **本质不安全** |
| 轻量超分 | 关 | −1.5 ~ +0.4 | 中性，保留 |

## 2. 缺陷一：纹理细节重建从未生效（死代码）

旧实现：

```python
detail = original - blur(original)
detail = detail * (mask == 0)   # 只在掩码外保留
w      = (mask / 255) * amount  # 只在掩码内非零
out    = result + detail * w    # 两者作用域互斥 → 恒为 0
```

"外部细节"与"注入权重"作用域互斥，乘积恒为 0——**该增强自阶段 21 起从未产生任何效果**，
而既有单测只断言"不报错 + 形状保持"，从未发现。实测全 12 用例 Δ=0.00 精确印证。

**修复**：用 `cv2.inpaint` 把外部细节场（平移 +128 后转 uint8）延拓进掩码内部再加权注入。
修复后确实生效（不再恒等）。

**但修复后实测是净负收益**：gradient corner_logo **−12.6 dB**、textured corner_logo
**−3.3 dB**——注入的外来高频无法还原真实底图纹理，且掩膜外若残留水印边缘，其高频会被
一并带进修复区。因此保留修复后的实现（不再是死代码），但**默认且部署层均不通行**。

## 3. 缺陷二：Poisson 无缝融合本质不安全

`cv2.seamlessClone(result, original, mask, …, NORMAL_CLONE)` 按**原图边界梯度重建修复区**
——对"去水印"是反向操作：刚填好的内容被整体替换，且掩膜未覆盖的残留水印会通过梯度
泄漏进修复区（gradient corner_logo −24.6、textured corner_logo −10.9、photo edge_text
−14.3 dB；而 textured faint_tiled 上又出现 +15.9 dB，属极端不稳定）。

**试过且无效的修法**：改用"去水印后的干净背景"作 dst（dst = 对膨胀掩膜做一次 inpaint）
——corner_logo 仍 −14 ~ −26 dB，textured faint_tiled 反而从 +15.9 翻到 −9.8。说明问题在
Poisson 重建机制本身，不在 dst 是否干净。

**处置**：保留实现（通用 inpainting 场景仍可能有用），但加**部署级放行闸**
`POSTPROCESS_POISSON_ALLOW`（默认 False）——即使调用方传 `poisson_blend=True` 也不执行；
调用前记录日志说明原因。

## 4. 自动回退网（best-effort）

为所有可选增强（伪影抑制 / 纹理 / Poisson / 轻量超分）统一加了一道安全网：用阶段 56 的
无参考质量分 `no_reference_inpaint_score` 比较该步前后，质量分下滑超过
`POSTPROCESS_AUTO_REVERT_TOL`（默认 0.02）即撤销该步并记 warning。

**诚实声明**：这道网**拦不住**上述两类劣化——Poisson/纹理注入后的区域在"修复区 vs 背景环"
的统计上仍可能自洽（分数不变），但内容已经与真值南辕北辙。这正是阶段 56 已声明的
"无参考指标在真实纹理上不可靠"的具体体现；因此最终安全性由**部署级放行闸 + 默认关闭**
兜底，自动回退只作为额外的尽力而为保护。

## 5. 测试（tests/test_optional_enhance_gate.py，8 例）

1. 纹理重建不再是死代码（外围有纹理时确实改变修复区）；
2. 外围平滑时跳过纹理重建（避免向干净填充区撒噪声）；
3. Poisson 默认未放行 → 不执行；
4. 放行后 Poisson 确实改写修复区；
5. 纹理重建同样受闸（放行前后结果不同）；
6. 自动回退：质量分明显下滑时撤销该步；
7. 自动回退：未下滑时保留；
8. 默认开启自动回退（`POSTPROCESS_AUTO_REVERT=True`）。

全部通过；既有 `tests/test_postprocess.py`（17 例）与 `test_postprocess_fidelity.py`（6 例）
零回归。

## 7. 边界

- 真实超分（改变画布尺寸）不参与自动回退（掩码/原图尺寸已不匹配）。
- 大批量 640 检测 + inpaint 循环曾偶发进程级硬退出（无 Python 回溯，疑似 OpenCV/内存），
  与代码逻辑无关；审计时改为"每用例独立进程"规避。
