## 1. 背景与目标

前序阶段已具备：

- 单图 / 自动 / 批量 / 历史重处理四套入口，最终都走 `core/inpainter` 完成修复；
- `quality_service.evaluate_quality` 能给修复结果打综合质量分（阶段 16 已加降采样加速）；
- `auto_pipeline.process_image` 抽出数组级 `process_image`，供 CLI / API / PDF / 视频统一复用（阶段 9）。

但 inpaint 输出存在两类常见观感问题，尚未自动收敛：

1. **接缝台阶**：inpaint 填充区与原图在掩码边界处有可见的明暗 / 色相台阶；
2. **轻微色偏 + 细节发糊**：GPU/LaMa 类模型在填充区常残留色偏，且整体高频细节被平滑。

阶段 18 在「修复完成后、落盘前」插入一层**纯像素后处理**，让成品直接观感更好，无需用户手动后期：

| 步骤 | 作用 | 依赖 |
|------|------|------|
| ① 色彩还原 (Color Match) | 把填充区颜色 / 对比度统计向周围原图对齐，修正色偏 | 原图 + 掩码 |
| ② 边缘融合 (Edge Blend) | 掩码边界窄带羽化，柔化填充区与原图接缝 | 原图 + 掩码 |
| ③ 锐化 (Sharpen) | unsharp mask 找回高频细节，整图轻量 | 无（整图） |

三步各自有独立开关（config），可单独关闭；**总开关关闭时直接透传 inpaint 原始结果，零额外开销**。

## 2. 架构与分层

严格遵循项目铁律 `ui → services → core → utils → config`，本阶段**新增服务层模块零 Gradio 依赖**。

关键设计约束：

- **接线点选在 services 层入口，而非 `core/inpainter`**：`core` 层严禁 import `services`（反向依赖违反铁律），因此增强逻辑只能挂在 inpaint 的**调用方**。三处最上游调用点统一接线，保证四套入口行为一致；
- **不引入新第三方依赖**：全部基于已有的 `cv2` / `numpy`；
- **复用 quality_service**：新增数组级 `evaluate_quality_arrays`（不读写文件），既供 `process_image` 在内存里对比「优化前 / 后」，也避免破坏既有路径版 `evaluate_quality` 的 API。

## 3. 三步增强算法

所有输入为 OpenCV 排布的 `H×W×3 uint8`（BGR）。

### 3.1 掩码规整 `_as_mask`

任意形态掩码 → 单通道 0/255 uint8：3 通道取首通道，非 0 即视为修复区。

### 3.2 色彩还原 `_color_match(result, mask, original, strength)`

逐通道把「掩码内」统计向「掩码外（周围原图）」对齐：

```
ext = (mask == 0)      # 周围
int_ = (mask > 0)      # 被修复区
mo, so = mean/std(原图·外部)
mr, sr = mean/std(结果·内部)
if sr < 1e-3:          # 修复区近乎纯色 → 仅均值对齐，避免除零
    target = r_int + (mo - mr) * strength
else:
    归一   = (r_int - mr) * (so / sr) + mo
    混合   = r_int * (1 - strength) + 归一 * strength
```

区域像素数不足 100 时统计不可靠，直接跳过。默认 `strength = 0.8`（0~1）。

### 3.3 边缘融合 `_edge_blend(result, mask, original, band)`

用「膨胀 - 腐蚀」得到边界环 → 高斯模糊成软 alpha（环中心≈1，外缘→0）：

```
ring  = cv2.dilate(mask) - cv2.erode(mask)
soft  = cv2.GaussianBlur(ring, (0,0), sigmaX=max(0.5, band*0.8)) / 255
out   = result * soft + original * (1 - soft)
```

掩码外 `soft=0`（保留原图），掩码内远离边界 `soft≈0`（保留填充结果），仅边界窄带平滑过渡。`band` 默认 3（0~20）。

### 3.4 锐化 `_sharpen(result, amount)`

unsharp mask：`result + amount * (result - 模糊)`。`amount` 越大模糊核越小（保留越多细节）：

```
sigma = max(0.4, 2.0 - amount)   # amount 0.6 → 1.4；amount 2.0 → 0.4
blurred = cv2.GaussianBlur(result, (0,0), sigmaX=sigma)
sharp   = clip(result + amount*(result - blurred))
```

`amount <= 0` 直接返回原图。默认 `amount = 0.6`（0~2）。

### 3.5 主入口 `postprocess(...)`

```python

                enable=None, sharpen=None, color_match=None, edge_blend=None):
```

执行顺序：色彩还原 → 边缘融合 → 锐化。每一步独立开关。

## 4. 质量对比联动 `evaluate_improvement`

复用 `quality_service.evaluate_quality_arrays`（数组级，不落盘）对比「原始 inpaint 结果」与「后处理结果」：

```python
def evaluate_improvement(original_rgb, mask, raw_result, improved_result) -> dict:
    qb = evaluate_quality_arrays(original_rgb, raw_result)
    qa = evaluate_quality_arrays(original_rgb, improved_result)
    delta = round(qa.score - qb.score, 1)
    return {
        "score_before": qb.score, "score_after": qa.score,
        "delta": delta, "better": delta > 0,
        "detail": f"质量分 {qb.score} → {qa.score}（{'+' if delta>=0 else ''}{delta}）",
        "level_before": qb.level, "level_after": qa.level,
    }
```

`process_image` / `tab_auto.process_auto_repair` 在 `postprocess_eval=True` 时计算该字典，并把 `quality_before / quality_after / delta / better` 注入返回 / 状态文案，供 CLI / 批量页反馈提升幅度。

## 8. 设计决策与权衡

- **为何不放在 `core/inpainter`**：`core` 严禁 import `services`，后处理依赖 `quality_service` 又属 services 层，故只能在调用方接线。
- **为何新增 `evaluate_quality_arrays` 而非复用路径版**：路径版需落盘再读取，批量与内存管线里对比「优化前/后」代价高；数组级函数在内存直接比，且路径版委托之保持 API 兼容。
- **为何几何两步（色彩还原 / 边缘融合）依赖原图 + 掩码**：只有拿到原图与掩码才知道「什么是背景、哪里是接缝」；单图手动涂抹场景原图 + 掩码齐备，故同样生效；纯无掩码场景自动降级为仅锐化。
