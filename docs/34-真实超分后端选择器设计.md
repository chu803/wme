# 阶段 34 · 真实超分后端选择器（UI 暴露）

> 日期：2026-08-06
> 目标：把真实超分（Real Super-Res）的**后端类型**（auto / esrgan / realesrgan）选择权真正暴露到 UI，让用户能在四张功能页上指定用哪个模型后端，而非永远沿用 `config.REAL_SUPERRES_BACKEND` 默认值。

---

## 1. 背景与动机

- 阶段 32 落地了「真·超分」模块（`core/superres.py` 的 `get_superres_backend(kind, ...)` 工厂，支持 `auto` / `esrgan` / `realesrgan` 三种 kind，缺 torch 时回退轻量超分）。
- 阶段 33 把真实超分接入视频（`process_video` / `remove_watermark_video` 均透传 `real_backend`），并把「开关 + 放大倍数」控件放到了单图 / 自动 / 批量 / 视频四页。
- **缺口**：四页虽然已有「是否启用」(`real_superres`) 与「放大倍数」(`real_scale`) 控件，但**后端类型** (`real_backend`) 始终是 `None`，运行时回落到 `config.REAL_SUPERRES_BACKEND`。用户无法在界面上切换想用的后端（例如想强制用纯 torch 的 ESRGAN，或想强制官方 Real-ESRGAN）。
- 调查确认：下游 `postprocess_service._resolve_backend` 与 `video_service._resolve_video_backend` **早已支持字符串类型的 kind 参数**（实例 / 字符串 / None 三种形态），因此只缺 UI 控件 + 参数透传，无需改动算法层。

本阶段 = 在四个页面新增「超分后端」下拉框，并把字符串类型一路透传到已存在且兼容的 `real_backend` 形参。

---

## 2. 后端类型语义

| kind | 含义 | 依赖 | `used_real` |
|------|------|------|-------------|
| `auto` | 依次尝试 `realesrgan` → `esrgan` → `None` | torch（+realesrgan+basicsr 可选） | 视命中 |
| `esrgan` | 纯 torch RRDB 生成器（不依赖 basicsr） | torch | true |
| `realesrgan` | 官方 Real-ESRGAN 权重路径 | torch + `realesrgan` + `basicsr` + 权重 | 始终 true |

缺 torch / 权重时，无论选哪个 kind，工厂都返回 `None`，上层自动回退轻量超分 —— 行为与改动前一致（零 torch 沙箱内可测、无回归）。

---

## 3. 改动清单

### 3.1 i18n（`utils/i18n.py`）
- 新增 `params.real_backend_label` / `params.real_backend_info`（zh-CN + en-US），文案说明三种后端的区别。
- 自检循环（zh-CN 段）扩展到断言这两个键存在，并断言 `real_backend_label == "超分后端"`。

### 3.2 复用组件（`ui/components.py`）
- `RepairParamHandles` 新增字段 `real_backend: gr.Dropdown`。
- `build_repair_params._body` 在「放大倍数」滑块同行下新增 `gr.Dropdown(choices=["auto","esrgan","realesrgan"], value=config.REAL_SUPERRES_BACKEND, ...)`，并 `reg_label_info` 注册。
- `param_values()` 加入 `"real_backend": h.real_backend.value`。
- 模块自检（`set(vals.keys())` 断言）加入 `"real_backend"`。

> 因 `RepairParamHandles` 被单图 / 自动 / 批量三页共用，新增字段一次性覆盖三页。

### 3.3 单图页（`ui/tab_single.py`）
- 新增 `pp_real_backend = gr.Dropdown(...)`。
- `run_btn.click` 的 `inputs` 末尾追加 `pp_real_backend`。
- `process_single` 早已声明 `real_backend: Optional[str] = None` 并转发，无需改签名。

### 3.4 自动页（`ui/tab_auto.py`）
- 新增 `pp_real_backend = gr.Dropdown(...)`。
- `repair_btn.click` 的 `inputs` 末尾（`mask_mode` 之后）追加 `pp_real_backend`。
- `process_auto_repair` 签名末位已有 `real_backend`，无需改签名。

### 3.5 批量页（`ui/tab_batch.py`）
- `_process_one` 新增 `real_backend: Optional[str] = None` 形参，转发 `process_auto_repair(..., real_backend=real_backend)`（原先硬编码 `real_backend=None`）。
- `run_batch` 新增 `real_backend: str = config.REAL_SUPERRES_BACKEND` 形参。
- 内部 `_processor` 闭包转发 `real_backend=real_backend`。
- `run_btn.click` 的 `inputs` 在 `params.real_scale` 之后追加 `params.real_backend`。

### 3.6 媒体（视频）页（`ui/tab_media.py`）
- `run_video` 新增 `real_backend: str = config.REAL_SUPERRES_BACKEND` 形参，转发 `process_video(..., real_backend=real_backend)`。
- `video_btn.click` 的 `inputs` 在 `video_params.real_scale` 之后追加 `video_params.real_backend`（`video_params` 即 `RepairParamHandles`）。

---

## 4. 兼容性 & 风险

- 下游 `_resolve_backend` / `_resolve_video_backend` 接受实例 / 字符串 / None 三种形态；下拉框传字符串，完全向后兼容。
- 默认值 `config.REAL_SUPERRES_BACKEND`（`"auto"`），不改任何既有默认行为。
- 零 torch 环境下：字符串 kind → 工厂返回 `None` → 回退轻量超分，输出尺寸与改动前一致。
- 未触碰 `ui→services→core→utils→config` 分层边界；`core/services/utils` 零 gradio 依赖不受影响。
