## 一、#24：2/3 不再阻断，但必须被说出来

旧的聚合契约（阶段 328 定的）把「跳过(2)」和「环境错误(3)」分别聚合成 2 和 3。
后果是**两种完全不同的语义共用了同一种红**：

- CI 上「缺数据集，某个门禁没跑成」与「质量不合格」长得一模一样；
- 本地文案又把 2 印成「⏭ 全部跳过」，读日志的人分不清「没测」和「测坏了」。

按用户判决（任务 #24）改定：

| 入口退出码 | 含义 |
|---|---|
| `0` | **没有质量失败**。可能含「未覆盖项」，但会逐条列出来（见下） |
| `1` | 有步骤判质量不通过——**包括约定外的码**（127/崩溃/被信号杀掉）：说不清的结果不是通过 |
| `2` | 无事可跑（`--list` 或步骤清单为空） |
| `3` | **入口自身**的环境问题（`--strict-env` 不满足） |

实现要点：

- `aggregate()` 只对「1」和「约定外码」判失败；2/3 不阻断。
- 新增 `uncovered(report)`：把判定码为 2/3 的步骤逐条列进输出，并带上子进程自己的结论
  （`report[i]["conclusion"]`，取子进程 stdout 最后一行）。
- 新增 `verdict_line(total, uncovered_count)`：**有未覆盖项时不许印「全部通过」**，
  改印「✅ 无质量失败（但 N 项未覆盖，见上）——未覆盖项未经判定」。
- 纪律写进注释与守卫：**质量类 WARN 只能用退出码 1 表达；2/3 只允许表达「没做判定」**。
  这样「WARN 判红、缺数据放行」就不再靠人记，而是靠码的语义分工。

## 二、#35：`--strict-env` 把画像从「告知」升级为「门禁」

阶段 361 让入口开头打印 `[ci_equivalent]/[full_dev]/[not_ci_env]`，但只是告知。
按用户判决，新增 `--strict-env`：

- 画像不是 `[ci_equivalent]` ⇒ **拒绝裁决**，退出码 3，并打印「下一步」；
- 不传该开关时行为不变（本地开发机是 `[full_dev]`，无条件强制会让本地入口常红）；
- **`ci.yml` 与 `publish.yml` 的入口步都加上它**（守卫逐文件断言）——
  「CI 绿」从此等价于「在一个确认是 runner 画像的环境上绿」，发布闸门同理。

判定逻辑抽成纯函数 `env_gate(tag, strict)`，只有一处真值来源。

## 三、#38：`dependencies` 从 `requirements-min.txt` 动态读取

`pip install wme-watermark-eraser` 此前**不会**装任何运行期依赖（安装后 import 就崩），
README 只能教用户手动补装。原因是 pyproject 刻意不写 `dependencies`，怕与清单两处漂移。

按用户判决改成 setuptools 的 file 形式：

```toml
[project]
dynamic = ["dependencies"]

[tool.setuptools.dynamic]
dependencies = { file = ["requirements-min.txt"] }
```

- 单一真值来源仍是清单文件，**不存在两处漂移**；
- 选 `requirements-min.txt` 而不是 `requirements.txt`：后者含 torch（`+cu128` 轮子不在
  PyPI 默认索引上，写进 `Requires-Dist` 会让普通 `pip install` 直接解析失败）；
- **实测**：`python -m build --wheel` 成功，wheel 的 METADATA 里出现 **15 条
  `Requires-Dist`**，逐条与清单一致（opencv/numpy/Pillow/scikit-image/scipy/gradio/…）；
- README §3.3 同步改写（依赖自动装；可选增强仍另装）。
