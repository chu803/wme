# 阶段 159 · `validate_selector` 退化样本一致性守卫（审计验证装置本身）

## 动机

`scripts/validate_selector.py`（阶段 56 遗留）用**合成数据已知的 ground truth** 校验无参考质量指标
`core.quality.no_reference_inpaint_score` 的选优方向是否**被写反**——它是「验证指标是否可信」的
**验证装置**。但该脚本此前**零专属测试**。

审计它 = 审计验证装置本身（经验 24：度量工具也是被测对象）。若验证装置自己会在退化情形下
给出**不可证伪的满分结论**，那么它下游支撑的一切「指标可信」判断都被污染。

## 探针（`probe_159.py`：stub `_one` 驱动真实 `main()` 判定块）

不加载 torch：直接 stub `validate_selector._one` 造受控 rows，再跑**真实** `main()` 的一致性判定块。
量化结果：

| 场景 | 旧实现输出 | 问题 |
|------|-----------|------|
| **全平局**（两引擎 ΔPSNR 与指标分都相等 ⇒ 指标零判别力） | `一致性：4/4 = 100.0%` | **零信息却给满分**（假绿） |
| **混合**（2 例真相悖 + 2 例平局） | `一致性：2/4 = 50.0%` | 平局被计入分子，把诚实的 `0/2 = 0%` 抬高 |

根因：判定块
```python
gt = "opencv" if do > dl else "lama"
mt = "opencv" if so > sl else "lama"
ok = (gt == mt)
```
在**平局**（`do == dl` 或 `so == sl`）时静默倒向 `"lama"`，于是「真值与指标都没有偏好」的退化样本
被**计入**一致性。全平局 ⇒ `agree == total` ⇒ 打印 100%，直接与该脚本「证明指标方向未被写反」
的目的相悖（对齐经验 7/15/22：度量会奖励劣化；「跳过」必须与「通过」区分；缺数据须与零可区分）。

## 缺陷分类

- **P1（defect · 验证装置裁决不可伪证）**：退化（平局）样本被读成「一致」。极端情形给出
  「零信息满分」，使验证装置的结论无法被数据证伪。
- 真实一致/相悖的普通路径本身 **by design 正确**（探针 3/4 已验证），本轮不改。

## 最小修复

- 平局单列 `=` 且**不计入**一致性；数据缺失单列 `—`；两者分别计数。
- 表尾汇报 `（平局·退化 N 例、数据缺失 M 例，未计入）`。
- 当**无**携带方向信息的有效样本时，显式声明「无法评估一致性 —— 切勿读成「一致」」，**绝不打印一致性率**。

## 守卫

`tests/test_validate_selector.py`（**7 例**，stub `_one` 驱动真实 `main()`）：

1. 全平局**绝不**报 `100.0%`，且显式声明「无法评估一致性」+ 汇报退化计数；
2. 平局剔除：混合场景必须报 `0/2 = 0.0%`（而非 `2/4 = 50.0%`）；
3. 真实一致仍计入（`4/4 = 100.0%`、退化 0 例）——回归不误伤；
4. 真实相悖为 `0/4 = 0.0%`；
5. 数据缺失单列且剔除（`2/2 = 100.0%`、缺失 2 例）；
6. 无任何有效结果 → `rc=1`；
7. 图例必须同时登记「= 平局」与「— 缺失」两种非判定标记。
