# 阶段 12 设计文档：模型管理增强

> 本文档配套 `core/model_manager.py`、`download_model.py`（重构）、`core/model_loader.py`（委托）、`config.py`（第 4.x 节）、`cli.py`、`api.py`、`ui/tab_models.py` 与 `main.py` 接线。
> 目标：在「插件引擎」（阶段 11，换算法）之外，进一步支持「多模型权重切换」——同一套 LaMa TorchScript 接口（输入 `image+mask`，输出修复图）可挂多个不同的 `.pt` 权重并随时切换，且带**下载进度条、完整性校验、备份与回滚**。

---

## 1. 背景与动机

阶段 11 让「修复引擎」可扩展（换算法）。但权重文件层面仍是单一写死：`core/model_loader` 只认 `config.MODEL_PATH`（即 `models/big-lama.pt`）。现实需求：

- 用户可能训练/获取多个 LaMa 兼容权重（如 FP32 版、不同数据集微调版、轻量版），想随时切换对比效果；
- 下载大权重（~205MB）需要可见的进度，而非「卡住不知进度」；
- 权重可能被下载截断/篡改，需要校验；升级新权重翻车时需要一键回滚。

阶段 12 用「模型槽（ModelSlot）」抽象解决，且**所有现有调用方零改动**：LaMa 引擎一律加载「当前模型槽（active）」的权重。

---

## 2. 分层与依赖约束（铁律不变）

```
ui/tab_models → api → core/model_manager → core/model_loader → core/inpainter → core/plugins
                                      ↘ download_model（download_to）
```

- `core/model_manager.py` 属于 **core 层**，严禁 import gradio / ui 组件；
- **零 torch 依赖**：torch 仅在 `load_model` 内部延迟导入，导入期不会因缺 torch 崩溃；
- `model_manager` 与 `download_model` 互相单向依赖：`model_manager` 延迟 import `download_model.download_to`，`download_model` 不反向依赖 `model_manager`，无循环依赖；
- 修复核心（`core/inpainter` / `detector` / `image_utils`）零改动。

## 4. 模型槽数据契约（ModelSlot）

| 字段 | 类型 | 含义 |
|------|------|------|
| `name` | str | 槽唯一键（小写），CLI/API 用它选择 |
| `display_name` | str | 界面显示名 |
| `filename` | str | 权重文件名（落在 `MODEL_DIR` 下） |
| `path` | Path | 权重文件绝对路径 |
| `expected_size` | int | 预期字节数（0 表示不校验体积） |
| `sha256` | str | SHA256 校验值（空表示不校验） |
| `urls` | tuple | 下载地址列表 |
| `note` | str | 备注 |
| `builtin` | bool | 是否内置槽（lama 为 True） |

`to_dict()` 供 JSON 序列化（`list_models()`）。

## 5. 注册来源与 active 切换

注册顺序（后者不覆盖已注册槽）：

1. **内置槽 `lama`** → 指向 `config.MODEL_PATH`（`big-lama.pt`），带默认下载源；
2. **`config.MODEL_SLOTS`** 显式登记（list[dict]，支持 `WME_MODEL_SLOTS` JSON 覆盖）；
3. **自动发现**：若 `MODEL_AUTO_DISCOVER=True`，扫描 `MODEL_DIR` 下 `.pt/.onnx` 自动注册为槽（不覆盖已有槽）。

`active` 模型：全局仅一个。切换用 `set_active_model(name)`：
- 校验槽存在，否则返回 False；
- 切换后清空权重缓存（避免误用旧权重）；
- 持久化到 `MODEL_STATE_FILE`（`.active_model.json`），重启仍生效；
- 启动时 `_load_state()` 读取该文件恢复 active（非法则回退 `config.ACTIVE_MODEL`）。

**关键收益**：`_BuiltinLama.inpaint` / `load_lama_model` 一律加载 active 槽权重，因此「切换模型」无需改任何调用方代码。

## 6. 下载（进度条 + 备份 + 校验 + 回滚）

### 6.1 download_model.py 重构
抽出底层 `download_to(dest, urls, progress_cb, auto_pick, expected_size, sha256, timeout, retry)`：
- 多源按顺序尝试，前一源失败自动切换；
- **断点续传**（Range 头）；
- 下载后校验体积（< 预期 90% 即失败）与可选 SHA256；
- 原 `download_model()` 改为调用 `download_to(config.MODEL_PATH, config.MODEL_DOWNLOAD_URLS, ...)` 的薄封装，**向后兼容**。

### 6.2 进度条
`progress_cb(downloaded, total, speed_kbps)` 在 `download_one` 每 0.5s 回调一次。
- **CLI**：默认文本进度条（`_default_progress`）；
- **UI**：`on_download` 用 `gr.Progress()` 包装该回调，实时刷新进度条：`frac = downloaded/total; progress(frac, f"{mb} | {speed}KB/s")`；
- **API**：`download_model(name, progress_cb)` 透传回调。

### 6.3 备份与回滚
- 覆盖前，先把现有权重复制为 `原路径 + MODEL_BACKUP_SUFFIX`（`.bak`）；
- 下载并校验成功后删除备份（已无用）；
- 若下载/校验失败：自动 `rollback_model` 从备份恢复，并告警；
- 显式「回滚」按钮/CLI 调用 `rollback_model(name)` 随时还原。

## 7. 四入口暴露方式

### 7.1 CLI（`cli.py`）
```
python cli.py --list-models              # 列出全部槽 + 当前模型
python cli.py --download-model [NAME]    # 下载（NAME 省略=当前），带进度
python cli.py --verify-model  [NAME]     # 校验完整性
python cli.py --set-model NAME           # 切换并持久化当前模型
```
`--list-models` 标出 `*` 当前模型、`✅/❌` 状态；`--verify-model` 未通过返回退出码 1。

### 7.2 程序库（`api.py`）
新增：`list_models()` / `get_active_model()` / `verify_model(name)` / `set_active_model(name)` / `download_model(name, progress_cb)`。全部对异常兜底。
`get_capabilities()` 新增 `active_model` 与 `models` 字段（安全 `_list_models_safe`）。

### 7.3 REST（`server.py`）
`GET /api/capabilities` 现含 `active_model` 与 `models`；客户端据此选择可传的 `engine` 与当前模型。

### 7.4 GUI（`ui/tab_models.py`）
新增「模型管理」标签页：
- Markdown 清单（槽名/状态/体积/当前标记）；
- 模型槽下拉 `model_selector`；
- 按钮：🔄 刷新 / ⭐ 设为当前模型 / ⬇️ 下载（gr.Progress 进度）/ 🔍 校验 / ↩️ 回滚；
- 状态信息区。所有逻辑委托 `core.model_manager`，界面不含业务。

`main.py` 启动自动下载目标改为 `model_manager.download_model(None)`（仅当 active 槽为内置 lama 或自带 urls 时才自动下载，避免误下错权重）。

## 8. 配置项（config.py 第 4.x 节）

| 配置常量 | 默认值 | 环境变量 | 含义 |
|----------|--------|----------|------|
| `ACTIVE_MODEL` | `"lama"` | `WME_ACTIVE_MODEL` | 初始当前模型槽（运行时切换持久化覆盖） |
| `MODEL_SLOTS` | `[]` | `WME_MODEL_SLOTS`(JSON) | 额外模型槽清单（list[dict]） |
| `MODEL_STATE_FILE` | `MODEL_DIR/.active_model.json` | — | 当前模型持久化文件 |
| `MODEL_BACKUP_SUFFIX` | `".bak"` | — | 覆盖前备份后缀 |
| `MODEL_AUTO_DISCOVER` | `True` | `WME_MODEL_AUTO_DISCOVER` | 是否在 MODEL_DIR 自动发现 .pt/.onnx |

`validate_config()` 软校验 `MODEL_SLOTS` 结构（每项需含 name+filename），错误仅告警；`get_config_snapshot()` 追加「当前模型槽 / 额外模型槽数 / 自动发现模型」。

## 9. 边界与约束

| 维度 | 约定 / 限制 |
|------|------------|
| 接口一致性 | 模型槽必须遵循 LaMa TorchScript 接口 `(image, mask) -> 修复图`；换算法请用插件（阶段 11） |
| 权重缓存 | 按路径单例缓存；切换 active 或 `force_reload` 清空缓存 |
| 自动发现 | 仅扫描 `MODEL_DIR` 下 `.pt/.onnx`；已注册槽不重复注册 |
| 下载源 | 槽自带 `urls` 优先，否则回退全局 `MODEL_DOWNLOAD_URLS` |
| 回滚前提 | 需存在 `.bak` 备份（仅在「覆盖前」生成过） |
| active 持久化 | 写入 `MODEL_STATE_FILE`；启动读取，非法回退默认 |
| 启动自动下载 | 仅 active 为内置 lama 或自带 urls 时触发，避免误下错权重 |
| 校验失败 | 下载后校验未过→自动回滚并抛异常，不留下残缺权重 |
| torch 缺失 | 注册表/校验/列表均不依赖 torch；仅 `load_model` 内部导入 torch |
| 核心算法 | `core.inpainter`/`detector`/`image_utils` 零改动 |

## 10. 验证结论

阶段 12 完成后执行的验证（全部通过）：

1. **`core/model_manager.py` 自检**：注册临时槽→`set_active_model`→`verify_model(缺失)` 断言正常；清理后恢复 lama。
2. **`config.py` 自检**：`_env_json` 解析、`validate_config`、`get_config_snapshot` 含新字段。
3. **`download_model.py` 重构**：`download_to` 与 `download_model` 均可调用；原入口向后兼容。
4. **`core/model_loader.py` 委托**：`load_lama_model`/`is_model_available`/`get_model_info` 经 `model_manager`；`get_model_info` 保留 `model_available`/`model_path` 兼容键；`inpainter` 导入无碍。
5. **`build_app` 装配**：225 blocks（新增模型管理标签页）。
6. **`cli.py`**：`--list-models` / `--verify-model` / `--set-model lama`(成功) / `--set-model nope`(退出码 1) 均正确。
7. **`api.py`**：`get_capabilities` 含 `active_model`+`models`；`list_models`/`verify_model`/`set_active_model`/`download_model` 可用；8 用例自检全过。
8. **端到端（无网络）**：在 `models/` 放下 `testmodel.pt` → 自动发现并出现在 `list_models`；`is_model_available('testmodel')=True`；`set_active_model('testmodel')` 后 `model_loader.is_model_available()=True`（active 生效）；`verify_model` 体积校验通过；复原 active=lama 并清理临时文件。

修复核心算法未被改动：`core/inpainter`/`detector`/`image_utils` 零改动；本阶段新增模型注册表 + 下载重构 + 接线 + 界面 + 文档。
