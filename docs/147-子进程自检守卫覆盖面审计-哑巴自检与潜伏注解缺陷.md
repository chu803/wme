## 二、缺陷（4 处，全部由**枚举/实测**定位）

### G1（P2）`ui/components.py` **重复登记**

`MODULES` 第 35 行与第 46 行**都**登记了 `ui/components.py`（后者带 Stage 138 说明）。
⇒ `ids=[m[0] for m in MODULES]` 产生重复 id、该模块自检被**跑两遍**。
⇒ 修：删除无说明的那条；新增 `test_selfcheck_registry_has_no_duplicates` 防回归。

### G2（P1）`config.py` 的**哑巴自检**（最隐蔽的形态）

实测：`config.py` 的自检块有 **21 条语句 / 26 次调用、却 0 个 `assert`**：

```python
_problems: list[str] = validate_config()      # ← 读了真值来源
if not _problems:
    print("  通过。未发现配置问题。")
else:
    for _index, _problem in enumerate(_problems, start=1):
        print(f"  [{_index}] {_problem}")     # ← 只打印
# ...然后正常结束，rc 恒为 0
```

⇒ **它读了真值来源、做了判定，却没让判定结果影响退出码**。
⇒ 后果：`validate_config()` 一旦因回归开始报问题（例如新增的成对约束元检查误报、
或 `_env_float` 的 NaN 拦截被删），**子进程守卫照样绿**。
⇒ 这是「哑巴自检」**最难发现**的形态 —— 它比「只 `print` 一句」充实得多，
   因此不会被「看代码一眼」发现，需要**结构化检查**才能暴露。

**修法**：`if _problems: raise SystemExit(1)`（打印保持原样，用户友好性不变）。

### G3（元层，P1）守卫**只断 `rc == 0`、不看输出、也不查自检有没有判定能力**

⇒ 这是 G2 能长期存在的**根本原因**：一个「什么都不做」的空自检 `rc` 同样是 0。
⇒ 修：
- 补 **`stdout` 非空**断言（挡住空自检）；
- 新增 **`test_selfcheck_modules_have_decision_power`**：用 **AST 递归**判断
  「`__main__` 块 ∪ 它直接调用的**本模块函数**」里是否存在 `assert` / `raise` /
  `SystemExit` / `sys.exit`。

> **两条设计要点（都是被实测教训逼出来的）**：
> 1. **必须递归到被调用的本模块函数** —— `ui/tab_history.py` 把断言放在
>    `_run_selfcheck()` 里；只看 `__main__` 块会**误报**它为哑巴
>    （我的首版探针正是这么误报的 —— 再一次栽在「作用域」上，经验 174/177）。
> 2. **跨模块调用刻意不计入** —— `config.py` 的 `__main__` 调用了 `validate_config()`，
>    但那只是把结果**打印出来**。把判定权交给别人、自己永远 0 退出，
>    **正是要抓的形态**，不能算作「有判定能力」。

### G4（覆盖面，P2）39 个模块未登记，而「未登记」与「忘了登记」在数据上无法区分

⇒ 修：
- **静态风险分类**（不盲跑未登记模块）：B 重依赖/副作用 13 个、W 写文件 2 个、
  S `scripts/` 一次性脚本 20 个、**A 候选可登记 6 个**；
- **实测 6 个候选**（rc / 耗时 / 输出 / **关键目录文件数快照比对**）：
  全部 rc=0、0.25~3.73s、输出非空、**目录文件数零变化** ⇒ 补登记；
- 新增 **`NOT_REGISTERED_BY_DESIGN`**：39 条**显式豁免清单**（每条都有理由），
  与 **`test_selfcheck_coverage_is_accounted_for`** 一起工作 ——
  磁盘上凡含 `__main__` 的模块必须**要么在 MODULES、要么在豁免清单**，否则测试变红。
  ⇒ 新增模块时**不可能静默漏登记**（经验 167/178）。

## 三、★ 意外收获：`undef_scan` 首次真正运行就抓到 **3 处潜伏缺陷**

146 阶段资产化的 `scripts/undef_scan.py` **当时有死代码缺陷**：
`__main__` 块里自检后直接 `raise SystemExit(0)` ⇒ **`main()` 不可达** ⇒
命令行参数（`--all` / 指定文件）**完全失效、且无任何症状**（它照样打印「自检通过」并 0 退出）。
⇒ 属「死代码 + 静默失效」族，**在 146 的自检与守卫下都通过了**（因为它确实有 print、有 assert）。
⇒ 修：`__main__` 改为「先 `_selftest()`，再 `raise SystemExit(main())`」。

修好后首次全仓扫描（215 个 `.py`）即抓到 **3 处**：

| 文件 | 未定义名 | 真实位置 | 为什么一直没炸 |
|---|---|---|---|
| `core/detector.py` | **`Dict`** | 3 处注解（`Dict[str, int]` / `Dict[int, List[int]]`），而 import 只有 `List, Optional, Tuple` | `from __future__ import annotations` |
| `services/validators.py` | **`_os`** | 3 处注解（`_os.PathLike`），而 import 是 `import os` | 同上 |
| `ui/tab_history.py` | **`Optional`** | 3 处注解（`Optional[str]`），**完全没导入 typing** | 同上 |

### 为什么这是真缺陷（而非「无害的字符串」）

`from __future__ import annotations` 让**所有注解延迟为字符串、永不求值** ⇒
运行时代码路径**永远不会**触发 `NameError`（这正是它们能潜伏至今的原因）。
**但任何会求值注解的东西都会立刻炸**：

- `typing.get_type_hints()`（实测：修复前会 `NameError`，修复后 **0 错误**）
- 文档生成（Sphinx autodoc）、`dataclasses` 的某些反射路径、pydantic 模型装配
- 类型检查器（mypy / pyright 会直接报错）

⇒ **静态枚举（AST）是发现这类缺陷的唯一手段**。已加固为守卫：
`test_no_undefined_names_repo_wide`（全仓 215 文件零可疑名）。

**修法**：`detector.py` 的 import 补 `Dict`；`validators.py` 补 `import os as _os`
（保留既有别名风格，改动面最小）；`tab_history.py` 补 `from typing import Optional`。

## 五、登记与边界

### G5（P2）全量跑另暴露一处**自检非幂等**：`services/export_service.py`

全量跑报 `test_module_selfcheck[services/export_service.py]` rc=1，尾部：

```
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]
  {"count":50,"threshold":50,"scope":"turn","targets":["...\results_cleaned_121754(1).zip"],"targetCount":1}
```

**根因**：该自检**走各导出函数的默认输出目录**（`config.EXPORT_DIR` = `exports/`），
每次运行**写 4 个产物、再删 4 个**。看似干净，实则**非幂等** ——
删除动作会累积进沙箱的「单轮批量删除」计数器（阈值 50），
当同一轮里前面的用例已累计删到 44+ 时，本自检的 `os.remove` 就把计数推过阈值 ⇒ 被护栏拦截。
⇒ **同一份代码，前几次跑是绿的、跑到第 N 次开始红**。
（`exports/` 已累积 **438** 个文件，多为历次自检/门禁的产物。）

**第一版修复不完整（实测踩到）**：只把 4 个用例的 `out_path` / `out_zip` 指向 `mkdtemp`
—— 结果 `exports/` **仍多出 2 个** `tmp*_cleaned_*.webp`。
⇒ 因为 `export_history_as_zip` 的**中间产物**（逐条记录重编码）走的是**默认目录**，
`out_zip` 只管最终 ZIP。⇒ **必须把默认目录也指向临时目录**（`config.EXPORT_DIR` 临时替换 + `finally` 恢复），
即**同时覆盖「显式输出路径」与「默认兜底路径」两条线**。

> 这与经验 **169**（「兜底值绕过清洗管线」）**同族**：
> **兜底路径往往绕过你以为已经守住的那层**。修复的验收判据也因此改为
> **连跑 3 次 + 目录文件数快照比对**（最终实测 `exports` 438 → 438，零副作用）。

Stage 136 对 `services/video_export.py` 做过同款修复（隔离到 `mkdtemp` 且 `finally` 自清理）；
本次把 `export_service` 对齐到同一做法。修完从「需 deselect」变为**可正常登记运行**。

### G6（元级，P2）**同族污染不止一个模块 —— 改为守卫层统一隔离**

修完 `export_service` 后，下一次全量跑**又**报同款失败，这次是 **`api.py`**：

```
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]
  {"count":50,"threshold":50,"scope":"turn","targets":["...\outputs\tmp4l9qtqro_cleaned_122833.png"],"targetCount":1}
```

⇒ `api.py` 的自检写 `outputs/` 再删，**同款非幂等**。
⇒ **这正是「枚举优于记忆」的又一次现形**（经验 178）：
我在「修同族缺陷」时**只修了先撞见的那一个**。

**改为元级修法（一次覆盖全部模块，且对未来新增模块自动生效）**：
`config` 的每个运行时目录都由 `_resolve_dir(env_key, default_name)` 从 `WME_<key>` 读取
⇒ 在 `test_module_selfcheck` 里给子进程**注入专用环境变量**，把
`WME_OUTPUT_DIR` / `WME_EXPORT_DIR` / `WME_CACHE_DIR` / `WME_TEMP_DIR` / `WME_LOG_DIR`
全部指向**本用例专属的临时目录**（pytest `tmp_path`）：

```python
env = dict(os.environ)
for var, sub in _RUNTIME_DIR_ENVS:
    d = tmp_path / sub; d.mkdir(parents=True, exist_ok=True)
    env[var] = str(d)
subprocess.run([sys.executable, mod], cwd=ROOT, env=env, ...)
```

**实测**：73 个守卫用例全通过，且 `outputs` / `exports` / `cache` / `temp` / `logs` / `uploads`
**六个运行时目录文件数零变化**。

> **这是「逐个修自检」与「守卫层统一改向」的分野**：
> 前者要**枚举所有会污染的自检**并逐个改（且明天新增模块照样漏）；
> 后者只需知道「污染都经由 `config` 的目录常量」这一条结构性事实，
> 就能**一次覆盖全部**并自动覆盖未来模块 —— 与 146 的护栏、145 的元检查是**同一思路**。
