# 阶段 374 · 首屏不再等 205 MB 模型下载

> 日期 2026-11-04 · 性质：**首屏体验修复（不改检测能力、不改承诺）**

## 一、问题（真机实测，不是推测）

`wme` 启动时先 `ensure_model_ready()` → 缺权重就**同步下载 205 MB**，下载完才 `launch_ui()`。
本机实测：GitHub 不可达时回退 `ghproxy` 只有 ~50 KB/s ⇒ 用户要盯着空终端 **几十分钟**，
而实际上程序**完全可以用 OpenCV 引擎先跑起来**（LaMa 只是效果增强）。

## 二、改法

1. **启动分两条路**（`main.model_startup_action`，纯函数）：
   - `"sync"`：权重已就位 ⇒ 同步预热（首屏即可用 LaMa）；
   - `"background"`：缺失 ⇒ **界面先起**（OpenCV 可用）+ 后台守护线程下载、预热。
2. **OCR 预热不再依赖权重**：从 `warm_up_model` 抽出 `_warm_up_ocr()`，两条路都在启动期触发
   （否则缺失权重时首个检测请求会冷启动卡顿）。
3. **防半写文件**：`model_manager` 新增进程内 `_DOWNLOAD_IN_PROGRESS` 标记 +
   `is_downloading()`；`is_model_available()` 在下载中**恒返回 False**；
   `download_model` 用 `try/finally` 保证成功/失败/回滚三种结局后都清标记。
   引擎选择本来就是**每次请求现查**（`core/inpainter` 调 `is_model_available()`），
   所以下载完成后下一次处理自动用上 LaMa，**无需重启**。

## 三、守卫

- `tests/test_model_bg_start374.py`（4 例）：
  启动策略两分支；下载中 `is_model_available` 必须 False；下载失败后标记必须清掉；
  后台准备线程**吞异常**（下载失败不能拖崩界面）。
- `tests/test_main_entry.py`：编排顺序改为两条路径——
  有模型 `banner→env→perf→device→warmup→launch`；缺模型 `…→background→launch` 且**不同步预热**；
  selftest 路径仍不得触发任何模型步骤。

## 四、实测

```
WME_MODEL_DIR=<空目录> python main.py
→ UI 就绪 5s（curl http=200），日志同时出现「未检测到 LaMa 权重：界面现在启动…」与
  「未检测到当前模型（lama），开始自动下载 ...」
```

CI 等价入口：`rc=0`（3421 passed / 38 skipped / 6 deselected，456.79s）。

⚠ 入口第一次跑时红了一次，**不是 374 的缺陷**：编码守卫把 gitignored 的 `.scratch/` 探针也当
"入口"扫（本地随手写个带 `⇒/✓` 的探针就能让它变红，而 CI 上没有该目录、永远看不到）。
已把 `.scratch` 加进该守卫的跳过集（与其它守卫的 `.scratch` 约定一致）。

## 五、边界

- 后台下载仍走既有源（GitHub → ghproxy 回退），**没有新增镜像**；
- 未在安装态（wheel）上重复本实验：用的是源码树 + 空模型目录模拟「首次运行」；
- 「模型管理」页查看进度是既有功能，本次未改；
- 若下载在国内网络彻底失败，界面依旧可用 OpenCV，只是没有 LaMa 效果（措辞已告知）。
