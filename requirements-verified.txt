#  为什么要单独留一份（阶段 347）：
#
#    阶段 297 的决定是「把 requirements 清单对齐到本机已验证的 venv 版本」，
#    出发点是好的：CI 装的和本机跑的是同一套版本，测出来的数字才有意义。
#    但它把「本机能装到」误当成了「PyPI 上有这个版本」——
#    本机 opencv 5.0.0.93 是从 CI 源码树（D:\a\opencv-python）构建出来的，
#    不是 PyPI 稳定发行版。⇒ 从那次改动起，CI 每次都红在 pip install
#    （26~92 秒，跑不完入口步），**照 README 装包的用户同样装不上**。
#
#    现在的分工：
#      · requirements-min.txt   —— **安装**用。下界 = 上一版 CI 装成功过的版本，
#                                  上界 = 本文件里这套验证过的版本。
#      · requirements-verified.txt —— **记录**用。这套组合本机验证过、门禁数字就是它测出来的；
#                                  以后要复现同一组数字时按这份装。
#
#  守卫：tests/test_requirements_ci_installable.py
#        （① 安装清单里的精确 pin 必须在「CI 装成功过」的集合内；
#          ② 其余包必须用区间；③ 本文件必须存在且被安装清单的上界覆盖。）
